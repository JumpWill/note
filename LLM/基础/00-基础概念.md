# LLM 基础概念

## 模型与架构

### LLM (Large Language Model, 大语言模型)

基于海量文本训练的概率模型，给定上文预测下一个 token。代表：GPT、Claude、Llama、Qwen、DeepSeek。

### Token

模型处理的最小文本单位。一个 token ≈ 0.75 个英文单词 ≈ 1-2 个中文字符。`cl100k_base` (GPT-4) 中文平均约 1.5 字/token。

用途：计费、上下文长度计算、控制生成。

### Transformer

当前 LLM 的基础架构 (Vaswani et al., 2017)。核心是 **Self-Attention** + Feed-Forward + Residual + LayerNorm。

- Encoder-only：BERT (理解类)
- Decoder-only：GPT 系 (生成类，主流 LLM 都用)
- Encoder-Decoder：T5 (翻译/摘要)

### Attention / Self-Attention

让序列中每个位置都能"看到"其他所有位置并加权聚合。Q、K、V 三个矩阵来自同一输入。

复杂度 O(n²)，是长上下文的主要瓶颈。

多头 (Multi-Head)：并行多组 Q/K/V，捕获不同子空间关系。

### KV Cache

推理时缓存已生成的 K/V，避免每步重算。自回归解码的标准优化，代价是显存占用与序列长度成正比。

## 训练流程

### Pre-training (预训练)

在无标注文本上用 **next-token prediction** 训练，得到 base 模型。成本极高 (千卡·月级)，数据 TB 级。

### Fine-tuning (微调)

在预训练模型上用小规模标注数据继续训练，适配下游任务。

- **SFT (Supervised Fine-Tuning)**：有监督指令微调，用 (指令, 回答) 对。
- **LoRA / QLoRA**：低秩适配，只训练少量参数，显存友好。

### RLHF (Reinforcement Learning from Human Feedback)

三步：SFT → 训练奖励模型 RM → PPO 优化策略。让模型对齐人类偏好。

### DPO (Direct Preference Optimization)

跳过 RM 和 PPO，直接用偏好对训练。RLHF 的简化替代，效果相当，训练更稳。

## 损失函数

### Loss Function (损失函数)

衡量模型预测与真实值的差距，训练目标就是最小化它。LLM 训练几乎只用 **交叉熵**。

### Cross-Entropy Loss (交叉熵)

分类/语言模型的标配。LLM 的 next-token prediction 就是对词表上每个 token 做多分类：

L = -∑ yᵢ log(pᵢ)

其中 yᵢ 是 one-hot 真实标签，pᵢ 是 softmax 后的预测概率。实践中：

- 每个 token 算一次，取平均
- 忽略 padding (用 `ignore_index=-100`)
- 数值技巧：log_softmax + NLLLoss 合在一起算，避免 log(0)

### Perplexity (困惑度, PPL)

语言模型的核心评估指标。**PPL = exp(L)**，直观含义：模型在每一步"有多困惑"。

PPL=10 表示模型平均在 10 个候选 token 里犹豫，越低越好。训练时 loss 下降，PPL 同步下降。

### MSE / MAE / Huber (回归损失)

- **MSE (L2)**：(y - ŷ)²，对异常值敏感
- **MAE (L1)**：|y - ŷ|，更鲁棒但梯度不连续
- **Huber**：小误差用 L2，大误差用 L1，两者折中

LLM 中一般不用，但在奖励模型、回归任务、扩散模型中常见。

### Contrastive Loss (对比损失)

拉近正样本对、拉远负样本对。代表：

- **InfoNCE**：CLIP、对比学习标配
- **Triplet Loss**：anchor / positive / negative 三元组
- **NT-Xent (SimCLR)**：归一化温度 + 交叉熵

Embedding 模型训练的核心损失。

### Ranking Loss (排序损失)

用于学习相对顺序而非绝对值：

- **MarginRankingLoss**：score(+) - score(-) > margin
- **Listwise (ListNet / ListMLE)**：整个列表的排序损失

检索、重排 (reranker) 任务常用。

### Focal Loss

对易分类样本降权、难样本加权，解决类别不平衡。公式：(1-pᵧ)^γ · CE。在目标检测、稀疏多分类 (如长尾意图) 中常用。

### Label Smoothing

把硬标签 (one-hot) 软化一点，比如 0.9 / 0.1 / 0.1... 防止模型过度自信、提升泛化。代价：PPL 看起来会升高，accuracy 可能略降，但实际下游任务更稳。

## 推理与生成

### Prompt

输入给模型的全部文本：系统提示 + 用户消息 + 上下文 + 问题。

### Context Window (上下文窗口)

模型一次能处理的最大 token 数。超出则截断或压缩 (RAG、摘要)。

- Claude Sonnet 4: 200K / 1M
- GPT-4 Turbo: 128K
- 早期模型: 2K~8K

### Temperature

控制采样随机性。

- T=0：贪心，最确定
- T=1：标准
- T>1：更发散 (容易胡言)

建议：事实/代码 0~0.3，创意 0.7~1.0。

### Top-p (Nucleus Sampling) / Top-k

- **Top-k**：只在概率最高的 k 个 token 里采样
- **Top-p**：累积到概率 p 截止 (动态集合大小)

通常 top_p=0.9~0.95 + 温度调优。

### Inference (推理)

模型生成输出的过程。区分 **训练** (training) 和 **推理** (inference)。

## 能力与限制

### Emergent Ability (涌现能力)

规模跨过某阈值后突然出现的能力 (如 CoT、零样本推理)。存在但被部分研究质疑。

### Hallucination (幻觉)

模型自信地生成看似合理但事实错误的内容。原因：训练数据噪声、解码方式、缺乏真实世界校验。

缓解：RAG、工具调用、Self-Check、低温度、引用溯源。

### Few-shot / Zero-shot

- **Zero-shot**：只给指令，不给示例
- **Few-shot**：在 prompt 中给几个示例再提问

### Chain-of-Thought (CoT, 思维链)

让模型"一步步想"，对推理/数学题显著提升。变体：

- **Self-Consistency**：多次采样投票
- **Tree of Thoughts (ToT)**：搜索多条思路

## 检索与增强

### RAG (Retrieval-Augmented Generation)

生成前先从知识库检索相关片段放进 prompt。解决知识陈旧、领域知识缺乏、私域数据问题。

流程：文档切片 → Embedding → 存入向量库 → 查询时召回 → 拼入 prompt → 生成。

### Embedding (嵌入)

把文本映射到稠密向量 (768~4096 维)，语义相似的文本距离近。用于语义检索、聚类、相似度。

### Vector Database (向量数据库)

存向量并支持 ANN (近似最近邻) 检索。代表：Milvus、Qdrant、Pinecone、pgvector、Chroma。

## 评估与对齐

### Benchmark

评测集。通用：MMLU、HumanEval、GSM8K、MT-Bench。中文：C-Eval、CMMLU。

### Alignment (对齐)

让模型行为符合人类意图和价值观 (Helpful / Honest / Harmless)。

### System Prompt / System Message

开发者给模型的隐藏指令，控制风格、角色、约束、工具使用规范。用户看不到。

## 部署与工程

### Quantization (量化)

把 FP16/BF16 权重压到 INT8/INT4，减小显存和加速推理，损失少量精度。代表：GPTQ、AWQ、GGUF。

7B 模型：FP16 ≈ 14G，INT4 ≈ 4G。

### Batching / Continuous Batching

多个请求合并推理。vLLM 的 continuous batching 把"生成完的请求"立刻换出，吞吐提升数倍。

### Speculative Decoding (投机解码)

小模型先草拟若干 token，大模型一次性验证/接受。加速 2~3x，质量无损。

### MoE (Mixture of Experts)

把 FFN 拆成多个"专家"，每次只激活部分 (如 Mixtral 8x7B 激活 2)。总参数大、推理成本低。
