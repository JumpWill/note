# 集群成本规划 (Cluster Cost Planning)

## 一、成本规划概述

### 什么是集群成本规划

**集群成本规划 (Cluster Cost Planning)** 是围绕**服务器规模、网络带宽、存储容量、数据库、中间件、运维和人力**,在满足业务可用性与性能 SLO 的前提下,**以可量化的方式预测、分配、控制和优化**集群全生命周期支出的工程实践。

**本质**:把"花钱"从"月底看账单"变成"持续可治理的工程问题"——让每一笔成本都可归因、可预测、可优化、可决策。

**核心目标**:

- **可预测**:在扩容、新业务上线前就能估算成本
- **可归因**:成本能拆分到业务、团队、服务、环境
- **可控制**:有预算、阈值和审批,防止意外超支
- **可优化**:识别浪费、低 ROI 资源、僵尸资源
- **可决策**:成本与 SLO 联动,避免"过度可用"或"过度廉价"
- **可演进**:支持业务增长、缩容和架构演进的成本模型

### 成本构成的常见维度

- **基础设施**:服务器、网络、存储、CDN、镜像分发
- **平台服务**:数据库、缓存、消息队列、对象存储、大数据组件
- **软件许可**:商业数据库、中间件、可观测平台、安全产品
- **运维与人力**:值班、SRE、容量规划、故障演练
- **能源与机房**:电力、冷却、机柜、跨地域传输

> 基础设施层面的成本,**80% 以上集中在服务器规模和网络带宽**——这是本文重点。

---

## 二、成本规划的核心视角

站在不同立场,看到的是不同问题:

| 视角 | 关心什么 | 关键问题 |
|------|----------|----------|
| **业务方** | 收入 vs 成本 | 增长带来多少成本?能否盈利? |
| **平台 / SRE** | 资源利用率、容量 | 还能撑多久?什么时候扩容? |
| **财务** | 预算、账单、可预测性 | 是否超预算?原因在哪? |
| **架构师** | 架构选择 vs 成本 | 自建 vs 托管 vs Serverless? |
| **运维** | 日常支出 | 哪些是浪费?哪些可以降配? |

> 成本规划需要**多视角共识**:不能只看技术最优,也不能只看财务最省。

## 三、服务器规模 (Server Capacity) 成本

### 1. 服务器规模与成本的关系

服务器规模是集群成本的**第一权重**,通常占基础设施成本的 **50%~70%**。

```text
总成本 ≈ 节点数 × 单价 × 运行时长
         + 扩容频率 × 边际成本
         + 资源闲置成本
```

- **节点数**:决定账单基数
- **节点规格**:CPU、内存、磁盘比例决定单价
- **运行时长**:小时 × 单价 = 月度账单
- **资源闲置率**:资源在低峰期的浪费

### 2. 服务器规模的核心指标

| 指标 | 含义 | 成本含义 |
|------|------|----------|
| **节点总数** | 集群中物理/虚拟节点数 | 决定基础成本 |
| **CPU 核心数** | 可分配 vCPU 总量 | 计算型业务主要成本 |
| **内存容量** | 可分配内存总量 | 内存密集型业务主要成本 |
| **本地磁盘** | 节点本地存储 | 日志、临时文件 |
| **节点规格** | 单节点 CPU:内存比 | 不同业务需要不同配比 |
| **单机利用率** | 节点平均利用率 | 利用率越低,单位成本越高 |
| **单机峰值利用率** | 节点最高利用率 | 决定是否需要扩容 |
| **节点生命周期** | 上线到下架时间 | 折旧与换代成本 |
| **机型代次** | ARM vs x86、新一代 vs 上一代 | 单位算力单价持续下降 |

### 3. 节点规模估算方法

#### 按业务规模估算

```text
所需节点数 ≈
  业务 QPS × 单请求 CPU 时间
  / 单节点 CPU 容量
  / 利用率系数 (0.6~0.7)
  / 故障冗余系数 (1+1/N)
```

#### 按容量估算

```text
所需节点数 =
  max(总 CPU 请求 / 单节点 CPU 容量,
      总内存请求 / 单节点内存容量)
  / 利用率系数
  / 冗余系数
```

#### 按增长估算

```text
未来 N 月节点数 = 当前节点数 × (1 + 月增长率) ^ N
```

> 永远要为**峰值、滚动发布、节点维护、故障转移**预留冗余。经验值:**平均利用率 50%~60%**,峰值不超过 80%。

### 4. 节点规格选型

- **计算型**:高 CPU、低内存——网关、API、批处理
- **内存型**:高内存、低 CPU——缓存、内存数据库
- **存储型**:大磁盘——数据库、日志服务
- **GPU / NPU**:AI 训练、推理
- **ARM vs x86**:ARM 通常单价更低,生态在不断完善
- **裸金属 vs 虚拟机**:性能 vs 弹性

> **节点规格要按业务画像选型**,避免"什么都用最大规格"。

### 5. 服务器成本优化手段

- **节点整合**:小规格节点整合为更少大规格节点,提高利用率
- **混部 (Colocation)**:在线 + 离线业务混合部署
- **弹性伸缩**:HPA + Cluster Autoscaler
- **Spot / 抢占式实例**:批处理、可中断任务
- **预留实例 / Savings Plans**:长期负载折扣
- **ARM 化**:同性能下单价更低
- **资源画像**:对每个服务建立 CPU/内存画像,拒绝"大锅饭"
- **节点池化**:按业务类型拆分节点池,独立伸缩
- **缩容策略**:低峰期缩容、闲置节点回收

## 四、网络带宽 (Network Bandwidth) 成本

### 1. 带宽的隐性成本

**网络带宽是除服务器外的第二大成本**,而且非常容易**被低估**:

- 跨可用区 (AZ) 流量
- 跨地域 (Region) 流量
- 互联网出口流量
- CDN 回源流量
- 内部服务间东西向流量
- 镜像分发、备份、日志同步

> **服务器内"免费",跨网"按 GB 收费"**——这是云上和 IDC 最大的差异。

### 2. 带宽计费模式

| 模式 | 适用 | 风险 |
|------|------|------|
| **按流量 (GB)** | 弹性、不可预测业务 | 突发流量导致账单失控 |
| **按带宽 (Mbps)** | 稳定大流量业务 | 低利用率时浪费 |
| **包年包月** | 长期稳定 | 资源浪费 |
| **CDN 阶梯** | 大流量分发 | 不同阶梯单价差异大 |

### 3. 带宽消耗的核心指标

| 指标 | 含义 | 关注点 |
|------|------|--------|
| **入向流量** | 公网入方向 | 通常免费,但有限速 |
| **出向流量** | 公网出方向 | **主要计费项** |
| **跨 AZ 流量** | 同 Region 不同 AZ | 通常按 GB 收费 |
| **跨 Region 流量** | 不同 Region 之间 | **单价最高** |
| **CDN 回源** | CDN 回源到源站 | 命中率低时成本飙升 |
| **东西向流量** | Pod ↔ Pod、Pod ↔ DB | 在云上同样计费 |
| **P95 带宽** | 95 分位带宽峰值 | 决定带宽包大小 |

### 4. 流量规模估算

#### 入口流量

```text
公网出流量 ≈
  日活用户数 × 每用户流量 × 并发系数
  + 爬虫、SDK 升级
  + API 出口流量
```

#### 内部东西向流量

```text
服务 A → 服务 B 流量 ≈
  A 的 QPS × 平均响应大小 × 调用 B 的概率
```

#### 跨 AZ / 跨 Region

```text
跨 AZ 流量 ≈
  跨 AZ 调用次数 × 平均请求大小
  + 跨 AZ 同步 / 复制流量
```

> 跨 Region 流量是**隐性大头**:异地多活、数据同步、灾备演练都会产生。

### 5. 带宽成本优化手段

- **CDN 加速**:静态资源、媒体内容、图片
- **压缩**:HTTP 压缩、gRPC/Protobuf、协议优化
- **缓存**:本地缓存、分布式缓存,减少后端重复传输
- **就近接入**:边缘节点、单元化
- **合并请求**:批量接口、GraphQL
- **跨 AZ 调度**:把强一致服务放同 AZ,弱一致服务容忍跨 AZ
- **专线 / VPC Peering**:高流量场景比按量便宜
- **镜像分发优化**:P2P、镜像分层、节点本地缓存
- **日志压缩与采样**:日志传输往往占大量带宽
- **预热 / 预取**:减少冷流量回源
- **WebSocket / 长连接复用**:替代频繁短连接

## 五、存储成本

### 1. 存储类型与成本

| 存储 | 用途 | 单价 | 优化点 |
|------|------|------|--------|
| **本地 SSD** | 节点本地 | 便宜 | 临时数据、缓存 |
| **块存储** | 数据库、有状态 | 较贵 | IOPS 不要过度预留 |
| **对象存储** | 图片、备份、日志 | 便宜(分阶梯) | 生命周期管理 |
| **文件存储** | 共享文件 | 中 | 避免大目录 |
| **归档存储** | 冷数据 | 极便宜 | 解冻成本与时长 |

### 2. 存储成本的核心指标

- 总量、增长率
- IOPS、吞吐
- 副本数、纠删码比例
- 冷热数据比例
- 备份保留时长
- 跨地域复制流量

### 3. 优化手段

- **冷热分层**:热数据 SSD、温 HDD、冷归档
- **数据生命周期**:自动降冷、过期清理
- **去重与压缩**:备份、日志、对象存储
- **副本策略**:纠删码替代多副本
- **删除孤儿**:被遗忘的 PV、镜像、备份

## 六、数据库与中间件成本

数据库往往是**单点最贵**的资源:

- **关系数据库**:RDS 实例规格、磁盘、备份、副本
- **NoSQL**:Redis 容量、连接数、副本
- **搜索引擎**:ES 节点数、磁盘、Shard 规划
- **数据仓库**:按扫描量、存储量、计算量
- **消息队列**:Topic/分区、存储时长、副本

### 优化思路

- **规格匹配实际负载**,避免"开局最大"
- **读写分离、分库分表**,分散单点压力
- **冷热数据分层**,大表分离
- **共享 vs 独享**:核心业务独享,通用业务共享
- **托管 vs 自建**:评估总拥有成本 (TCO)
- **License 优化**:商业软件审计与按需

---

## 七、人力与运维成本

常被忽视的"看不见的成本":

- **值班与响应**:7x24 值班、On-call
- **故障复盘与改进**:每次事故都有人力代价
- **容量规划与扩容**:人工评估、灰度验证
- **合规审计**:等保、SOC2、GDPR
- **培训与知识传递**

> **自动化每减少 1 小时人工,持续 3 年就能省出一台服务器的钱**——自动化是 ROI 最高的投入。

## 八、成本规划的方法论

### 1. 自下而上 (Bottom-Up)

- 从单个服务估算
- 累计到集群
- 适合新业务、精细化运营

### 2. 自上而下 (Top-Down)

- 从总预算反推
- 分配到各业务
- 适合预算约束强、增长期

### 3. 混合法

- 业务侧:自上而下定预算
- 平台侧:自下而上汇总
- 双向校验,避免漏算

### 4. 三种典型模型

- **基线模型**:满足现有业务
- **增长模型**:加上业务增长
- **峰值模型**:满足大促、活动峰值

> **永远要规划峰值**,而不是平均。

## 九、FinOps:云成本治理框架

### 1. FinOps 三大阶段

```text
Inform (知)   →  Allocate (分)   →  Optimize (优)   →  Operate (持续)
```

- **Inform**:让团队看到自己的成本
- **Allocate**:把成本归属到团队、项目
- **Optimize**:识别浪费,实施优化
- **Operate**:持续治理和文化建设

### 2. 核心实践

- **Showback**:让团队看到自己消耗的成本
- **Chargeback**:真正向团队收费(内部转账)
- **预算告警**:超预算自动通知
- **成本仪表盘**:每日、每周、每月趋势
- **标签规范**:业务、环境、团队、负责人必填
- **异常检测**:识别异常账单

### 3. 团队协作

- 财务 + 工程 + 业务三方对齐
- FinOps 团队或兼职 Owner
- 成本回顾会 (Cost Review)

## 十、成本优化的常见场景

### 1. 服务器规模优化

| 现象 | 可能原因 | 优化手段 |
|------|----------|----------|
| **平均利用率 < 30%** | 规格过大、冗余过多 | 降配、整合、混部 |
| **峰值经常 100%** | 容量不足 | 弹性扩容、限流 |
| **节点数增长过快** | 业务增长超预期 | 容量预测、提前采购 |
| **节点大量空跑** | 资源请求过大 | 调整 requests |
| **P95/P99 高** | 长尾请求、热点 | 性能优化、缓存 |

### 2. 网络带宽优化

| 现象 | 可能原因 | 优化手段 |
|------|----------|----------|
| **公网出流量激增** | 视频、图片、爬虫 | CDN、压缩、防盗链 |
| **跨 AZ 流量高** | 服务跨 AZ 调用 | 同 AZ 调度、降副本 |
| **CDN 回源率高** | 命中率低 | 缓存策略、预热 |
| **内部服务间流量大** | 频繁调用、大响应 | 合并接口、压缩 |
| **跨 Region 流量高** | 同步链路、灾备 | 异步、压缩、降频 |

### 3. 存储优化

| 现象 | 可能原因 | 优化手段 |
|------|----------|----------|
| **存储增长失控** | 无清理策略 | 生命周期、TTL |
| **备份占用过高** | 备份过频、过久保留 | 增量、压缩、归档 |
| **PV 大量存在** | StatefulSet、孤儿 PVC | 自动回收 |

## 十一、成本规划的实施步骤

### 1. 建立基线

1. 梳理当前账单与资源清单
2. 拆解到团队、服务、环境
3. 标记浪费和异常
4. 形成首份"成本基线报告"

### 2. 引入治理

1. 统一标签规范,强制 metadata
2. 部署成本可观测 (Kubecost、Vantage)
3. 制定预算与告警
4. 设立成本 Owner

### 3. 持续优化

1. 月度成本回顾
2. 季度容量规划
3. 半年架构评审 (成本维度)
4. 年度预算与采购

### 4. 文化落地

1. 成本纳入绩效考核
2. 重大变更要做成本影响评估
3. 优化案例分享
4. 与 SLO 联动,避免"过度可用"

## 十二、成本与 SLO / 性能的平衡

> **不要为了省钱牺牲 SLO,也不要为了 SLO 过度堆资源。**

- **过度可用**:三个 9 的服务用五个 9 的资源
- **过度廉价**:服务频繁超时
- **黄金分割**:在 SLA 范围内找到成本最优解

### 1. 决策矩阵

| 业务等级 | 资源冗余 | 弹性策略 | 备份策略 |
|----------|----------|----------|----------|
| **核心交易** | 高(>50%) | 弹性 + 预留 | 多地域实时 |
| **重要业务** | 中(30%~50%) | 弹性为主 | 同城 + 异地 |
| **一般业务** | 低(<30%) | 完全弹性 | 同城 |
| **内部工具** | 极低 | Spot / Serverless | 弱备份 |

### 2. 容量 vs 成本曲线

```text
成本
  ↑             ╭──── 过度可用区
  │           ╱
  │         ╱
  │       ╱
  │     ╱  ← 甜蜜点:利用率 50%~70%
  │   ╱
  │ ╱ ← 危险区:利用率 > 80%,故障风险
  └──────────→ 容量
```

## 十三、容量规划与成本预测

### 1. 容量预测方法

- **线性回归**:简单业务
- **季节性模型**:电商、内容
- **业务驱动预测**:订单量、用户量
- **机器学习预测**:复杂场景

### 2. 预测输入

- 业务计划 (新功能、新市场)
- 增长曲线 (DAU/MAU/订单)
- 季节性 (大促、节假日)
- 性能优化 (单实例能力提升)

### 3. 预测输出

- 未来 N 个月的 CPU、内存、带宽、存储需求
- 节点扩容/缩容计划
- 预算预测

### 4. 安全余量

- 峰值冗余:30%~50%
- 故障冗余:N+1 或 N+2
- 发布冗余:滚动期间双倍容量

## 十四、采购与计费策略

### 1. 实例类型选择

| 类型 | 折扣 | 适用 |
|------|------|------|
| **按量** | 0% | 短期、突发 |
| **包年包月** | 30%~50% | 稳定基线 |
| **预留实例 (RI)** | 40%~60% | 1~3 年稳定 |
| **Savings Plans** | 30%~50% | 灵活承诺 |
| **Spot** | 60%~90% | 可中断任务 |
| **Serverless** | 视使用 | 极低频或极高弹性 |

### 2. 跨云 / 多云策略

- **避免厂商锁定**:核心服务可迁移
- **利用价格差异**:计算在 A 云,存储在 B 云
- **风险分散**:避免单云故障
- **成本管理复杂度**:多云也意味着多套账单治理

### 3. 长期采购

- 提前 3~6 个月规划
- 利用厂商促销 (节日、行业活动)
- 折扣换承诺,承诺换稳定性

## 十五、成本监控与告警

### 1. 监控维度

- 每日 / 每周 / 每月账单
- 按团队、服务、环境拆分
- 同比 / 环比
- 异常波动检测

### 2. 告警规则

- 单日账单超阈值
- 月度累计超预算 X%
- 某服务成本突增 X%
- 资源利用率持续过低

### 3. 工具

- 云厂商成本中心
- Kubecost (K8s 成本)
- Vantage、CloudHealth
- 自建 PromQL + 账单数据

## 十六、组织与流程

### 1. 成本 Owner

- 每个核心服务有成本 Owner
- Owner 负责:规划、优化、复盘
- 与 SLO Owner 可以是同一人

### 2. 变更的成本评审

- 新服务上线前:成本估算
- 重大架构变更:成本对比
- 大促前:成本预案
- 缩容 / 下线:成本回收确认

### 3. 定期复盘

- 月度成本回顾
- 季度架构评审
- 年度战略对齐

## 十七、常见误区

- **只看总账单,不看分项**:大数遮盖异常
- **过度关注单价,忽略总量**:便宜资源堆出高成本
- **忽略隐性成本**:跨 AZ 流量、备份、镜像
- **平均利用率 < 30% 还继续扩容**:先整合再扩容
- **只算技术成本,不算人力**:值班、运维也是钱
- **预留实例买了又不用**:浪费更严重
- **省钱影响 SLO**:得不偿失
- **标签缺失,无法归因**:无法优化
- **大促才想扩容**:临时扩容溢价高
- **预算只做一年**:跟不上业务节奏

## 十八、核心要点速记

### 服务器规模

- 服务器规模是**第一大成本**,占基础设施 50%~70%
- 节点规格要**按业务画像**选型,不搞"一刀切"
- **平均利用率 50%~60%,峰值不超过 80%**
- 整合、混部、弹性是三大优化方向
- ARM、Spot、预留实例可显著降本
- 节点规格选错,后期改造成本极高

### 网络带宽

- 带宽是**第二大成本**,且最容易被低估
- 跨 Region 流量单价最高,**慎用异地同步**
- 跨 AZ 也按 GB 收费,强一致服务同 AZ
- **CDN + 压缩 + 缓存**是降带宽三大法宝
- 日志、镜像、备份是隐藏带宽大户
- P95 带宽决定带宽包大小,别只看平均

### 治理与文化

- 成本是**工程问题**,不是财务问题
- **FinOps** = Inform → Allocate → Optimize → Operate
- 每笔成本都要**有 Owner、有标签、有预算**
- 成本回顾与架构评审要**定期进行**
- 优化要看**每请求/每用户/每订单成本**
- **不要为了省钱牺牲 SLO**,也不要堆资源
- 自动化 ROI 极高,1 小时人工节省 3 年就是一台服务器
- 容量规划要预测**峰值,不是平均**
- 标签规范是成本归因的前提,缺失等于没有治理

### 容量与采购

- 容量规划 = 基线 + 增长 + 峰值 + 冗余
- 提前 3~6 个月采购,利用促销
- 长期稳定负载用 RI/SP,弹性负载用 Spot/Serverless
- 大促临时扩容溢价高,**用弹性而非一次性买大**
