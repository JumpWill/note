# 容器与编排 (Containers & Orchestration)

## 一、容器概述

### 什么是容器

**容器**:在操作系统层面虚拟化,**共享内核**的轻量级"虚拟机"

- 进程级隔离
- 共享宿主机 OS
- 比 VM 启动快、体积小
- 主流实现:Docker、containerd、CRI-O、Podman

### 容器 vs 虚拟机

| 维度       | 容器             | 虚拟机              |
|------------|------------------|---------------------|
| 启动       | 毫秒-秒          | 秒-分钟             |
| 大小       | MB               | GB                  |
| 性能       | 接近原生         | 接近原生(2-5% 损耗) |
| 隔离       | 进程级(较弱)     | 系统级(强)          |
| 启动密度   | 100-1000/机      | 10-50/机            |
| OS         | 共享宿主         | 独立 OS             |
| 镜像       | 几 MB-几 GB      | 几 GB-几 TB         |
| 适用       | 微服务、CI/CD    | 多 OS、强隔离       |

### 容器发展史

```
2000s  - chroot, FreeBSD Jails
2008    - LXC (Linux Containers)
2013    - Docker 出现(基于 LXC)
2014    - Rocket、rkt
2015    - Kubernetes 1.0
2015    - CNCF 成立
2016+   - 容器编排大战
2018+   - K8s 成为事实标准
2020s   - 云原生, eBPF, 服务网格
```

## 二、容器底层技术

### 1. Linux 内核特性

容器是基于**Linux 内核的进程隔离机制**,不是真正的"容器"。

**关键技术**:
- **Namespaces**: 资源隔离(进程、网络、文件系统等)
- **Cgroups**: 资源限制(CPU、内存、IO)
- **Union FS**: 镜像分层(ausfs、overlay2)
- **Capabilities**: 权限细分

详见 [02-层次结构.md](02-层次结构.md) 第九节 (虚拟化与容器时代的层次结构)

### 2. Namespaces

| 类型     | 隔离内容            |
|----------|---------------------|
| PID      | 进程 ID             |
| Network  | 网络                |
| Mount    | 文件系统挂载        |
| UTS      | 主机名              |
| IPC      | 进程间通信          |
| User     | 用户和组            |
| Cgroup   | cgroup 根           |
| Time     | 时钟 (Linux 5.6+)   |

**查看进程的命名空间**:

```bash
ls -l /proc/$$/ns/
readlink /proc/$$/ns/pid
```

**创建命名空间**:

```bash
unshare -p -n -m -f bash    # 新的 PID + Network + Mount + Fork
nsenter -t PID -p -n -m bash   # 进入已存在的命名空间
```

### 3. Cgroups (v1 vs v2)

**Cgroup v1**:每个资源独立挂载点
- `/sys/fs/cgroup/cpu/`
- `/sys/fs/cgroup/memory/`
- `/sys/fs/cgroup/blkio/`

**Cgroup v2** (统一层次):
- `/sys/fs/cgroup/cgroup.subtree_control`
- 启用控制器: `echo "+cpu +memory" > cgroup.subtree_control`

**cgroup 操作**:

```bash
# 创 cgroup
mkdir /sys/fs/cgroup/myapp

# 限制 CPU
echo 100000 > /sys/fs/cgroup/myapp/cpu.max    # 100ms / 100ms = 1 核

# 限制内存
echo 1G > /sys/fs/cgroup/myapp/memory.max

# 限制 IO
echo "253:0 1048576" > /sys/fs/cgroup/myapp/io.max    # 1MB/s

# 加进程
echo 1234 > /sys/fs/cgroup/myapp/cgroup.procs
```

### 4. 联合文件系统 (Union FS)

**Union FS**:多个目录"叠加"成一个,只读层 + 可写层

**驱动**:
- **aufs**: 旧版 Docker 默认
- **overlay2**: 现代推荐
- **btrfs / zfs**: 高端选择
- **vfs**: 不支持分层(慢)

**镜像分层**:

```text
Layer 4 (可写)     <- 容器运行时修改
Layer 3 (只读)     <- RUN 命令
Layer 2 (只读)     <- apt-get install
Layer 1 (只读)     <- COPY ./app
Layer 0 (只读)     <- FROM ubuntu
```

### 4. Dockerfile 详解

**Dockerfile 指令**:

| 指令        | 作用                                |
|-------------|-------------------------------------|
| FROM        | 基础镜像                            |
| LABEL       | 标签                                |
| ENV         | 环境变量                            |
| ARG         | 构建参数                            |
| WORKDIR     | 工作目录                            |
| USER        | 用户                                |
| VOLUME      | 数据卷                              |
| EXPOSE      | 暴露端口                            |
| COPY        | 复制文件(本地)                      |
| ADD         | 复制文件(支持 URL、tar)             |
| RUN         | 执行命令                            |
| CMD         | 容器启动命令(可被覆盖)              |
| ENTRYPOINT  | 入口点                              |
| ONBUILD     | 镜像作为基础镜像时触发              |
| STOPSIGNAL  | 停止信号                            |
| HEALTHCHECK | 健康检查                            |
| SHELL       | 默认 shell                          |

**示例 (Node.js 应用)**:

```dockerfile
# 多阶段构建
FROM node:20-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 运行时镜像
FROM node:20-alpine
LABEL maintainer="alice@example.com"
ENV NODE_ENV=production
WORKDIR /app
COPY --from=builder /app/dist ./dist
COPY package*.json ./
RUN npm ci --only=production
USER node
EXPOSE 3000
HEALTHCHECK --interval=30s --timeout=3s \
    CMD wget -qO- http://localhost:3000/health || exit 1
CMD ["node", "dist/index.js"]
```

**最佳实践**:
- 基础镜像用 alpine / distroless
- 多阶段构建减小镜像
- 不用 root 运行
- 不在 Dockerfile 存密钥
- 用 .dockerignore
- 合并 RUN 命令
- 利用层缓存

## 五、Kubernetes (K8s)

### 1. 什么是 K8s

**Kubernetes (K8s)**:Google 开源的**容器编排平台**

- 自动化部署、扩缩容、运维
- 跨主机容器管理
- 服务发现、负载均衡
- 自愈能力
- 滚动更新、回滚

### 2. 架构

```
┌─────────────── Master/Control Plane ───────────────┐
│  ┌──────┐ ┌──────┐ ┌─────────┐ ┌─────────┐ ┌─────┐  │
│  │ API  │ │Sched │ │ Controller│ │  etcd  │ │ CM  │  │
│  │Server│ │uler  │ │ Manager │ │  KV     │ │     │  │
│  └──┬───┘ └──┬───┘ └─────────┘ └─────────┘ └─────┘  │
└─────┼────────┼─────────────────────────────────────────┘
      │        │
      ▼        ▼
┌──────── Worker Node ─────────┐
│  ┌────┐  ┌────┐  ┌────┐       │
│  │kubelet│ │kube-proxy│ │       │
│  └────┘  └────┘  └────┘       │
│  ┌───Container Runtime──┐     │
│  │ ┌──┐ ┌──┐ ┌──┐     │     │
│  │ │P1│ │P2│ │P3│ ...  │     │
│  │ └──┘ └──┘ └──┘     │     │
│  └──────────────────────┘     │
└──────────────────────────────┘
```

### 3. 核心概念

#### (1) Pod

**Pod**:K8s 最小部署单位,1+ 个共享网络的容器

- 共享 PID、Network、IPC
- 共享存储卷
- 同一调度单元
- 同一生命周期

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: myapp
  labels:
    app: myapp
spec:
  containers:
  - name: web
    image: nginx:1.25
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"
    livenessProbe:
      httpGet:
        path: /
        port: 80
      initialDelaySeconds: 3
      periodSeconds: 3
    readinessProbe:
      httpGet:
        path: /
        port: 80
```

#### (2) Deployment

**Deployment**:Pod 的副本管理

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:1.25
        ports:
        - containerPort: 80
```

#### (3) Service

**Service**:为一组 Pod 提供稳定访问入口

```yaml
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP   # ClusterIP / NodePort / LoadBalancer / ExternalName
```

**类型**:
- **ClusterIP**: 默认,仅集群内
- **NodePort**: 每个 Node 暴露端口
- **LoadBalancer**: 云 LB
- **ExternalName**: CNAME

#### (4) Ingress

**Ingress**:HTTP/HTTPS 路由

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web
spec:
  rules:
  - host: example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: web
            port:
              number: 80
  tls:
  - hosts:
    - example.com
    secretName: web-tls
```

### 5. K8s 架构组件

#### 控制平面 (Control Plane)

- **kube-apiserver**: API 入口
- **etcd**: 分布式 KV 存储
- **kube-scheduler**: Pod 调度
- **kube-controller-manager**: 控制器
- **cloud-controller-manager**: 云厂商集成

#### Worker 节点

- **kubelet**: 节点 agent
- **kube-proxy**: 网络代理
- **container runtime**: 容器运行时 (containerd, CRI-O)

#### 关键插件

- **CNI**: 网络(Flannel, Calico, Cilium)
- **CSI**: 存储
- **CRI**: 容器运行时
- **DNS**: CoreDNS

### 6. K8s 网络模型

- 每个 Pod 有独立 IP
- Pod 之间可以直接通信(无 NAT)
- 节点和 Pod 可以通信
- 容器间共享网络(同一 Pod)

**CNI 插件**:
- **Flannel**: 简单 overlay

### 8. K8s 实用操作

    cpu: 500m

  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 30
  periodSeconds: 10
  failureThreshold: 3
readinessProbe:
  httpGet:
    path: /ready
    port: 8080

  periodSeconds: 5

# 节点亲和
affinity:
  nodeAffinity:
    requiredDuringSchedulingIgnoredDuringExecution:
      nodeSelectorTerms:
      - matchExpressions:
        - key: kubernetes.io/hostname
          operator: In
          values: [node1, node2]

# Pod 反亲和
affinity:
  podAntiAffinity:
    preferredDuringSchedulingIgnoredDuringExecution:
    - weight: 100
      podAffinityTerm:
        topologyKey: kubernetes.io/hostname
        labelSelector:
          matchLabels:
            app: web

# 污点容忍
tolerations:
- key: "dedicated"
  operator: "Equal"
  value: "gpu"
  effect: "NoSchedule"

- **K8s** = 容器编排事实标准
- **Pod** = K8s 最小单位,共享网络
- **Deployment** = 无状态 Pod 副本
- **StatefulSet** = 有状态
- **DaemonSet** = 每 Node 跑一个
- **Service** = 稳定的访问入口
- **Ingress** = HTTP/HTTPS 路由
- **ConfigMap / Secret** = 配置
- **HPA** = 自动水平扩缩
- **PV/PVC** = 持久卷
- **kubectl apply -f** = 声明式
- **kubectl get pods -A** = 看所有
- **kubectl logs -f** = 跟踪
- **kubectl exec -it** = 进入
- **kubectl port-forward** = 端口转发
- **kubectl rollout undo** = 回滚
- **kubectl describe** = 排查
- **Namespaces**: 进程/网络/挂载/UTS/IPC/User
- **Cgroups v2**: 统一 /sys/fs/cgroup/
- **Overlay2** = 现代联合 FS
- **Virtio** = 容器内推荐驱动
- **CNI** = 容器网络 (Calico/Cilium/Flannel)
- **CSI** = 容器存储
- **Falco** = 运行时安全
- **Trivy** = 镜像扫描
- **Cosign** = 镜像签名
- **GitOps** = 仓库即真理
- **多阶段构建** = 减小镜像
- **不存密钥** = 用 Secret/环境变量
- **alpine / distroless** = 小镜像
- **不用 root** = USER 1000
- **资源限制** = requests + limits
- **健康检查** = liveness + readiness
- **镜像标签** = 用版本号,不 latest
