# 虚拟化 (Virtualization)

## 一、虚拟化概述

### 什么是虚拟化

**虚拟化**:用软件模拟硬件,让一台物理机变成多台逻辑机器

- 物理资源(CPU、内存、IO) 抽象成逻辑资源
- 多个 VM 共享一套硬件
- 资源隔离,互不影响

### 虚拟化的好处

- **资源利用率**:一台机器跑多 VM
- **隔离**:VM 之间互不影响
- **灵活**:快速创建、销毁、迁移 VM
- **降低成本**:少买物理机
- **快照/克隆**:快速部署
- **高可用**:VM 漂移 (Live Migration)
- **灾备**:VM 复制到异地

### 虚拟化类型

| 类型                  | 全称                          | 适用           |
|-----------------------|-------------------------------|----------------|
| **全虚拟化**          | Full Virtualization           | 通用           |
| **半虚拟化**          | Para-Virtualization (PV)      | 性能更好       |
| **硬件辅助虚拟化**    | Hardware-assisted (HVM)       | 现代主流       |
| **操作系统级虚拟化**  | OS-level (容器)               | 轻量           |
| **裸金属虚拟化**      | Bare-metal (Type 1)           | 企业           |
| **寄居虚拟化**        | Hosted (Type 2)               | 桌面           |

## 二、CPU 虚拟化

### 1. x86 保护环 (Privilege Ring)

```text
Ring 0  - 内核 (最高权限)
Ring 1  - 系统服务 (很少用)
Ring 2  - 系统服务 (很少用)
Ring 3  - 用户应用 (最低权限)
```

- 传统 x86:内核 Ring 0,应用 Ring 3
- 虚拟化:需要 VM 内核也能跑 Ring 0

### 2. 虚拟化技术

**全虚拟化 (Full Virtualization)**:
- VM 内核以为自己在 Ring 0
- 实际被 Hypervisor 拦截(Trap-and-Emulate)
- 无需修改 Guest OS
- 性能较差(陷入再模拟)

**半虚拟化 (Para-Virtualization)**:
- 修改 Guest OS,知道自己是 VM
- 通过 Hypercall 与 Hypervisor 通信
- 性能好,但需改 OS
- 例: Xen (早期 PV)

**硬件辅助虚拟化 (HVM)**:
- CPU 提供虚拟化扩展
- **Intel VT-x** (vmx)
- **AMD-V** (svm)
- 性能接近原生
- 现代默认

### 3. 关键特性

**CPU 虚拟化扩展**:
- VMCS (Virtual Machine Control Structure)
- VM Entry / VM Exit
- EPT (Extended Page Tables) - 二级页表
- NPT (Nested Page Tables) - AMD
- VPID (Virtual Processor ID)

**CPU 模式**:
- 根模式 (Root Mode) - Hypervisor
- 非根模式 (Non-Root Mode) - Guest

## 三、内存虚拟化

### 1. 影子页表 (Shadow Page Table)

- 早期方案
- Guest 页表 → Host 页表(影子)
- VMM 维护一致性
- 性能差(Trap 频繁)

### 2. EPT / NPT (扩展页表)

- **Intel EPT (Extended Page Tables)**
- **AMD NPT (Nested Page Tables)**
- **硬件支持的二级页表**

```text
Guest 虚拟地址
   ↓ Guest 页表
Guest 物理地址
   ↓ EPT/NPT
Host 物理地址 (真实)
```

- 一次地址翻译
- TLB 缓存效率高
- 性能接近原生

### 3. 大页支持

- 2 MB / 1 GB 大页
- 减少 TLB miss
- VM 启动时配置
- KVM: `<memory backed='hugepages'>`

## 四、IO 虚拟化

### 1. IO 虚拟化方案

| 方案            | 性能 | 兼容性 | 特点             |
|-----------------|------|--------|------------------|
| **全模拟**      | 差   | 高     | 模拟硬件,通用    |
| **半虚拟化**    | 中   | 中     | Virtio,需驱动    |
| **PCI 直通**    | 高   | 中     | 设备直接分配 VM  |
| **SR-IOV**      | 极高 | 低     | 硬件虚拟化       |

### 2. Virtio (半虚拟化 IO)

- **Virtio**:标准半虚拟化 IO 框架
- Guest 有 virtio 驱动(前端)
- Host 有 virtio 后端 (QEMU / vhost)
- 比全模拟快几倍

**Virtio 设备**:
- **virtio-net**:网络
- **virtio-blk**:块设备
- **virtio-scsi**:SCSI
- **virtio-balloon**:内存气球(动态内存)
- **virtio-gpu**:GPU
- **virtio-9p**:文件系统共享

**变种**:
- **vhost-net/virtio-net**: 内核态后端,高性能
- **vhost-user**: 用户态后端
- **vDPA (vhost Data Path Acceleration)**: 硬件加速

### 3. PCI 直通 (Passthrough)

- **VFIO** (Virtual Function I/O): Linux 内核驱动
- 物理设备直接分配给 VM
- VM 独占设备,性能接近原生
- 需要 IOMMU (Intel VT-d / AMD-Vi)
- 适合:高性能网卡、GPU、NVMe

```bash
# 查看 IOMMU
dmesg | grep -i iommu
# 启动参数
intel_iommu=on
amd_iommu=on
```

### 4. SR-IOV (Single Root I/O Virtualization)

- 物理设备虚拟出**多个虚拟功能 (VF)**
- 每个 VF 可分配给不同 VM
- 性能接近原生,接近裸金属
- 适用:SR-IOV 网卡、GPU

```bash
# 查 SR-IOV 网卡
lspci -nn | grep -i ethernet
# 看 VF
cat /sys/bus/pci/devices/*/sriov_totalvfs
cat /sys/bus/pci/devices/*/sriov_numvfs
# 启用
echo 4 > /sys/bus/pci/devices/0000:01:00.0/sriov_numvfs
```

### 5. 设备直通 vs 共享设备

- **直通 (Passthrough)**: 设备专属一个 VM
- **共享设备**: 多 VM 共享
- SR-IOV 两者兼顾

## 五、主流虚拟化方案

### 1. KVM (Kernel-based Virtual Machine)

**KVM**:Linux 内核内置的虚拟化(基于硬件辅助)

- **开源、免费**
- Linux 内核一部分(从 2.6.20 起)
- 需要硬件支持 (Intel VT-x / AMD-V)
- 常与 QEMU 结合使用

**架构**:
```
Guest → QEMU (用户态模拟) → KVM (内核) → 硬件
```

**KVM 工具**:
- **libvirt**: API 管理
- **virsh**: 命令行
- **virt-manager**: GUI
- **virt-install**: 创建 VM
- **virt-clone**: 克隆

**KVM 安装**:
```bash
# RHEL/CentOS
yum install qemu-kvm libvirt virt-install virt-manager

# 启用
systemctl enable --now libvirtd

# 验证
lsmod | grep kvm
lscpu | grep Virtualization
virt-host-validate
```

### 2. QEMU (Quick Emulator)

**QEMU**:通用机器模拟器 + 虚拟化

- **开源、免费**
- 单独使用:纯模拟(慢)
- + KVM:硬件加速
- 支持多种架构:x86、ARM、MIPS、PowerPC

### 3. KVM + QEMU 实战

```bash
# 创建 VM (命令行)
virt-install \
    --name myvm \
    --ram 2048 \
    --vcpus 2 \
    --disk size=20 \
    --cdrom /tmp/ubuntu.iso \
    --network bridge=br0 \
    --graphics vnc,listen=0.0.0.0

# 启动
virsh start myvm
virsh list --all

# 看
virsh console myvm
virsh domdisplay myvm
virsh dominfo myvm

# 关机/重启/暂停
virsh shutdown myvm
virsh reboot myvm
virsh suspend myvm
virsh resume myvm

# 删除
virsh destroy myvm
virsh undefine myvm

# 资源调整
virsh setmem myvm 4G
virsh setvcpus myvm 4

# 快照
virsh snapshot-create-as myvm snap1 "first snapshot"
virsh snapshot-list myvm
virsh snapshot-revert myvm snap1

# 克隆
virt-clone -o myvm -n myvm-clone -f /var/lib/libvirt/images/clone.qcow2

# 控制台
virt-manager    # GUI
virt-viewer myvm  # 看
```

### 4. libvirt XML 配置

```bash
virsh dumpxml myvm > myvm.xml
virsh edit myvm
```

```xml
<domain type='kvm'>
  <name>myvm</name>
  <memory unit='KiB'>2097152</memory>
  <vcpu>2</vcpu>
  <os>
    <type arch='x86_64'>hvm</type>
    <boot dev='cdrom'/>
  </os>
  <devices>
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2'/>
      <source file='/var/lib/libvirt/images/myvm.qcow2'/>
      <target dev='vda' bus='virtio'/>
    </disk>
    <interface type='bridge'>
      <source bridge='br0'/>
      <model type='virtio'/>
    </interface>
    <graphics type='vnc' port='-1'/>
  </devices>
</domain>
```

### 5. 磁盘格式

| 格式            | 特点                               |
|-----------------|------------------------------------|
| **raw**         | 原始,无额外开销,大                 |
| **qcow2**       | QEMU 复制写入,支持快照、压缩、加密 |
| **vmdk**        | VMware 格式                        |
| **vhd / vhdx**  | Hyper-V 格式                       |

**qcow2 优势**:
- 稀疏(实际占用 < 分配)
- 快照
- 压缩
- 加密

```bash
# 创建 qcow2
qemu-img create -f qcow2 -o size=20G,preallocation=metadata myvm.qcow2

# 查信息
qemu-img info myvm.qcow2

# 转换
qemu-img convert -f raw -O qcow2 input.img output.qcow2
qemu-img convert -O vmdk input.qcow2 output.vmdk

# 调整大小
qemu-img resize myvm.qcow2 +10G
```

### 6. 网络

**NAT (默认)**:
- VM 通过 Host 访问外网
- 简单

**Bridge**:
- VM 与 Host 同网段
- 性能好

**Host-only**:
- VM 之间互连
- 不通外网

**Macvtap**:
- 高性能,无 bridge

```bash
# 创建 bridge
ip link add br0 type bridge
ip link set eth0 master br0
ip link set br0 up

# 永久(在 /etc/network/interfaces 或 netplan)
```

## 六、其他虚拟化方案

### 1. Xen

- **半虚拟化 (PV)** 和 **硬件辅助 (HVM)**
- 高性能,云厂商用
- AWS 早期基于 Xen
- 复杂,管理工具少

### 2. VMware vSphere / ESXi

- **商业,企业主流**
- 成熟、稳定
- 贵的:许可费
- vCenter 管理
- vMotion 实时迁移

### 3. Hyper-V

- **微软虚拟化**
- Windows Server 内置
- 适合 Windows 环境
- 集成度高

### 4. VirtualBox

- **Oracle,免费**
- Type 2 寄居虚拟化
- 适合桌面、测试
- 跨平台

### 5. Proxmox VE

- **开源,企业级**
- 基于 KVM + LXC
- 集成 Web UI
- 类似 vSphere
- 商业订阅可选

### 6. oVirt / RHV

- **红帽虚拟化**
- 基于 KVM
- 已被 RHEL 弃用
- 但 oVirt 社区继续

## 七、虚拟机迁移

### 1. 实时迁移 (Live Migration)

**实时迁移**:VM 在不停机的情况下,从一个物理机迁到另一个

- 内存同步(预拷贝、停机拷贝、后拷贝)
- 短暂停机(毫秒级)
- 适合维护、负载均衡

### 2. 迁移方式

- **冷迁移 (Cold)**: 关停后迁
- **热迁移 (Live)**: 边跑边迁
- **存储迁移**:只迁存储
- **混合迁移**:VM + 存储

### 3. KVM 实时迁移

```bash
virsh migrate --live myvm qemu+ssh://dest/system
# 或指定参数
virsh migrate --live --copy-storage-all myvm qemu+ssh://dest/system
```

### 4. vSphere vMotion

- ESXi 专属
- 业界标杆
- 与 HA / DRS 集成

## 八、虚拟化性能

### 1. 性能损耗

- **CPU 虚拟化**: 1-5% (硬件辅助)
- **内存虚拟化**: 1-3% (EPT)
- **IO 虚拟化**: 5-30% (virtio 模式)
- **网络虚拟化**: 5-20% (vhost)

### 2. 性能优化

- **CPU**: Pinning (绑核)、NUMA 拓扑
- **内存**: 大页、balloon 调优
- **IO**: virtio 驱动、多队列、io_uring
- **网络**: vhost-net、SR-IOV、DPDK

### 3. 性能监控

```bash
# 主机看 VM
virsh domstats myvm
virsh domifstat myvm vnet0
virsh domblkstat myvm vda

# VM 看资源
top
iostat 1
```

## 十、Type 1 vs Type 2

### Type 1 (Bare-Metal / 裸金属)

- **直接装在硬件上**
- 性能好
- 企业首选
- 例:ESXi、Xen、KVM、Hyper-V Server

### Type 2 (Hosted / 寄居)

- **装在 OS 上**
- 性能差
- 桌面首选
- 例:VirtualBox、VMware Workstation

### 架构对比

```
Type 1:
硬件 → Hypervisor → VM
硬件 → Hypervisor (在硬件上)

Type 2:
硬件 → Host OS → Hypervisor → VM
```

## 十四、虚拟化实战案例

### 1. 部署 Web VM

```bash
# 创建
virt-install \
    --name web1 \
    --ram 4096 \
    --vcpus 4 \
    --disk size=50,format=qcow2,bus=virtio \
    --cdrom /tmp/ubuntu-22.04.iso \
    --network bridge=virbr0,model=virtio \
    --graphics vnc,listen=0.0.0.0,password=secret \
    --noautoconsole

# 看
virsh list --all
virsh domifaddr web1

# 启动
virsh start web1
```

### 2. 性能调优 (高 IO)

```bash
# 用 virtio + 多队列 + 大页
# 磁盘
--disk bus=virtio,cache=writeback,io=native
# 网络
--network model=virtio,driver.iommu=on
# CPU
--cpu host-passthrough
# 内存
--memory backing='hugepages=on'
```

### 3. 实时迁移

```bash
# 源
virsh migrate --live \
    --copy-storage-all \
    --verbose \
    myvm qemu+ssh://dest-host/system
```

### 4. 备份

```bash
# 快照
virsh snapshot-create-as myvm backup-$(date +%F)

# 导出
virsh dumpxml myvm > myvm.xml
qemu-img convert -O qcow2 myvm.qcow2 myvm-backup.qcow2

# 完整备份(停机)
virsh shutdown myvm
qemu-img convert -O qcow2 -c myvm.qcow2 myvm-backup.qcow2
virsh start myvm
```

## 十六、虚拟化面试题

### 1. 虚拟化的关键挑战

> **CPU 虚拟化**:指令集(特权指令)、中断
> **内存虚拟化**:Guest 物理地址 → Host 物理地址
> **IO 虚拟化**:设备模拟、共享、半虚拟化

### 2. 全虚拟化 vs 半虚拟化

> **全虚拟化**:Guest OS 不修改,模拟所有硬件
> **半虚拟化**:Guest OS 知道自己是 VM,通过 Hypercall 通信
> **半虚拟化性能更好**,但需改 OS

### 3. 影子页表 vs EPT

> **影子页表**:VMM 维护,Trap 同步
> **EPT**:硬件二级页表,一次翻译
> **EPT 快得多**

### 4. KVM 是怎么工作的

> KVM 是 Linux 内核模块,把 Linux 变成 Hypervisor。
> 配合 QEMU (用户态) 提供完整虚拟化。

### 5. 实时迁移步骤

> 1. 预拷贝: 反复拷贝内存
> 2. 停机拷贝: 停 VM,拷剩余
> 3. 在目标机恢复
> 4. 切换网络

### 6. 容器 vs VM

> **VM**:完整 OS,强隔离,启动慢
> **容器**:共享内核,轻量,启动快
> **VM 适合多 OS / 强隔离**
> **容器适合微服务 / 高密度**

### 7. SR-IOV 工作原理

> 物理网卡 (PF) 虚拟出多个虚拟功能 (VF)
> 每个 VF 可分配给不同 VM
> 性能接近裸金属,绕过虚拟化层

### 8. 虚拟化性能损耗

> - CPU: 1-5%
> - 内存: 1-3%
> - IO: 5-30% (virtio 5-10%, 全模拟 30%)
> - 网络: 5-20%
