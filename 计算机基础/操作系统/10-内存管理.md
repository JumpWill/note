# 内存管理 (Memory Management)

## 一、内存管理概述

### 为什么需要内存管理

- **多道程序**:多个程序同时驻留内存,需要隔离
- **保护**:进程 A 不能访问进程 B 的内存
- **高效利用**:有限物理内存容纳更多程序
- **抽象**:给每个进程"独享"大内存的假象

### 内存管理的目标

| 目标       | 说明                                         |
|------------|----------------------------------------------|
| **抽象**   | 提供线性、连续、独立的地址空间               |
| **保护**   | 进程间互不干扰,内核受保护                    |
| **共享**   | 安全地共享数据(库、IPC)                      |
| **虚拟化** | 物理内存不够时,部分放磁盘                    |
| **高效**   | 提高内存利用率,减少碎片                      |

### 内存层次 (速度由快到慢,容量由小到大,成本由高到低)

```text
寄存器      ~ 1 ns      几百字节      CPU 内
L1 Cache    ~ 1-2 ns    几十 KB       CPU 内
L2 Cache    ~ 3-10 ns   几百 KB~几 MB CPU 内/附近
L3 Cache    ~ 10-20 ns  几 MB~几十 MB  CPU 共享
主存 (DRAM) ~ 50-100 ns 几 GB~几十 GB 系统
SSD         ~ 50-200 μs 几百 GB~几 TB
HDD         ~ 5-15 ms   几 TB
远程存储     秒级         几乎无限
```

**核心**:利用**局部性原理**(时间/空间)让 90% 访问命中上层。

## 二、地址空间

### 1. 三种地址

| 名称                    | 含义                                  | 谁产生          |
|-------------------------|---------------------------------------|-----------------|
| **逻辑地址** (虚拟地址) | 进程看到的地址                        | CPU/编译器      |
| **线性地址**            | 段机制转换后的地址                    | 段机制          |
| **物理地址**            | 实际内存芯片上的地址                  | MMU/物理硬件    |

### 2. 地址转换

```text
逻辑地址 → [段机制] → 线性地址 → [页机制 + MMU] → 物理地址
                                                  ↑
                                            TLB 加速
```

### 3. CPU 寻址能力

- **32 位 CPU**:2^32 = 4 GB
- **64 位 CPU**:2^64 = 16 EB(实际只用到 48 位,256 TB)

## 三、内存管理方案 (无虚拟内存)

### 1. 单一连续分配 (Single Contiguous)

- 内存分两半:系统区 + 用户区
- 一个用户程序独占用户区
- **缺点**:内存浪费,只能跑一个程序
- 早期 OS 用(MS-DOS)

### 2. 固定分区 (Fixed Partition)

- 内存分成几个固定大小的分区
- 每个分区装一个程序
- **缺点**:内部碎片,程序小于分区会浪费

### 3. 动态分区 (Variable Partition)

- 按程序大小分配
- **外部碎片**严重
- 需要**合并 / 紧缩 (compaction)**
- 适合批处理

### 4. 简单方案对比

| 方案     | 优点       | 缺点                  |
|----------|------------|-----------------------|
| 单一连续 | 简单       | 单用户,浪费           |
| 固定分区 | 实现简单   | 内部碎片,大小固定     |
| 动态分区 | 无内部碎片 | 外部碎片,合并成本高   |

## 四、虚拟内存 (Virtual Memory)

### 1. 虚拟内存的核心思想

**给每个进程一个独立、连续、超大(可能比物理内存还大)的地址空间**。

- 程序按"虚拟地址"编程
- 实际运行时,部分数据在内存,部分在磁盘
- 缺失时,内核把磁盘数据调到内存
- 程序感觉不到,以为自己独享大内存

### 2. 虚拟内存的好处

- **隔离**:每个进程独立的地址空间
- **扩展**:地址空间可超过物理内存
- **共享**:同一物理页可映射到多个进程(如共享库)
- **保护**:权限检查防越权
- **简化**:程序员无需关心物理内存布局

### 3. 虚拟内存需要解决的问题

- **地址转换**:虚拟地址 → 物理地址
- **缺页处理**:数据不在内存时从磁盘调入
- **页面置换**:内存满时换出哪一页
- **一致性**:多进程共享同一物理页时

## 五、分页 (Paging) - 核心方案

### 1. 基本概念

- 把**虚拟地址空间**和**物理内存**都分成固定大小的块
- **虚拟页 (Virtual Page, VP)**:虚拟地址空间中的块
- **物理页帧 (Page Frame, PF)**:物理内存中的块
- **页大小**:通常 4 KB(其他:2 MB、1 GB 大页)

### 2. 虚拟地址结构

```text
32 位虚拟地址:
┌─────────────────┬─────────────┐
│   页号 (20 bit) │ 页内偏移(12 bit) │
└─────────────────┴─────────────┘
       ↑                ↑
   20 位页号         12 位偏移 (4KB)

64 位虚拟地址 (4 级页表):
┌──────┬──────┬──────┬──────┬──────┐
│ PGD  │ PUD  │ PMD  │ PTE  │Offset│
│ 9    │ 9    │ 9    │ 9    │ 12   │
└──────┴──────┴──────┴──────┴──────┘
```

### 3. 页表 (Page Table)

- **页表项 (PTE)**:记录虚拟页到物理页帧的映射
- 页表本身存放在内存中

**PTE 内容**:

| 字段                 | 含义                       |
|----------------------|----------------------------|
| 物理页帧号           | 物理页的基地址             |
| 有效位 (V)           | 1=在内存,0=在磁盘          |
| 访问位 (A)           | 是否被访问过               |
| 修改位 (D)           | 是否被修改过(脏位)         |
| 权限位 (R/W/X)       | 读写执行权限               |
| 用户/内核位          | 用户态/内核态可访问        |
| 缓存位 (PWT,PCD,PAT) | 缓存策略                   |
| 全局位 (G)           | 是否全局(TLB 刷新策略)     |

**典型 PTE (x86 4KB 页)**:

```text
63          54 53      52 51   12 11  9 8  7 6    5    4    3   2   1   0
┌────────────┬──────────┬───────┬─────┬──────┬─────┬─────┬─────┬─────┐
│  保留/扩展 │  PROTKEY │ 保留  │ PAT │ AVAIL│  D  │  A  | PCD | PWT |US/RW|P |
└────────────┴──────────┴───────┴─────┴──────┴─────┴─────┴─────┴─────┘
```

### 4. 地址转换过程

```text
CPU 发出虚拟地址 VA
        ↓
    MMU 查 TLB
    ├─ TLB 命中 → 直接得到物理地址
    └─ TLB 缺失 → 查页表
            ├─ 页表命中 → 获得物理地址,更新 TLB
            └─ 页表无效 (P=0) → 缺页异常 (Page Fault)
                                  ├─ 合法 → 从磁盘调入,更新页表
                                  └─ 非法 (如空指针) → SIGSEGV
```

### 5. 缺页 (Page Fault)

**发生条件**:访问的页不在物理内存(PTE 的 P 位 = 0)

**处理流程**:

```text
1. CPU 触发缺页异常
2. 内核检查:
   - 地址是否合法?
   - 权限是否够?
3. 合法:
   a. 找一个空闲物理页(没有就换出)
   b. 从磁盘读数据到该物理页
   c. 更新页表
   d. 重新执行该指令
4. 非法:
   - 发 SIGSEGV,进程被杀
```

**缺页类型**:

| 类型                  | 原因                       | 是否可避免                |
|-----------------------|----------------------------|---------------------------|
| **强制缺页** (冷启动) | 第一次访问                 | 不可避免                  |
| **容量缺页**          | 物理内存装不下工作集       | 加大内存                  |
| **冲突缺页**          | 映射算法导致反复换出       | 改用全相联 / 优化替换算法 |

### 6. 多级页表 (Multi-Level Page Table)

**为什么需要**:
- 32 位:1 级页表 4 MB
- 64 位:1 级页表 2^52 字节(不可能)
- 多级页表按需分配

**32 位 2 级页表**:

```text
10 bits       10 bits       12 bits
┌──────────┬────────────┬──────────┐
│ 页目录号 │  页表号    │ 页内偏移 │
│  (PGD)   │   (PTE)    │ (Offset) │
└──────────┴────────────┴──────────┘
       ↓              ↓
  1024 个页目录项  1024 个页表项
```

**64 位 4 级页表** (x86_64):

- PGD (Page Global Directory)
- PUD (Page Upper Directory)
- PMD (Page Middle Directory)
- PTE (Page Table Entry)
- Offset (页内偏移)

### 7. 大页 (Huge Page)

**为什么需要大页**:
- 大量小页 → TLB 压力大 → 大量 TLB miss
- 大页 → TLB 命中率高 → 性能提升

**x86 大页**:

| 大小       | 用途               | 名称                 |
|------------|--------------------|----------------------|
| 2 MB       | 标准大页           | `hugepages`          |
| 1 GB       | 透明大页 / 巨型页  | `gigantic pages`     |

**配置** (Linux):

```bash
# 默认大页
echo 1024 > /proc/sys/vm/nr_hugepages
# 1G 大页
echo 4 > /sys/kernel/mm/hugepages/hugepages-1048576kB/nr_hugepages

# 挂载
mount -t hugetlbfs hugetlbfs /mnt/huge

# 透明大页 (THP)
echo always > /sys/kernel/mm/transparent_hugepage/enabled
```

**应用场景**:
- 数据库 (Oracle、MySQL、PostgreSQL)
- 大型 JVM 应用
- 内存密集型 HPC

### 8. 反向页表 (Inverted Page Table)

**思想**:用物理页框索引,记录哪个进程的哪个虚拟页在该物理页

**优点**:
- 页表大小只与物理内存成正比
- 64 位系统必备方案

**代表**:
- **PowerPC**
- **IBM POWER / z/Architecture**
- **x86_64 的 HMM (Heterogeneous Memory Management) 部分使用**

## 六、TLB (Translation Lookaside Buffer)

### 1. 什么是 TLB

**TLB**:**页表的硬件缓存**,MMU 内部,极快(~1 ns)

**作用**:把"虚拟页号 → 物理页框"的映射缓存起来

### 2. TLB 工作过程

```text
CPU 发出虚拟地址
   ↓
MMU 查 TLB
├─ 命中 (hit) → 直接获得物理页框,无需查内存中的页表
└─ 缺失 (miss) → 查页表,得到 PTE,填充 TLB
                  (可能引发缺页,见上文)
```

### 3. TLB 性能指标

- **TLB 命中率**:理想 > 99%
- **TLB 缺失开销**:~10-30 个周期(查页表)
- **缺页开销**:~几百万个周期(磁盘 I/O)

**性能公式**:

```
T_avg = T_TLB_hit × P_hit + T_TLB_miss × (1 - P_hit)
```

### 4. TLB 刷新 (TLB Flush)

**什么时候刷新**:

- **进程切换**:不同进程的页表不同,必须刷
- **页表修改**:内核改页表后,需"invalidate"对应 TLB 项

**刷新的开销**:

- 简单实现:把所有 TLB 项标为无效(代价大)
- **ASID (Address Space ID)**:为每个进程分配 ID,TLB 项带 ASID,不需整体刷新
- **PCID (Process Context ID)** (x86):类似 ASID

### 5. TLB 优化

- **大页**:减少 TLB 项数
- **预取**:预测未来访问,提前加载 TLB
- **HugeTLB**:显式大页
- **THP (Transparent Huge Pages)**:自动大页(可能反而降级,需谨慎)
- **ASLR / KASLR**:地址空间随机化

## 七、内存分配器 (Allocator)

### 1. 内核内存分配

#### (1) 页分配器 (Page Allocator)

- **基本单位**:页 (4 KB)
- **伙伴系统 (Buddy System)**:
  - 内存按 2^n 划分块(1, 2, 4, 8, 16, ..., 1024 页)
  - 申请:找满足大小的最小块,不够就拆
  - 释放:相邻的"伙伴"块就合并
  - 减少**外部碎片**

**buddy 分配示例**:

```text
申请 4 页
   1. 找 2^2=4 页的空闲块
   2. 没找到 → 找 2^3=8 页
   3. 找到 8 页 → 拆成两个 4 页
   4. 一个分配出去,一个放回 4 页的空闲链表
```

#### (2) slab 分配器 (Linux 经典)

**问题**:伙伴系统分配粒度太粗(最小 4 KB),内核中很多小对象(struct、inode)更小。

**解决**:**slab / slub / slob**

- **slab**:把多个小对象装在一个或多个页中
- **slub**:slab 的改进版,更简单,Linux 默认
- **slob**:极简,嵌入式

**工作原理**:

```text
┌─ kmem_cache ─────────────┐
│  32-byte 对象的 cache   │
│                          │
│  ┌─────────────────┐    │
│  │  slab 1         │    │
│  │  - 多个 object   │    │
│  │  - 空闲链表      │    │
│  └─────────────────┘    │
│  ┌─────────────────┐    │
│  │  slab 2         │    │
│  └─────────────────┘    │
└──────────────────────────┘
```

**优势**:

- 减少内部碎片
- 对象分配极快(从 cache 取)
- 常用对象有"热缓存"
- 减少换页 (因为 object 连续)

#### (3) vmalloc

- **用于分配虚拟连续、物理不连续的内存**
- 适合大块(几 MB)的非 DMA 内存
- 通过页表映射实现虚拟连续

#### (4) GFP flags

```c
GFP_KERNEL     // 通用,可睡眠
GFP_ATOMIC     // 不可睡眠,中断上下文
GFP_DMA        // 分配 DMA 内存
GFP_USER       // 用户态可访问
GFP_HIGHUSER   // 高端内存(> 1GB)
GFP_NOIO       // 不能启动 IO
GFP_NOFS       // 不能启动 FS
```

### 2. 用户内存分配

#### (1) malloc / free (C 库)

- 内部用 **brk / mmap** 系统调用
- 小分配用 brk(堆顶指针上推)
- 大分配用 mmap(独立映射区域)
- glibc 用 ptmalloc2 算法

**malloc 内存布局**:

```text
高地址
  栈 (向下)
  ↓
  共享区 (mmap)
  ↑
  堆 (向上) ← brk
  BSS
  数据段
  代码段
低地址
```

#### (2) 内存池 (Memory Pool)

**用途**:预分配内存,避免运行时分配失败

- **jemalloc** (FreeBSD、Firefox、Redis)
- **tcmalloc** (Google)
- **mimalloc** (Microsoft)
- **ptmalloc** (glibc 默认)

#### (3) C++ new/delete

- 底层是 malloc / free
- 但对象构造/析构

#### (4) Java GC

- 标记-清除
- 标记-整理
- 复制算法
- 分代收集 (Young/Old)
- G1、ZGC、Shenandoah

## 八、内存保护与安全

### 1. 内存保护机制

#### (1) 段保护 (x86)

- 段描述符中的 DPL (Descriptor Privilege Level)
- 与 CPL 比较,决定访问权限
- **现代 OS 基本不用段机制**(64 位模式退化)

#### (2) 页保护 (主流)

- **R/W 位**:可读/可写
- **U/S 位**:用户态可访问/仅内核态
- **NX (No Execute) 位**:禁止执行(防代码注入)
- **写时复制 (COW)**:父子进程共享只读页

#### (3) 内存保护键 (Memory Protection Keys, MPK)

- x86 MPK / PKU
- 每个页有 4 位 key
- 线程的 PKRU 寄存器决定 key 的访问权限
- 高效的细粒度保护

#### (4) ASLR (Address Space Layout Randomization)

- 栈、堆、库、mmap、二进制位置随机化
- 防止攻击者猜测地址
- Linux 1:1 随机化、PIE、Stack canary 等

### 2. 内存越界与漏洞

| 漏洞类型                 | 描述                         | 防御               |
|--------------------------|------------------------------|--------------------|
| **栈溢出**               | 函数返回地址被覆盖           | Stack Canary、ASLR |
| **堆溢出**               | 堆元数据被破坏               | 安全的分配器       |
| **UAF** (Use After Free) | 释放后继续使用               | 引用计数、GC       |
| **Double Free**          | 同一块内存释放两次           | 安全的分配器       |
| **整型溢出**             | 算术运算溢出导致逻辑错误     | 安全的类型         |
| **TOCTOU**               | 检查和使用之间被改变         | 原子操作           |

### 3. 内存加固 (Memory Hardening)

- **KASLR**:内核地址随机化
- **KASAN**:内核地址消毒器(检测越界/UAF)
- **SMAP/SMEP**:防止内核访问用户态
- **影子内存 (Shadow Memory)**:用元数据检测越界

## 九、内存映射 (mmap)

### 1. mmap 概述

**mmap**:把文件或设备映射到进程地址空间

**好处**:

- 比 read/write 高效(少一次内核→用户拷贝)
- 多进程可共享同一映射
- 适合大文件操作

### 2. mmap 类型

| 类型                       | 说明                            |
|----------------------------|---------------------------------|
| **FILE-backed mmap**       | 把文件映射到内存                |
| **Anonymous mmap**         | 匿名映射(无文件),如 malloc 大块 |
| **Shared mmap**            | 多进程共享,MAP_SHARED           |
| **Private mmap**           | 写时复制,MAP_PRIVATE            |

### 3. mmap 用法

```c
#include <sys/mman.h>

// 把文件映射到内存
int fd = open("data.txt", O_RDWR);
struct stat sb;
fstat(fd, &sb);
char *p = mmap(NULL, sb.st_size, PROT_READ|PROT_WRITE,
               MAP_SHARED, fd, 0);
// 像访问数组一样访问 p
p[0] = 'a';
munmap(p, sb.st_size);
close(fd);

// 匿名映射
char *p = mmap(NULL, 4096, PROT_READ|PROT_WRITE,
               MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
```

### 4. mmap 在数据库中的应用

- **mmap 文件**:InnoDB、SQLite、LevelDB、RocksDB
- **mmap 设备**:高性能驱动

## 十、Swap (交换分区/文件)

### 1. 什么是 Swap

**Swap**:把内存中不活跃的页换出到磁盘,腾出空间给活跃页。

**作用**:

- 扩展虚拟内存(总可用空间 = 物理内存 + swap)
- **支持休眠 (Hibernate)**:系统断电后,从 swap 恢复

### 2. Swap 类型

| 类型          | 优点                    | 缺点             |
|---------------|-------------------------|------------------|
| **Swap 分区** | 性能稳定,无文件系统开销 | 分区大小固定     |
| **Swap 文件** | 灵活,可调大小           | 略慢(有 FS 开销) |

**现代推荐:Swap 文件**(可动态调整大小)

### 3. Swap 大小建议

| 物理内存 | 建议 swap 大小              |
|----------|-----------------------------|
| < 2 GB   | 内存 × 2                    |
| 2-8 GB   | 等于内存                    |
| 8-64 GB  | 4-8 GB(可不要)              |
| > 64 GB  | 一般不需要,可配 1-2 GB 应急 |

### 4. Swap 配置

```bash
# 创建 swap 文件
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile

# 写 /etc/fstab
/swapfile none swap sw 0 0

# swap 优先级
swapon -p 10 /swapfile
```

### 5. Swappiness

**`vm.swappiness`** (0-100):

- 0:尽量不 swap
- 100:积极 swap
- 默认 60
- **数据库服务器**建议 1-10
- **桌面** 60 即可

```bash
sysctl vm.swappiness=10
```

## 十一、NUMA (Non-Uniform Memory Access)

### 1. 什么是 NUMA

**NUMA**:多插槽服务器中,每个 CPU 有"本地"内存和"远端"内存,访问速度不同。

```text
┌─ Socket 0 ────────┐    ┌─ Socket 1 ────────┐
│  CPU 0   CPU 1    │    │  CPU 2   CPU 3    │
│     ↓     ↓       │    │     ↓     ↓       │
│   本地内存 (DDR)  │←──→│   本地内存 (DDR)  │
│     (近,快)       │    │     (近,快)       │
└───────────────────┘    └───────────────────┘
       远端内存 (访问另一个 Socket 的内存,慢)
```

### 2. NUMA 调优

```bash
# 看 NUMA 拓扑
numactl --hardware
lscpu | grep NUMA

# 看进程在哪个 NUMA 节点
cat /proc/PID/numa_maps

# 把进程绑到特定 NUMA 节点
numactl --cpunodebind=0 --membind=0 command
numactl --all command

# 自动平衡
numad                      # 自动 NUMA 守护进程
```

### 3. NUMA 问题

- **跨 NUMA 内存访问**:慢(几倍延迟)
- **调度器自动 NUMA balancing**:Linux 自动迁移内存到本地
- **数据本地性**:进程尽量用本地内存

## 十二、内存回收与 OOM

### 1. 内存回收

**触发时机**:物理内存不足时

**Linux 内存回收策略**:

- **页回收 (Page Reclaim)**:换出到 swap
- **slab 回收**:回收 slab 缓存
- **页框回收 (PFRA)**:Page Frame Reclaim Algorithm
- **直接回收 (Direct Reclaim)**:同步,可能阻塞
- **后台回收 (kswapd)**:异步,守护进程

### 2. OOM Killer

**OOM (Out Of Memory)**:内存耗尽时,内核用 OOM Killer 杀进程

```bash
# 看 OOM 分数
cat /proc/PID/oom_score
cat /proc/PID/oom_score_adj
# oom_score_adj 范围 -1000 ~ 1000
# -1000 = OOM 永不杀
# 1000 = 最先杀

# 系统级:禁止 OOM
sysctl vm.oom_kill_allocating_task=0
sysctl vm.overcommit_memory=2
```

**OOM 选择杀谁**:

- 计算每个进程的 `oom_score` = 内存使用量(比例) + 调整
- 选 `oom_score` 最高的
- 杀它后系统可恢复

**保护进程免 OOM**:

```bash
echo -1000 > /proc/PID/oom_score_adj
```

### 3. overcommit

**Linux 默认允许 overcommit**(申请的虚拟内存可超过物理内存 + swap)

```bash
# 模式
vm.overcommit_memory:
  0 = heuristic (默认)
  1 = always overcommit
  2 = 不允许超过 (CommitLimit)

# 查看
cat /proc/meminfo | grep -i commit
# CommitLimit:  总共可申请
# Committed_AS: 已经申请
```

**风险**:都申请但都不实际使用,触发 OOM

## 十五、内存管理的发展

### 1. 早期 (单块程序)

- 单一连续分配
- 静态重定位

### 2. 70s-80s (分页+交换)

- 虚拟内存
- 按需调页 (Demand Paging)
- 页面置换算法

### 3. 90s-00s (复杂分页)

- 多级页表
- 大页
- NUMA 感知

### 4. 10s+ (用户态/异构)

- **HMM (Heterogeneous Memory Management)**
- **CXL (Compute Express Link)**:内存池化、内存共享
- **Persistent Memory (PMEM) / Intel Optane**:持久内存,介于内存和 SSD 之间
- **用户态驱动 (io_uring / SPDK / DPDK)**:绕开内核
- **DPU (Data Processing Unit)**:卸载内存操作

### 5. 未来

- **CXL 3.0**:内存池化(多机共享内存)
- **Compute Memory**:内存内计算(Processing In Memory)
- **量子内存**(研究阶段)

## 十六、核心要点速记

- **虚拟内存 = 抽象 + 保护 + 扩展 + 共享**
- **分页** = 主流方案,页大小 4 KB
- **MMU** = 硬件做地址转换
- **TLB** = 页表的硬件缓存
- **缺页** = 虚拟页不在内存,触发磁盘 I/O
- **多级页表** = 解决单级页表过大问题
- **大页** = 减少 TLB miss
- **写时复制 (COW)** = fork 高效的关键
- **伙伴系统** = 解决外部碎片
- **slab/slub** = 解决内核小对象分配
- **GFP_ATOMIC** = 中断上下文分配
- **GFP_KERNEL** = 进程上下文可睡眠分配
- **vm.swappiness** = swap 倾向 (0-100)
- **OOM Killer** = 内存耗尽杀进程
- **NUMA** = 多 CPU 内存访问不均
- **asid / pcid** = 减少 TLB flush
- **ASLR** = 地址空间随机化
- **mmap** = 高效的内存映射
- **/proc/meminfo** = 内存详细信息
- **页帧回收 PFRA** = 内存回收
- **内存分配器** = glibc ptmalloc / jemalloc / tcmalloc
- **Persistent Memory** = 持久内存,新趋势
- **CXL** = 内存池化,新趋势
- **HugePage** = 2MB / 1GB 大页
- **写穿 (Write Through)** vs **写回 (Write Back)** = 缓存策略
- **page cache** = 磁盘页缓存
- **swap** = 内存换出到磁盘
- **ASLR / KASLR** = 地址随机化,防 ROP
