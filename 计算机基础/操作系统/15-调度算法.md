# 调度算法 (Scheduling Algorithms)

## 一、调度概述

### 调度的层次

Linux 调度从外到内有 4 层:

```text
1. 长期调度 (Long-term / Admission)
   决定哪些新进程进入就绪队列(系统负载控制)
   现代 OS 多已弱化

2. 中期调度 (Medium-term / Swapping)
   决定哪些进程换出到 swap
   平衡内存负载

3. 短期调度 (Short-term / CPU)
   决定哪个就绪进程占用 CPU
   频繁执行(每毫秒)

4. 实际 OS 主要做:短期调度 + 中期调度
```

### 调度时机 (何时调度)

- **进程退出**
- **进程阻塞** (等待 I/O、锁、信号等)
- **时间片用完**
- **进程主动让出** (yield)
- **新进程创建**
- **进程优先级改变**
- **中断唤醒等待进程**

### 调度要解决的问题

- **公平**:每个进程获得合理的 CPU
- **效率**:CPU 不闲置
- **响应**:交互任务响应快
- **吞吐**:单位时间完成任务多
- **周转**:任务从进系统到出系统总时间短
- **避免饥饿**:不让低优先级任务永远得不到 CPU

### 调度算法评估指标

- **周转时间 (Turnaround Time)**:完成时间 - 到达时间
- **带权周转时间**:周转时间 / 服务时间
- **等待时间 (Waiting Time)**:在就绪队列中等待时间
- **响应时间 (Response Time)**:首次响应 - 到达时间
- **吞吐 (Throughput)**:单位时间完成的任务数
- **CPU 利用率**

## 二、批处理系统调度算法

### 1. FCFS (First-Come First-Served, 先来先服务)

**原理**:按到达顺序执行,非抢占

**优点**:
- 简单
- 公平(先来先得)
- 无饥饿

**缺点**:
- 平均等待时间长
- **护航效应 (Convoy Effect)**:大任务阻塞小任务
- 不适合交互

**示例**:

```text
进程     到达    服务时间    完成    周转    等待
A         0       4         4       4       0
B         1       3         7       6       3
C         2       1         8       6       5
D         3       2         10      7       5

平均等待 = (0+3+5+5)/4 = 3.25
平均周转 = (4+6+6+7)/4 = 5.75
```

### 2. SJF (Shortest Job First, 短作业优先)

**原理**:选服务时间最短的任务,非抢占

**特点**:
- **最优平均等待时间**(对批处理)
- 但**长任务可能饥饿**
- 需预知服务时间(实际难)

**SJF 不可抢占版本**:任务开始后不打断

**SRTF (Shortest Remaining Time First)**:可抢占,新任务到来时若剩余时间更短则抢占

**示例**:

```text
进程  到达  服务
A      0    7
B      2    4
C      4    1
D      5    4

SRTF 调度顺序:
0-2: A (剩余 5)
2-4: B (剩余 2)
4-5: C (剩余 0)
5-7: B (剩余 0)
7-11: A (剩余 4)
11-15: D (剩余 0)

A: 0-2, 7-15  = 完成 15, 周转 15
B: 2-4, 5-7   = 完成 7,  周转 5
C: 4-5        = 完成 5,  周转 1
D: 11-15      = 完成 15, 周转 10

平均等待 = (8+1+0+5)/4 = 3.5
```

### 3. HRRN (Highest Response Ratio Next, 高响应比优先)

**响应比** = (等待时间 + 服务时间) / 服务时间 = 1 + 等待/服务

**原理**:选响应比最高的任务(非抢占,任务结束才重新选)

**特点**:
- 综合 FCFS 和 SJF
- 等待越长,响应比越高
- 避免饥饿

**示例**:

```text
进程  到达  服务
A      0    3
B      2    6
C      4    4
D      6    5

0-3: A
3 时,等待: B=1, C=0, D=0
  R_B = (1+6)/6 = 1.17
  R_C = (0+4)/4 = 1
  R_D = 1 (还没到)
  选 B
3-9: B
9 时,等待: C=5, D=3
  R_C = (5+4)/4 = 2.25
  R_D = (3+5)/5 = 1.6
  选 C
9-13: C
13-18: D
```

### 4. 批处理算法对比

| 算法  | 优点         | 缺点           |
|-------|--------------|----------------|
| FCFS  | 简单         | 平均等待长     |
| SJF   | 最优平均     | 长任务饥饿     |
| SRTF  | 改进 SJF     | 仍会饥饿       |
| HRRN  | 折中         | 计算响应比开销 |

## 三、交互系统调度算法

### 1. RR (Round Robin, 时间片轮转)

**原理**:每个进程分配**固定时间片**,时间片用完就切换

**特点**:
- **公平** (每个进程都能得到 CPU)
- **响应好** (最坏响应 = 时间片)
- 适合**分时系统**
- 时间片太小:切换开销大
- 时间片太大:变 FCFS

**关键参数 - 时间片长度**:

- 太小(1 ms):切换开销占比大,效率低
- 太大(1 s):响应慢
- **典型**:10-100 ms
- Linux 默认: 1-6 ms (动态)
- Windows: 15-30 ms (旧),动态调整

**示例** (时间片=4):

```text
进程  到达  服务
A      0    8
B      1    4
C      2    9
D      3    5

0-4: A (剩 4)
4-8: B (剩 0)  → 完成 B
8-12: C (剩 5)
12-13: D (剩 4) (4 ms)
13-17: A (剩 0)  → 完成 A
17-21: C (剩 1) (4 ms)
21-25: D (剩 0)  → 完成 D
25-26: C (剩 0)  → 完成 C

完成: A=17, B=8, C=26, D=25
周转: A=17, B=7, C=24, D=22
```

### 2. 优先级调度 (Priority Scheduling)

**原理**:按优先级分配 CPU,高优先级先跑

**类型**:
- **静态优先级**:创建时确定,不变
- **动态优先级**:运行时根据行为调整(老化、反饥饿)

**问题**:
- **优先级反转**:低优先级任务持有高优先级任务需要的锁
- **饥饿**:低优先级任务可能永远等不到

**优先级继承** (Priority Inheritance):持有锁的低优先级任务临时提升到高优先级,避免反转

**Linux nice 值**:
- -20 (最高) ~ 19 (最低)
- 普通用户只能往低调(nice 提高)
- root 可以任意调

### 3. 多级反馈队列 (MLFQ, Multilevel Feedback Queue)

**原理**:**多级队列**,优先级可动态调整

**规则** (经典 MLFQ):

```text
1. 优先级 N 的队列,运行时间片 2^N (或固定)
2. 新任务进入最高优先级队列
3. 同队列内 RR
4. 用完时间片 → 降到下一级队列
5. 定期把所有任务提升到最高优先级(防止饥饿)
6. I/O 密集型任务(交互)留高层 → 响应好
   CPU 密集型任务降到低层 → 调度不频繁
```

**特点**:
- **自适应**:不需要预知任务类型
- **兼顾响应和吞吐**
- **经典代表**:Windows 早期调度器、CTSS (1962)
- 现代变种:O(1)、Linux CFS (BFS/EEVDF)

**示例** (3 级队列,时间片 1, 2, 4):

```text
A(服务 8), B(服务 4), C(服务 6), D(服务 2)

0-1: A (剩 7) → 降到 Q1
1-2: B (剩 3) → 降到 Q1
2-3: C (剩 5) → 降到 Q1
3-4: D (剩 1) → 降到 Q1
4-5: A (剩 6) → 降到 Q2
5-7: B (剩 1) → 降到 Q2
7-8: C (剩 4) → 降到 Q2
8-12: A (剩 2) → 降到 Q3
12-14: B (剩 0) → 完成
14-15: C (剩 3) → 降到 Q2
...
```

### 4. 交互系统算法对比

| 算法   | 响应 | 公平 | 复杂度 | 适合           |
|--------|------|------|--------|----------------|
| RR     | 好   | 高   | 低     | 通用分时       |
| 优先级 | 好   | 低   | 中     | 关键任务       |
| MLFQ   | 好   | 中   | 中     | 通用交互       |

## 四、实时系统调度算法

### 1. 实时系统特点

- **硬实时**:必须满足截止时间(否则灾难)
- **软实时**:尽量满足,偶尔不满足可接受
- **任务特征**:
  - 周期 (Period, P)
  - 截止时间 (Deadline, D)
  - 最坏执行时间 (WCET, C)

**关键指标 - 处理器利用率 U**:

```
U = Σ (Ci / Pi)
```

**可调度性条件 (RMS)**:U ≤ n(2^(1/n) - 1) (n = 任务数)

| n   | 最大 U       |
|-----|--------------|
| 1   | 100%         |
| 2   | 82.8%        |
| 3   | 77.9%        |
| ∞   | 69.3% (ln 2) |

### 2. Rate Monotonic (RM, 单调速率)

**原理**:**周期越短,优先级越高**

**特点**:
- 静态优先级
- **最优的固定优先级算法**
- 可调度性充分条件: U ≤ n(2^(1/n) - 1)
- 但充分条件非必要(实际可调度 U 可更高)

**示例**:

```text
T1: P=50, C=25
T2: P=100, C=10

T1 优先级 > T2
```

### 3. EDF (Earliest Deadline First, 最早截止时间优先)

**原理**:**动态优先级**,选截止时间最近的任务**

**特点**:
- **理论上最优**(U ≤ 100% 即可调度)
- 动态调度,实现复杂
- **单处理器最优**
- 多处理器不最优

**示例**:

```text
T1: 周期 100, C 50, 截止 100
T2: 周期 200, C 80, 截止 200

调度顺序: 每次选 deadline 最近的
```

### 4. LLF (Least Laxity First, 最小松弛度优先)

**松弛度** = 截止时间 - 当前时间 - 剩余执行时间

**原理**:选松弛度最小的任务

**特点**:
- 考虑剩余执行时间
- 适合需要精细控制的场景

### 5. SCHED_DEADLINE (Linux 3.14+)

Linux 内核的截止时间调度,EDF 实现。

**任务参数**:

```c
struct sched_attr {
    __u32 size;
    __u32 sched_policy;       // SCHED_DEADLINE
    __u64 sched_flags;
    __u64 sched_nice;
    __u32 sched_priority;
    __u64 sched_runtime;       // 单次运行时间 (CPU 带宽)
    __u64 sched_deadline;     // 截止时间
    __u64 sched_period;       // 周期
};
```

**使用**:
- 视频/音频播放器
- 工业控制
- 机器人
- 航空航天

### 6. 实时调度算法对比

| 算法     | 优先级   | 可调度上限  | 实现复杂度 | 适用     |
|----------|----------|-------------|------------|----------|
| RM       | 静态     | 69.3% (n→∞) | 低         | 嵌入式   |
| EDF      | 动态     | 100%        | 中         | 软实时   |
| LLF      | 动态     | ~100%       | 高         | 特殊场景 |
| DEADLINE | 动态     | 100%        | 中         | Linux    |

## 五、Linux 调度器发展史

### 1. 历史版本

| Linux 版本   | 调度器               | 特点                                     |
|--------------|----------------------|------------------------------------------|
| 1.0          | 简单调度             | 简单循环                                 |
| 2.4          | 简单调度             | O(n)                                     |
| 2.6.0-2.6.22 | O(1) 调度器          | O(1) 时间                                |
| 2.6.23-6.5   | **CFS**              | 基于红黑树,vruntime                      |
| 6.6+         | **EEVDF**            | Earliest Eligible Virtual Deadline First |

### 2. O(1) 调度器 (2003-2007)

**特点**:
- 140 个优先级队列
- 0-99:实时
- 100-139:普通 (nice 映射)
- 每次调度选最高优先级队列第一个
- 交互式进程 bonus 奖励
- **缺点**:对交互判断不准,桌面性能差

### 3. CFS (Completely Fair Scheduler) 2007-2023

**核心思想**:
- "完美多任务" 模型
- 给每个进程一个**虚拟运行时间 (vruntime)**
- 总是选 vruntime 最小的进程
- 公平:所有进程获得相等 CPU

**数据结构**:
- **红黑树 (RB-Tree)**:vruntime 作为键
- O(log n) 插入/删除
- 最左节点 = vruntime 最小 = 下一个调度

**关键概念**:

#### (1) 权重 (Weight)

| nice | 权重  | 相对 CPU |
|------|-------|----------|
| -20  | 88761 | 10x      |
| -10  | 9548  | 3.2x     |
| 0    | 1024  | 1x       |
| 10   | 110   | 0.3x     |
| 19   | 15    | 0.05x    |

#### (2) vruntime 计算

```c
// 简化版
vruntime += delta_exec * NICE_0_WEIGHT / weight;
```

- delta_exec = 实际运行时间
- 高权重(nice 负) → vruntime 增长慢 → 跑得更多

#### (3) 调度周期 (sched_latency)

- 默认 6 ms
- 目标:所有可运行任务都在这时间内跑一遍
- 任务数 * 最小粒度 = 实际周期(任务太多时)

```text
周期 = max(sched_latency, nr_running * sched_min_granularity)
```

- sched_min_granularity = 0.75 ms (默认)

#### (4) 任务分组 (Task Group)

- **cgroup** 支持任务分组
- 不同组有不同权重
- 用途:容器资源分配

### 4. EEVDF (Linux 6.6+)

**EEVDF** = **E**arliest **E**ligible **V**irtual **D**eadline **F**irst

**核心改进**:
- 加**虚拟截止时间**概念
- 类似 EDF,但基于虚拟时间
- 更好**延迟保证**
- 适合混合工作负载

**关键概念**:
- **eligible**:任务在特定时间前不能被调度(避免插队)
- **virtual deadline**:虚拟截止时间
- 选最早 virtual deadline 的任务

**Linux 6.6 默认调度器**

### 5. 调度类 (Scheduling Class)

Linux 调度有**5 个调度类**,按优先级排列:

```text
┌─ stop_sched_class     (停止,最高优先级)
├─ dl_sched_class        (Deadline, EDF)
├─ rt_sched_class        (实时 RT, FIFO/RR)
├─ fair_sched_class      (CFS, 普通进程)
└─ idle_sched_class      (Idle, 最低)
```

调度时**先选高优先级类**,同类内用各自的算法。

### 6. 调度器调优参数

```bash
# /proc/sys/kernel/
sched_latency_ns          # 调度周期 (默认 6ms)
sched_min_granularity_ns  # 最小粒度 (0.75ms)
sched_wakeup_granularity_ns # 唤醒粒度 (1ms)
sched_migration_cost_ns   # 迁移开销
sched_tunable_scaling     # 缩放模式

# /proc/sys/kernel/
sched_cfs_bandwidth_slice_us  # CFS 带宽 slice
sched_rt_runtime_us      # RT 进程总带宽
sched_rt_period_us       # RT 进程带宽周期
```

## 六、CPU 亲和性 (Affinity)

### 1. 概念

**CPU 亲和性**:把进程/线程绑到特定 CPU 上

**好处**:
- 减少跨核迁移的 Cache 失效
- 提高 CPU 缓存命中率
- 提高实时性
- 适合 NUMA

**坏处**:
- 负载不均
- 不灵活

### 2. 亲和性 API

```c
// 单进程
cpu_set_t mask;
CPU_ZERO(&mask);
CPU_SET(0, &mask);
CPU_SET(2, &mask);
sched_setaffinity(0, sizeof(mask), &mask);

// 多进程
sched_setaffinity(pid, sizeof(mask), &mask);

// 看亲和性
sched_getaffinity(0, sizeof(mask), &mask);
```

### 3. taskset 命令

```bash
# 启动时绑
taskset -c 0,2 command

# 修改已运行
taskset -p 0x05 1234
taskset -p 0,2 1234

# 看当前
taskset -p $$
```

### 4. cgroup 亲和性

```bash
# cpuset cgroup
echo "0,2" > /sys/fs/cgroup/cpuset/test/cpuset.cpus
echo "0" > /sys/fs/cgroup/cpuset/test/cpuset.mems
```

## 七、调度域 (Scheduling Domain) 与负载均衡

### 1. NUMA 调度

**Linux 自动 NUMA 调度**:

- 任务默认在本地节点
- 定期 NUMA 平衡(迁移到空闲节点)
- 进程扫描自己的内存使用,标记访问模式
- 调度器决定是否迁移

```bash
# NUMA 平衡开关
echo 1 > /proc/sys/kernel/numa_balancing

# 看 numa 统计
cat /proc/<pid>/numa_maps
numastat -p <pid>
```

### 2. 调度域 (sched_domain)

Linux 把 CPU 分层组织:

```text
SMT (一个核多线程)
└── MC (一个 CPU 多核)
    └── NUMA (跨 CPU)
```

**每层有自己的负载均衡策略**:
- **SMT 域**:超线程间快速迁移
- **MC 域**:多核间相对慢
- **NUMA 域**:跨 CPU,更慢

### 3. 负载均衡 (Load Balancing)

**触发**:
- **Tick 平衡**:每个 tick 检查,部分 CPU 负载高时迁移
- **空闲平衡**:CPU 变空闲时从别的 CPU 拉任务
- **新唤醒任务**:在空闲 CPU 上唤醒

**`sched_load_balance`**:核心函数

## 八、实时调度 (Linux SCHED_FIFO / SCHED_RR / SCHED_DEADLINE)

### 1. SCHED_FIFO (先来先服务实时)

```bash
# 设 SCHED_FIFO,优先级 50
chrt -f -p 50 1234
chrt -f -p 50 -- command args
```

**特点**:
- 一旦占用 CPU,一直跑到阻塞/退出/被抢占
- 不受 CFS 影响
- 优先级 1-99 数字越大越高
- 同优先级按 FIFO

**风险**:
- 写错代码会卡死系统
- 必须小心同步和死锁

### 2. SCHED_RR (时间片轮转实时)

```bash
chrt -r -p 50 1234
```

**特点**:
- 同 SCHED_FIFO,但加时间片(默认 100ms)
- 同优先级轮转
- 时间片用完就切换

### 3. SCHED_DEADLINE (截止时间)

```c
struct sched_attr attr = {
    .sched_policy = SCHED_DEADLINE,
    .sched_runtime = 10 * 1000 * 1000,   // 10 ms / period
    .sched_deadline = 20 * 1000 * 1000,  // 20 ms
    .sched_period  = 100 * 1000 * 1000, // 100 ms
};
sched_setattr(0, &attr, 0);
```

**特点**:
- 任务保证在 deadline 前完成
- runtime:任务实际需要的 CPU 时间
- period:周期
- deadline:相对 period 的截止时间(通常 == period)
- kernel 保证:总 runtime / total period ≤ 系统 capacity

### 4. 实时限制

```bash
# 实时进程总带宽
sysctl kernel.sched_rt_runtime_us=950000
sysctl kernel.sched_rt_period_us=1000000
# 0.95 秒 / 1 秒 = 95% (5% 留给非实时)
# 设为 -1 表示无限制(危险)
```

**意义**:实时任务不能完全占满 CPU,需留些给系统和其他任务

### 5. 实时调度应用

- 音频/视频处理 (PulseAudio, PipeWire)
- 工业控制
- 机器人
- 航空电子
- 高速交易
- 数据库关键线程

## 九、调度算法对比

| 算法           | 类型   | 抢占 | 复杂度 | 公平 | 响应 | 吞吐 | 适用       |
|----------------|--------|------|--------|------|------|------|------------|
| FCFS           | 批处理 | 否   | 低     | 高   | 差   | 中   | 简单       |

## 十、调度器选择与调优

### 1. 选择 CPU 调度器

Linux 6.6+ 默认 **EEVDF**(6.6 之前 CFS)

```bash
# 查看
cat /sys/kernel/debug/sched_features
chrt -m  # 看可用调度策略
```

### 2. 调优场景

#### 桌面/交互

- nice 提高系统服务
- 重要进程 nice 降低
- 用 desktop profile(`tuned` 或 `anaconda`)

#### 服务器/吞吐

- nice 调整关键服务
- CPU 亲和性(数据库绑核)
- 关 CFS 带宽限制

#### 实时

- chrt 设置实时进程
- `SCHED_DEADLINE` 视频/音频
- 配合 `nice` 隔离
- 关闭透明大页(THP)

#### NUMA 优化

```bash
numactl --cpunodebind=0 --membind=0 program
echo 0 > /proc/sys/kernel/numa_balancing  # 关闭自动平衡
```

### 3. 性能分析

```bash
# 看调度延迟
perf sched latency

# 看上下文切换
pidstat -w
perf stat -e context-switches

# 看调度器
cat /proc/sched_debug
```

### 4. 调优经验

- **多线程 + CPU 密集型**:绑核
- **多线程 + IO 密集型**:多核,绑核也可能反作用
- **实时性要求高**:SCHED_FIFO + 优先级继承
- **数据库**:绑核 + 大页 + 直接 IO
- **容器**:cgroup 限制
- **NUMA**:本地内存优先

## 十一、调度器演进方向

### 1. 现有问题

- CFS 不擅长延迟敏感场景
- 多任务切换开销
- NUMA 感知
- 能效

### 2. 新方案

- **EEVDF** (Linux 6.6+):改善延迟
- **Energy Aware Scheduling (EAS)**:ARM 节能
- **代理执行 (Proxy Execution)**:TLA 改进
- **用户态调度**:`sched_setattr` + 用户态
- **协作调度**:内核与用户态协作

### 3. 现代趋势

- **多级调度**:硬件协处理器
- **专用调度**:AI 加速器、DPU
- **eBPF 调度**:动态定制
- **Serverless 调度**:无服务器

## 十二、核心要点速记

- **3 大类型**:批处理、交互、实时
- **FCFS**:简单,护航效应
- **SJF**:最优平均等待,长任务饥饿
- **SRTF**:可抢占 SJF
- **HRRN**:综合 SJF 和 FCFS
- **RR**:时间片轮转,公平
- **MLFQ**:多级反馈,自适应
- **RM**:周期越短优先级越高,嵌入式
- **EDF**:最早截止,理论最优
- **CFS**:完全公平,Linux 主流
- **EEVDF**:Linux 6.6+ 新调度
- **5 个调度类**:stop > dl > rt > fair > idle
- **nice -20~19**,数字小优先级高
- **CPU 亲和性**:taskset / sched_setaffinity
- **SCHED_FIFO**:实时先来先服务
- **SCHED_RR**:实时时间片
- **SCHED_DEADLINE**:runtime/deadline/period
- **chrt 命令**:设置实时调度
- **NUMA**:本地优先, numactl
- **调度延迟**:CFS 默认 6 ms
- **最小粒度**:0.75 ms
- **优先级继承**:解决优先级反转
- **多级反馈队列**:Windows 早期、CTSS 起源
- **rm 限制**:`U ≤ n(2^(1/n) - 1)` ≈ 69.3%
- **edf 限制**:`U ≤ 100%`
- **优先级反转**:低优先级持锁,高优先级等
