# 日志与监控 (Logging & Monitoring)

## 一、日志系统概述

### 日志的作用

- **故障排查**:错误、警告、堆栈
- **性能分析**:慢查询、慢请求
- **安全审计**:登录、操作、攻击
- **业务分析**:用户行为、转化
- **合规要求**:留存 N 年

### 日志级别 (syslog)

| 级别      | 数字 | 含义                       |
|-----------|------|----------------------------|
| emerg     | 0    | 系统不可用                 |
| alert     | 1    | 必须立即处理               |
| crit      | 2    | 严重                       |
| err       | 3    | 错误                       |
| warning   | 4    | 警告                       |
| notice    | 5    | 重要但非错误               |
| info      | 6    | 信息                       |
| debug     | 7    | 调试                       |

### Linux 日志系统演进

```
Syslog (1980s)
   ↓
Syslog-ng / rsyslog (2000s)
   ↓
systemd-journald (2010s)
   ↓
云原生日志 (Loki / Fluentd / Vector)
```

## 二、journald (systemd 日志)

### 1. journalctl 命令

```bash
# 全部
journalctl

# 跟踪
journalctl -f

# 特定服务
journalctl -u nginx
journalctl -u nginx -u php-fpm

# 进程/用户
journalctl _PID=1234
journalctl _UID=1000

# 优先级
journalctl -p err
journalctl -p warning
journalctl -p "emerg".."err"

# 时间
journalctl --since today
journalctl --since "1 hour ago"
journalctl --since "2024-01-01" --until "2024-01-02"
journalctl --since -7d

# 启动相关
journalctl -b
journalctl -b -1
journalctl -b -p err

# 内核日志
journalctl -k

# 格式
journalctl -o short
journalctl -o cat
journalctl -o json
journalctl -o json-pretty
journalctl -o verbose

# 大小
journalctl -n 100
journalctl --since today -n 50

# 字段过滤
journalctl -u nginx PRIORITY=err
journalctl SYSLOG_IDENTIFIER=sshd

# 模式匹配
journalctl -g "error|warn"

# 清理
journalctl --disk-usage
journalctl --vacuum-time=2d
journalctl --vacuum-size=500M

# 导出
journalctl -u nginx -o json > nginx.json
journalctl -u nginx --since today > /tmp/nginx.log
```

### 2. journald 配置

```bash
# /etc/systemd/journald.conf
[Journal]
Storage=persistent              # persistent / volatile / auto
Compress=yes                    # 压缩
SystemMaxUse=2G                  # 最大占用
SystemKeepFree=1G                # 保留空间
SystemMaxFileSize=200M           # 单文件最大
MaxRetentionSec=2month           # 保留时间
ForwardToSyslog=no               # 不转 syslog
ForwardToWall=yes                # 警告发终端
RateLimitIntervalSec=30s
RateLimitBurst=10000
```

### 3. journal 位置

```
/run/log/journal/         # 临时 (内存),默认
/var/log/journal/         # 持久 (磁盘)
```

### 4. journalctl 与 logger

```bash
# 程序写日志
logger "Hello World"
logger -p user.err "Error"
logger -t myapp "Tagged message"
logger -n loghost -P 514 "Remote log"  # 发到远程 syslog
```

## 三、rsyslog (经典日志系统)

### 1. rsyslog 配置

```bash
# /etc/rsyslog.conf 或 /etc/rsyslog.d/*.conf
```

**主配置**:

```text
# 模块
module(load="imuxsock")        # 本地 socket
module(load="imjournal")       # systemd journal

# 规则
*.info;mail.none;authpriv.none;cron.none    /var/log/messages
authpriv.*                                    /var/log/secure
mail.*                                        /var/log/maillog
cron.*                                        /var/log/cron
*.emerg                                       :omusrmsg:*
*.crit                                        /var/log/critical
local0.*                                      /var/log/myapp.log
```

**格式**:
- `*.info` 所有设施,info 级别以上
- `mail.err` mail 设施,err 级别以上
- `cron.=debug` cron,仅 debug
- `*.!info` 所有设施,**不包含** info

**动作**:
- `/var/log/file` 写文件
- `@loghost:port` 发到远程
- `:omusrmsg:*` 紧急广播给所有登录用户
- `user1` 转发到其他设施

### 2. 设施 (Facility)

| 设施          | 数字  | 用途              |
|---------------|-------|-------------------|
| auth/authpriv | 4/10  | 认证              |
| cron          | 9     | cron              |
| daemon        | 3     | 守护进程          |
| kern          | 0     | 内核              |
| local0-7      | 16-23 | 本地自定义        |
| mail          | 2     | 邮件              |
| syslog        | 5     | syslog 自身       |
| user          | 1     | 用户级            |

### 3. 重启 rsyslog

```bash
systemctl restart rsyslog
rsyslogd -f /etc/rsyslog.conf
```

### 4. 远程日志

```bash
# 服务端
module(load="imtcp")
input(type="imtcp" port="514")

# 客户端
*.* @loghost:514
*.* @@loghost:514          # TCP
*.* @udp://loghost:514     # UDP
*.* @@tcp://loghost:514   # TCP
```

### 5. 模板

```text
$template MyFormat,"%timegenerated% %HOSTNAME% %syslogtag%%msg%\n"
*.* ?MyFormat
```

## 四、syslog-ng (现代替代)

### 1. 配置文件

```bash
# /etc/syslog-ng/syslog-ng.conf
```

```text
@version: 4.0
@include "scl.conf"

source s_local { system(); internal(); };
source s_network { udp(port(514)); };

destination d_file { file("/var/log/messages"); };
destination d_remote { tcp("loghost" port(514)); };

filter f_sys { facility(syslog); level(info..emerg); };

log { source(s_local); filter(f_sys); destination(d_file); };
log { source(s_local); destination(d_remote); };
```

### 2. 优势

- 高性能
- 灵活过滤
- 模板化
- 数据库输出
- TLS 加密

## 六、logrotate (日志轮转)

### 1. 配置文件

```bash
# /etc/logrotate.conf (主配置)
# /etc/logrotate.d/ (子配置)
```

**示例 - /etc/logrotate.d/myapp**:

```text
/var/log/myapp/*.log {
    daily                        # 周期: daily/weekly/monthly/yearly/size
    rotate 7                     # 保留 7 份
    size 100M                    # 或大小
    missingok                    # 文件不存在不报错
    notifempty                   # 空文件不轮转
    compress                     # gzip 压缩
    delaycompress                # 延迟 1 次压缩
    copytruncate                 # 复制后清空(进程可继续写)
    # create 0640 user group     # 新文件权限
    # createolddir 0755 user group
    dateext                      # 用日期后缀
    dateformat -%Y%m%d          # 日期格式
    sharedscripts               # 多文件共享 postrotate
    postrotate
        systemctl reload myapp  # 通知服务重开日志
    endscript
}
```

### 2. 关键选项

| 选项                | 作用                              |
|---------------------|-----------------------------------|
| daily/weekly/etc    | 轮转周期                          |
| size 100M           | 达到大小轮转                      |
| rotate N            | 保留 N 份                         |
| compress            | gzip 压缩                         |
| delaycompress       | 延迟 1 轮再压缩                   |
| missingok           | 缺失不报错                        |
| notifempty          | 空文件不轮转                      |
| copytruncate        | 复制后清空(适合服务继续写)        |
| create 0640 ...     | 新文件权限/属主                   |
| sharedscripts       | 多个 log 共享脚本                 |
| postrotate ...      | 轮转后操作(通知服务)              |

### 3. 测试与执行

```bash
# 语法测试
logrotate -d /etc/logrotate.conf
logrotate -d /etc/logrotate.d/myapp

# 强制执行
logrotate -f /etc/logrotate.conf

# 调试
logrotate -dv
```

### 4. logrotate + journald

- 传统日志走 logrotate
- journald 自己的日志由 journald 管理(`--vacuum`)

## 七、auditd (审计)

### 1. auditd 概述

**auditd**:Linux 审计系统,记录系统调用级事件

- **C2 安全标准**
- **追踪**:谁、什么、何时、何处
- **事件**:登录、文件访问、命令执行、系统调用

### 2. 安装与启动

```bash
yum install audit
systemctl enable --now auditd
auditctl -s                    # 状态
```

### 3. auditctl 规则

```bash
# 监控文件
auditctl -w /etc/passwd -p wa -k passwd_changes
# -w 监控哪个文件
# -p 权限: w=write, a=attribute change, r=read, x=execute
# -k 关键字(便于搜索)

# 监控系统调用
auditctl -a exit,always -S execve -k exec_commands

# 监控目录
auditctl -w /etc/ -p wa -k etc_changes

# 看规则
auditctl -l

# 清空
auditctl -D
```

### 4. ausearch 搜索

```bash
# 找特定事件
ausearch -k passwd_changes
ausearch -k exec_commands
ausearch -ts today
ausearch -ts "2024-01-01 12:00:00"
ausearch -ua 1000                # 用户
ausearch -f /etc/passwd
ausearch -m USER_LOGIN
```

### 5. aureport 报告

```bash
aureport --summary
aureport -au                     # 认证
aureport -f                       # 文件
aureport -x                      # 详细
aureport --failed                # 失败
```

### 6. 配置文件

```bash
# /etc/audit/auditd.conf
log_file = /var/log/audit/audit.log
max_log_file = 50
max_log_file_action = rotate
space_left = 100
space_left_action = email
action_mail_acct = root
```

```bash
# /etc/audit/rules.d/audit.rules
# 删除临时规则
-D
# 缓冲区
-b 8192
# 失败模式
-f 1
# 监控 /etc/passwd
-w /etc/passwd -p wa -k passwd
# 监控 /etc/shadow
-w /etc/shadow -p wa -k shadow
# 监控 sudo
-w /usr/bin/sudo -p x -k sudo
# 监控系统调用
-a always,exit -F arch=b64 -S execve -k exec
```

### 7. 永久规则

```bash
# 用 augenrules 自动加载
augenrules --load

# 写在 /etc/audit/rules.d/ 下的文件
# 文件名必须以 .rules 结尾
```

## 八、监控基础

### 监控的层次

```
应用监控     - APM, 业务指标
中间件监控   - Redis, MQ, DB
系统监控     - CPU/内存/IO/网络
硬件监控     - 服务器, 网络设备
机房监控     - 温湿度, 电源
业务监控     - 用户体验, 转化率
```

### 监控的指标类型 (USE / RED)

**USE 方法** (利用率/饱和度/错误):

- **Utilization** (利用率)
- **Saturation** (饱和度)
- **Errors** (错误数)

**RED 方法** (服务监控):

- **Rate** (请求率)
- **Errors** (错误率)
- **Duration** (延迟)

**四个黄金指标** (Google SRE):

- **Latency** (延迟)
- **Traffic** (流量)
- **Errors** (错误)
- **Saturation** (饱和度)

### 1. 告警分级

| 级别    | 颜色    | 处理时间      | 通知方式        |
|---------|---------|---------------|-----------------|
| P0/P1   | 红色    | 立即 (5 分钟) | 电话、短信、IM  |
| P2      | 橙色    | 30 分钟       | IM、短信        |
| P3      | 黄色    | 当天          | 邮件、IM        |

### 2. 告警规则设计

**好的告警**:
- **具体**: "主机 X 的 CPU > 90%,已 5 分钟"
- **可操作**: 告诉接收人做什么
- **可监控**: 告警本身要监控
- **去重**: 同样问题不重复发
- **静默**: 维护期静默
- **升级**: 不响应自动升级

**坏的告警**:
- 频繁误报
- 没有动作指引
- 阈值不合理

### 2. 配置

```yaml

  scrape_interval: 15s
  evaluation_interval: 15s

  - job_name: 'prometheus'
    static_configs:
      - targets: ['localhost:9090']

  - job_name: 'node'
    static_configs:
      - targets: ['node1:9100', 'node2:9100']

  - job_name: 'mysql'

      - targets: ['mysql:9104']

    kubernetes_sd_configs:
      - role: pod
    relabel_configs:
      - source_labels: [__meta_kubernetes_pod_annotation_prometheus_io_scrape]
        action: keep
        regex: true
```

### 3. PromQL 查询

```promql
# CPU 使用率
100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 内存使用
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100

# 磁盘使用
100 - ((node_filesystem_avail_bytes{fstype!~"tmpfs"} * 100) / node_filesystem_size_bytes)

# 网络流量
rate(node_network_receive_bytes_total[5m])

# 服务的 QPS
rate(http_requests_total[5m])

# 服务 P99 延迟
histogram_quantile(0.99, rate(http_request_duration_seconds_bucket[5m]))
```

### 4. 告警规则

```yaml
# alert.rules.yml
groups:
- name: host
  rules:
  - alert: HighCPU
    expr: 100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "CPU > 80% on {{ $labels.instance }}"
      description: "CPU is {{ $value }}%"

  - alert: HostDown
    expr: up{job="node"} == 0
    for: 1m
    labels:
      severity: critical
    annotations:
      summary: "Host {{ $labels.instance }} down"
```

### 1. ELK Stack

**Filebeat 配置** (/etc/filebeat/filebeat.yml):

```yaml
filebeat.inputs:

  paths:
    - /var/log/myapp/*.log

    app: myapp

  hosts: ["logstash:5044"]
```

**Logstash 配置** (/etc/logstash/conf.d/myapp.conf):
```text
input {
  beats { port => 5044 }
}
filter {
  grok {
    match => { "message" => "%{TIMESTAMP_ISO8601:timestamp} %{LOGLEVEL:level} %{GREEDYDATA:msg}" }
  }
  date {
    match => [ "timestamp", "ISO8601" ]
  }
}
output {
  elasticsearch {
    hosts => ["es:9200"]
    index => "myapp-%{+YYYY.MM.dd}"
  }
}
```

## 十八、可观测性 (Observability)

### 1. 三大支柱

- **Metrics (指标)**: Prometheus、Grafana
- **Logs (日志)**: Loki、ELK
- **Traces (追踪)**: Jaeger、SkyWalking

### 2. SLI / SLO / SLA

- **SLI (Service Level Indicator)**: 服务水平指标
  - 例: P99 延迟
- **SLO (Service Level Objective)**: 服务水平目标
  - 例: P99 < 100 ms
- **SLA (Service Level Agreement)**: 服务水平协议
  - 例: 月度可用性 99.9%

### 3. Error Budget (错误预算)

- SLO 99.9% → 错误预算 0.1%
- 月度: 43.2 分钟宕机
- 用完 = 暂停发版,优先修稳定性

### 4. 监控告警金字塔

```
L4  业务指标     (DAU, 转化率)
L3  应用监控     (QPS, 延迟, 错误)
L2  中间件监控   (DB, MQ, Cache)
L1  系统监控     (CPU, 内存, IO, 网络)
L0  硬件监控     (服务器, 交换机)
```

## 十九、日志规范

### 1. 日志格式

**推荐**: JSON 结构化

```json
{
  "timestamp": "2024-01-15T10:30:00.123Z",
  "level": "info",
  "service": "myapp",
  "trace_id": "abc123",
  "user_id": "12345",
  "message": "User logged in",
  "duration_ms": 23,
  "extra": {
    "method": "POST",
    "path": "/api/login"
  }
}
```

### 2. 日志最佳实践

- **结构化**: JSON
- **时间戳**: ISO 8601
- **级别**: 标准 (trace/debug/info/warn/error/fatal)
- **关键字段**: trace_id, user_id, request_id
- **不要打敏感信息**: 密码、token、身份证
- **大小限制**: 单行不超过几 KB
- **采样**: 高 QPS 服务采样

### 3. ELK 查询示例

```bash
# 错误日志
level:error

# 特定服务
service:myapp AND level:error

# 时间范围
@timestamp:[2024-01-15 TO 2024-01-16]

# 聚合
level:error | stats count by service
```

### 4. 隐私合规

- **GDPR**: 欧盟数据保护
- **个保法**: 中国个人信息保护法
- **不记录**: 密码、token、身份证、银行卡
- **脱敏**: 手机号 138****1234
- **留存期**: 通常 90 天 - 1 年
