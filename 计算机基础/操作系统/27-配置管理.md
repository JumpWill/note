# 配置管理 (Configuration Management)

## 一、配置管理概述

### 什么是配置管理

**配置管理 (Configuration Management)**:用**自动化**方式管理**基础设施**和**应用配置**

- 描述式: "我想要这样的状态"
- 自动化: 工具自动达到
- 可重复: 在多台机器一致
- 可追溯: Git 记录变更
- 可恢复: 失败可回滚

### 配置管理的核心价值

- **一致性**: 所有机器配置相同
- **自动化**: 减少手工操作
- **可扩展**: 轻松管理 1 万台
- **可审计**: Git 记录一切
- **快速恢复**: 出问题一键重建
- **知识沉淀**: 配置即文档

### 配置管理 vs 传统脚本

| 维度     | 传统脚本   | 配置管理工具 |
|----------|------------|--------------|
| 状态     | 命令式     | 声明式       |
| 一致性   | 难保证     | 保证         |
| 幂等性   | 需自己实现 | 内置         |
| 失败恢复 | 难         | 内置         |
| 报告     | 需自己写   | 内置         |
| 学习曲线 | 低         | 中           |
| 适合规模 | 10-50 台   | 100-10000 台 |

## 三、Ansible 详解

### 1. Ansible 概述

**Ansible**:**推送式**、**无客户端**、**YAML** 配置

- 只需要 SSH + Python
- 学习曲线低
- 适合中小规模(< 5000 节点)
- 红帽维护

**特点**:

- **声明式**: 描述期望状态
- **幂等性**: 多次执行结果一致
- **无代理**: 不需要装客户端
- **模块化**: 1000+ 内置模块
- **Playbook**: YAML 配置
- **Inventory**: 主机清单

### 2. 安装

```bash
# RHEL/CentOS
yum install ansible

# Ubuntu
apt install ansible

# pip
pip install ansible

# 验证
ansible --version
```

### 3. Inventory (主机清单)

**静态 Inventory** (`/etc/ansible/hosts` 或自定义):

```ini
# 简单格式
[webservers]
web1.example.com
web2.example.com
web3.example.com

[databases]
db1.example.com
db2.example.com

[loadbalancers]
lb1.example.com

# 变量
[webservers]
web1.example.com http_port=80
web2.example.com http_port=8080

# 子组
[web:children]
webservers
loadbalancers

# 范围
[webservers]
web[01:10].example.com

# 主机变量
[webservers]
web1.example.com ansible_host=192.168.1.10
```

**动态 Inventory**:从云 API 拉取(AWS EC2、GCP Compute、Azure、OpenStack、Kubernetes)

```yaml
# aws_ec2.yml
plugin: aws_ec2
regions:
  - us-east-1
keyed_groups:
  - key: tags.Role
    prefix: role
```

### 4. Ad-hoc 命令

```bash
# 测试连接
ansible all -m ping

# 执行命令
ansible webservers -m shell -a "uptime"
ansible all -m command -a "df -h" --become
ansible all -m shell -a "systemctl restart nginx" --become

# 复制文件
ansible all -m copy -a "src=/etc/hosts dest=/tmp/hosts"

# 安装包
ansible webservers -m yum -a "name=httpd state=present" --become

# 看主机信息
ansible all -m setup
ansible web1 -m setup -a "filter=ansible_eth0"

# 指定用户
ansible all -m ping -u alice

# 指定 inventory
ansible -i myhosts all -m ping
```

### 5. Playbook (剧本)

**基础 Playbook** (`site.yml`):

```yaml
---
- name: 配置 Web 服务器
  hosts: webservers
  become: yes
  vars:
    http_port: 80
    max_clients: 200
  tasks:
    - name: 安装 httpd
      yum:
        name: httpd
        state: present
      notify: restart httpd

    - name: 启动并启用 httpd
      service:
        name: httpd
        state: started
        enabled: yes

    - name: 部署网站配置
      template:
        src: templates/httpd.conf.j2
        dest: /etc/httpd/conf/httpd.conf
        owner: root
        group: root
        mode: '0644'
      notify: restart httpd

    - name: 部署网站内容
      copy:
        src: files/index.html
        dest: /var/www/html/index.html

    - name: 开放防火墙
      firewalld:
        service: http
        permanent: yes
        state: enabled
      notify: reload firewalld

    - name: SELinux 允许 httpd
      seboolean:
        name: httpd_can_network_connect
        state: yes
        persistent: yes

  handlers:
    - name: restart httpd
      service:
        name: httpd
        state: restarted

    - name: reload firewalld
      service:
        name: firewalld
        state: reloaded
```

### 6. Playbook 运行

```bash
# 检查语法
ansible-playbook --syntax-check site.yml

# 干跑(不执行)
ansible-playbook --check site.yml

# 详细
ansible-playbook -v site.yml
ansible-playbook -vvv site.yml

# 步骤执行
ansible-playbook --start-at-task="安装 httpd" site.yml
ansible-playbook --step site.yml

# 限制主机
ansible-playbook -l web1 site.yml
ansible-playbook -l webservers site.yml

# 并发
ansible-playbook -f 10 site.yml

# 标签
ansible-playbook -t install site.yml
ansible-playbook --skip-tags install site.yml
```

### 8. 变量与事实

**变量类型**:

```yaml
# vars: 在 playbook 中
- hosts: web
  vars:
    http_port: 80
  tasks:
    - debug:
        msg: "Port: {{ http_port }}"

# vars_files: 外部文件
vars_files:
  - vars/common.yml
  - vars/{{ env }}.yml

# vars_prompt: 提示输入
vars_prompt:
  - name: username
    prompt: "Enter username"
    private: no

# host_vars / group_vars
# group_vars/all.yml       所有
# group_vars/web.yml        web 组
# host_vars/web1.yml        web1 主机

# 优先级: 命令行 > vars_prompt > host_vars > group_vars > vars_files > vars > defaults
```

**Jinja2 模板**:

```jinja
# config.j2
{% for port in listen_ports %}
Listen {{ port }}
{% endfor %}

server {
    listen {{ http_port }};
    server_name {{ ansible_fqdn }};
    root {{ doc_root }};
    {% if ssl_enabled %}
    ssl on;
    {% endif %}
}
```

**Facts (事实)**:Ansible 自动收集的主机信息

```yaml
- debug:
    msg: >
      Host: {{ ansible_fqdn }}
      OS: {{ ansible_distribution }} {{ ansible_distribution_version }}
      CPU: {{ ansible_processor_count }}
      Memory: {{ ansible_memtotal_mb }} MB
      IPs: {{ ansible_all_ipv4_addresses }}
```

### 9. 条件、循环、注册

```yaml
- name: 条件
  hosts: all
  tasks:
    - name: 仅在 CentOS 装
      yum:
        name: epel-release
        state: present
      when: ansible_distribution == "CentOS"

- name: 循环
  hosts: all
  tasks:
    - name: 装多个包
      yum:
        name: "{{ item }}"
        state: present
      loop:
        - git
        - curl
        - vim
        - htop

- name: 循环字典
  hosts: all
  vars:
    users:
      - name: alice
        uid: 1001
      - name: bob
        uid: 1002
  tasks:
    - name: 创用户
      user:
        name: "{{ item.name }}"
        uid: "{{ item.uid }}"
      loop: "{{ users }}"

- name: 注册变量
  hosts: all
  tasks:
    - name: 查版本
      command: nginx -v
      register: nginx_version
      changed_when: false

    - name: 打印
      debug:
        msg: "{{ nginx_version.stderr }}"

    - name: 失败处理
      command: /bin/false
      failed_when: false
      register: result

    - name: 用结果
      debug:
        msg: "RC: {{ result.rc }}"
      when: result.rc != 0
```

## 四、SaltStack 详解

### 1. SaltStack 概述

**SaltStack**:**高速**、**可扩展**的配置管理

- 基于 ZeroMQ
- 推送/拉取都支持
- 适合大规模(> 5000 节点)
- Python 编写

### 2. 架构

```text
Master (控制端)
   ↓
Minions (被控端)
```

**通信**: ZeroMQ (pub/sub + req/rep)

### 3. 安装

```bash
# Master
yum install salt-master
systemctl enable --now salt-master

# Minion
yum install salt-minion
echo "master: salt.example.com" > /etc/salt/minion
systemctl enable --now salt-minion

# 接受 key
salt-key -L
salt-key -A
salt-key -a minion-name
```

### 4. 执行命令

```bash
# 全部
salt '*' test.ping
salt '*' cmd.run "uptime"

# 指定
salt 'web*' cmd.run "df -h"
salt -E 'web(1|2|3)' cmd.run "whoami"

# 状态 (state)
salt '*' state.apply

# 配置
salt '*' grains.items
salt '*' pillar.items
```

### 5. Salt State (SLS)

```yaml
# /srv/salt/webserver.sls
nginx:
  pkg:
    - installed
  service:
    - running
    - enable: True
    - watch:
      - file: /etc/nginx/nginx.conf

/etc/nginx/nginx.conf:
  file:
    - managed
    - source: salt://nginx.conf
    - mode: 644

# 状态
salt '*' state.apply webserver
salt 'web*' state.highstate
```

### 6. Grains (静态信息)

```bash
salt '*' grains.ls
salt '*' grains.items
salt '*' grains.get os
salt '*' grains.get ipv4
```

### 7. Pillars (动态信息)

```yaml
# /srv/pillar/top.sls
base:
  '*':
    - common

# /srv/pillar/common.sls
user: alice
sudo: true
```

```bash
salt '*' pillar.items
salt '*' pillar.get user
```

### 8. Salt 反应器 (Reactor)

```yaml
# /etc/salt/master.d/reactor.conf
reactor:
  - 'salt/minion/*/start':
    - /srv/reactor/init.sls

# /srv/reactor/init.sls
{% if data['act'] == 'start' %}
highstate:
  cmd.state.apply:
    - tgt: {{ data['id'] }}
{% endif %}
```

### 9. Salt SSH

```bash
salt-ssh '*' test.ping
salt-ssh 'web*' cmd.run "uptime"
```

### 10. Salt 优缺点

**优点**:

- 极快(ZeroMQ)
- 大规模
- 灵活(推送/拉取)

**缺点**:

- 学习曲线陡
- 社区比 Ansible 小

## 五、Puppet 详解

### 1. Puppet 概述

**Puppet**:**拉取式**、**模型化**的配置管理

- 客户端主动拉配置
- 适合大规模
- 模型化语言
- 商业版:Puppet Enterprise

### 2. 架构

```text
Puppet Master
   ↓ 拉
Puppet Agent
   ↓
应用配置
```

### 3. 安装

```bash
# Master
yum install puppetserver
systemctl enable --now puppetserver

# Agent
yum install puppet
systemctl enable --now puppet
```

### 4. 资源声明 (Puppet DSL)

```puppet
# /etc/puppet/code/environments/production/modules/nginx/manifests/init.pp
class nginx {
  package { 'nginx':
    ensure => installed,
  }

  service { 'nginx':
    ensure => running,
    enable => true,
    require => Package['nginx'],
  }

  file { '/etc/nginx/nginx.conf':
    ensure  => file,
    source  => 'puppet:///modules/nginx/nginx.conf',
    notify  => Service['nginx'],
    require => Package['nginx'],
  }
}
```

### 5. Puppet 应用

```bash
# 试运行
puppet apply --noop site.pp

# 真实应用
puppet apply site.pp

# 客户端拉配置
puppet agent --test
```

## 六、Chef 详解

### 1. Chef 概述

**Chef**:**编程式**、**Ruby DSL**、**拉取式** 配置管理

- 客户端主动拉配置
- 用 Ruby 写配置(灵活)

- 商业版:Chef Automate

**架构**:

```text
Chef Server (中央)
   ↓ 拉
Chef Client (节点)
```

- **Knife**: CLI 工具
- **Berkshelf**: Cookbook 依赖管理
- **Test Kitchen**: Cookbook 测试框架
- **ChefSpec**: 单元测试

### 3. 安装

```bash

wget https://packages.chef.io/files/stable/chef-workstation/23.7.1042/ubuntu/22.04/chef-workstation_23.7.1042-1_amd64.deb

```

### 4. Cookbook 结构

```text

├── files/
```

### 5. Recipe 示例 (Ruby DSL)

```ruby

  action :install

  action [:enable, :start]

  source 'nginx.conf.erb'

  mode '0644'

# 部署文件

  source 'index.html'
end
```

### 7. Chef 优缺点

## 七、Terraform

### 1. Terraform 概述

**Terraform**:HashiCorp 的**基础设施即代码 (IaC)** 工具

- 声明式:HCL 语言
- 跨云: AWS / Azure / GCP / AliCloud
- 状态管理
- 模块化
- 强大的生态(2000+ provider)

### 2. 核心概念

- **Provider**:云厂商插件
- **Resource**:基础设施组件
- **State**:状态(资源实际状态)
- **Module**:可复用代码块
- **Variable / Output**:变量和输出
- **HCL**:HashiCorp 配置语言

### 3. 简单示例

```hcl
# main.tf
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = "us-east-1"
}

resource "aws_instance" "web" {
  ami           = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"
  tags = {
    Name = "WebServer"
  }
}

output "instance_ip" {
  value = aws_instance.web.public_ip
}
```

### 4. 常用命令

```bash
terraform init              # 初始化
terraform plan              # 计划(看变化)
terraform apply             # 应用
terraform apply -auto-approve
terraform destroy           # 销毁
terraform fmt               # 格式化
terraform validate          # 验证
terraform show              # 看状态
terraform output            # 看输出
terraform state list        # 列状态
terraform state show aws_instance.web
terraform refresh           # 刷新状态
terraform import aws_instance.web i-xxx
terraform taint aws_instance.web
```

### 5. State 管理

```hcl
# 本地(默认)
# terraform.tfstate

# 远程(推荐)
terraform {
  backend "s3" {
    bucket = "my-tf-state"
    key    = "prod/terraform.tfstate"
    region = "us-east-1"
    dynamodb_table = "my-tf-locks"
  }
}
```

支持的 backend:

- S3, Azure Storage, GCS
- Consul
- etcd
- HTTP
- local (默认)

### 6. 模块化

```hcl
# modules/webserver/main.tf
variable "ami" {}
variable "instance_type" {}

resource "aws_instance" "this" {
  ami           = var.ami
  instance_type = var.instance_type
}

output "ip" {
  value = aws_instance.this.public_ip
}

# 调用
```

## 八、Kustomize

### 1. Kustomize 概述

**Kustomize**:**Kubernetes 原生**配置管理工具

- 不需要模板
- **Base + Overlay** 模式
- `kubectl` 内置支持

### 2. 目录结构

```text
myapp/
├── base/
│   ├── kustomization.yaml
│   ├── deployment.yaml
│   ├── service.yaml
│   └── configmap.yaml
└── overlays/
    ├── dev/
    │   └── kustomization.yaml
    └── prod/
        └── kustomization.yaml
```

### 3. base/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
- deployment.yaml
- service.yaml
- configmap.yaml
```

### 4. overlays/prod/kustomization.yaml

```yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: production
namePrefix: prod-
replicas:
- name: web
  count: 5

images:
- name: myapp
  newName: myregistry/myapp
  newTag: v1.5.0

resources:
- ../../base

patches:
- target:
    kind: Deployment
    name: web
  patch: |-
    - op: replace
      path: /spec/template/spec/containers/0/resources
      value:
        limits:
          cpu: "1"
          memory: 1Gi
        requests:
          cpu: 500m
          memory: 512Mi

configMapGenerator:
- envs:
  - prod.env
```

### 5. 常用

```bash
# kubectl 内置
kubectl apply -k overlays/prod/

# 独立 kustomize
kustomize build overlays/prod/
```

## 九、Helm

### 1. Helm 概述

**Helm**:Kubernetes 的**包管理**工具

- 模板化
- 版本管理
- 仓库
- 易于共享

### 2. 概念

- **Chart**:Helm 包(类似 rpm)
- **Release**:Chart 的一个实例
- **Repository**:Chart 仓库
- **Values**:配置文件

### 3. Chart 结构

```text
mychart/
├── Chart.yaml            # Chart 元数据
├── values.yaml           # 默认值
├── templates/            # K8s YAML 模板
│   ├── deployment.yaml
│   ├── service.yaml
│   ├── ingress.yaml
│   └── _helpers.tpl
├── charts/               # 依赖
└── README.md
```

### 4. 常用命令

```bash
# 装 helm
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# 仓库
helm repo add stable https://charts.helm.sh/stable
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update
helm search repo nginx

# 安装
helm install my-nginx bitnami/nginx
helm install my-nginx bitnami/nginx -f values.yaml
helm install my-nginx bitnami/nginx --set replicaCount=3

# 查
helm list
helm list -A
helm status my-nginx

# 升级
helm upgrade my-nginx bitnami/nginx -f new-values.yaml

# 回滚
helm rollback my-nginx 1

# 删除
helm uninstall my-nginx

# 仓库管理
helm repo list
helm repo add
helm repo update
```

### 5. Chart 模板 (Go template)

```yaml
# templates/deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: {{ .Release.Name }}-{{ .Chart.Name }}
  labels:
    app: {{ .Values.app.name }}
    version: {{ .Chart.AppVersion }}
spec:
  replicas: {{ .Values.replicaCount }}
  selector:
    matchLabels:
      app: {{ .Values.app.name }}
  template:
    metadata:
      labels:
        app: {{ .Values.app.name }}
    spec:
      containers:
      - name: {{ .Chart.Name }}
        image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
        ports:
        - containerPort: {{ .Values.service.port }}
        resources:
          {{- toYaml .Values.resources | nindent 10 }}
```

### 6. values.yaml

```yaml

image:
  repository: nginx
  tag: 1.25
  pullPolicy: IfNotPresent

service:
  port: 80
  type: ClusterIP

resources:
  requests:
    cpu: 100m
    memory: 128Mi
  limits:
    cpu: 500m
    memory: 512Mi
```

## 十一、配置管理最佳实践

### 1. 仓库组织

- **配置仓库**: 单独 Git 仓库

- 角色名清晰
- 变量名一致
- 任务名描述

### 3. 幂等性

- **不要写非幂等的命令**

- 用 `state: present/absent`
- 改文件用 `template` / `lineinfile`

### 4. 测试

- **单元测试**: 模拟执行

- **CI/CD**: 测试配置变更

```bash
# Ansible lint

molecule test

# Serverspec (Ruby)
serverspec
```

### 5. 加密

- **Ansible Vault**: 加密敏感数据
- **不要提交密钥**
- **用环境变量 / KMS**
- **轮换密钥**

### 6. 审计

- **Git 记录一切变更**
- **PR 审查**
- **谁改了什么**
- **回滚容易**

### 7. 文档

- README
- Wiki
- 注释
- CHANGELOG

- **Ansible** = 简单推送式,YAML,SSH,无客户端

- **Puppet** = 拉取,模型化,大规模

- **Terraform** = IaC,跨云,声明式

- **Inventory** = 主机清单

- **Manifest** = Puppet 配置
