# 性能分析与调优 (Performance Analysis & Tuning)

## 一、性能分析概述

### 性能调优的目标

- **提高吞吐量**:单位时间完成任务多
- **降低延迟**:响应快
- **提高资源利用率**:不浪费 CPU、内存、IO
- **提高稳定性**:不崩溃、不超时
- **降低成本**:用更少机器做更多事

### 性能调优的层次

```text
1. 业务层    (应用逻辑、算法)
2. 应用层    (Web 框架、数据库)
3. JVM/语言运行层 (GC、线程池)
4. OS 层     (CPU、内存、IO、网络)
5. 硬件层    (CPU、内存、磁盘、网卡)
6. 网络层    (LAN、WAN、跨机房)
```

**调优顺序**:从上层到下层(因为上层问题占 80%)

### 性能调优的方法论

1. **定目标**:SLA/QPS/延迟/错误率
2. **测基线**:现状是什么
3. **定位瓶颈**:CPU/内存/IO/网络/应用
4. **分析原因**:为什么慢
5. **改一处**:小步迭代
6. **测改进**:对比基线
7. **继续优化**:返回 3

**黄金法则**:**先测量,后优化**(不要盲目调)

## 二、性能指标

### 1. 关键指标

| 指标                              | 含义                        |
|-----------------------------------|-----------------------------|
| **QPS (Queries Per Second)**      | 每秒查询数                  |
| **TPS (Transactions Per Second)** | 每秒事务数                  |
| **延迟 (Latency)**                | 单次操作响应时间 (ms)       |
| **P99 延迟**                      | 99% 请求的延迟上界          |
| **P95 延迟**                      | 95% 请求的延迟上界          |
| **吞吐 (Throughput)**             | 单位时间处理量 (MB/s, IOPS) |
| **错误率**                        | 失败请求比例                |
| **可用性 (Availability)**         | 系统可用时间百分比          |
| **CPU 利用率**                    | CPU 忙的时间比例            |
| **内存使用率**                    | 内存占用比例                |
| **IO 等待**                       | 进程等 IO 的时间比例        |

### 2. 性能 vs 容量 vs 资源

- **性能**:单位时间能干多少(快)
- **容量**:能存多少(大)
- **资源**:用了多少(省)

三者需要**平衡**:
- 性能高 → 资源多
- 资源省 → 性能低

### 3. 长尾延迟

**长尾延迟**:少量请求特别慢,影响整体体验

- **P99 延迟** 比**平均延迟**更重要
- 99% 快的应用 + 1% 慢的应用 = 实际体验差

## 三、CPU 性能分析

### 1. CPU 使用率指标

- **用户态 (us)**:用户进程
- **内核态 (sy)**:内核代码
- **nice (ni)**:低优先级用户
- **空闲 (id)**:闲置
- **IO 等待 (wa)**:等 IO
- **硬中断 (hi)**:硬件中断
- **软中断 (si)**:软中断
- **偷取 (st)**:虚拟化下被宿主机偷
- **客户机 (gn, qemu)**

### 2. 监控工具

```bash
# top / htop
top
htop

# 每核 CPU
mpstat -P ALL 1

# 整体 CPU
mpstat 1
vmstat 1
sar -u 1 5

# 找 CPU 高的进程
ps -eo pid,user,pri,ni,%cpu,comm --sort=-%cpu | head
pidstat -u 1 -p PID

# 找 CPU 高的线程
ps -L -e -o pid,tid,pri,%cpu,comm | sort -k4 -rn | head
top -H -p PID
```

### 3. CPU 性能分析

```bash
# perf 分析
perf top                    # 实时热点
perf record -a -g command   # 记录
perf report                 # 看报告
perf stat command           # 统计

# bpftrace
bpftrace -e 'kprobe:schedule { @[comm] = count(); }'

# 跟踪调度
perf sched record
perf sched latency

# CPU 亲和性
taskset -c 0 command
taskset -p 0x3 1234

# 中断亲和
cat /proc/irq/24/smp_affinity
echo 0-7 > /proc/irq/24/smp_affinity_list
```

### 4. CPU 调优

```bash
# 调度器
echo performance > /sys/devices/system/cpu/cpu*/cpufreq/scaling_governor
# performance = 最高性能
# ondemand/Conservative = 动态
# powersave = 最省电

# CPU 频率
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq
cat /sys/devices/system/cpu/cpu*/cpufreq/scaling_max_freq

# 隔离 CPU
systemctl set-property isolated_cores=0,1

# 关闭透明大页 (数据库)
echo never > /sys/kernel/mm/transparent_hugepage/enabled

# 微码更新
yum update microcode_ctl

# 编译器优化 -O2/-O3/-Ofast
# 去掉 -g

# 进程优先级
nice -n -20 command
chrt -f -p 99 PID
```

### 5. CPU 性能常见问题

| 问题              | 原因               | 解决                    |
|-------------------|--------------------|-------------------------|
| CPU 高(us)        | 应用 CPU 密集      | 优化算法、改语言、并行  |
| CPU 高(sy)        | 内核态忙,系统调用  | 减少 syscalls,batch     |
| CPU 高(wa)        | 进程等 IO          | 优化 IO、用 SSD         |
| CPU 高(hi/si)     | 中断太多           | 中断亲和、网卡多队列    |
| CPU 高(st)        | 虚拟化被偷         | 绑核、用大页            |
| load average 高   | 任务数超过 CPU 数  | 加 CPU、优化任务        |
| 上下文切换多      | 任务切换频繁       | 减少线程、用协程        |
| 中断多            | 网卡/磁盘中断      | 中断亲和、多队列        |

### 6. 软中断 / 硬中断

```bash
# 看软中断
cat /proc/softirqs
# 看硬中断
cat /proc/interrupts
mpstat -I ALL 1

# 网卡多队列
ethtool -L eth0 combined 8
```

## 四、内存性能分析

### 1. 内存指标

```bash
# 总体
free -h
free -s 1                  # 1 秒刷新
cat /proc/meminfo

# 详细
slabtop                    # 内核 slab 缓存
vmstat 1                   # 虚拟内存统计
sar -r 1                   # 内存使用率
ps -eo pid,vsz,rss,comm --sort=-rss | head
```

### 2. 内存区域

- **VSS (Virtual Set Size)**:虚拟内存大小
- **RSS (Resident Set Size)**:物理内存占用
- **PSS (Proportional Set Size)**:按比例的物理内存(共享库分摊)
- **USS (Unique Set Size)**:独享物理内存
- **Swap**:交换分区使用

### 3. 进程内存分析

```bash
# 看进程
ps -o pid,user,vsz,rss,pmem,comm

# 详细
pmap -d PID
cat /proc/PID/smaps
cat /proc/PID/status

# 找内存泄漏
valgrind --leak-check=full program
ASAN_OPTIONS=detect_leaks=1 program
```

### 4. OOM 分析

```bash
# OOM killer 日志
dmesg | grep -i oom
grep -i "killed process" /var/log/syslog

# 看进程的 OOM 分数
cat /proc/PID/oom_score
cat /proc/PID/oom_score_adj
# 设为 -1000,永不 OOM
echo -1000 > /proc/PID/oom_score_adj
```

### 5. 内存调优

```bash
# vm 调优
sysctl -w vm.swappiness=10          # 减少 swap
sysctl -w vm.dirty_ratio=20         # 写入阈值
sysctl -w vm.dirty_background_ratio=5
sysctl -w vm.min_free_kbytes=65536
sysctl -w vm.vfs_cache_pressure=100

# 大页
echo 1024 > /proc/sys/vm/nr_hugepages
mount -t hugetlbfs hugetlbfs /mnt/huge

# 透明大页
echo madvise > /sys/kernel/mm/transparent_hugepage/enabled

# 缓存
sync
echo 3 > /proc/sys/vm/drop_caches  # 释放(测试用)

# OOM 调整
sysctl -w vm.oom_kill_allocating_task=0
```

### 6. swap 调优

```bash
# 查 swap
swapon --show
cat /proc/swaps

# 创建 swap 文件
fallocate -l 4G /swapfile
chmod 600 /swapfile
mkswap /swapfile
swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 调 swappiness
sysctl -w vm.swappiness=1  # 数据库
```

### 7. 内存性能常见问题

| 问题              | 原因                | 解决                   |
|-------------------|---------------------|------------------------|
| 内存耗尽          | 应用吃内存          | 优化代码、限制进程     |
| 内存泄漏          | 没释放              | 用 valgrind 检测       |
| 频繁 swap         | 物理内存不够        | 加内存、降 swappiness  |
| 缓存命中率低      | 缓存设计差          | 优化算法、增大缓存     |
| 大页失效          | 分配碎片            | 用大页                 |

### 8. IO 性能常见问题

| 问题            | 原因                | 解决                  |
|-----------------|---------------------|-----------------------|
| IO 延迟高       | 磁盘慢 / IO 队列长  | 换 SSD、加大队列深度  |

| inode 满        | 小文件太多          | 重新格式化加 inode    |
| 读慢            | 缓存失效            | 加缓存、预读          |
| 写慢            | 同步写              | 异步、批量            |
| fsync 慢        | 磁盘刷盘慢          | 用 BBU、SSD           |

### 2. brendan gregg 性能方法论

**USE 方法**(Utilization, Saturation, Errors):

- **Utilization** (利用率):资源忙的时间
- **Saturation** (饱和度):资源排队的程度
- **Errors** (错误率):错误事件数

**每个资源(CPU/内存/IO/网络)都按 USE 检查**

**RED 方法** (Rate, Errors, Duration):

- **Rate** (请求率)
- **Errors** (错误率)
- **Duration** (延迟)

适用于服务监控

## 十六、核心要点速记

- **USE 方法**:Utilization / Saturation / Errors
- **RED 方法**:Rate / Errors / Duration
- **CPU 三剑客**:top / mpstat / perf
- **内存三剑客**:free / vmstat / slabtop
- **IO 三剑客**:iostat / iotop / fio
- **网络三剑客**:nicstat / nstat / iperf3
- **perf top** = 实时热点
- **perf record + report** = 录制 + 报告
- **火焰图** = 可视化调用栈
- **bpftrace** = 高级追踪
- **strace -c** = 系统调用统计
- **valgrind** = 内存检测
- **ASan / TSan** = 编译时检测
- **大页** = 减少 TLB miss
- **swappiness 10** = 减少 swap
- **BBR** = 现代 TCP 拥塞算法
- **O_DIRECT** = 数据库绕过 cache
- **ulimit -n 1000000** = 大 fd
- **perf** = 第一选择
- **先测量,后优化** = 黄金法则
- **80/20 法则**:80% 性能问题在 20% 的代码
