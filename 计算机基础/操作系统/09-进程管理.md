# 进程管理 (Process Management)

## 一、进程概述

### 什么是进程

**进程 (Process)** 是程序在某个数据集合上的一次**运行活动**,是操作系统进行**资源分配和调度的基本单位**。

- **程序**:静态的、磁盘上的可执行文件(如 `/bin/ls`)
- **进程**:动态的、内存中正在运行的程序实例
- **关系**:一个程序可对应多个进程(如开多个终端跑 `ls`)

### 进程的特点

- **动态性**:生命周期(创建 → 运行 → 终止)
- **并发性**:多个进程可同时运行(宏观)
- **独立性**:每个进程有独立地址空间
- **异步性**:执行走走停停,推进速度不可预知
- **结构性**:由程序、数据、PCB 三部分组成

### 进程 vs 程序

| 维度       | 程序                  | 进程                          |
|------------|-----------------------|-------------------------------|
| 实体       | 文件 (静态)           | 执行实例 (动态)               |
| 存在位置   | 磁盘                  | 内存                          |
| 生命周期   | 永久                  | 临时                          |
| 资源       | 无                    | 占用 CPU、内存、I/O 等        |
| 一对多     | 一个程序可对应多进程  | 一个进程只属于一个程序        |
| 标识       | 文件名                | PID (Process ID)              |

## 二、进程控制块 (PCB)

### 什么是 PCB

**PCB (Process Control Block)**:操作系统为每个进程**保存的描述信息**,是进程存在的唯一标志。

**类比**:PCB 就像人的身份证,记录这个人的所有属性。

### PCB 的内容 (Linux 中是 `task_struct`)

```text
struct task_struct {          // 简化版
    // 标识符
    pid_t pid;                // 进程 ID
    pid_t tgid;               // 线程组 ID
    uid_t uid, euid;          // 用户 ID,有效 UID
    gid_t gid, egid;          // 组 ID

    // 状态
    volatile long state;      // 状态 (R/S/D/T/Z/X)
    int exit_code;            // 退出码
    int exit_signal;          // 退出信号

    // 优先级
    int prio, static_prio, normal_prio;
    unsigned int rt_priority;
    const struct sched_class *sched_class;

    // 进程关系
    struct task_struct *parent;  // 父进程
    struct list_head children;   // 子进程链表
    struct list_head sibling;   // 兄弟进程

    // 内存管理
    struct mm_struct *mm;       // 内存描述符
    pgd_t *pgd;                 // 页表

    // 文件系统
    struct fs_struct *fs;       // 当前工作目录
    struct files_struct *files; // 打开的文件

    // 信号
    struct signal_struct *signal;
    sigset_t blocked, real_blocked;
    sigset_t pending, real_pending;

    // 凭证
    struct cred *cred;          // 凭证

    // 时间
    u64 start_time;             // 启动时间
    u64 real_start_time;
    cputime_t utime, stime;     // 用户态/内核态 CPU 时间

    // 调度
    int on_cpu;                 // 在哪个 CPU 上跑
    int on_rq;                  // 在就绪队列上
    int nr_cpus_allowed;
    cpumask_t cpus_allowed;     // CPU 亲和性

    // 命名空间
    struct nsproxy *nsproxy;    // 命名空间

    // ... 还有 io, signal, futex 等
};
```

### PCB 关键字段速查

| 字段类别       | 字段                                   |
|----------------|----------------------------------------|
| **标识符**     | PID、PPID、UID、GID、TGID、PGID        |
| **状态**       | 运行/就绪/阻塞/退出/僵尸等             |
| **优先级**     | 静态/动态优先级、nice 值、rt_priority  |
| **程序计数器** | PC、寄存器、栈指针                     |
| **内存信息**   | 段表、页表、代码/数据/堆栈指针         |
| **I/O 信息**   | 已打开文件、I/O 设备                   |
| **进程关系**   | 父子、兄弟、进程组                     |
| **时间信息**   | 创建时间、运行时间、CPU 时间           |
| **信号**       | 阻塞信号、待处理信号、信号处理函数     |
| **凭证**       | 真实 UID/GID、有效 UID/GID、capability |
| **资源限制**   | rlimit                                 |
| **调度**       | CPU 亲和性、调度策略、调度实体         |

### PCB 的组织方式

- **链表**:同一状态的进程组成链表
- **索引表**:用 PID 索引 PCB
- **多级队列**:不同优先级不同队列
- **树结构**:父子关系

## 三、进程的状态

### 1. 三状态模型 (经典)

```text
                ┌──────────┐
                │  New     │ ← 刚创建
                └────┬─────┘
                     ↓
                ┌──────────┐
        ┌──────→│  Ready   │ ← 就绪
        │       └────┬─────┘
        │            ↓ 调度
        │       ┌──────────┐
        │       │ Running  │ ← 运行
        │       └────┬─────┘
        │            ↓ 等待事件
        │       ┌──────────┐
        │       │ Blocked  │ ← 阻塞
        │       └────┬─────┘
        │            ↓ 事件完成
        └────────────┘
                     ↓
                ┌──────────┐
                │ Exit     │ ← 终止
                └──────────┘
```

### 2. Linux 的 7 个状态 (task->state)

| 状态宏                 | 标志位     | 含义                                        |
|------------------------|------------|---------------------------------------------|
| `TASK_RUNNING`         | `R`        | **运行/就绪** —— 在就绪队列,等待或正在跑    |
| `TASK_INTERRUPTIBLE`   | `S`        | **可中断睡眠** —— 等待事件,信号可唤醒       |
| `TASK_UNINTERRUPTIBLE` | `D`        | **不可中断睡眠** —— 不可被信号打断 (如 I/O) |
| `__TASK_STOPPED`       | `T`        | **停止** —— 收到 SIGSTOP 等                 |
| `__TASK_TRACED`        | `t`        | **被追踪** —— 调试器暂停                    |
| `EXIT_ZOMBIE`          | `Z`        | **僵尸** —— 已终止,等待父进程回收           |
| `EXIT_DEAD`            | `X`        | **死亡** —— 即将销毁                        |

### 3. ps 命令中的状态

```bash
ps aux
# 状态码含义
# R - Running
# S - Sleeping (interruptible)
# D - Disk sleep (uninterruptible)
# T - Stopped
# t - Traced
# Z - Zombie
# X - Dead
# I - Idle (内核空闲线程)
# < - 高优先级
# N - 低优先级
# L - 锁定内存
# s - session leader
# l - 多线程
# + - 前台进程
```

### 4. 进程状态转换详解

| 转换                              | 触发事件                          |
|-----------------------------------|-----------------------------------|
| New → Ready                       | 进程创建完成,加入就绪队列         |
| Ready → Running                   | 调度器选中                        |
| Running → Ready                   | 时间片用完 / 被高优先级抢占       |
| Running → Blocked (S/D)           | 等待 I/O、信号、锁等              |
| Blocked → Ready                   | 事件发生,被唤醒                   |
| Running → Stopped                 | 收到 SIGSTOP/SIGTSTP              |
| Stopped → Ready                   | 收到 SIGCONT                      |
| Running → Zombie (Z)              | 进程 exit,等待父进程 wait         |
| Zombie → X                        | 父进程调用 wait 或忽略            |

### 5. 特殊状态:Zombie(僵尸)进程

**产生原因**:子进程退出,父进程没有调用 `wait()` 回收,内核保留子进程的退出信息。

**危害**:
- 占用 PID(系统 PID 有限)
- 占用少量内核资源(PCB)

**处理**:
- 父进程 `wait()` / `waitpid()`
- 杀掉父进程(init 会接管)
- 设置 SIGCHLD 为 SIG_IGN (Linux)

### 6. 特殊状态:D (不可中断睡眠)

**特点**:
- 不能被信号打断
- 通常发生在关键 I/O 中
- ps 显示 `D`
- **top / iotop** 可看到

**如果 D 状态进程长时间卡住**:
- 可能是 I/O 设备故障
- 可能是 NFS 卡死
- 通常需要重启

## 四、进程的创建与终止

### 1. 进程创建

#### (1) 创建过程 (Linux)

```text
1. 调用 fork() / clone() 系统调用
2. 内核分配新的 PID
3. 复制父进程的 task_struct
4. 复制父进程的部分资源(可共享)
5. 子进程状态设为 TASK_RUNNING
6. 子进程开始运行(或从 fork() 返回)
7. 父进程从 fork() 返回(子进程 PID)
8. 子进程从 fork() 返回 0
```

#### (2) 关键系统调用

| 系统调用        | 作用                              | 头文件           |
|-----------------|-----------------------------------|------------------|
| `fork()`        | 复制进程 (写时复制)               | `unistd.h`       |
| `vfork()`       | 类似 fork,但子进程共享父进程内存  | `unistd.h`       |
| `clone()`       | 更灵活,Linux 专用,线程也用它      | `sched.h`        |
| `exec*()`       | 替换进程映像(代码和数据)          | `unistd.h`       |
| `posix_spawn()` | 综合 fork+exec,POSIX 标准         | `spawn.h`        |
| `system()`      | 在 shell 中执行命令               | `stdlib.h`       |
| `popen()`       | 创建管道执行命令                  | `stdio.h`        |

#### (3) fork() 详解

**核心特性:写时复制 (Copy-On-Write, COW)**

- 父子进程**共享**内存页(只读)
- 任一方**写入**才复制
- 大大提升效率

```c
pid_t pid = fork();

if (pid < 0) {
    // 错误
} else if (pid == 0) {
    // 子进程
    printf("I am child, pid=%d\n", getpid());
} else {
    // 父进程
    printf("I am parent, child pid=%d\n", pid);
}
```

#### (4) exec*() 详解

**功能**:在当前进程空间加载并运行新程序,替换原有代码和数据。

**exec 系列**:

| 函数            | 路径搜索 | 参数格式     | 使用       |
|-----------------|----------|--------------|------------|
| `execl()`       | 手动     | 列表         | 已知参数   |
| `execlp()`      | 自动     | 列表         | PATH 中找  |
| `execle()`      | 手动     | 列表+环境    | 自定义 env |
| `execv()`       | 手动     | 数组         | 变长参数   |
| `execvp()`      | 自动     | 数组         | PATH 中找  |
| `execvpe()`     | 自动     | 数组+环境    | GNU 扩展   |

```c
// 用 exec 替换进程映像
char *args[] = {"ls", "-l", "/tmp", NULL};
execvp("ls", args);
perror("exec failed");
exit(1);
```

#### (5) fork + exec 模式

**经典用法**:创建子进程执行新程序

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程
    execlp("ls", "ls", "-l", NULL);
    exit(1);
} else {
    // 父进程
    wait(NULL);  // 等待子进程结束
}
```

### 2. 进程终止

#### (1) 正常终止

- **main 返回**:return 0
- **调用 exit()**:C 标准库,刷新缓冲,关闭文件
- **调用 _exit() / _Exit()**:系统调用,直接终止
- **最后一个线程返回或调用 pthread_exit**

#### (2) 异常终止

- **abort()**:发送 SIGABRT
- **被信号终止**:kill 默认动作
- **运行时错误**:段错误(SIGSEGV)、除零(SIGFPE)

#### (3) 退出码

**约定**:
- 0 = 成功
- 非 0 = 失败
- 1 = 通用错误
- 2 = 命令行参数错误
- 127 = 命令未找到
- 128+N = 被信号 N 终止
  - 130 = SIGINT (Ctrl+C)
  - 137 = SIGKILL
  - 139 = SIGSEGV (段错误)

```bash
$ ls /nonexistent
ls: cannot access '/nonexistent': No such file or directory
$ echo $?
2
```

### 3. 进程退出流程

```text
1. 进程调用 exit() / _exit() / main 返回
2. 内核清理:
   a. 关闭打开的文件描述符
   b. 释放内存
   c. 释放其他资源(锁、信号量)
   d. 设置 task->exit_code
   e. 设置 task->state = EXIT_ZOMBIE
3. 通知父进程 (SIGCHLD)
4. 等待父进程调用 wait()
5. 父进程 wait() 后,内核释放 task_struct
6. 进程彻底消亡
```

## 五、进程调度

### 1. 调度器要解决的问题

- **在多个就绪进程中选一个**
- **什么时候切换**(时间片 / 主动让出)
- **在哪个 CPU 上跑**(负载均衡)

### 2. 调度器的发展

| Linux 版本   | 调度器                              | 特点                       |
|--------------|-------------------------------------|----------------------------|
| 2.4 之前     | 简单调度                            | O(n) 算法,慢               |
| 2.6.0~2.6.22 | O(1) 调度器                         | O(1) 时间复杂度,基于优先级 |
| 2.6.23~      | **CFS** (Completely Fair Scheduler) | 基于红黑树,完全公平        |
| 6.6+         | **EEVDF**                           | 进一步优化延迟             |

### 3. CFS 详解 (Linux 现代调度器)

**CFS (Completely Fair Scheduler)** = 完全公平调度器

**核心思想**:
- 不维护固定时间片
- 给每个进程一个**虚拟运行时间 (vruntime)**
- 总选 vruntime 最小的进程
- 保证所有进程"公平"获得 CPU

**数据结构:红黑树 (RB-Tree)**

```text
         ┌──────────┐
         │ Task B   │  ← vruntime=10
         │(中间节点)│
         └────┬─────┘
        ┌─────┴─────┐
   ┌────┴────┐  ┌───┴────┐
   │ Task A  │  │ Task C │
   │ vrt=5   │  │ vrt=15 │
   └─────────┘  └─────────┘
   ↑ 最小值,    ↑ 当前调度这个
     选 next
```

**关键概念**:

- **vruntime**:进程实际运行时间 ÷ 权重(优先级高的权重小,vr 增长慢)
- **权重 (weight)**:由 nice 值映射(权重数组 0~139)
- **调度延迟 (sched_latency)**:所有可运行任务都跑一遍的目标时间
- **最小粒度 (sched_min_granularity)**:防止频繁切换
- **nice 值**:`-20` (最高) ~ `19` (最低)
- **实时优先级**:`0` (普通) `1-99` (RT, SCHED_RR / SCHED_FIFO)

**调度决策流程**:

```text
1. 时钟中断 (每 1ms)
2. 更新当前进程的 vruntime
3. 检查是否需要抢占:
   - 当前 vruntime > 下一个最小 vruntime + 阈值?
   - 时间片是否用完?
4. 如果需要,标记 need_resched
5. 调度器选下一个进程(红黑树最左节点)
6. 上下文切换
```

**nice 值与权重**:

| nice | 权重  | 相对 CPU |
|------|-------|----------|
| -20  | 88761 | 10x      |
| -10  | 9548  | 3.2x     |
| 0    | 1024  | 1x       |
| 10   | 110   | 0.3x     |
| 19   | 15    | 0.05x    |

### 4. 调度策略

**Linux 支持的调度策略**:

| 策略                  | 优先级 | 用途                       |
|-----------------------|--------|----------------------------|
| `SCHED_NORMAL` (CFS)  | 0~     | 普通进程                   |
| `SCHED_BATCH`         | 0~     | 批处理                     |
| `SCHED_IDLE`          | 0~     | 极低优先级                 |
| `SCHED_FIFO`          | 1~99   | 实时,先来先服务            |
| `SCHED_RR`            | 1~99   | 实时,时间片轮转            |
| `SCHED_DEADLINE`      | -      | 截止时间调度 (Linux 3.14+) |

**实时调度 (SCHED_FIFO / RR)**:

- 优先级 1-99,数字越大优先级越高
- **SCHED_FIFO**:一直跑直到阻塞/退出/被抢占
- **SCHED_RR**:加时间片
- 抢占 CFS 进程
- **风险**:死循环会卡死系统

**DEADLINE 调度** (Linux 3.14+):

- 参数:`runtime` (单次最大运行时间)、`deadline` (完成期限)、`period` (周期)
- 适合:音视频、工业控制
- 例子:视频播放保证 60 fps

### 5. 调度相关的命令与 API

```bash
# nice / renice
nice -n -10 command    # 启动时设优先级
renice -n 5 -p PID     # 修改已运行进程

# chrt - 设置实时优先级
chrt -f -p 50 1234    # SCHED_FIFO, 优先级 50, PID 1234
chrt -r -p 50 1234    # SCHED_RR

# taskset - CPU 亲和性
taskset -c 0,2 command     # 绑到 CPU 0 和 2
taskset -p 0,1 1234

# 查看进程的调度
chrt -p 1234
cat /proc/1234/sched
```

```c
#include <sched.h>

// 设置调度策略
struct sched_param param = {.sched_priority = 50};
sched_setscheduler(0, SCHED_FIFO, &param);

// 设 CPU 亲和性
cpu_set_t set;
CPU_ZERO(&set);
CPU_SET(0, &set);
sched_setaffinity(0, sizeof(set), &set);
```

### 6. 进程优先级

**Linux 优先级** (2 个范围):

```text
实时优先级 (RT priority):  0-99
普通优先级 (nice):        -20 到 19
```

**内核表示**:

| 概念            | 说明                       |
|-----------------|----------------------------|
| `prio`          | 内核统一优先级 (0-139)     |
| `static_prio`   | 静态优先级 (从 nice 映射)  |
| `normal_prio`   | 普通优先级                 |
| `rt_priority`   | 实时优先级 (0-99)          |

**优先级关系**:

```c
prio = max(RT_PRIO_MAX - 1 - rt_priority, 0) + normal_prio;
```

- 实时进程:0-99(数字小,优先级高)
- 普通进程:100-139(数字大,优先级低)
- 总是优先调度实时进程

### 7. CPU 亲和性 (Affinity)

**作用**:把进程/线程绑到特定 CPU 上跑

**好处**:
- 减少跨 CPU 缓存失效
- 提高缓存命中率
- 适合 CPU 密集型场景

**坏处**:
- 负载不均
- 调度不灵活

**API**:

```c
// 用户态
sched_setaffinity(pid, sizeof(mask), &mask);
sched_getaffinity(pid, sizeof(mask), &mask);

// 进程绑到 CPU 0
cpu_set_t mask;
CPU_ZERO(&mask);
CPU_SET(0, &mask);
sched_setaffinity(0, sizeof(mask), &mask);
```

**工具**:

```bash
taskset -c 0,1,2 command  # 启动时绑
taskset -p 0x03 1234      # 修改已运行
```

### 8. 进程切换 (上下文切换)

**Context Switch**:CPU 从一个进程切换到另一个进程

**步骤**:

```text
1. 触发:时间片/系统调用/中断
2. 保存当前进程上下文:
   - 用户态寄存器(通用寄存器、栈指针)
   - 内核态寄存器
   - 程序计数器(PC)
   - 状态字(PSW)
3. 切换页表(CR3)
4. 切换内核栈
5. 加载新进程上下文
6. 跳转到新进程
```

**开销**:
- 直接开销:约 1-10 微秒
- 间接开销:Cache 失效 (TLB, L1/L2/L3)
- 频繁切换会**严重**影响性能

**监控**:

```bash
# 系统级
vmstat 1
# 看 cs (context switch) 列

# 进程级
cat /proc/1234/status | grep ctxt
# voluntary_ctxt_switches / nonvoluntary_ctxt_switches

# perf
perf stat -e context-switches command
```

**Context Switch 类型**:

- **自愿切换 (Voluntary)**:进程主动让出 CPU(阻塞 I/O、等待锁)
- **非自愿切换 (Involuntary)**:被调度器抢占(时间片到)

## 六、进程关系

### 1. 父子关系

```text
        systemd (PID 1)
         ├─ sshd (PID 100)
         │   └─ bash (PID 1234)
         │       └─ vim (PID 5678)
         ├─ cron (PID 200)
         └─ nginx (PID 300)
             └─ nginx worker (PID 301)
```

- 每个进程都有 1 个**父进程 (PPID)**
- 父进程死了,进程成为**孤儿**,被 init (PID 1) 收养
- 子进程死了,父进程没回收 → **僵尸**

### 2. 进程组 (Process Group)

- 一组相关进程的集合
- 每个进程组有**组 ID (PGID)**
- **会话 (Session)**:一个或多个进程组
- 同一会话共享**控制终端**

**用途**:
- 信号可以发给整个进程组
- 关闭终端时,内核给所有进程组发 SIGHUP

**相关命令**:

```bash
# 看进程组
ps -o pid,pgid,sid,comm

# 杀进程组
kill -- -PGID     # 负号表示 PGID
kill -- -1234     # 杀进程组 1234

# setsid 创建新会话
setsid command
```

### 3. 线程组

- 同一进程的所有线程共享 TGID
- 主线程 (TID = TGID = PID)
- 其他线程有不同的 TID

```bash
# 看进程的线程
ps -L -p 1234
# 或
ls /proc/1234/task/
```

### 4. 命名空间 (Namespace)

**Namespace**:提供**进程隔离**的内核机制,是容器的基础

| 命名空间      | 隔离内容                |
|---------------|-------------------------|
| PID           | 进程 ID                 |
| Mount         | 挂载点                  |
| Network       | 网络                    |
| UTS           | 主机名、域名            |
| IPC           | 进程间通信              |
| User          | 用户和组                |
| Cgroup        | cgroup 根               |
| Time          | 时钟 (Linux 5.6+)       |

**例子**:
- Docker 用 namespaces + cgroups 隔离容器
- `unshare` 命令可以创建新的 namespace

```bash
unshare -p -n -m bash    # 新的 PID + Network + Mount 命名空间
```

## 七、进程相关重要概念

### 1. PID (Process ID)

- 进程唯一标识
- 32 位整数,理论上 0 ~ 4,294,967,294
- 实际受 `/proc/sys/kernel/pid_max` 限制(默认 4194304)
- **0 = 调度进程 (swapper)**,**1 = init (systemd)**
- PID 用完会循环

**PID 复用**:进程退出后,内核可能会把它的 PID 分配给新进程(避免短时间耗尽)

### 2. PPID (Parent PID)

- 父进程 PID
- 进程创建时确定
- 父进程死亡时 PPID 改为 1 (init)

### 3. UID / GID

- **真实 UID (RUID)**:启动进程的用户
- **有效 UID (EUID)**:用于权限检查,通常等于 RUID
- **保存的 UID (SUID)**:用于切换回原 UID
- 特殊:
  - **SUID 位**:文件被设了 SUID 后,执行时 EUID = 文件 owner UID
  - **SGID 位**:类似,作用于组

```bash
# 经典例子:passwd 修改 /etc/shadow
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd
#     ↑
#     SUID 位
```

### 4. PID 命名空间层次

```text
Global PID namespace (主机)
  ├─ Container 1 PID namespace
  │    ├─ PID 1 (container init)
  │    ├─ PID 2
  │    └─ PID 3
  └─ Container 2 PID namespace
       ├─ PID 1 (container init)
       └─ PID 2
```

### 5. Capabilities

**Linux Capabilities**:把 root 权限细粒度拆分

| Capability             | 作用                       |
|------------------------|----------------------------|
| `CAP_SYS_ADMIN`        | 大量管理操作               |
| `CAP_NET_ADMIN`        | 网络管理                   |
| `CAP_SYS_TIME`         | 设置系统时间               |
| `CAP_SYS_PTRACE`       | ptrace 其他进程            |
| `CAP_DAC_OVERRIDE`     | 绕过文件权限               |
| `CAP_NET_BIND_SERVICE` | 绑定 1024 以下端口         |
| `CAP_CHOWN`            | 改变文件属主               |

**使用**:

```bash
# 给可执行文件加能力
setcap cap_net_bind_service=+ep /usr/bin/python3

# 看进程能力
getpcaps PID
cat /proc/PID/status | grep Cap
```

## 八、进程间关系详解

### 1. 父子进程的同步

#### (1) wait / waitpid

```c
#include <sys/wait.h>

pid_t wait(int *status);                  // 等待任一子进程
pid_t waitpid(pid_t pid, int *status, int options);

// options:
//  WNOHANG:不阻塞
//  WUNTRACED:报告已停止子进程
//  WCONTINUED:报告继续运行的子进程

// 用法
pid_t pid = fork();
if (pid == 0) {
    // 子进程
    sleep(2);
    _exit(42);
} else {
    int status;
    pid_t w = waitpid(pid, &status, 0);
    if (WIFEXITED(status)) {
        printf("child exited with code %d\n", WEXITSTATUS(status));
    }
}
```

#### (2) SIGCHLD

- 子进程退出时,内核给父进程发 SIGCHLD
- 默认动作:忽略
- 建议:父进程注册 SIGCHLD handler,在 handler 中 `wait()`

```c
void sigchld_handler(int sig) {
    int saved_errno = errno;
    while (waitpid(-1, NULL, WNOHANG) > 0)
        ;
    errno = saved_errno;
}

signal(SIGCHLD, sigchld_handler);
```

### 2. 孤儿进程

**定义**:父进程先于子进程退出,子进程由 init (PID 1) 接管。

**特点**:
- PPID 改为 1
- init 进程会 wait() 回收它们
- 不会变僵尸

### 3. 僵尸进程

**定义**:子进程已退出,但父进程没有 `wait()`,内核保留 PCB。

**产生条件**:
- 子进程退出
- 父进程没调用 wait
- 父进程仍在运行

**危害**:
- 占 PID
- 占用 PCB 资源

**清理**:
- 父进程 wait
- 杀掉父进程(让 init 接管)
- 双 fork 模式:孙进程被 init 接管

**双 fork 模式 (避免僵尸)**:

```c
pid_t pid = fork();
if (pid == 0) {
    // 子进程
    pid = fork();
    if (pid == 0) {
        // 孙进程:实际干活
        // 退出后被 init 接管
        exec(...);
    }
    // 子进程立刻退出
    _exit(0);
}
// 父进程 wait 子进程
wait(NULL);
```

## 十、O(1) 调度器 (历史)

**O(1) Scheduler**:Linux 2.6.0~2.6.22 使用的调度器

**特点**:
- 调度决策 O(1) 时间复杂度(与进程数无关)
- 140 个优先级队列 (0-99 RT, 100-139 普通)
- 每次调度选最高优先级队列的队首
- 交互式进程奖励 (bonus)
- **问题**:对交互/批处理判断不准确,导致桌面性能差
- **被 CFS 取代** (2.6.23)

## 十一、其他经典调度算法

### 1. 批处理系统

| 算法                    | 思路                            | 优缺点                    |
|-------------------------|---------------------------------|---------------------------|
| **FCFS** (先来先服务)   | 按到达顺序                      | 简单,平均等待时间长       |
| **SJF** (短作业优先)    | 选运行时间最短的                | 最优平均等待,但长任务饥饿 |
| **HRRN** (高响应比优先) | 综合等待时间和服务时间          | 折中,需预知服务时间       |

### 2. 交互式系统

| 算法                          | 思路                                  | 优缺点                  |
|-------------------------------|---------------------------------------|-------------------------|
| **RR** (时间片轮转)           | 每个进程固定时间片                    | 公平,响应快,但开销大    |
| **优先级调度**                | 优先级高的先跑                        | 灵活,但低优先级饥饿     |
| **多级反馈队列 (MLFQ)**       | 多级队列,优先级可调                   | 兼顾响应和吞吐,但参数多 |

### 3. 实时系统

| 算法                              | 思路                              |
|-----------------------------------|-----------------------------------|
| **Rate Monotonic**                | 周期越短优先级越高                |
| **Earliest Deadline First (EDF)** | 截止时间最早的先跑                |
| **LLF** (Least Laxity First)      | 松弛度最小优先                    |

### 4. 调度算法对比

| 算法   | 吞吐量 | 响应时间 | 周转时间 | 公平性 | 复杂度 |
|--------|--------|----------|----------|--------|--------|
| FCFS   | 低     | 不定     | 高       | 中     | 低     |
| SJF    | 高     | -        | 低       | 低     | 中     |
| RR     | 中     | 好       | 中       | 高     | 低     |
| 优先级 | 中     | 好       | 不定     | 低     | 中     |
| MLFQ   | 高     | 好       | 中       | 中     | 高     |
| CFS    | 高     | 好       | 中       | 高     | 中     |
| EDF    | 高     | 好       | 低       | 高     | 中     |

## 十二、Linux 进程管理关键点

### 1. 进程的生命周期

```text
创建 (fork) → 就绪 (Ready) → 运行 (Running) →
  ↓ 等待 I/O
阻塞 (Blocked/Sleeping) → 唤醒 (回到就绪) →
  ↓ exit()
僵尸 (Zombie) → 父进程 wait() → 销毁
```

### 2. 进程是资源分配的单位

- 独立地址空间
- 独立的文件描述符表
- 独立的信号处理
- 共享:父子可共享文件锁

### 3. 进程是调度单位

- Linux 中,**线程**才是真正的调度单位
- 进程是**资源容器**,线程是**调度实体**
- 详见线程笔记 (本系列)

### 4. 进程的"重量级"

- 进程切换开销大(页表、内核栈、文件表)
- 线程更轻量(共享地址空间)
- 协程更轻量(用户态调度)
