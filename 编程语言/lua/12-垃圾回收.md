# 12 - 垃圾回收(GC)

Lua 使用**增量标记-清除**(incremental mark-and-sweep)垃圾回收器,自动管理内存。

## 一、GC 基本概念

### 1. 自动内存管理

```lua
-- Lua 自动管理:无需 malloc / free
local t = {1, 2, 3}    -- 创建
t = nil                 -- 解除引用
-- GC 在合适的时候释放 t 占用的内存
```

### 2. 两个核心数字

```lua
-- 间歇率(pause):GC 启动新循环前等待多久
-- 步进倍率(step multiplier):GC 速度相对于内存分配速度

print(collectgarbage("setpause", 200))    -- 设 200,堆翻倍才启动
print(collectgarbage("setstepmul", 200))   -- 设 200,GC 以 2x 速度运行

-- 默认值
-- pause = 200(达到 2 倍内存时启动)
-- stepmul = 200(GC 速度 = 2x 分配速度)
```

## 二、`collectgarbage` 函数

### 1. 主要操作

```lua
-- 完整 GC 循环
collectgarbage("collect")    -- 等价 collectgarbage()

-- 返回当前使用的内存(KB,有小数)
local kb = collectgarbage("count")
print(kb)    -- 比如 25.32(单位 KB)

-- 启动 / 停止 / 重启自动 GC
collectgarbage("stop")       -- 停止(只能手动触发)
collectgarbage("restart")    -- 重新启动
collectgarbage("step")       -- 单步
```

### 2. 完整 API

| 参数 | 作用 |
| --- | --- |
| `"collect"` | 完整 GC |
| `"count"` | 内存(KB) |
| `"stop"` | 停止自动 GC |
| `"restart"` | 启动 |
| `"pause"` | 设间歇率,返回旧值 |
| `"stepmul"` | 设步进倍率,返回旧值 |
| `"step"` | 单步(参数:KB 工作量,0 = 不可分割一步) |
| `"setpause"` | 同 `"pause"` |
| `"setstepmul"` | 同 `"stepmul"` |
| `"generational"` | 分代 GC(Lua 5.4+,实验) |
| `"incremental"` | 增量模式 |

## 三、调优场景

### 1. 大量对象,低实时性

```lua
-- 后台批处理,不在乎暂停时间
collectgarbage("setpause", 100)   -- 积极回收
collectgarbage("setstepmul", 400)  -- 快速 GC
```

### 2. 实时游戏 / 关键路径

```lua
-- 关键操作前停止 GC,操作后恢复
collectgarbage("stop")
do_critical_work()
collectgarbage("restart")
```

### 3. 内存受限

```lua
-- 频繁 GC,内存占用更低
collectgarbage("setpause", 110)
collectgarbage("setstepmul", 500)
```

## 四、weak table 弱引用

普通引用会阻止 GC,weak table 中的引用不会。

```lua
local t = {}

-- 弱 key 表
setmetatable(t, {__mode = "k"})

local key = {}
t[key] = "value"
print(t[key])  -- "value"

key = nil
collectgarbage("collect")

print(t[key])  -- nil(key 被回收)
```

### 模式

```lua
-- __mode = "k":弱 key
-- __mode = "v":弱 value
-- __mode = "kv":都弱

-- 应用:对象池、缓存、内存表
local cache = setmetatable({}, {__mode = "v"})

local function get_cached(key)
    if cache[key] then return cache[key] end
    local v = expensive_compute(key)
    cache[key] = v
    return v
end
```

## 五、finalizer `__gc`

```lua
-- 元方法 __gc 在对象被 GC 时触发

local Counter = {n = 0}
Counter.__index = Counter

setmetatable(Counter, {__gc = function(self)
    print("GC 销毁:", self.name)
    Counter.n = Counter.n - 1
end})

local function new(name)
    local self = setmetatable({name = name}, Counter)
    Counter.n = Counter.n + 1
    return self
end

local a = new("a")
local b = new("b")
print(Counter.n)    -- 2

a = nil
b = nil
collectgarbage("collect")
collectgarbage("collect")    -- 可能要两次
print(Counter.n)    -- 0
```

### 应用:文件 / 资源自动关闭

```lua
local FileHandle = {}
FileHandle.__index = FileHandle

setmetatable(FileHandle, {__gc = function(self)
    if self.f and not self.f:closed() then
        self.f:close()
        print("自动关闭:", self.path)
    end
end})

function FileHandle.new(path)
    local f = io.open(path, "r")
    local self = setmetatable({f = f, path = path}, FileHandle)
    return self
end

local h = FileHandle.new("data.txt")
h = nil
collectgarbage("collect")
```

## 六、调试 GC 问题

### 1. 内存泄漏检测

```lua
-- 观察内存增长
local before = collectgarbage("count")
do_work()
collectgarbage("collect")
local after = collectgarbage("count")

print(string.format("delta: %.2f KB", after - before))
```

### 2. 强制 GC

```lua
-- 测试代码中,周期性强制 GC
for i = 1, 10000 do
    process(i)
    if i % 1000 == 0 then
        collectgarbage("collect")
    end
end
```

### 3. 泄漏排查

```lua
-- weak table 检测泄漏
-- 把疑似泄漏的对象放进 weak table
-- 强制 GC 后,weak table 中留下的就是泄漏

local tracked = setmetatable({}, {__mode = "v"})

local function leak_check(obj)
    tracked[#tracked + 1] = obj
end

-- 在可疑代码处
leak_check(my_obj)
collectgarbage("collect")
-- 如果 #tracked 不变,说明 obj 被引用
```

## 七、综合实战:内存监控器

```lua
-- memory_monitor.lua
local M = {}

local stats = {
    initial = 0,
    current = 0,
    peak = 0,
}

function M.start()
    collectgarbage("collect")
    stats.initial = collectgarbage("count")
    stats.current = stats.initial
    stats.peak = stats.initial
end

function M.snapshot(label)
    collectgarbage("collect")
    local now = collectgarbage("count")
    stats.current = now
    if now > stats.peak then stats.peak = now end

    print(string.format(
        "[%s] mem=%.2f KB delta=%.2f KB peak=%.2f KB",
        label or "", now, now - stats.initial, stats.peak
    ))
end

function M.gc()
    collectgarbage("collect")
    print("after gc:", collectgarbage("count"), "KB")
end

return M
```

```lua
-- main.lua
package.path = "./?.lua;" .. package.path

local mem = require("memory_monitor")
mem.start()

local data = {}
for i = 1, 100000 do
    data[i] = {x = i, y = i * 2, name = "item" .. i}
end
mem.snapshot("after build")

data = nil
mem.gc()
mem.snapshot("after cleanup")
```

## 八、要点速记

- **GC 算法:增量标记-清除**
- **两个参数:`pause`(间歇率) + `stepmul`(步进倍率)**
- **`collectgarbage("collect")` 强制完整 GC**
- **`collectgarbage("count")` 返回 KB 数**
- **弱引用:`__mode = "k" / "v" / "kv"`**
- **`__gc` 元方法:对象被 GC 时触发,适合资源清理**
- **关键路径前 `stop`,完成后 `restart`**
- **Lua 5.4+ 实验性:分代 GC**
- **Lua 没有引用计数,纯追踪式 GC**
- **不存在内存泄漏(理论上),但可存在"逻辑泄漏"**
