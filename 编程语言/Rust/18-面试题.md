## 一、所有权与借用

### 1. Rust 的所有权三原则?

```rust
// 1. 每个值有唯一所有者
// 2. 同时只能有一个所有者(move)
// 3. 所有者离开作用域,值 drop

let s1 = String::from("hello");
let s2 = s1;            // s1 被 move,失效
// println!("{}", s1);   // ❌ 编译错误

// println!("{}", s2);   // ✅
// s2 离开作用域时 drop,内存释放
```

### 2. Copy 与 Move 的区别?

```rust
// Copy:标量/小类型,赋值时复制
let x = 5;
let y = x;             // 复制
println!("{} {}", x, y); // ✅ 都可用

// Move:堆分配类型,赋值时转移所有权
let s = String::from("hi");
let s2 = s;            // move
// println!("{}", s);   // ❌ s 失效

// 需要副本显式 clone
let s3 = s2.clone();   // 深拷贝
```

**自动实现 Copy 的类型**:`i32`/`u8`/`f64`/`bool`/`char`/`(T, U)`(元素全 Copy)/`[T; N]`(元素全 Copy)。

### 3. 借用规则?

```rust
let mut s = String::from("hi");

// 同一时刻:要么 1 个 &mut,要么多个 &,不能混合
let r1 = &s;
let r2 = &s;
let r3 = &mut s;        // ❌ 编译错误

// NLL 后可
println!("{} {}", r1, r2);
let r4 = &mut s;        // ✅ r1, r2 已不再使用
```

### 4. 悬垂引用?

```rust
// ❌ 编译错误
// fn dangle() -> &String {
//     let s = String::from("hi");
//     &s                  // s 离开作用域,引用悬垂
// }

// ✅ 返回所有权
fn no_dangle() -> String {
    String::from("hi")
}
```

### 5. `&str` 与 `String` 的区别?

```rust
// String:堆分配,可变长,拥有所有权
let s: String = String::from("hi");

// &str:不可变切片,通常指向 String 或字面量
let slice: &str = "hi";         // 字面量是 &'static str
let slice2: &str = &s[..];     // 借用 String

// 函数参数优先 &str(接受范围更广)
fn print(s: &str) { println!("{}", s); }
print("hello");                 // &str
print(&String::from("hi"));     // &String -> &str(Deref)
```

### 6. 切片是什么?

```rust
// 切片是对连续序列的视图,不拥有数据
let s = String::from("hello world");
let part: &str = &s[0..5];      // "hello"

// 数组切片
let arr = [1, 2, 3, 4, 5];
let slice: &[i32] = &arr[1..4]; // [2, 3, 4]

// 切片 = (指针 + 长度)
// 切片不能越过所有权边界(编译期)
```

## 二、生命周期

### 1. 生命周期标注的目的?

```rust
// 显式标注,告诉编译器多个引用的关系
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

// 省略规则让多数情况无需标注
fn first_word(s: &str) -> &str { ... }  // 自动推断
```

### 2. 三个省略规则?

```rust
// 1. 每个引用参数有独立生命周期
// 2. 单个输入生命周期 → 输出生命周期相同
// 3. &self / &mut self → 输出生命周期与 self 相同

// 这三个规则覆盖 90% 场景,无需手动标注
```

### 3. 结构体存引用的要求?

```rust
// 必须标注生命周期
struct ImportantExcerpt<'a> {
    part: &'a str,
}

// 实现方法
impl<'a> ImportantExcerpt<'a> {
    fn announce_and_return(&self, ann: &str) -> &str {
        self.part
    }
}
```

### 4. `'static` 生命周期?

```rust
// 'static:整个程序运行期间
let s: &'static str = "我是字面量";

// 字符串字面量都是 'static
// Box::leak 也可得到 'static(慎用)
```

### 5. 生命周期边界 `'a: 'b`?

```rust
// 'a: 'b 表示 'a 至少和 'b 一样久
fn choose<'a, 'b: 'a>(first: &'a str, _second: &'b str) -> &'a str {
    first
}
```

## 三、错误处理

### 1. panic! vs Result?

```rust
// panic!:不可恢复错误,程序终止
panic!("crash");              // 主动
let v = vec![1, 2];
v[99];                        // 越界,debug 模式 panic

// Result<T, E>:可恢复错误,显式处理
fn read() -> Result<String, io::Error> {
    std::fs::read_to_string("a.txt")
}
```

### 2. `?` 操作符?

```rust
// 自动传播错误:Err -> 立即返回
fn read() -> Result<String, io::Error> {
    let mut f = File::open("a.txt")?;   // 失败直接返回
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
```

### 3. 自定义错误类型?

```rust
use thiserror::Error;

#[derive(Error, Debug)]
pub enum AppError {
    #[error("io: {0}")]
    Io(#[from] io::Error),

    #[error("parse: {0}")]
    Parse(#[from] serde_json::Error),

    #[error("not found")]
    NotFound,
}

// 库用 thiserror(具体类型)
// 应用用 anyhow(任意类型)
```

### 4. panic 安全?

```rust
let m = Arc::new(Mutex::new(0));
let m2 = m.clone();

let _ = thread::spawn(move || {
    let mut g = m2.lock().unwrap();
    *g += 1;
    panic!("crash");       // 锁中毒
}).join();

// 可获取仍可获取(可能 PoisonError)
let r = m.lock().unwrap_or_else(|p| p.into_inner());
```

## 四、Trait 与泛型

### 1. trait 是什么?

```rust
// 一组方法签名的集合,定义共享行为
pub trait Summary {
    fn summarize(&self) -> String;
}

struct NewsArticle { pub title: String }
impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        self.title.clone()
    }
}
```

### 2. 孤儿规则?

```rust
// 不能为外部类型实现外部 trait
// ❌
impl Display for Vec<MyType> { ... }  // Display 是外部,Vec 是外部

// ✅ 用 newtype
struct MyVec(Vec<MyType>);
impl Display for MyVec { ... }
```

### 3. 静态分发 vs 动态分发?

```rust
// 静态分发(impl Trait):编译期单态化,零开销
fn process<T: Summary>(x: T) { ... }

// 动态分发(dyn Trait):运行时通过 vtable 查找
fn process(x: &dyn Summary) { ... }

// impl Trait 性能更好但代码膨胀
// dyn Trait 用于异构集合
```

### 4. 关联类型 vs 泛型?

```rust
// 关联类型:一个 impl 只能有一个具体类型
trait Iterator {
    type Item;
    fn next(&mut self) -> Option<Self::Item>;
}

// 泛型:每个 impl 可以有不同具体类型
trait From<T> {
    fn from(value: T) -> Self;
}
```

### 5. 对象安全?

```rust
// dyn Trait 要求 trait 是对象安全的
// ❌ 不安全(Self 返回值)
trait Cloneable {
    fn clone(&self) -> Self;     // 返回 Self
}

// ✅ 安全
trait Draw {
    fn draw(&self);
}
```

## 五、智能指针

### 1. `Box<T>` 用途?

```rust
// 1. 堆分配
let b = Box::new(5);

// 2. 递归类型(编译期大小未知)
enum List {
    Cons(i32, Box<List>),
    Nil,
}

// 3. Trait Object
let drawable: Box<dyn Draw> = Box::new(Circle { r: 1.0 });
```

### 2. `Rc<T>` vs `Arc<T>`?

```rust
// Rc:单线程引用计数共享所有权
use std::rc::Rc;
let a = Rc::new(5);
let b = Rc::clone(&a);

// Arc:多线程版本(原子)
use std::sync::Arc;
let a = Arc::new(5);
let b = Arc::clone(&a);    // 跨线程传递
```

### 3. `RefCell<T>` 内部可变性?

```rust
use std::cell::RefCell;

// 编译期保证不变,运行时检查
let cell = RefCell::new(5);
{
    let mut r = cell.borrow_mut();
    *r += 1;
}
// 借用在运行时检查,违反规则 panic
```

### 4. 循环引用?

```rust
use std::rc::{Rc, Weak};

// Weak 不增加引用计数,打破循环
struct Node {
    value: i32,
    parent: RefCell<Weak<Node>>,      // 父:弱引用
    children: RefCell<Vec<Rc<Node>>>, // 子:强引用
}
```

### 5. Drop 顺序?

```rust
// 变量 drop 顺序:声明的反序(后声明先 drop)
// 结构体字段:按声明顺序 drop
// Box<T>:drop 时先 drop T 再释放堆

let s1 = String::from("a");
let s2 = String::from("b");
// 离开作用域时:先 drop s2,再 drop s1
```

### 6. Deref coercion 规则?

```rust
// &T -> &U 当 T: Deref<Target=U>
// &mut T -> &mut U 当 T: DerefMut<Target=U>
// &mut T -> &U 当 T: Deref<Target=U>(可变转不可变)
```

## 六、闭包与迭代器

### 1. 闭包的三种 trait?

```rust
// Fn:不可变借用捕获,可重复调用
let c = || println!("hi");
c(); c();                       // ✅

// FnMut:可变借用捕获
let mut n = 0;
let mut inc = || { n += 1; };
inc(); inc();                   // ✅

// FnOnce:获取所有权,只能调用一次
let s = String::from("hi");
let consume = move || drop(s);   // s 被消耗
consume();
// consume();                   // ❌
```

### 2. 迭代器三件套?

```rust
let v = vec![1, 2, 3];

// iter():&T(借用)
for x in v.iter() { }           // v 仍可用

// iter_mut():&mut T
for x in v.iter_mut() { *x *= 2; }

// into_iter():T(消耗)
for x in v.into_iter() { }      // v 已消耗
```

### 3. 适配器是惰性的?

```rust
let v = vec![1, 2, 3, 4, 5];

// map/filter 是惰性的,只描述,未执行
let pipeline = v.iter()
    .map(|x| {
        println!("map: {}", x);  // 不会打印
        x * 2
    })
    .filter(|x| *x > 4);

// 只有 collect 才触发执行
let result: Vec<_> = pipeline.collect();
```

### 4. 迭代器性能?

迭代器是**零成本抽象**,与手写循环编译后性能相当。

## 七、并发

### 1. Send 与 Sync?

```rust
// Send:所有权可在线程间转移
// Sync:&T 可被多线程同时持有

// 大多数类型 Send + Sync
// Rc<T>:不 Send(非线程安全)
// Arc<T>:Send + Sync
// Mutex<T>:Sync(Mutex 内部保证)
```

### 2. 线程创建?

```rust
use std::thread;

let handle = thread::spawn(move || {
    println!("hello from thread");
});

// join 等待完成
handle.join().unwrap();

// 跨线程传递数据:move 闭包强制转移所有权
let data = vec![1, 2, 3];
thread::spawn(move || {
    println!("{:?}", data);   // data 已被 move
});
```

### 3. channel 类型?

```rust
// mpsc:多生产者单消费者
let (tx, rx) = std::sync::mpsc::channel();

// sync_channel(n):有缓冲
let (tx, rx) = std::sync::mpsc::sync_channel(10);

// tokio::sync::mpsc:异步版本
// crossbeam-channel:更高性能

// 关闭原则:发送方关闭,接收方不能关闭
```

### 4. Mutex vs RwLock?

```rust
// Mutex:排他锁
// RwLock:读写锁(读并发,写排他)

let lock = std::sync::RwLock::new(5);
{
    let r = lock.read().unwrap();     // 可并发读
    let w = lock.write().unwrap();    // 排他
}
```

### 5. async/await 关键?

```rust
// async 函数返回 impl Future<Output = T>
// .await 等待 future 完成
// 需运行时(tokio / async-std)

#[tokio::main]
async fn main() {
    let result = fetch().await;
}

// 关键约束:.await 时持有的锁不能跨 await
// 用 tokio::sync::Mutex 替代 std::sync::Mutex
```

## 八、宏

### 1. macro_rules! vs 过程宏?

```rust
// macro_rules!:声明宏,模式匹配
macro_rules! vec_new {
    () => { Vec::new() };
    ($($x:expr),*) => {{
        let mut v = Vec::new();
        $(v.push($x);)*
        v
    }};
}

// 过程宏:更强大,需独立 proc-macro crate
// 3 种:
//   #[proc_macro_derive(Name)]   派生宏
//   #[proc_macro_attribute]      属性宏
//   #[proc_macro]                 函数式宏
```

## 九、Unsafe

### 1. 五种 unsafe 行为?

```rust
unsafe {
    // 1. 解引用裸指针
    let p: *const i32 = &5;
    println!("{}", *p);

    // 2. 调用 unsafe 函数
    unsafe_fn();

    // 3. 访问/修改可变静态变量
    static mut COUNTER: u32 = 0;
    COUNTER += 1;

    // 4. 实现 unsafe trait
    // impl Send for MyType {}

    // 5. 访问 union 字段
}
```

### 2. unsafe 不做什么?

- 不关闭借用检查
- 不关闭并发检查
- 不关闭类型检查

unsafe 只关闭编译器**无法证明**的安全检查,程序员保证不变式。

## 十一、性能与优化

### 1. 零成本抽象?

Rust 的抽象(泛型、trait、迭代器、闭包)在编译期单态化或内联,运行时无额外开销。

### 2. 优化方向?

```rust
// 1. 避免堆分配:用栈值或 &'static

// 6. #[inline] 标注小函数
// 7. #[inline(always)] / #[cold] 标注路径

```

### 3. cargo bench + criterion?


## 十二、典型场景题

### 1. 实现 LRU cache?

```rust
use std::collections::HashMap;
use std::cell::RefCell;

struct LRUCache<K, V> {
    map: RefCell<HashMap<K, Rc<RefCell<Node<K, V>>>>>,
    head: Rc<RefCell<Node<K, V>>>,
    cap: usize,
}

struct Node<K, V> {
    key: K,
    val: V,
    prev: Option<Rc<RefCell<Node<K, V>>>>,
    next: Option<Rc<RefCell<Node<K, V>>>>,
}

// 实现思路:HashMap + 双向链表
// get:命中则移到头部,返回 value
// put:已存在更新;否则插入头部;超容淘汰尾部
```

### 2. 实现线程安全的计数器?

```rust
use std::sync::atomic::{AtomicU64, Ordering};

struct Counter(AtomicU64);

impl Counter {
    fn inc(&self) -> u64 {
        self.0.fetch_add(1, Ordering::SeqCst)
    }

    fn get(&self) -> u64 {
        self.0.load(Ordering::SeqCst)
    }
}

// 多线程下无需锁,性能好
```

### 3. 实现简单的 pub-sub?

```rust
use std::sync::mpsc;

// 简单实现
struct Broker {
    subs: Vec<mpsc::Sender<String>>,
}

impl Broker {
    fn subscribe(&mut self) -> mpsc::Receiver<String> {
        let (tx, rx) = mpsc::channel();
        self.subs.push(tx);
        rx
    }

    fn publish(&self, msg: String) {
        for sub in &self.subs {
            let _ = sub.send(msg.clone());
        }
    }
}

// 实际用 tokio::sync::broadcast(异步多播)
```

## 十四、要点速记

- **所有权 3 原则:唯一所有者、move、自动 drop**

- **trait 隐式实现,接受接口返回具体类型**
- **`impl Trait` 静态分发零开销,`dyn Trait` 动态分发可异构**
- **`Box` 堆分配,`Rc` 单线程共享,`Arc` 多线程共享**
- **`RefCell` 运行时借用检查,内部可变性**
- **`Send` = 跨线程所有权转移,`Sync` = 多线程引用**
- **`channel` 发送方关闭,关闭后不能再发**
- **`std::sync::Mutex` 不能跨 `.await`**
- **`#[derive(...)]` 自动实现常见 trait**
- **`unsafe` 不关闭借用检查,只关闭编译期无法证明的安全检查**
- **零成本抽象 = 编译期单态化 + 内联**
