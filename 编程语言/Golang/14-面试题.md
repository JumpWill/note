# 14 - Go 面试题

按主题分类,每题含代码示例与答案要点。

## 一、基础

### 1. Go 与其他语言的主要区别?

- 静态类型 + 编译型 + GC
- 内置并发(goroutine + channel)
- 无类,使用结构体 + 方法
- 无继承,使用嵌入(组合)
- 接口隐式实现(鸭子类型)
- defer / panic / recover 异常处理
- 工具链齐全(go test / go vet / gofmt)

### 2. Go 的数据类型有哪些?

**基本类型**:`bool` / `string` / 整数(`int8/16/32/64`、`uint8/16/32/64`、`byte`、`rune`) / 浮点(`float32/64`)

**复合类型**:数组、切片、map、结构体、指针、函数、接口、channel

### 3. `make` 与 `new` 的区别?

```go
// new(T):分配零值内存,返回 *T
p := new(int)       // *int,值为 0

// make(T, ...):仅用于 slice/map/channel,初始化,返回 T
s := make([]int, 0, 10)
m := make(map[string]int)
ch := make(chan int, 5)

// 区别:
// - new 用于任意类型,返回指针
// - make 仅用于 slice/map/channel,返回类型本身
```

### 4. 字符串不可变吗?

```go
s := "hello"
// s[0] = 'H'    // � 编译错误,字符串不可变

// 需转 []byte 修改,会产生新内存
b := []byte(s)
b[0] = 'H'
s = string(b)        // "Hello"

// Go 1.20+ 用 unsafe.String 零拷贝
```

### 5. byte 与 rune 的区别?

```go
// byte = uint8,处理 ASCII(单字节字符)
// rune = int32,处理 Unicode(可多字节)

s := "你好 Go"
fmt.Println(len(s))                  // 7(字节数)
fmt.Println(utf8.RuneCountInString(s)) // 5(字符数)

for i, r := range s {
    fmt.Printf("%d: %c ", i, r)       // 按 rune 遍历
}
```

## 二、Slice

### 1. 数组与切片的区别?

```go
// 数组:固定长度,值类型(赋值拷贝)
a := [3]int{1, 2, 3}
b := a                  // 完整拷贝
b[0] = 99
fmt.Println(a[0])       // 1(原数组不变)

// 切片:动态长度,引用类型(共享底层数组)
s1 := []int{1, 2, 3}
s2 := s1
s2[0] = 99
fmt.Println(s1[0])       // 99(共享底层)
```

### 2. 切片的底层结构?

```go
// 切片由 3 部分组成
type SliceHeader struct {
    Data uintptr  // 指向底层数组
    Len  int      // 长度
    Cap  int      // 容量
}
```

### 3. `append` 的扩容策略?

```go
s := []int{1, 2, 3}
s = append(s, 4)
// 如果 cap 够,直接追加
// 如果 cap 不够:
//   - 容量 < 1024:翻倍
//   - 容量 >= 1024:增加 25%

// 建议:已知大小时预分配
s := make([]int, 0, 1000)  // 避免多次扩容
```

### 4. 切片共享底层数组的坑?

```go
arr := [5]int{1, 2, 3, 4, 5}
s1 := arr[0:3]              // [1, 2, 3]
s2 := arr[2:5]              // [3, 4, 5]
s1[2] = 99                  // 改 s1[2] = 99
fmt.Println(s2[0])          // 99(共享底层数组!)
```

### 5. `append` 后切片指向新数组的判断?

```go
s1 := []int{1, 2, 3}
s2 := s1[:2]
// 容量够:共享;不够:分配新数组
s2 = append(s2, 4)
fmt.Println(s1[2])  // 可能是 4(共享),也可能是 3(新数组)

// 解决方案:不确定时用 copy
s3 := make([]int, len(s1))
copy(s3, s1)
```

## 三、Map

### 1. map 是线程安全的吗?

```go
// ❌ 不是,多 goroutine 并发读写会 panic
var m = make(map[string]int)
go func() { m["a"] = 1 }()
go func() { _ = m["a"] }()

// ✅ 方案 1:sync.Mutex / RWMutex
var mu sync.RWMutex
mu.Lock(); m["a"] = 1; mu.Unlock()

// ✅ 方案 2:sync.Map(读多写少)
var sm sync.Map
sm.Store("a", 1)
v, _ := sm.Load("a")
```

### 2. map 的键有什么限制?

键必须**可比较**(`==` 可用):

```go
// ✅ 可:bool / 数字 / string / 指针 / 数组(元素可比较)
// ❌ 不可:slice / map / 函数
```

### 3. map 遍历顺序是确定的吗?

```go
// 不是,Go 故意随机化遍历顺序,防止依赖
m := map[string]int{"a": 1, "b": 2}
for k, v := range m {
    fmt.Println(k, v)   // 顺序每次可能不同
}

// 需要稳定顺序:取出 key 排序
keys := make([]string, 0, len(m))
for k := range m {
    keys = append(keys, k)
}
sort.Strings(keys)
for _, k := range keys {
    fmt.Println(k, m[k])
}
```

### 4. 如何删除 map 中的元素?

```go
m := map[string]int{"a": 1}
delete(m, "a")                // 单个删除

// Go 1.21+:清空 map
clear(m)

// 删除不存在的键不报错
delete(m, "nonexistent")      // 安全
```

## 四、函数与闭包

### 1. defer 的执行顺序?

```go
// LIFO:后进先出
func main() {
    defer fmt.Println(1)
    defer fmt.Println(2)
    defer fmt.Println(3)
}
// 输出:3 2 1
```

### 2. defer 闭包参数问题?

```go
// 闭包捕获变量,推迟到执行时求值
for i := 0; i < 3; i++ {
    defer func() {
        fmt.Println(i)
    }()
}
// 输出:3 3 3

// 立即求值:作为参数传入
for i := 0; i < 3; i++ {
    defer func(n int) {
        fmt.Println(n)
    }(i)
}
// 输出:2 1 0
```

### 3. Go 闭包循环变量(Go 1.22 前)?

```go
// Go 1.22 前:所有闭包共享同一 i
for i := 0; i < 3; i++ {
    go func() {
        fmt.Println(i)
    }()
}
// 修复:循环内重新赋值
for i := 0; i < 3; i++ {
    i := i
    go func() { fmt.Println(i) }()
}

// Go 1.22+:循环变量每轮独立,无需修复
```

### 4. 函数返回局部变量的指针可以吗?

```go
// 可以!Go 编译器通过逃逸分析处理
func newCounter() *int {
    n := 0
    return &n    // n 逃逸到堆,函数返回后仍可访问
}
```

### 5. Go 有默认参数吗?

没有,常用变通方式:


## 五、错误处理

### 1. Go 的错误处理惯用法?

```go
// 显式返回 + 检查
if err := doSomething(); err != nil {
    return fmt.Errorf("do failed: %w", err)
}

// 错误包装保留链
errors.Is(err, ErrNotFound)        // 比较
errors.As(err, &ve)                 // 类型
```

### 2. `panic` 与 `recover`?

```go
func main() {
    defer func() {
        if r := recover(); r != nil {
            fmt.Println("recovered:", r)
        }
    }()
    panic("oops")    // 终止当前 goroutine
}

// recover 仅在 defer 中有效
// panic 适用于不可恢复错误,非正常流控制
```

### 3. 错误与异常的区别?

- **错误**(error):可预期的、正常的错误流,显式处理
- **异常**(panic):不可恢复的程序错误,如数组越界

库函数返回 error 而非 panic,让调用方决定。

## 六、并发

### 1. goroutine 与线程的区别?

| | goroutine | OS 线程 |
| --- | --- | --- |
| 调度 | Go runtime(GMP) | OS 内核 |
| 栈大小 | 初始 2KB,可增长 | 固定 MB 级 |
| 切换成本 | 纳秒 | 微秒 |
| 创建成本 | 极低 | 较高 |
| 数量 | 数十万 | 数千 |

### 2. GMP 调度模型?

```text
        G (Goroutine)         用户级协程
        M (Machine)           OS 线程
        P (Processor)         逻辑处理器,持本地队列

        P0            P1            P2
       ↙  ↘         ↙  ↘         ↙  ↘
      M0  G队列      M1  G队列      M2  G队列

策略:
- work stealing:空闲 P 偷其他 P 的 G
- hand off:    M 阻塞时 G 移交其他 M
- preemptive:  Go 1.14+ 支持抢占
```

### 3. channel 关闭原则?

- **发送方关闭**(非接收方)
- 关闭后**不能再发送**,否则 panic
- 接收剩余元素返回 ok=false
- 多个发送方时,用 `sync.Once` 保证只关一次

```go
ch := make(chan int, 5)
go func() {
    defer close(ch)
    for i := 0; i < 5; i++ {
        ch <- i
    }
}()

for v := range ch {
    fmt.Println(v)
}
```

### 4. select 有什么用?

```go
select {
case v := <-ch1:
    fmt.Println("ch1:", v)
case v := <-ch2:
    fmt.Println("ch2:", v)
case ch3 <- 42:
    fmt.Println("sent")
case <-time.After(time.Second):
    fmt.Println("timeout")
default:
    fmt.Println("no channel ready")
}

// 多 channel 等待 + 超时 + 非阻塞
```

### 5. sync.Mutex 与 sync.RWMutex?

```go
// Mutex:写锁,排他
// RWMutex:读写锁
//   - 读:可并发(RLock)
//   - 写:排他(Write + 释放所有读)
//
// 读多写少用 RWMutex,写多读少用 Mutex
```

### 6. 原子操作与锁的选择?

```go
// 原子:简单类型(int/uint/pointer)、无复合操作、要求极致性能
var counter int64
atomic.AddInt64(&counter, 1)

// 锁:复杂操作、需要临界区、读多写少
var mu sync.Mutex
mu.Lock()
m["key"] = value
mu.Unlock()
```

### 7. goroutine 泄漏如何排查?

```go
// 1. 用 pprof:
import _ "net/http/pprof"
// go func() { http.ListenAndServe(":6060", nil) }()

// 2. goroutine 数监控
// runtime.NumGoroutine()

// 3. 常见泄漏原因:
//   - channel 无发送方接收
//   - time.After 未释放
//   - 死循环无退出条件
//   - 锁未释放
```

### 8. 无缓冲与有缓冲 channel?

```go
// 无缓冲 make(chan T):同步,发送阻塞直到接收
ch := make(chan int)

// 有缓冲 make(chan T, n):异步,缓冲满才阻塞
ch := make(chan int, 10)

// 同步场景用无缓冲(如信号传递)
// 异步队列用有缓冲(削峰)
```

## 七、内存管理

### 1. 逃逸分析是什么?

编译器决定变量分配在栈还是堆:

```go
// 1. 外部引用 → 堆
func escape() *int {
    a := 1
    return &a    // a 逃逸到堆
}

// 2. 栈空间不足 → 堆
func escape2() {
    s := make([]int, 10000)   // 超过栈大小
}

// 3. 动态大小 → 堆
func escape3() {
    n := 10
    s := make([]int, n)        // n 编译期未知
}

// 4. 闭包捕获 → 堆
func escape4() func() {
    a := 1
    return func() int { return a }
}

// 验证:go build -gcflags="-m"
```

### 2. GC 算法?

- **三色标记清除**(Go 1.5+)
- 白色:未访问;灰色:已标记但子未标记;黑色:已标记
- **并发执行**(与用户代码并发)
- **写屏障**:保证不漏标正在被引用的对象

调优:

```bash
GOGC=200      # 堆翻倍时触发,默认 100,数值越大越不频繁
GOGC=off      # 关闭 GC
GODEBUG=gctrace=1    # 打印 GC 信息
```

### 3. 栈内存与堆内存?

- **栈**:函数局部变量,函数返回自动释放,无需 GC
- **堆**:跨函数共享的对象,需 GC 回收

栈分配效率高,无需 GC,优先分配。

### 4. 内存泄漏场景?

```go
// 1. goroutine 阻塞
ch := make(chan int)
go func() {
    val := <-ch    // 永远阻塞,goroutine 泄漏
}()

// 2. 切片引用底层数组
arr := make([]int, 1e6)
small := arr[:3]    // small 不释放,arr 也不释放

// 3. time.Ticker 没 Stop
ticker := time.NewTicker(time.Second)
// 忘记 ticker.Stop()

// 4. context 没 cancel
// goroutine 监听 ctx.Done() 但无人 cancel
```

```go
    fmt.Println("string:", v)

    fmt.Println("unknown")
```

### 3. 实现 LRU?

```go
type LRUCache struct {
    cap  int
    list *list.List
    m    map[any]*list.Element
}

func (c *LRUCache) Get(key any) any {
    if e, ok := c.m[key]; ok {
        c.list.MoveToFront(e)
        return e.Value.(*entry).value
    }
    return nil
}

func (c *LRUCache) Put(key, value any) {
    if e, ok := c.m[key]; ok {
        c.list.MoveToFront(e)
        e.Value.(*entry).value = value
        return
    }
    if c.list.Len() >= c.cap {
        oldest := c.list.Back()
        delete(c.m, oldest.Value.(*entry).key)
        c.list.Remove(oldest)
    }
    e := c.list.PushFront(&entry{key, value})
    c.m[key] = e
}
```

### 4. 限流器(令牌桶)?

```go
type TokenBucket struct {
    mu       sync.Mutex
    capacity int
    tokens   float64
    refill   float64
    last     time.Time
}

func (tb *TokenBucket) Allow() bool {
    tb.mu.Lock()
    defer tb.mu.Unlock()

    now := time.Now()
    tb.tokens += now.Sub(tb.last).Seconds() * tb.refill
    if tb.tokens > float64(tb.capacity) {
        tb.tokens = float64(tb.capacity)
    }
    tb.last = now

    if tb.tokens >= 1 {
        tb.tokens--
        return true
    }
    return false
}
```
