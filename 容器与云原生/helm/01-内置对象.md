# Helm 模板内置对象（Built-in Objects）

> Helm 模板里**不靠 `.Values` 也能访问**的一组特殊变量——release / chart / cluster 上下文都在里面。
> 与 `.Values` 配合使用，几乎所有模板都依赖这几个对象。

---

## 一、它们从哪来

```text
helm install / template 时，Helm 注入一组 root context
                         │
                         ▼
template execution context = {
   .Values, .Release, .Chart, .Files,
   .Capabilities, .Template, .IsDryrun, ...
}
                         │
                         ▼
     每个 {{ template "foo" . }} 的 . 就是这个上下文
```

`$` 也指向 root（覆盖嵌套 with / range 后的局部 `.`），用 `$var` 可始终取 root。

---

## 二、核心 6 个对象速查表

| 对象 | 类型 | 干嘛 | 典型用途 |
| --- | --- | --- | --- |
| **`.Values`** | map | 用户传进来的 values（默认 + --set + -f） | 业务参数 |
| **`.Release`** | object | 本次 release 的运行时元数据 | 资源命名、label、注解 |
| **`.Chart`** | object | chart 的元数据（Chart.yaml） | 版本号、文档链接 |
| **`.Files`** | object | 读 chart 里的**非模板文件** | ConfigMap 挂载、证书文件 |
| **`.Capabilities`** | object | K8s 集群能力探测 | API 版本兼容（apps/v1 vs apps/v1beta1） |
| **`.Template`** | object | 当前模板文件的元信息 | 调试、日志 |

---

## 三、`.Values`（最常用）

合并来源（高优先级覆盖低）：

```text
defaults values.yaml          # chart 内置
  ↑
chart values.yaml             # chart 内置（可选）
  ↑
-f / --values                # 用户文件（可多次）
  ↑
--set / --set-string         # 命令行（最高）
```

**模板里访问**：

```yaml
image:
  repository: {{ .Values.image.repository }}
  tag: {{ .Values.image.tag | default .Chart.AppVersion }}
  pullPolicy: {{ .Values.image.pullPolicy | default "IfNotPresent" }}
```

> 注意：`.Values` 的结构是 chart 自己定的，**没有固定 schema**——在 `values.yaml` 里自由组织。

---

## 四、`.Release`（运行时上下文）

每次 `helm install/upgrade` 时由 Helm 注入，**所有 release 都是不一样的**。

```go
type Release struct {
    Name      string              // release 名（helm install <name>）
    Namespace string              // 部署到的 namespace
    IsUpgrade bool              // 当前是 install 还是 upgrade
    IsInstall bool              // 同上
    Revision  int               // release 版本号（每次升级 +1）
    Service   string              // "Helm"（一般用不到）
    Time      Time              // 当前时间（time.Time）
    // Helm 3.14+ 还有：
    IsUninstall bool
}
```

**实战用法**：

```yaml
# 资源命名加 release 名避免冲突
metadata:
  name: {{ .Release.Name }}-config
  labels:
    app.kubernetes.io/instance: {{ .Release.Name }}
    app.kubernetes.io/managed-by: {{ .Release.Service }}
    app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}

# annotation 记录版本号（rollback 时一目了然）
metadata:
  annotations:
    revision: {{ .Release.Revision | quote }}
    deployedAt: {{ .Release.Time | quote }}

# install vs upgrade 行为不同
spec:
  replicas: {{ if .Release.IsInstall }}{{ .Values.initialReplicas }}{{ else }}{{ .Values.replicas }}{{ end }}
```

## 五、`.Chart`（chart 自身元数据）

来自 `Chart.yaml`：

```yaml
# Chart.yaml
apiVersion: v2
name: my-app
version: 0.1.0
appVersion: "1.25.0"
type: application
description: ...
icon: https://...
home: https://...
sources:
  - https://...
keywords: [...]
maintainers: [...]
annotations: [...]
kubeVersion: ">=1.24.0-0"
dependencies: [...]
```

**模板里访问**：

```yaml
# 标签 + 注解（强烈推荐每个资源都打）
metadata:
  name: {{ include "my-app.fullname" . }}
  labels:
    app.kubernetes.io/name: {{ .Chart.Name }}
    app.kubernetes.io/version: {{ .Chart.AppVersion | quote }}
    helm.sh/chart: {{ printf "%s-%s" .Chart.Name .Chart.Version | replace "+" "_" }}
spec:
  # 默认镜像 tag 用 Chart.yaml 里的 appVersion
  containers:
    - name: {{ .Chart.Name }}
      image: "{{ .Values.image.repository }}:{{ .Values.image.tag | default .Chart.AppVersion }}"
```

**完整字段**（来自 Chart.yaml + Helm 自动补的）：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `.Chart.Name` | Chart.yaml | chart 名 |
| `.Chart.Version` | Chart.yaml | chart 版本（注意是 chart 自身的版本，不是应用版本） |
| `.Chart.AppVersion` | Chart.yaml | 应用版本（image tag 默认值） |
| `.Chart.Type` | Chart.yaml | `application` / `library` |
| `.Chart.Description` | Chart.yaml | 描述 |
| `.Chart.Home` | Chart.yaml | 主页 URL |
| `.Chart.Sources` | Chart.yaml | 源码 URL 列表 |
| `.Chart.Keywords` | Chart.yaml | 关键词 |
| `.Chart.Maintainers` | Chart.yaml | 维护者列表 |
| `.Chart.Annotations` | Chart.yaml | 注解 |
| `.Chart.ApiVersion` | Chart.yaml | `v1` / `v2` |
| `.Chart.KubeVersion` | Chart.yaml | 兼容 K8s 版本约束 |
| `.Chart.Dependencies` | Chart.yaml | 子 chart 依赖列表 |
| `.Chart.Icon` | Chart.yaml | 图标 URL |

> ⚠️ **`.Chart.Version` ≠ `.Chart.AppVersion`**：
> - Chart 版本：`0.1.0`，**升 chart 模板代码**时 +1
> - App 版本：`1.25.0`，**升应用本身**时 +1
> 镜像 tag 应该用 `AppVersion`（业务版本），CI/CD 版本号应该用 `Version`（chart 版本）。

## 六、`.Files`（读 chart 内非模板文件）

模板文件（`templates/` 下）渲染时会丢注释和 yaml 字段——**非模板文件原样读**才能用。

### 6.1 用法

```go
.GetBytes   // → []byte
.Get        // → string
.Glob       // → Files map，按 glob 匹配
.GetBytes   // 读单个二进制文件
```

### 6.2 典型场景：ConfigMap 挂配置文件

```text
my-chart/
├── templates/
│   └── configmap.yaml
└── files/
    ├── nginx.conf
    └── app.toml
```

```yaml
# templates/configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: {{ .Release.Name }}-config
data:
  nginx.conf: |-
    {{ .Files.Get "files/nginx.conf" | indent 4 }}
  app.toml: |-
    {{ .Files.Get "files/app.toml" | indent 4 }}
  # 二进制文件
  cert.pem: {{ .Files.Get "files/cert.pem" | b64enc | quote }}
  # glob
  all-json: |-
    {{ range $path, $content := .Files.Glob "files/json/*.json" }}
    === {{ $path }} ===
    {{ $content | indent 4 }}
    {{ end }}
```

### 6.3 注意事项

- **Helm 3 必须在 `files/` 目录下**（Helm 2 可以放任何位置）
- **每个 release 都会打包所有文件**——大文件别放 `files/`（拖慢 install/upgrade）
- `.Files.Glob` 返回的是 `Files` 类型，**遍历时建议用 `$` 锚定根**

## 七、`.Capabilities`（K8s 集群能力）

模板里**根据集群 API 版本生成不同 yaml**用的。Helm 3 的 API 都 GA 了，主要是 fallback 兼容老集群。

```yaml
# 字段
apiVersions:
  - batch/v1
  - batch/v1beta1        # Helm 3.x 这里就只剩 v1，但仍是 list
kubeVersion:             # kubeVersion.Version（String），检测服务端版本
  Version: "v1.30.0"
  Major: "1"
  Minor: "30"
  GitVersion: "v1.30.0"
```

### 典型用法：API 版本回退（实际很少用了）

```yaml
apiVersion: {{ if .Capabilities.APIVersions.Has "networking.k8s.io/v1/Ingress" }}networking.k8s.io/v1{{ else }}networking.k8s.io/v1beta1{{ end }}
kind: Ingress
```

> ⚠️ **Helm 3 实际不再用 `.Capabilities.APIVersions`**——直接用 `networking.k8s.io/v1` 即可。Helm 3 保留这个对象主要是为了向后兼容。
> 真正用得到的是 **kubeVersion**：

```yaml
# 需要 K8s ≥ 1.25 才有 Pod Resources API
spec:
  {{- if ge (semver (splitList "." .Capabilities.KubeVersion.Version)._0 | int) 126 }}
  resources:                    # Pod.resources（K8s 1.25+ 才有）
    ...
  {{- end }}
```

**常用操作**：

```go
.Capabilities.APIVersions.Has "apps/v1/Deployment"   // bool
.Capabilities.KubeVersion.Version                   // "v1.30.0"
.Capabilities.KubeVersion.Major                      // "1"
.Capabilities.KubeVersion.Minor                      // "30"
```

## 八、`.Template`（当前模板文件元信息）

```go
type Template struct {
    Name    string             // 模板名（路径去掉 templates/ 和 .yaml）
    BasePath string             // chart 根目录的绝对路径
}
```

```yaml
# 调试时打印
{{ .Template.Name }}            # e.g. "deployment"
{{ .Template.BasePath }}         # /tmp/chart/my-chart
```

**实战**：一般用得不多，主要用于**调试日志**或在 `_helpers.tpl` 里给子模板传参。

## 九、子 chart / dependencies 上下文

子 chart 的模板看到的 `.` 是**自己的 root context**，不是父 chart 的。要访问父 chart 的对象：

```yaml
# 父 chart 用 include 调子 chart 时显式传 root
{{ include "subchart.template" . }}

# 子 chart 想用父 chart 的 .Values
{{ .Values.subchartName.foo }}     # 父 chart 的 .Values.subchartName
```

**Helm 3 中** `.Subcharts` / `.Dependencies` 字段（Go 类型）：

```go
type Chart struct {
    ...
    Dependencies []*chart.Chart  // 所有子 chart（含 dependencies / files/）
    // 访问父 chart 的元数据要用 .Chart.Metadata
}
```

模板里通过 `range` 遍历子 chart 不太常见，主要是 `_helpers.tpl` 里偶尔用。

## 十、其他（小但有用）

| 字段 | 类型 | 何时为 true | 用途 |
| --- | --- | --- | --- |
| `.IsDryrun` | bool | `helm install --dry-run` 或 `helm template` | 跳过某些破坏性 hook |
| `.IsUpgrade` | bool | `helm upgrade` | 升级期特殊处理 |
| `.IsInstall` | bool | `helm install` 首次部署 | 初始化逻辑 |
| `.IsUninstall` | bool | `helm uninstall`（Helm 3.14+） | 卸载期 hook |

```yaml
{{- if .IsInstall }}
# 首次部署才执行的初始化 job
apiVersion: batch/v1
kind: Job
metadata:
  name: {{ .Release.Name }}-init
...
{{- end }}
```

## 十一、`$`（root context）

每个 `{{ template "x" . }}` 传下去的都是当前 root。`with` / `range` 会**改 `.`**：

```yaml
{{- with .Values.server }}
host: {{ .host }}                # ← 这个 . 是 .Values.server
port: {{ .port }}
{{- end }}
# 这里 . 又回到 root
```

要访问 root：

```yaml
{{- with .Values.server }}
host: {{ .host }}                # 局部
# 想访问 release 名？
releaseName: {{ $.Release.Name }}   # ← 用 $ 锚 root
{{- end }}
```

`$` 始终指向**最初始的 root context**，不会被任何 `with` / `range` 改写。

## 十二、实战模式（最常见的 5 种用法）

### 12.1 资源命名 + labels

```yaml
# templates/_helpers.tpl
{{- define "my-app.fullname" -}}
{{- if .Values.fullnameOverride -}}
{{- .Values.fullnameOverride | trunc 63 | trimSuffix "-" -}}
{{- else -}}
{{- $name := default .Chart.Name .Values.nameOverride -}}
{{- if contains $name .Release.Name -}}
{{- .Release.Name | trunc 63 | trimSuffix "-" -}}
{{- else -}}
{{- printf "%s-%s" .Release.Name $name | trunc 63 | trimSuffix "-" -}}
{{- end -}}
{{- end -}}
{{- end -}}
```

### 12.2 默认值兜底

```yaml
image:
  repository: {{ .Values.image.repository | default "nginx" }}
  tag: {{ .Values.image.tag | default .Chart.AppVersion | quote }}
  pullPolicy: {{ .Values.image.pullPolicy | default "IfNotPresent" }}
replicas: {{ .Values.replicas | default 3 }}
```

### 12.3 模板条件渲染

```yaml
{{- if .Values.serviceAccount.create }}
apiVersion: v1
kind: ServiceAccount
metadata:
  name: {{ include "my-app.fullname" . }}
{{- end }}
```

### 12.4 多环境差异

```yaml
{{- if eq .Values.env "prod" }}
resources:
  requests: { cpu: "500m", memory: "1Gi" }
  limits:   { cpu: "2",    memory: "4Gi" }
{{- else }}
resources: {}
  requests: { cpu: "50m",  memory: "64Mi" }
{{- end }}
```

### 12.5 部署策略

```yaml
spec:
  strategy:
    {{- if eq .Values.env "prod" }}
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0
    {{- else }}
    type: Recreate
    {{- end }}
```

## 十三、踩坑清单

| 现象 | 原因 |
| --- | --- |
| `.Files.Get` 报错 `file not found` | 文件不在 `files/` 目录 / 路径写错 |
| `.Chart.AppVersion` 是空 | Chart.yaml 没写 |
| release 名字含 release 名导致超 63 字符 | 没 `trunc 63 \| trimSuffix "-"` |
| 子 chart 看不到父 chart 的 `.Values` | 子 chart 的 `.Values` 只到自己这层；用 `.Values.global.xxx` 共享 |
| `with` 嵌套后访问外层报错 | `.` 变了；用 `$.xxx` |
| `.Capabilities.APIVersions.Has` 永远 false | Helm 3 大多 API 都 GA，没法靠这个判断；改用 KubeVersion |
| `.Release.Time` 时间不对 | Helm 默认是 UTC，不是本地时间 |
