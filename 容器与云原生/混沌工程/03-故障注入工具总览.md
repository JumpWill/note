# 故障注入工具总览 (Fault Injection Tools Overview)

> 本章系统梳理主流混沌工程工具,对比它们的能力、适用场景与选型建议。

## 一、故障注入工具全景

### 1.1 工具生态图

```text
                          ┌────────────────────┐
                          │   商业平台 (SaaS)    │
                          │  Gremlin / Steadybit │
                          └────────────────────┘
                                      ↑
                          ┌────────────────────┐
                          │   云厂商原生工具      │
                          │ AWS FIS / Azure CCO │
                          └────────────────────┘
                                      ↑
┌──────────┐    ┌────────────────┐  ┌────────────────┐
│主机级工具 │    │ 容器/K8s 级工具 │  │  应用级工具     │
│stress-ng │    │ Chaos Mesh     │  │ Toxiproxy      │
│ChaosBlade│    │ Litmus         │  │ Pumba           │
│fault     │    │ ChaosBlade K8s │  │ MockServer     │
│          │    │ PowerfulSeal   │  │                │
└──────────┘    └────────────────┘  └────────────────┘
       ↑                ↑                  ↑
       └────────────────┴──────────────────┘
                  故障注入能力层层递进
```

### 1.2 工具分类

```text
按部署位置分类:

1. 主机级工具 (Host-level)
   - 作用: 单个主机资源故障
   - 工具: stress-ng, chaosblade
   - 适用: 测试环境

2. 容器级工具 (Container-level)
   - 作用: 容器/Pod 故障
   - 工具: Pumba, PowerfulSeal
   - 适用: Docker / K8s

3. K8s 资源级 (K8s-level)
   - 作用: K8s 资源故障
   - 工具: Chaos Mesh, Litmus, ChaosBlade
   - 适用: K8s 集群

4. 应用级 (Application-level)
   - 作用: 应用层故障
   - 工具: Toxiproxy, byteman
   - 适用: 中间件故障注入

5. 平台级 (Platform-level)
   - 作用: 跨服务跨节点
   - 工具: Gremlin, Steadybit
   - 适用: 商业 SaaS

6. 云级 (Cloud-level)
   - 作用: 云区域/可用区故障
   - 工具: AWS FIS, Azure Chaos Studio
   - 适用: 云原生
```

## 二、主流工具详解

### 2.1 Chaos Monkey (Netflix)

```text
类型: 主机级 (源起)
官网: https://github.com/Netflix/chaosmonkey
语言: Go
维护: Netflix (2010-2018 活跃, 后续维护少)
License: Apache 2.0
```

#### 核心功能

```text
- 随机终止 EC2 实例
- 随机终止 ASG 中的实例
- 跨可用区故障
- 可配置时间窗口 (默认工作时间)
- App 动态注册
```

#### 使用示例

```go
// 启动 Chaos Monkey
chaosmonkey.ApplicationMain(
    chaosmonkey.NewApp(...)
    chaosmonkey.TerminatorEnabled(true)
    chaosmonkey.Leashed(false)
    chaosmonkey.MeanTimeBetweenChaos(
        time.Minute,
        5*time.Minute,
    )
)
```

#### 优缺点

```text
优点:
  - 简单 (杀实例就完事)
  - Netflix 验证 (15+ 年)
  - 经典

缺点:
  - 久未更新
  - 局限于 EC2
  - 不能模拟复杂故障
  - 不适合 K8s

现状: 历史地位, 但已被新工具取代
```

### 2.3 Chaos Mesh (CNCF)

```text
类型: K8s 级
官网: https://chaos-mesh.org/
GitHub: https://github.com/chaos-mesh/chaos-mesh
维护: PingCAP
License: Apache 2.0
CNCF: Sandbox 项目
```

#### 核心功能

```text
故障类型:
  - PodChaos: Pod 故障 (杀, 重启)
  - NetworkChaos: 网络故障 (延迟, 丢包, 分区, 带宽)
  - StressChaos: CPU/内存压力
  - DiskChaos: 磁盘故障
  - DNSChaos: DNS 故障
  - TimeChaos: 时钟漂移
  - KernelChaos: 内核故障
  - JVMChaos: JVM 故障
  - AwsChaos: AWS 故障 (模拟 AWS API)
  - GcpChaos: GCP 故障
  - ProcessChaos: 进程故障

工作流:
  1. 定义实验 (YAML)
  2. 应用实验 (kubectl apply)
  3. 自动执行
  4. 监控和报告
  5. 归档 (自动保存到 archive)
```

#### 安装

```bash
# Helm 安装
helm repo add chaos-mesh https://charts.chaos-mesh.org
helm install chaos-mesh chaos-mesh/chaos-mesh \
  --namespace chaos-mesh \
  --create-namespace \
  --set chaosDaemon.runtime=containerd \
  --set chaosDaemon.socketPath=/run/containerd/containerd.sock
```

#### 实验示例

```yaml
# Pod 故障 (杀 Pod)
apiVersion: chaos-mesh.org/v1alpha1
kind: PodChaos
metadata:
  name: pod-kill-example
  namespace: chaos-mesh
spec:
  action: pod-kill
  mode: one
  selector:
    namespaces:
      - production
    labelSelectors:
      app: web
  scheduler:
    cron: "@every 30s"  # 每 30 秒杀一次
  duration: "30s"
```

```yaml
# 网络延迟
apiVersion: chaos-mesh.org/v1alpha1
kind: NetworkChaos
metadata:
  name: network-delay-example
spec:
  action: delay
  mode: all
  selector:
    namespaces:
      - production
    labelSelectors:
      app: web
  delay:
    latency: "100ms"
    correlation: "100"
    jitter: "50ms"
  duration: "5m"
```

```yaml
# CPU 压力
apiVersion: chaos-mesh.org/v1alpha1
kind: StressChaos
metadata:
  name: cpu-stress
spec:
  mode: all
  selector:
    namespaces:
      - production
    labelSelectors:
      app: web
  stressors:
    cpu:
      workers: 2
      load: 80  # 80% 压力
  duration: "5m"
```

```text

维护: MayaData
License: Apache 2.0
CNCF: Incubating 项目
```

#### 核心概念

```text
ChaosExperiment:
  故障实验定义 (YAML)

ChaosEngine:
  实验运行实例 (绑定到目标)

ChaosResult:
  实验结果

ChaosHub:
  共享故障库 (Git Repo)

  Web UI 平台
```

#### 安装

```bash
# Helm 安装
helm repo add litmuschaos https://litmuschaos.github.io/litmus-helm/
helm install litmus litmuschaos/litmus \
  --namespace litmus \
  --create-namespace
```

#### 实验示例

```yaml
# Pod 杀实验
apiVersion: litmuschaos.io/v1alpha1
kind: ChaosExperiment
metadata:
  name: pod-delete
  namespace: litmus
spec:
  description:
    Kill the pod
  definition:
    scope: Namespaced
  method:
    image: "litmuschaos/go-runner:latest"
    commands:
    - /bin/bash
    - -c
    - |
      kubectl delete pod -n ${{ invocation.experimentObject.metadata.namespace }}
        -l ${{ invocation.experimentObject.spec.labelSelectors }}
        --force=true
      sleep 10
  imagePullPolicy: Always
  definition:
    scope: Namespaced
  kind: Experiment
```

```yaml
# 启动实验
apiVersion: litmuschaos.io/v1alpha1
kind: ChaosEngine
metadata:
  name: pod-delete-engine
  namespace: production
spec:
  appinfo:
    appkind: deployment
    applabel: app=web
  chaosServiceAccount: pod-delete-sa
  experiments:
  - name: pod-delete
```

#### 优缺点

```text
优点:
  - 大量预定义实验
  - 强大 ChaosHub 共享
  - 详细结果分析
  - 活跃社区

缺点:
  - 概念较多
  - 学习曲线陡
  - 文档可改进
```

### 2.7 Toxiproxy

```text
类型: 应用级网络代理
官网: https://github.com/Shopify/toxiproxy
语言: Go
维护: Shopify
License: MIT
```

#### 核心功能

```text
- TCP 代理
- 模拟网络故障:
  - 延迟 (latency)
  - 丢包 (packet loss)
  - 带宽限制 (bandwidth)
  - 超时 (timeout)
  - 慢关闭 (slow close)
  - 重置 (reset peer)
- 不需要修改应用
- 透明代理

适用: 数据库, 消息队列, 微服务
```

#### 使用

```bash
# 启动 toxiproxy server
docker run -d --name toxiproxy -p 8474:8474 -p 20000:20000 shopify/toxiproxy

# 创建代理 (MySQL)
curl -X POST http://localhost:8474/proxies -d '{
  "name": "mysql",
  "listen": "0.0.0.0:20000",
  "upstream": "mysql-real:3306",
  "enabled": true
}'

# 添加延迟
curl -X POST http://localhost:8474/proxies/mysql/toxics -d '{
  "type": "latency",
  "attributes": {"latency": 100, "jitter": 20}
}'

# 移除
curl -X DELETE http://localhost:8474/proxies/mysql/toxics/latency
```

## 四、工具选型指南

### 4.1 选型决策树

```text
开始
  ↓
Q1: 预算充足?
  ├─ 是 → 考虑商业 (Gremlin, Steadybit)
  └─ 否 → 开源
       ↓
Q2: 主要用 K8s?
  ├─ 是 → Chaos Mesh / Litmus / ChaosBlade
  └─ 否 → Pumba (Docker) / ChaosBlade
       ↓
Q3: 需要丰富故障类型?
  ├─ 是 → ChaosBlade (40+ 故障)
  └─ 否 → Chaos Monkey
       ↓
Q4: 需要中文文档?
  ├─ 是 → ChaosBlade (阿里文档全)
  └─ 否 → 英文
       ↓
Q5: 团队技术栈?
  ├─ Go → Chaos Mesh
  ├─ Java → ChaosBlade
  └─ 通用 → Litmus
```

### 4.2 按场景推荐

| 场景 | 推荐工具 | 原因 |
|------|---------|------|
| **初创小团队** | Chaos Mesh 或 ChaosBlade | 易用, 免费, 文档好 |
| **K8s 中型团队** | Chaos Mesh | CNCF, 完整 K8s 集成 |
| **大型企业 K8s** | Litmus + Chaos Mesh | Litmus 实验库丰富, Chaos Mesh 编排 |
| **混合架构 (VM + K8s)** | ChaosBlade | 多平台支持 |
| **金融强需求** | Gremlin (商业) | 合规, 报告专业 |
| **数据库测试** | Toxiproxy | 专业的网络代理故障注入 |
| **阿里生态** | ChaosBlade | 阿里内部验证, 中文支持好 |
| **字节生态** | Chaos Mesh | 与 K8s 生态紧密结合 |
| **学术研究** | Chaos Monkey | 经典, 适合学习原理 |

## 五、工具核心能力详解

### 5.1 故障类型详解

```text
完整故障类型清单:

【资源类】
  - CPU: 满载, 占用, 降频
  - 内存: 满载, OOM, 泄漏
  - 磁盘: IO 满, 空间满, 读写错误
  - 网络: 延迟, 丢包, 乱序, 分区, 带宽限制
  - 文件: 删除, 损坏, 权限

【进程类】
  - 进程杀 (kill -9)
  - 进程挂起 (sleep)
  - 进程异常退出
  - 进程慢响应
  - CPU 100% 占用

【容器类】
```
