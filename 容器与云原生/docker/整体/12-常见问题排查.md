# Docker 常见问题排查 (Troubleshooting)

> 本章系统讲解 Docker 使用中的常见故障、排查方法与解决方案。

## 一、故障排查思路

### 1.1 排查流程

```text
故障现象
   ↓
1. 容器状态? (docker ps -a)
   ↓
2. 容器日志? (docker logs)
   ↓
3. 容器详情? (docker inspect)
   ↓
4. 进入容器调试 (docker exec)
   ↓
5. 网络测试
   ↓
6. 资源使用 (docker stats)
   ↓
7. 系统级 (内核、存储、网络)
```

### 1.2 排查工具清单

```bash
# Docker 工具
docker ps / logs / inspect / exec / stats / events

# 容器内工具
# - nicolaka/netshoot (网络调试)
# - alpine (基础工具)
# - busybox (极简)

# 系统工具
strace, ltrace, nsenter, tcpdump, iperf3, htop, free, df

# 网络工具
ping, traceroute, nslookup, dig, curl, wget, nmap

# 进程工具
ps, top, pstree, lsof, /proc/<pid>/...
```

## 二、容器启动问题

### 2.1 容器立即退出 (Exit Code)

```bash
# 查看所有容器 (含已停止)
docker ps -a

# 查看退出码
docker ps -a --format "{{.Names}}: {{.Status}}"

# 常见 Exit Code
# 0      - 正常退出
# 1      - 应用错误
# 125    - Docker daemon 错误
# 126    - 命令无法执行
# 127    - 命令未找到
# 128 + N - 被信号 N 终止 (137 = SIGKILL, 143 = SIGTERM)
# 137    - OOMKilled (内存超限)
# 139    - Segmentation fault

# 查看日志
docker logs <container>
docker logs --previous <container>  # 上次实例
```

### 2.2 容器无法启动

```bash
# 1. 镜像不存在
docker run nginx:1.25
# Unable to find image 'nginx:1.25' locally
# 解决: docker pull nginx:1.25

# 2. 端口冲突
docker run -p 80:80 nginx
# bind: address already in use
# 解决: 改端口 或 停占用进程
sudo lsof -i :80
sudo kill <pid>

# 3. 卷冲突
docker run -v mydata:/data nginx
# Error response from daemon: Volume is already in use
# 解决: 检查是否有其他容器在使用

# 4. 网络冲突
docker network create --subnet 172.20.0.0/16 my-net
# Error: Pool overlaps with other one
# 解决: 检查现有网络, 使用不同子网

# 5. 配置错误 (YAML / JSON)
docker stack deploy -c docker-compose.yml
# 解决: docker compose config 验证

# 6. 资源不足 (OOM)
# 解决: 加内存 / 释放内存
docker system prune -af
```

### 2.3 镜像拉取失败

```bash
# 1. 网络问题
docker pull nginx
# Error response from daemon: Get "https://registry-1.docker.io/v2/": dial tcp: lookup registry-1.docker.io on 127.0.0.11: no such host
# 解决: 检查 DNS / 代理 / 防火墙

# 2. 认证失败
docker pull myregistry/private
# Error: pull access denied
# 解决: docker login myregistry

# 3. 镜像不存在
docker pull myorg/myapp:nonexistent
# Error: manifest unknown
# 解决: 检查镜像名和 tag

# 4. 速率限制
# Error: toomanyrequests
# 解决: 注册 Docker Hub / 配置镜像加速器
```

## 三、网络问题

### 3.1 容器间无法通信

```bash
# 1. 不在同一网络
docker run --name web nginx
docker run --name api my-api
# api 无法访问 web (默认 bridge 只能用 IP)
# 解决: 用自定义网络
docker network create my-net
docker network connect my-net web
docker network connect my-net api

# 2. 端口未暴露
docker exec api curl web:80
# 在容器内可访问, 但外部不行
# 解决: docker run -p 80:80

# 3. 防火墙
sudo iptables -L INPUT -n
# 阻止了容器端口
# 解决: 开放端口或关闭防火墙

# 4. DNS 解析失败
docker exec api nslookup web
# server can't find web
# 解决: 检查网络, 确保在同一用户自定义网络
```

### 3.2 端口映射问题

```bash
# 1. 端口未正确暴露
docker run -p 8080:80 nginx
# 外部访问 http://localhost:8080 不通
# 解决: 检查 -p 是否正确, 容器内服务是否监听 80

# 2. 容器内服务监听地址错误
# 应用监听 127.0.0.1:80 (只接受容器内)
# 解决: 监听 0.0.0.0:80

# 3. 多端口冲突
docker run -p 80:80 web
docker run -p 80:80 db
# Error: bind: address already in use
# 解决: 改端口 / 停止旧容器
```

### 3.3 DNS 问题

```bash
# 1. 自定义网络 DNS 解析失败
docker exec web nslookup api
# 解决: 在同一网络
docker network inspect my-net

# 2. /etc/resolv.conf 配置问题
docker exec web cat /etc/resolv.conf
# 解决: 指定 --dns 或 --dns-search

# 3. 跨主机 DNS (Swarm)
docker exec <container> nslookup service_name
# Swarm 自动 DNS
# 解决: 服务加入同一 overlay 网络
```

## 四、存储问题

### 4.1 卷问题

```bash
# 1. 卷挂载失败
docker run -v mydata:/data alpine
# Error: Volume not found
# 解决: docker volume create mydata

# 2. Bind mount 权限问题
docker run -v /host/path:/container/path alpine
# permission denied
# 解决: 调整宿主机目录权限 / 用 :ro 只读

# 3. 磁盘空间满
docker system df
# 解决:
#    a. 清理镜像: docker image prune -a
#    b. 清理卷: docker volume prune
#    c. 清理容器: docker container prune
#    d. 调整日志: --log-opt max-size

# 4. 卷被占用无法删除
docker volume rm mydata
# Error: volume in use
# 解决: docker rm 关联容器后再删卷
```

### 4.2 数据丢失

```text
# 1. 容器删除后数据丢失
# 解决: 用 Volume / Bind Mount 持久化

# 2. 容器迁移后找不到数据
# 问题: 用 hostPath, 容器漂移到其他节点
# 解决: 用 Volume driver (NFS, 云盘)

# 3. tmpfs 数据丢失
# 问题: tmpfs 是内存, 容器停止即丢失
# 解决: 用普通 Volume

# 4. 备份恢复问题
# 解决: 定期备份, 测试恢复流程
```

## 五、性能问题

### 5.1 容器运行慢

```bash
# 1. CPU 占用高
docker stats
# NAME      CPU %    MEM
# web       95.0%    200MiB    ← CPU 满载

# 排查:
docker top <container>           # 看哪个进程
docker exec <container> ps aux
# 优化应用代码 / 增加 CPU 限制

# 2. 内存占用高
docker stats
# web       0.5%    1.5GiB / 2GiB    ← 内存紧张

# 排查:
docker exec <container> jmap -heap  # Java 应用
docker exec <container> cat /proc/meminfo
# 优化内存 (内存泄漏 / 缓存过大)

# 3. IO 慢
docker exec <container> iostat
# 解决: SSD, tmpfs, 卷挂载优化
```

### 5.2 OOMKilled

```bash
# 现象: 容器被 kill, 退出码 137
docker inspect <container> | grep -A 3 State
# "OOMKilled": true

# 解决:
# 1. 增加 memory 限制
docker run -m 1g my-app    # 从 512m 改 1g

# 2. 优化应用内存
docker exec <container> jmap -histo:live <pid>  # Java
# 找内存占用最多的类

# 3. 检查系统 swap
sysctl vm.swappiness    # 建议 0 或 1

# 4. 监控
docker run --memory-swappiness=0 -m 1g my-app
```

## 六、Docker daemon 问题

### 6.1 daemon 无法启动

```bash
# 1. 端口冲突
sudo systemctl start docker
# Error: port 2375 already in use
# 解决: 停占用进程 / 改 daemon.json port

# 2. 配置文件错误
sudo systemctl status docker
# 查看日志: journalctl -u docker

# 3. 数据目录权限
sudo systemctl start docker
# Error: permission denied
# 解决: chown -R root:root /var/lib/docker
sudo chmod 711 /var/lib/docker

# 4. 磁盘满
sudo systemctl start docker
# Error: no space left on device
# 解决: 清理磁盘
```

### 6.2 daemon 性能问题

```bash
# 1. 高 CPU
top
# dockerd CPU 占用高
# 排查:
sudo strace -p <dockerd-pid>
sudo lsof -p <dockerd-pid>

# 2. 高内存
docker system events --since 1h
# 查看异常事件

# 3. 慢操作
docker info
# 关注:
# - Storage Driver
# - Cgroup Driver
# - Number of Docker objects
```

## 七、镜像构建问题

### 7.1 Dockerfile 构建失败

```bash
# 1. 网络问题 (apt/pip 拉包失败)
docker build -t myapp .
# E: Unable to fetch some archives
# 解决: Dockerfile 中使用国内源
# 或 docker build --network=host ...

# 2. 权限问题
COPY ./files /app/
# COPY failed: permission denied
# 解决: chmod 644 或 chown

# 3. 文件找不到
COPY app.conf /etc/
# COPY failed: file not found
# 解决: 检查路径, 使用 .dockerignore

# 4. 镜像过大
docker build -t myapp .
# 层数过多
# 解决: 合并 RUN, 多阶段构建
```

### 7.2 构建速度慢

```bash
# 1. 启用 BuildKit
export DOCKER_BUILDKIT=1
docker build -t myapp .

# 2. 优化缓存
# 顺序: 不常变在前, 常变在后
COPY package.json .
RUN npm install
COPY . .           # 源码常变, 在后

# 3. 远程缓存
docker build \
  --cache-from myapp:cache \
  --build-arg BUILDKIT_INLINE_CACHE=1 \
  -t myapp:2.0 .

# 4. 跳过不需要的步骤
docker build --target runtime -t myapp .   # 多阶段构建的指定阶段
```

## 八、Docker Compose / Swarm 问题

### 8.1 Compose 问题

```bash
# 1. 服务启动顺序
docker compose up
# api: ERROR - connection to db:5432 refused

# 解决: depends_on + healthcheck
services:
  api:
    depends_on:
      db:
        condition: service_healthy

  db:
    healthcheck:
      test: ["CMD", "pg_isready"]

# 2. 配置覆盖不生效
docker compose -f docker-compose.yml -f docker-compose.override.yml up
# 解决: 检查多个文件的优先级

# 3. 网络冲突
docker compose up
# network my-net declared as external, but could not be found
# 解决: docker network create my-net
```

### 8.2 Swarm 问题

```bash
# 1. 服务无法调度
docker service ps web
# REJECTED - insufficient resources
# 解决: 增加节点 / 减少副本 / 调整资源

# 2. Manager 故障
docker node ls
# Manager 故障可能阻塞集群
# 解决: 多数 Manager 在线则集群正常
# 5 Manager 容忍 2 故障

# 3. 滚动更新卡住
docker service update --image myapp:2.0 web
docker service ps web
# 卡在中间
# 解决: --update-failure-action rollback
# 或手动: docker service rollback

# 4. 节点 NotReady
docker node ls
# node-1     Ready   (但过几小时又 NotReady)
# 排查:
ssh node-1
sudo systemctl status docker
df -h /var/lib/docker
```

## 九、生产问题排查案例

### 9.1 案例:容器无法启动 - OOM

```bash
# 现象: 容器一直重启
docker ps
# NAME      STATUS             RESTARTS
# api       Restarting (1)    3

# 排查:
docker logs api
# OOMKilled

docker inspect api | grep Memory
# "Memory": 536870912,

# 解决:
docker run -m 1g api    # 增加内存
# 或
# 优化应用内存泄漏
```

### 9.2 案例:磁盘满

```bash
# 现象: docker pull 失败
docker pull nginx
# no space left on device

# 排查:
df -h
# /var/lib/docker 100%

docker system df
# 占用最多是镜像

# 解决:
docker image prune -a --filter "until=720h"
docker container prune
docker volume prune

# 或调整日志:
# /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

### 9.3 案例:容器间通信慢

```bash
# 现象: 跨主机服务调用慢
docker service create --name api ...
docker service ps api

# 排查:
docker exec api ping db
# 时间很长

# 解决:
# 1. 检查网络
docker network inspect my-overlay

# 2. 优化 MTU
docker network create --opt com.docker.network.driver.mtu=9000 my-net

# 3. 启用加密 (但性能下降)
docker network create --opt encrypted my-net

# 4. 优化 DNS
docker exec api cat /etc/resolv.conf
```

### 9.4 案例:容器启动慢

```bash
# 现象: 容器启动耗时 30s+
docker stats
# 重启时间过长

# 排查:
docker run -it myapp:latest sh
# 在容器内查看启动日志
# 通常: 应用启动慢 / 网络 DNS 慢 / 镜像拉取慢

# 解决:
# 1. 优化应用启动 (Spring Boot 慢启动等)
# 2. 镜像预拉到所有节点
docker pull myapp:latest
# 3. 用 host 网络
docker run --network host myapp
```

## 十、紧急恢复

### 10.1 Docker daemon 完全宕机

```bash
# 1. 紧急启动 daemon
sudo systemctl restart docker

# 2. 检查 daemon 日志
sudo journalctl -u docker -n 100

# 3. 重置 daemon 配置 (极端情况)
sudo mv /etc/docker/daemon.json /etc/docker/daemon.json.bak
sudo systemctl restart docker

# 4. 检查磁盘空间
df -h
```

### 10.2 Swarm 集群不可用

```bash
# 1. 检查 Manager 状态
docker node ls

# 2. 强制重启 Manager
ssh manager-1
sudo systemctl restart docker

# 3. 重新初始化 (极端)
docker swarm init --force-new-cluster --advertise-addr 10.0.0.10

# 4. 加入其他节点
```

### 10.3 数据丢失恢复

```bash
# 1. 停止所有容器
docker compose down

# 2. 恢复 Volume
#    从备份恢复
docker run --rm \
  -v mydata:/data \
  -v $(pwd)/backup:/backup \
  alpine tar xzf /backup/mydata-backup.tar.gz -C /data

# 3. 重启
docker compose up -d
```

## 核心要点速记

### 容器退出码

```text
0     - 正常
1     - 应用错误
137   - OOMKilled (SIGKILL)
143   - SIGTERM
139   - Segmentation fault
126   - 命令无法执行
127   - 命令未找到
```

### 网络排查

```bash
docker network ls                 # 列表
docker network inspect <net>      # 详情
docker exec <c> ping <target>    # 测试
docker exec <c> nslookup <host>   # DNS
```

### 资源排查

```bash
docker stats                      # 实时
docker stats <container>          # 单个
docker system df                  # 磁盘
docker system prune               # 清理
```

### 日志排查

```bash
docker logs <container>           # 标准
docker logs -f <c>                # 跟踪
docker logs --tail 100 <c>        # 最后 100
docker logs --since 1h <c>        # 最近 1 小时
```

### 容器调试

```bash
docker exec -it <c> bash         # 进入
docker run --rm -it --network <net> nicolaka/netshoot  # 网络调试
docker logs --previous <c>       # 上次启动日志
docker inspect <c> | jq           # 详细信息
```

### 紧急清理

```bash
docker system prune -af --volumes  # 清理所有
```

### 性能问题排查

```text
启动慢 → 镜像大小、启动脚本、网络 DNS
运行慢 → CPU/内存/磁盘 IO/网络
重启 → 探针失败、内存不足、配置错误
```

### 常见错误速查

```text
1. 镜像找不到 → docker pull
2. 端口占用 → sudo lsof -i :<port>
3. 卷冲突 → 检查关联容器
4. 网络冲突 → 检查子网
5. OOM → 增加 -m 限制
6. DNS 失败 → 自定义网络
7. 磁盘满 → docker system prune
8. 权限 → chmod / chown
```

### 关键路径

```text
/var/lib/docker/
├── overlay2/        # 镜像层
├── containers/      # 容器
├── volumes/         # 卷
└── network/         # 网络配置

/etc/docker/
├── daemon.json      # daemon 配置
└── keys.json        # TLS 密钥
```
