# Docker 数据持久化与卷 (Volumes & Persistence)

> 本章详解 Docker 数据持久化方案:Volume、Bind Mount、tmpfs 三种方式,以及生产实践。

## 一、数据持久化概述

### 1.1 为什么需要持久化

```text
Docker 容器默认: 文件系统是临时的
- 容器停止 → 数据保留
- 容器删除 → 数据丢失

生产需求:
- 数据库数据 (MySQL, PostgreSQL)
- 用户上传文件
- 应用配置
- 日志文件 (某些场景)
```

### 1.2 三种持久化方式

```text

│  Volume     │  Bind Mount       │  tmpfs       │
├─────────────┼──────────────────┼──────────────┤
│ Docker 管理  │  宿主机目录       │  内存          │
│ 推荐生产     │  开发调试          │  临时数据     │
│ 跨平台       │  依赖路径          │  性能高       │
│ 备份迁移     │  直接访问          │  重启丢失     │
└─────────────┴──────────────────┴──────────────┘
```

## 二、Volume (卷)

### 2.1 概念

**Volume** 是 Docker 推荐的持久化方式,由 Docker 自己管理存储位置。

```text
Volume 默认位置: /var/lib/docker/volumes/<name>/_data

优势:
- Docker 管理,易于备份
- 支持 volume driver (跨主机)
- 跨平台 (Linux/Windows/Mac 行为一致)
- 安全 (不会误改宿主关键目录)
```

### 2.2 Volume 命令

```bash
# 创建 volume
docker volume create mydata
# 默认驱动: local (宿主本地)

# 创建指定驱动的卷
docker volume create --driver local \
  --opt type=nfs \
  --opt o=addr=10.0.0.10,rw \
  --opt device=:/exports/mydata \
  mynfs

# 列出卷
docker volume ls

# 查看卷详情
docker volume inspect mydata
# 输出:
# [
#   {
#     "CreatedAt": "2026-08-18T...",
#     "Driver": "local",
#     "Mountpoint": "/var/lib/docker/volumes/mydata/_data",
#     "Labels": {},
#     "Scope": "local"
#   }
# ]

# 删除卷
docker volume rm mydata

# 清理未用卷
docker volume prune

# 查看某个容器的卷
docker inspect <container> | grep -A 5 Mounts
```

### 2.3 使用 Volume

```bash
# 方式 1: -v
docker run -d -v mydata:/data nginx

# 方式 2: --mount (更详细)
docker run -d \
  --mount source=mydata,target=/data \
  nginx

# 方式 3: 匿名卷 (自动生成)
docker run -d -v /data nginx
# 自动创建 <hash> 名称的卷

# 多个卷
docker run -d \
  -v mydata:/data \
  -v mylogs:/var/log/app \
  -v myconfig:/etc/app \
  nginx

# 只读卷
docker run -d -v mydata:/data:ro nginx
```

### 2.4 Volume 共享

```bash
# 容器间共享数据 (挂载同一个卷)
docker run -d --name writer -v shared:/data alpine touch /data/file
docker run -d --name reader -v shared:/data:ro alpine cat /data/file

# 数据卷容器 (高级用法)
# 创建一个专门存储数据的容器
docker create -v /data --name datastore alpine

# 其他容器 --volumes-from 复用
docker run -d --volumes-from datastore --name app1 nginx
docker run -d --volumes-from datastore --name app2 nginx
```

### 2.5 Volume 驱动

```text
内置驱动:
- local - 宿主机本地 (默认)

第三方驱动:
- aws-ebs    - AWS EBS
- gcp-pd     - GCP Persistent Disk
- azure-file - Azure File Storage
- rexray/ebs - EBS 跨主机
- convoy      - 多种后端
- flocker     - 集群存储

使用:
docker volume create --driver rexray/ebs \
  --opt volumeid=vol-1234 \
  myebs
```

## 三、Bind Mount (绑定挂载)

### 3.1 概念

**Bind Mount** 把宿主机的**任意目录或文件**挂载到容器中。

```text
特点:
- 挂载宿主任意路径
- 容器可直接读写宿主
- 跨平台行为不一致 (Mac 需要特殊路径)
```

### 3.2 使用 Bind Mount

```bash
# 挂载宿主目录
docker run -d \
  -v /host/path:/container/path \
  nginx

# 挂载宿主文件
docker run -d \
  -v /host/file.conf:/etc/nginx/nginx.conf:ro \
  nginx

# --mount 方式 (更明确)
docker run -d \
  --mount type=bind,source=/host/path,target=/data \
  nginx

# 读写控制
-v /host:/container:ro    # 只读
-v /host:/container:rw    # 读写 (默认)
```

### 3.3 典型场景

```bash
# 1. 开发环境: 代码热更新
docker run -d \
  -v $(pwd)/src:/app/src \
  -v $(pwd)/config:/app/config \
  my-dev-app

# 2. 共享配置
docker run -d \
  -v /etc/localtime:/etc/localtime:ro \
  nginx

# 3. 调试 (进入容器看宿主文件)
docker run -it \
  -v /var/log:/var/log:ro \
  --rm alpine

# 4. 数据库数据 (开发环境)
docker run -d \
  -v /data/mysql:/var/lib/mysql \
  -e MYSQL_ROOT_PASSWORD=xxx \
  mysql:8.0

# ⚠️ 生产慎用 (路径依赖, 难迁移)
```

## 四、tmpfs (内存文件系统)

### 4.1 概念

**tmpfs** 存储在内存中,容器停止后数据丢失。

```text
特点:
- 内存存储 (极快)
- 不持久化
- 适合:
  - 临时文件
  - 敏感数据 (密码、密钥)
  - 不需要持久化的数据

注意:
- 容器内存限制同样适用
- tmpfs 大小受 --tmpfs size 选项限制
```

### 4.2 使用 tmpfs

```bash
# 方式 1: --tmpfs
docker run -d \
  --tmpfs /tmp \
  --tmpfs /run \
  alpine

# 指定大小
docker run -d \
  --tmpfs /tmp:rw,size=100m \
  alpine

# 方式 2: --mount
docker run -d \
  --mount type=tmpfs,destination=/tmp,tmpfs-size=100m \
  alpine

# 多个 tmpfs
docker run -d \
  --tmpfs /tmp:size=50m \
  --tmpfs /var/run:size=10m \
  alpine
```

### 4.3 tmpfs 应用场景

```bash
# 1. 临时处理
docker run --rm \
  --tmpfs /data:size=1g \
  alpine sh -c "dd if=/dev/zero of=/data/file bs=1M count=1024"

# 2. 密码 (不持久)
docker run --rm \
  --tmpfs /secrets:size=1m \
  alpine

# 3. 性能敏感
docker run -d \
  --tmpfs /tmp:rw,size=500m \
  nginx

# 4. 缓存 (重启清空)
docker run -d \
  --tmpfs /cache:size=1g \
  my-app
```

## 五、三种方式对比

### 5.1 对比表

| 维度 | Volume | Bind Mount | tmpfs |
|------|--------|-----------|-------|
| 宿主位置 | Docker 管理 | 任意 | 内存 |
| 跨平台 | ✅ 一致 | ⚠️ Mac 特殊 | ✅ |
| 数据持久 | ✅ | ✅ | ❌ |
| 性能 | 高 | 高 | 最高 |
| 备份迁移 | 简单 | 复杂 | N/A |
| Volume driver | ✅ | ❌ | � |
| 推荐场景 | 生产 | 开发/调试 | 临时/敏感 |

### 5.2 选择建议

```text
✅ 用 Volume:
  - 生产数据库
  - 持久化应用数据
  - 需要备份迁移
  - 跨主机共享 (volume drivers)

✅ 用 Bind Mount:
  - 开发环境
  - 配置文件注入
  - 调试 (挂载宿主日志目录)
  - 需要直接访问宿主文件

✅ 用 tmpfs:
  - 临时数据
  - 敏感信息
  - 性能敏感临时存储
```

## 六、生产实战

### 6.1 数据库容器持久化

```bash
# PostgreSQL
docker run -d \
  --name postgres \
  -e POSTGRES_PASSWORD=secret \
  -v pgdata:/var/lib/postgresql/data \
  -v pgconf:/etc/postgresql \
  -p 5432:5432 \
  postgres:15-alpine

# MySQL
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=secret \
  -v mysqldata:/var/lib/mysql \
  -v mysqlconf:/etc/mysql/conf.d \
  -p 3306:3306 \
  mysql:8.0

# MongoDB
docker run -d \
  --name mongodb \
  -v mongodbdata:/data/db \
  -v mongodbconfig:/data/configdb \
  -p 27017:27017 \
  mongo:7

# Redis (持久化)
docker run -d \
  --name redis \
  -v redisdata:/data \
  -p 6379:6379 \
  redis:7-alpine redis-server --appendonly yes
```

### 6.2 文件上传服务

```bash
# 上传文件目录
docker run -d \
  --name upload-service \
  -v uploads:/var/www/uploads \
  -v logs:/var/log/service \
  my-upload-app

# 数据备份
docker run --rm \
  -v uploads:/data:ro \
  -v $(pwd)/backup:/backup \
  alpine tar czf /backup/uploads-$(date +%Y%m%d).tar.gz -C /data .
```

### 6.3 配置文件挂载

```bash
# Nginx 配置
docker run -d \
  --name nginx \
  -v ./nginx.conf:/etc/nginx/nginx.conf:ro \
  -v ./conf.d:/etc/nginx/conf.d:ro \
  -v ./html:/usr/share/nginx/html:ro \
  -v nginx_logs:/var/log/nginx \
  -p 80:80 \
  nginx:alpine

# 应用配置 (敏感配置用 Secret)
docker run -d \
  --name my-app \
  -v ./app-config.yaml:/app/config.yaml:ro \
  --env-file ./.env \
  my-app:1.0
```

### 6.4 多容器数据共享

```bash
# 创建数据卷
docker volume create app-data

# 上传容器写入
docker run -d \
  --name uploader \
  -v app-data:/uploads \
  upload-app

# 处理容器读取
docker run -d \
  --name processor \
  -v app-data:/data:ro \
  process-app

# 日志分析容器读取同一日志目录
docker run -d \
  --name log-analyzer \
  -v app-logs:/logs:ro \
  analyzer-app
```

## 七、Volume 备份与迁移

### 7.1 Volume 备份

```bash
# 方法 1: 启动临时容器打包卷
docker run --rm \
  -v mydata:/data:ro \
  -v $(pwd)/backup:/backup \
  alpine tar czf /backup/mydata-$(date +%Y%m%d).tar.gz -C /data .

# 方法 2: 直接打包宿主目录
sudo tar czf mydata-backup.tar.gz /var/lib/docker/volumes/mydata/_data

# 方法 3: 使用 docker cp
docker run --rm \
  -v mydata:/data \
  alpine cp -r /data /backup/
```

### 7.2 Volume 恢复

```bash
# 创建新卷
docker volume create mydata-restored

# 恢复数据
docker run --rm \
  -v mydata-restored:/data \
  -v $(pwd)/backup:/backup \
  alpine tar xzf /backup/mydata-20260818.tar.gz -C /data
```

### 7.3 跨主机迁移

```bash
# 1. 导出 Volume (源主机)
docker run --rm \
  -v mydata:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/mydata.tar.gz -C /data .

# 2. 传输到目标主机
scp mydata.tar.gz user@target-host:/tmp/

# 3. 在目标主机导入
ssh user@target-host
docker volume create mydata
docker run --rm \
  -v mydata:/data \
  -v /tmp:/backup \
  alpine tar xzf /backup/mydata.tar.gz -C /data
```

## 八、Volume 驱动与生产实践

### 8.1 主流 Volume 驱动

```text
云厂商:
- AWS EBS      - 块存储,高性能
- GCP PD       - 持久磁盘
- Azure Disk   - Azure 块存储
- 阿里云 NAS   - 阿里云 NAS

分布式存储:
- GlusterFS
- CephFS / RBD
- MinIO (对象存储)

网络文件系统:
- NFS
- SMB (Windows)
- CIFS
```

### 8.2 NFS Volume 示例

```bash
# 1. 创建 NFS Volume
docker volume create \
  --driver local \
  --opt type=nfs \
  --opt o=addr=10.0.0.10,rw \
  --opt device=:/exports/data \
  mynfs

# 2. 使用
docker run -d \
  -v mynfs:/data \
  my-app

# 3. 验证
docker volume inspect mynfs
```

### 8.3 跨主机 Volume (生产推荐)

```bash
# 方式 1: NFS (简单)
# N 台机器挂载同一个 NFS, 共享数据

# 方式 2: 云厂商块存储 (推荐)
# AWS EBS 跨可用区挂载
docker volume create --driver ebs mydata

# 方式 3: 分布式存储
# cephFS, glusterFS
docker volume create --driver cephfs mydata
```

## 九、备份与恢复实战

### 9.1 自动备份脚本

```bash
#!/bin/bash
# backup-volumes.sh
# 每日备份所有 Docker 卷

BACKUP_DIR=/backup/docker/$(date +%Y%m%d)
mkdir -p $BACKUP_DIR

# 获取所有卷
VOLUMES=$(docker volume ls -q)

for VOL in $VOLUMES; do
    echo "Backing up volume: $VOL"
    docker run --rm \
        -v $VOL:/data:ro \
        -v $BACKUP_DIR:/backup \
        alpine tar czf /backup/$VOL-$(date +%Y%m%d).tar.gz -C /data .
done

# 清理 7 天前的备份
find /backup -mtime +7 -delete
```

### 9.2 自动化 (Cron)

```bash
# crontab -e
0 2 * * * /path/to/backup-volumes.sh
```

### 9.3 备份验证

```bash
# 1. 检查备份文件
ls -la /backup/docker/$(date +%Y%m%d)/

# 2. 测试恢复 (重要!)
docker run --rm \
  -v mydata-test:/data \
  -v /backup/docker/$(date +%Y%m%d):/backup:ro \
  alpine tar xzf /backup/mydata-XXX.tar.gz -C /data
docker run --rm -v mydata-test:/data alpine ls -la /data

# 3. 验证数据完整性
docker run --rm -v mydata-test:/data md5sum -r /data/file.txt
# 与原数据 md5 对比
```

## 核心要点速记

### 三种持久化方式

```text
Volume:     Docker 管理, 推荐生产
Bind Mount: 宿主目录, 开发调试
tmpfs:      内存, 临时数据
```

### 命令对比

```text
# Volume
docker volume create mydata
docker run -v mydata:/data nginx

# Bind Mount
docker run -v /host/path:/container/path nginx

# tmpfs
docker run --tmpfs /tmp:size=100m nginx
```

### 选型决策

```text
生产数据库 → Volume (云盘 / NFS)
配置文件注入 → Bind Mount
敏感临时数据 → tmpfs
开发热更新 → Bind Mount
```

### 备份速记

```bash
# 备份
docker run --rm \
  -v mydata:/data:ro \
  -v $(pwd):/backup \
  alpine tar czf /backup/backup.tar.gz -C /data .

# 恢复
docker run --rm \
  -v mydata:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/backup.tar.gz -C /data
```

### 跨主机持久化

```text
- 云厂商块存储 (EBS, 云盘) - 推荐
- NFS - 简单
- 分布式存储 (Ceph, GlusterFS) - 大规模
```

### 实战模式

```bash
# PostgreSQL 持久化
docker run -d \
  -v pgdata:/var/lib/postgresql/data \
  postgres:15

# 配置注入
docker run -d \
  -v ./config.yaml:/app/config.yaml:ro \
  my-app

# 临时数据
docker run -d \
  --tmpfs /tmp:size=500m \
  nginx
```
