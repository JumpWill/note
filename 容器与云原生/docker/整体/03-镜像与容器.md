# Docker 镜像与容器 (Images & Containers)

> 本章详解 Docker 镜像与容器的完整生命周期、操作命令与实战技巧。

## 一、Docker 镜像

### 1.1 镜像概念

```text
Docker 镜像 = 只读的应用打包
- 分层构建 (UnionFS)
- 不可变 (immutable)
- 标准化 (OCI 规范)

镜像组成:
- 基础层 (Base Image): 如 ubuntu, alpine, golang
- 依赖层 (Dependencies): 应用运行时
- 应用层 (Application): 业务代码
- 配置层 (Configuration): 启动参数
```

### 1.2 镜像命名规范

```text
镜像完整名称:
[REGISTRY/][NAMESPACE/]REPOSITORY[:TAG][@DIGEST]

例:
nginx                                            # 默认 Docker Hub,library/nginx,latest
nginx:1.25                                        # 指定 tag
nginx:1.25.3-alpine                               # 多段 tag
myregistry.com/myorg/myapp:1.0                   # 私有 registry
gcr.io/google-containers/pause:3.5                # GCP Registry
myregistry.com/myorg/myapp@sha256:abc...          # 不可变 digest
```

### 1.3 镜像操作命令

```bash
# 搜索镜像
docker search nginx
docker search --limit 5 mysql

# 拉取镜像
docker pull nginx                            # 默认 :latest
docker pull nginx:1.25
docker pull ubuntu:22.04
docker pull --platform linux/arm64 nginx    # 指定平台

# 查看本地镜像
docker images
docker images -a                  # 包含中间层
docker images --filter dangling=true  # 悬空镜像

# 删除镜像
docker rmi nginx:1.25
docker image rm nginx

# 清理未用镜像
docker image prune
docker image prune -a           # 包括被停止容器的镜像

# 打标签
docker tag nginx:1.25 myregistry.com/myorg/nginx:v1.0

# 镜像详情
docker inspect nginx:1.25
docker history nginx:1.25       # 查看镜像层

# 保存/加载镜像
docker save -o nginx.tar nginx:1.25
docker load -i nginx.tar

# 推送镜像
docker login myregistry.com
docker push myregistry.com/myorg/myapp:1.0
```

### 1.4 镜像标签 (Tag) 规范

```text
推荐 tag 命名:
- v1.0.0          # SemVer (推荐)
- v1.0.0-alpine   # 版本 + 变体
- 1.25.3          # 纯版本
- latest          # 默认 (生产慎用!)
- stable          # 稳定版

⚠️ 不要在生产使用 :latest
   因为 latest 可能指代不同版本
```

## 二、Docker 容器

### 2.1 容器 vs 镜像

```text
镜像 (Image)   = 类 (Class)
容器 (Container) = 对象 (Instance)

镜像: 只读模板,静态
容器: 运行实例,可变层 (可写层)

一个镜像可以创建多个容器 (共享底层)
```

### 2.2 容器生命周期

```text
Docker 容器生命周期:

Created  → docker create
   ↓
Running → docker start (up)
   ↓
Paused  → docker pause / unpause
   ↓
Stopped → docker stop (graceful) / kill (SIGKILL)
   ↓
Removed → docker rm

状态查询: docker ps -a (所有) / docker ps (运行中)
```

### 2.3 docker run 完整选项

```bash
docker run [OPTIONS] IMAGE [COMMAND] [ARG...]

# ===== 基础选项 =====
-d, --detach                # 后台运行
-i, --interactive           # 保持 STDIN
-t, --tty                   # 分配伪终端
--name string               # 容器名
--hostname string           # 容器主机名
--rm                        # 容器退出自动删除
--restart policy            # 重启策略

# ===== 网络选项 =====
-p, --publish list          # 端口映射 host:container
                              # -p 8080:80
                              # -p 127.0.0.1:8080:80
                              # -p 8080:80/tcp
                              # -p 8080:80/udp
                              # -p 8080-8090:8080-8090
-P, --publish-all           # 暴露 EXPOSE 端口
--expose list                # 仅声明, 不映射
--network network           # 加入网络
--ip string                 # 指定 IP
--dns list                  # DNS 服务器
--add-host list             # 添加 hosts 映射

# ===== 资源限制 =====
--cpus decimal              # CPU 数量 (0.5 = 半核)
--memory, -m bytes          # 内存限制
--memory-swap bytes         # 内存+swap 限制
--memory-reservation bytes  # 内存软限制
--cpuset-cpus string        # 限制 CPU 核心 (0,1,2)
--cpuset-mems string        # 限制内存节点
--shm-size bytes            # /dev/shm 大小
--pids-limit int            # 最大进程数

# ===== 存储 =====
-v, --volume list           # 挂载卷
                              # -v mydata:/data
                              # -v /host/path:/container/path
                              # -v /host/path:/container/path:ro
--mount mount               # 更详细的挂载
                              # type=bind,source=...,target=...
--tmpfs list                # 内存文件系统
--read-only                 # 根文件系统只读

# ===== 环境变量 =====
-e, --env list              # 环境变量
                              # -e KEY=VALUE
                              # -e KEY (从宿主导入)
--env-file list             # 从文件导入
                              # --env-file .env

# ===== 安全 =====
-u, --user string           # 用户
                              # -u root
                              # -u 1000:1000 (uid:gid)
                              # -u nobody
--privileged                # 特权模式 (⚠️)
--cap-add list              # 添加 capability
--cap-drop list             # 移除 capability
--security-opt list         # 安全选项
                              # --security-opt seccomp=unconfined
                              # --security-opt apparmor=unconfined
                              # --security-opt no-new-privileges
--read-only                 # 根 FS 只读

# ===== 健康检查 =====
--health-cmd string         # 健康检查命令
--health-interval duration  # 检查间隔
--health-timeout duration   # 超时
--health-retries int        # 重试次数
--health-start-period duration  # 启动宽限期

# ===== 日志 =====
--log-driver string         # 日志驱动
--log-opt list              # 日志选项
                              # --log-opt max-size=10m
                              # --log-opt max-file=3

# ===== 其他 =====
-u, --user                  # 用户
-w, --workdir string       # 工作目录
--entrypoint string         # 覆盖 ENTRYPOINT
--label list                # 添加标签
                              # --label env=prod
--label-file list           # 从文件
--add-host list             # 添加 hosts
--device list               # 暴露设备
                              # --device /dev/snd
--cap-add list              # capability
--ulimit ulimit             # ulimit
                              # --ulimit nofile=1024:2048

# 完整示例
docker run -d \
  --name my-nginx \
  --restart unless-stopped \
  -p 80:80 \
  -v /host/html:/usr/share/nginx/html:ro \
  -e ENV=production \
  --memory 512m \
  --cpus 1.0 \
  --health-cmd "curl -f http://localhost/ || exit 1" \
  --health-interval 30s \
  --log-opt max-size=10m \
  --log-opt max-file=3 \
  nginx:alpine
```

### 2.4 容器管理命令

```bash
# 查看容器
docker ps                     # 运行中
docker ps -a                  # 全部
docker ps -q                  # 仅 ID
docker ps --filter "status=running"
docker ps --filter "name=nginx"
docker ps --format "{{.Names}}: {{.Status}}"

# 启动/停止
docker start <container>
docker stop <container>
docker restart <container>
docker kill <container>       # SIGKILL
docker pause <container>
docker unpause <container>

# 删除
docker rm <container>
docker rm -f <container>      # 强制
docker container prune        # 清理已停止容器

# 进入容器
docker exec -it <container> bash
docker exec -u root -it <container> sh
docker exec <container> ls /

# 查看日志
docker logs <container>
docker logs -f <container>         # 跟踪
docker logs --tail 100 <container>
docker logs --since 1h <container>

# 查看资源
docker stats
docker stats <container>      # 单个
docker stats --no-stream       # 快照

# 查看详情
docker inspect <container>
docker top <container>          # 进程

# 文件传输
docker cp <container>:/path ./local
docker cp ./local <container>:/path

# 重命名
docker rename <old> <new>

# 导出/导入容器文件系统
docker export <container> > file.tar
docker import file.tar myimage:latest

# 清理
docker container prune -f
docker system prune -af
```

### 2.5 容器日志详解

```bash
# 默认 JSON 日志驱动
# /var/lib/docker/containers/<id>/<id>-json.log

# 查看日志

# 时间戳

  }
```

## 三、容器资源管理

### 3.1 资源限制详解

```bash
# CPU 限制
docker run --cpus=2.0 nginx           # 最多 2 核
docker run --cpuset-cpus="0,1" nginx  # 只能用 CPU 0 和 1

# 内存限制
docker run -m 512m nginx              # 最多 512 MB
docker run --memory-swap 1g nginx    # 总内存 1GB (含 swap)

# 不限制 (默认)
docker run nginx                    # 无限制

# 资源查看
docker stats
```

### 3.2 OOM 与资源压力

```text
内存压力场景:

1. 内存使用达到 limit
   → OOM Killer (Linux 内核)
   → 容器进程被 kill
   → 退出码 137 (128 + SIGKILL 9)

2. CPU 超过 limit
   → throttled (节流,变慢)
   → 不会直接 kill
```

```bash
# 查看容器退出原因
docker inspect <container> | grep -A 3 State

# 查看 OOMKilled
kubectl describe pod <pod>
# Last State: Terminated, Reason: OOMKilled

# 解决:
# 1. 增加 memory limit
# 2. 优化应用内存 (内存泄漏)
# 3. 加节点内存
```

### 3.3 资源监控

```bash
# 实时资源
docker stats

# 输出:
# CONTAINER    CPU %    MEM USAGE / LIMIT     MEM %    NET I/O        BLOCK I/O   PIDS
# my-nginx     0.05%    2.5MiB / 512MiB      0.49%    1.07kB / 0B    0B / 0B     3

# 单次快照
docker stats --no-stream

# 指定容器
docker stats <container>

# 自定义格式
docker stats --format "{{.Name}}: {{.CPUPerc}} {{.MemUsage}}"

# 输出到文件 (用于监控)
docker stats --no-stream > stats.txt
```

## 四、容器网络

### 4.1 端口映射

```bash
# 基本映射
docker run -p 8080:80 nginx
# 访问 http://localhost:8080 → 容器 80

# 指定 IP
docker run -p 127.0.0.1:8080:80 nginx
docker run -p 0.0.0.0:8080:80 nginx

# 端口范围
docker run -p 8080-8090:8080-8090 nginx

# TCP / UDP
docker run -p 53:53/udp dns-server
docker run -p 53:53/tcp dns-server

# 随机端口
docker run -P nginx    # 自动分配宿主机端口到 EXPOSE

# 查看端口映射
docker port <container>
```

### 4.2 网络模式

```bash
# 1. bridge (默认)
docker run --network bridge nginx
docker run nginx    # 默认就是 bridge

# 2. host (共享宿主网络)
docker run --network host nginx
# 容器直接使用宿主 IP,无网络隔离
# 适用: 网络性能要求高、监控 agent

# 3. none (无网络)
docker run --network none alpine
# 适用: 完全隔离的任务

# 4. container (共享另一个容器网络)
docker run --network container:<other> alpine

# 5. 自定义网络
docker network create my-net
docker run --network my-net --name web nginx
docker run --network my-net --name api my-api
# 容器间可通过 name 互通 (Docker DNS)
```

### 4.3 DNS 与容器名解析

```bash
# 自定义网络中,容器可通过名字互通
docker network create backend
docker run -d --network backend --name db postgres
docker run -d --network backend --name api my-api
# api 容器内: ping db → 解析为 db 容器 IP

# 自定义 DNS
docker run --dns 8.8.8.8 --dns 8.8.4.4 nginx
docker run --dns-search example.com nginx

# 自定义 hosts
docker run --add-host api.internal:10.0.0.5 nginx
```

## 五、容器数据管理

### 5.1 Volume (推荐)

```bash
# 创建卷
docker volume create mydata

# 查看卷
docker volume ls
docker volume inspect mydata

# 挂载卷
docker run -d -v mydata:/data nginx

# 匿名卷
docker run -d -v /data nginx    # 自动生成匿名卷

# 删除卷
docker volume rm mydata

# 清理未用卷
docker volume prune
```

### 5.2 Bind Mount

```bash
# 挂载宿主目录
docker run -d -v /host/path:/container/path nginx
docker run -d -v /host/path:/data:ro nginx    # 只读

# 挂载单个文件
docker run -d -v /host/file.conf:/etc/app.conf nginx

# 实用场景:
# - 开发环境同步代码 (热更新)
# - 共享配置文件
# - 调试 (挂载到容器内部)
```

### 5.3 tmpfs

```bash
# 内存文件系统 (容器停止数据丢失)
docker run -d --tmpfs /tmp nginx
docker run -d --tmpfs /tmp:rw,size=100m nginx

# 适用:
# - 临时数据
# - 敏感信息 (密码)
# - 性能要求高的临时存储
```

### 5.4 三种方式对比

| 维度 | Volume | Bind Mount | tmpfs |
|------|--------|-----------|-------|
| 位置 | Docker 管理 | 宿主任意 | 内存 |
| 跨平台 | ✅ | ❌ (路径依赖) | ✅ |
| 性能 | 高 | 高 | 最高 |
| 数据持久 | ✅ | ✅ | ❌ |
| 推荐场景 | 生产 | 开发/调试 | 临时数据 |

## 七、容器健康检查

### 7.1 HEALTHCHECK 指令

```dockerfile
# Dockerfile
FROM nginx:alpine

HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
  CMD curl -f http://localhost/ || exit 1
```

参数:
- `--interval` - 检查间隔 (默认 30s)
- `--timeout` - 检查超时 (默认 30s)
- `--start-period` - 启动宽限期 (默认 0s)
- `--retries` - 失败重试次数 (默认 3)
- `CMD` - 检查命令 (返回 0 = healthy)

### 7.2 docker run 健康检查

```bash
docker run -d \
  --health-cmd "curl -f http://localhost/ || exit 1" \
  --health-interval 30s \
  --health-timeout 3s \
  --health-retries 3 \
  --health-start-period 40s \
  nginx:alpine
```

### 7.3 查看健康状态

```bash
# 查看健康状态
docker inspect --format='{{.State.Health.Status}}' <container>
# 输出: healthy / unhealthy / starting / none

# 查看完整健康信息
docker inspect --format='{{json .State.Health}}' <container> | jq

# 所有容器健康状态
docker ps --format "{{.Names}}: {{.State}}"
```

## 八、容器实战技巧

### 8.1 容器与主机数据交换

```bash
# 复制文件
docker cp <container>:/path ./local
docker cp ./local <container>:/path

# 复制整个目录
docker cp mycontainer:/etc/nginx/ ./nginx-backup

# 跨主机传输
docker save -o image.tar myapp
docker load -i image.tar

# 或用 docker 仓库
docker push myregistry/myapp:tag
```

### 8.2 容器故障排查

```bash
# 1. 容器无法启动
docker run -it --rm <image> sh    # 交互式调试

# 2. 容器启动后立即退出
docker logs <container>           # 查看错误日志
docker ps -a                       # 看退出状态

# 3. 端口无法访问
docker port <container>            # 查看端口映射
docker inspect <container> | grep IPAddress

# 4. 性能问题
docker stats                       # 实时资源
docker top <container>             # 进程

# 5. 网络问题
docker exec <container> ping target
docker network inspect <network>

# 6. 磁盘满
docker system df
```

### 8.3 容器清理

```bash
# 清理已停止容器
docker container prune

# 清理未使用镜像
docker image prune
docker image prune -a           # 包括被停止容器的镜像

# 清理未使用卷
docker volume prune

# 清理未使用网络
docker network prune

# 一次性清理所有
docker system prune
docker system prune -a --volumes  # 包括卷
```

## 九、容器最佳实践

### 9.1 镜像最佳实践

```text
1. 使用官方基础镜像 (alpine 推荐,体积小)
2. 多阶段构建 (减小最终镜像)
3. 合并 RUN 命令 (减少镜像层)
4. .dockerignore 排除不必要文件
5. 不要在镜像中硬编码密钥
6. 用非 root 用户运行
7. 添加 HEALTHCHECK
8. 指定具体 tag,不用 latest
9. 镜像打标签用版本号
10. 用国内镜像加速器
```

### 9.2 容器运行最佳实践

```text
1. 设置资源限制 (CPU、内存)
2. 设置 restart 策略 (unless-stopped)
3. 配置健康检查
4. 用日志驱动限制大小 (防止磁盘满)
5. 用只读根 FS + 数据卷
6. 不用 --privileged
7. 限制 capability (--cap-drop ALL)
8. 用 user namespace (K8s 1.25+)
9. 不要在容器内运行 SSH
10. 用 Docker Compose / K8s 编排
```
