# Docker 性能调优与监控 (Performance Tuning & Monitoring)

> 本章讲解 Docker 性能优化策略、监控方案、cAdvisor/Prometheus 集成与生产最佳实践。

## 一、Docker 性能概述

### 1.1 性能瓶颈

```text
Docker 应用常见性能瓶颈:

1. CPU 瓶颈
   - 容器 CPU 满载
   - CPU 共享冲突

2. 内存瓶颈
   - OOMKilled
   - 内存交换 (swap)

3. 磁盘 IO 瓶颈
   - 日志写入慢
   - 镜像层拉取慢
   - 数据卷 IO 慢

4. 网络瓶颈
   - 跨主机通信延迟
   - 端口冲突
   - DNS 解析慢

5. 镜像启动慢
   - 镜像过大
   - 启动脚本复杂
```

### 1.2 性能监控指标

```text
关键指标 (黄金信号):
- Rate      - 每秒请求数 (QPS)
- Errors    - 错误率
- Duration  - 响应时间 (P50/P99/P999)
- Saturation - 饱和度 (队列、连接数)

USE 方法:
- Utilization - 资源使用率
- Saturation  - 资源饱和度
- Errors      - 错误事件

RED 方法:
- Requests    - 请求数
- Errors      - 错误数
- Duration    - 时长
```

## 二、Docker 资源调优

### 2.1 资源限制最佳实践

```bash
# 1. CPU 限制
docker run --cpus=2.0 my-app              # 最多 2 核
docker run --cpuset-cpus="0,1" my-app     # 只能用 0,1 核

# 2. 内存限制
docker run -m 512m my-app                 # 最多 512 MB
docker run --memory-swap 1g my-app       # 内存+swap 总和 1GB

# 3. PIDs 限制
docker run --pids-limit 100 my-app        # 最多 100 个进程

# 4. 磁盘 IO (需要 v2 cgroup)
docker run --device-read-bps /dev/sda:1mb \
  --device-write-bps /dev/sda:1mb my-app

# 5. 块 IO 权重
docker run --blkio-weight 500 my-app     # IO 权重 (相对)
```

### 2.2 CPU 调优

```bash
# CPU 份额 (默认 1024)
docker run --cpu-shares 512 my-app        # 50% CPU
docker run --cpu-shares 2048 my-app       # 200% (多于 1 核)

# CPU 核心绑定
docker run --cpuset-cpus="0,1" my-app     # 绑定到 CPU 0,1

# CFS 配额 (1.13+)
docker run --cpu-period=100000 \
  --cpu-quota=50000 my-app               # 50% CPU
```

### 2.3 内存调优

```bash
# 内存限制与 swap
docker run -m 512m my-app                       # 内存 512MB
docker run --memory-swap 1g my-app             # 内存+swap 1GB
docker run --memory-swappiness=0 my-app        # 关闭 swap (推荐)

# OOM 处理
docker run -m 512m --oom-kill-disable my-app   # OOM 不杀
docker run -m 512m --oom-score-adj=-500 my-app  # 降低被杀优先级

# Kernel Memory (限制内核占用)
docker run --kernel-memory 100m my-app

# 内存预留
docker run -m 1g --memory-reservation 512m my-app
```

### 2.4 网络性能

```bash
# 1. 使用 host 网络 (性能优先)
docker run --network host my-app
# 性能: 接近原生
# 缺点: 端口冲突, 无网络隔离

# 2. 使用 macvlan / ipvlan
docker network create -d macvlan \
  --subnet=192.168.1.0/24 \
  --gateway=192.168.1.1 \
  -o parent=eth0 \
  my-net
# 绕过 NAT, 性能接近物理网络

# 3. 调优内核网络参数
# /etc/sysctl.d/docker.conf
net.core.somaxconn = 65535
net.ipv4.tcp_max_syn_backlog = 65535
net.core.netdev_max_backlog = 65535
net.ipv4.tcp_tw_reuse = 1

# 4. 调整 MTU
docker network create --opt com.docker.network.driver.mtu=9000 my-net
```

### 2.5 磁盘 IO 性能

```bash
# 1. 使用 SSD
# 2. 挂载 tmpfs (内存)
docker run --tmpfs /tmp:rw,size=1g my-app

# 3. 块 IO 限制
docker run --device-read-bps /dev/sda:50mb my-app

# 4. 避免 overlay2 在 XFS (用 ext4 更快)
mkfs.ext4 /dev/sdb1

# 5. 镜像层合并减少
# 多阶段构建 + 合并 RUN 命令
```

## 三、Docker 监控

### 3.1 内置监控

```bash
# docker stats (实时)
docker stats
docker stats --no-stream         # 快照
docker stats <container>         # 指定容器
docker stats --format "{{.Name}}: {{.CPUPerc}} {{.MemUsage}}"

# 输出示例:
# CONTAINER    NAME      CPU %    MEM USAGE / LIMIT     MEM %    NET I/O         BLOCK I/O   PIDS
# abc123       web       0.05%    2.5MiB / 512MiB      0.49%    1.07kB / 648B   0B / 0B    3
# def456       db        0.32%    145MiB / 1GiB       14.1%    2.5MB / 1.2MB    12MB / 8MB  15

# docker top
docker top <container>           # 类似 ps

# docker events
docker events                    # 实时事件流
docker events --since 1h         # 最近 1 小时
```

### 3.2 cAdvisor (容器指标)

```text
cAdvisor (Container Advisor):
- Google 开源
- 自动采集容器指标 (CPU, 内存, 网络, 磁盘)
- 内置 Prometheus exporter (端口 8080)
- 在 K8s 中由 kubelet 内置
- 在 Docker 中可单独部署
```

```bash
# Docker 部署 cAdvisor
docker run -d \
  --name cadvisor \
  --volume=/:/rootfs:ro \
  --volume=/var/run:/var/run:ro \
  --volume=/sys:/sys:ro \
  --volume=/var/lib/docker/:/var/lib/docker:ro \
  --volume=/dev/disk/:/dev/disk:ro \
  --publish=8080:8080 \
  --detach=true \
  --privileged=true \
  gcr.io/cadvisor/cadvisor:latest
```

### 3.3 Prometheus + Grafana

```bash
# 1. 创建 docker-compose.yml (监控栈)
cat > docker-compose.monitoring.yml << 'EOF'
version: '3.8'

services:
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml:ro
      - prometheus-data:/prometheus
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'
      - '--storage.tsdb.path=/prometheus'
      - '--storage.tsdb.retention.time=30d'
    ports:
      - "9090:9090"
    networks:
      - monitor

  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
      - GF_USERS_ALLOW_SIGN_UP=false
    volumes:
      - grafana-data:/var/lib/grafana
    ports:
      - "3000:3000"
    networks:
      - monitor
    depends_on:
      - prometheus

  node-exporter:
    image: prom/node-exporter:latest
    container_name: node-exporter
    pid: host
    volumes:
      - /proc:/host/proc:ro
      - /sys:/host/sys:ro
    networks:
      - monitor
    deploy:
      mode: global    # Swarm: 每节点一个

  cadvisor:
    image: gcr.io/cadvisor/cadvisor:latest
    container_name: cadvisor
    volumes:
      - /:/rootfs:ro
      - /var/run:/var/run:ro
      - /sys:/sys:ro
      - /var/lib/docker/:/var/lib/docker:ro
    privileged: true
    networks:
      - monitor
    deploy:
      mode: global

volumes:
  prometheus-data:
  grafana-data:

networks:
  monitor:
    driver: overlay
EOF

# 2. 配置 Prometheus
cat > prometheus.yml << 'EOF'
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: prometheus
    static_configs:
      - targets: ['localhost:9090']

  - job_name: node-exporter
    dns_sd_configs:
      - names:
        - 'tasks.node-exporter'
        type: 'A'
        port: 9100

  - job_name: cadvisor
    dns_sd_configs:
      - names:
        - 'tasks.cadvisor'
        type: 'A'
        port: 8080
EOF

# 3. 部署
docker stack deploy -c docker-compose.monitoring.yml monitor
```

### 3.5 日志收集

```bash
# Docker 日志驱动
docker run --log-driver json-file \
  --log-opt max-size=10m \
  --log-opt max-file=3 \
  my-app

# 日志驱动:

  my-app
```

## 四、镜像优化

### 4.1 减小镜像体积

```text
优化方法:
1. 使用最小基础镜像
   - alpine (5MB)
   - distroless (20MB)
   - scratch (0MB)

2. 多阶段构建
   - 减小 50-90% 体积

3. 合并 RUN 命令
   - 减少镜像层数

4. 清理缓存
   - rm -rf /var/lib/apt/lists/*
   - yarn cache clean

5. .dockerignore 排除
   - .git, node_modules, .md
```

### 4.2 加速镜像构建

```text
优化方法:
1. 利用构建缓存
   - COPY 文件少的在前 (package.json)
   - 大文件 (源码) 在后

2. BuildKit (推荐)
   - 并行构建
   - 缓存复用
   - 增量构建

3. 远程缓存
   - GitHub Actions cache
   - Docker Hub autobuild cache

4. 启用 BuildKit
export DOCKER_BUILDKIT=1
docker build -t myapp .

5. --cache-from 复用其他镜像的缓存
docker build --cache-from myapp:latest -t myapp:2.0 .
```

### 4.3 启动速度优化

```dockerfile
# 1. ENTRYPOINT 用 exec 格式 (避免 shell)
ENTRYPOINT ["myapp"]

# 2. 最小化 CMD
CMD ["--help"]

# 3. 不要在启动脚本中做复杂操作
# 4. 预编译 (Go 等静态编译语言)
# 5. distroless 镜像 (无 shell)
```

## 五、Docker Compose 中的资源限制

### 5.1 deploy 资源限制

```yaml
version: '3.8'

services:
  web:
    image: myapp
    deploy:
      replicas: 3
      resources:
        limits:
          cpus: '0.5'
          memory: 512M
        reservations:
          cpus: '0.25'
          memory: 256M
      restart_policy:
        condition: on-failure
        delay: 5s
        max_attempts: 3
      update_config:
        parallelism: 2
        delay: 10s
        order: start-first
```

```yaml
    healthcheck:
      test: ["CMD", "pg_isready"]
```

## 六、监控实战案例

### 6.1 完整监控栈

```text
生产监控组件:

数据采集层:
- cAdvisor         - 容器指标
- node-exporter    - 主机指标
- 各种 exporter     - 应用指标 (Redis, MySQL, etc)

存储层:
- Prometheus       - 时序数据库
- Loki             - 日志聚合

可视化层:
- Grafana          - 仪表盘

告警层:
- Alertmanager      - 告警路由
- Slack/PagerDuty   - 告警通知
```

### 6.2 关键告警规则

```yaml
groups:
- name: docker_alerts
  rules:
  # 容器 CPU 高使用率
  - alert: HighContainerCPU
    expr: rate(container_cpu_usage_seconds_total[5m]) > 0.9
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "Container {{ $labels.name }} high CPU"

  # 容器内存高使用率
  - alert: HighContainerMemory
    expr: container_memory_usage_bytes / container_spec_memory_limit_bytes > 0.9
    for: 5m
    labels:
      severity: warning

  # 容器 OOM Killed
  - alert: ContainerOOMKilled
    expr: increase(container_oom_events_total[5m]) > 0
    labels:
      severity: critical

  # 容器频繁重启
  - alert: ContainerRestarting
    expr: rate(container_restart_count[15m]) > 0
    for: 5m
    labels:
      severity: warning

  # 节点磁盘满
  - alert: DiskSpaceLow
    expr: (node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 < 10
    for: 10m
    labels:
      severity: critical
```

## 核心要点速记

### 资源限制速查

```bash
docker run \
  --cpus 2.0 \                    # CPU 限制
  -m 1g \                         # 内存限制
  --pids-limit 100 \              # 进程数限制
  --cpuset-cpus "0,1" \           # CPU 绑定
  --memory-swappiness 0 \         # 关闭 swap
  --tmpfs /tmp:size=100m \       # 内存盘
  my-app
```

### 监控工具链

```text
cAdvisor (容器) → Prometheus (存储) → Grafana (展示)
        ↓
    Alertmanager (告警)
```

### 监控关键指标

```text
- container_cpu_usage_seconds_total     # CPU 使用
- container_memory_usage_bytes          # 内存使用
- container_network_*_bytes_total       # 网络流量
- container_fs_*_bytes_total            # 磁盘 IO
- rate(container_restart_count[15m])     # 重启率
```

### 性能优化优先级

```text
1. CPU 限制与核心绑定
2. 内存限制与 swap 关闭
3. 网络选择 (host/macvlan)
4. 日志驱动配置
5. 镜像优化 (体积小)
6. 健康检查
```

### docker stats 输出


### 告警阈值

```text
- CPU > 90% 持续 5 分钟
- 内存 > 90% 持续 5 分钟
- OOMKilled (立即告警)
- 重启 > 0 持续 15 分钟
- 磁盘 < 10% (持续 10 分钟)
```

### 镜像优化口诀

```text
小:  alpine / distroless / scratch
少:  合并 RUN, 清理缓存, .dockerignore
快:  缓存优化, BuildKit, --cache-from
安全:  签名 (Cosign), 扫描 (Trivy)
```

```text
1. 应用层 (代码优化)
2. 镜像层 (大小、启动)
```
