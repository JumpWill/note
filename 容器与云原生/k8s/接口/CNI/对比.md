# CNI 主流方案对比

## 一、概述

本文档系统对比三大主流 CNI 方案：**Flannel**、**Calico**、**Cilium**，帮助根据业务需求选择最合适的方案。

| 维度 | Flannel | Calico | Cilium |
|------|---------|--------|--------|
| 维护方 | Flannel-io（社区） | Tigera（公司） | Isovalent / Cisco |
| CNCF | sandbox | **Graduated** | **Graduated** |
| 数据面 | vxlan / host-gw / ipip / udp | iptables / eBPF / IPIP / VXLAN / BGP | **eBPF**（XDP / TC / sock_ops） |
| NetworkPolicy | ❌（雏形） | ✅ **K8s 事实标准** | ✅ K8s + Cilium 扩展（L7） |
| 替换 kube-proxy | ❌ | ✅（eBPF data plane） | ✅ |
| 性能 | 中 | 高（eBPF）/ 中（iptables） | **最高** |
| 可观测 | 无 | 弱 | **Hubble**（service map + flow + L7） |
| L7 策略 | ❌ | ✅（Enterprise） | ✅（原生） |
| BGP 物理网络 | ❌ | ✅（生产推荐） | ❌ |
| 双栈 IPv4/IPv6 | 部分 | ✅ | ✅ |
| 内核要求 | 3.10+ | 3.10+ | **4.19+，建议 5.10+** |
| 资源占用 | 极低 | 中 | 中（BPF maps 占用内存） |
| 商业版 | 无 | Tigera Enterprise | Isovalent Enterprise |
| 学习曲线 | 平 | 中（BGP 陡） | 陡（eBPF） |
| 适用集群规模 | <500 | <5000 | <10000 |

## 二、整体架构对比

```text
Flannel 架构（极简）：

  ┌──────────────────────────┐
  │   flanneld (DaemonSet)    │
  │   - 监听 etcd              │
  │   - 创建 veth pair          │
  │   - 配置 flannel.X 设备    │
  └────────────┬───────────────┘
               │
  ┌────────────▼───────────────┐
  │   etcd（子网分配）         │
  └─────────────────────────────┘

Calico 架构（生产级）：

  ┌──────────────────────────┐
  │   calico-node              │
  │   ├─ Felix (策略)          │
  │   ├─ BIRD (BGP)            │
  │   └─ confd (配置同步)      │
  └────────────┬───────────────┘
               │
  ┌────────────▼───────────────┐
  │   typha (集群扩展)         │
  └────────────┬───────────────┘
               │
  ┌────────────▼───────────────┐
  │   datastore               │
  │   (K8s API / etcd)         │
  └─────────────────────────────┘

Cilium 架构（eBPF 现代）：

  ┌──────────────────────────┐
  │   cilium-agent             │
  │   ├─ eBPF Programs         │
  │   ├─ Hubble Server        │
  │   ├─ ClusterMesh Agent    │
  │   └─ Envoy (L7)           │
  └────────────┬───────────────┘
               │
  ┌────────────▼───────────────┐
  │   eBPF Maps               │
  │   (cilium_lb, policy...)  │
  └────────────┬───────────────┘
               │
  ┌────────────▼───────────────┐
  │   K8s API (CRD)            │
  │   CiliumNetworkPolicy...  │
  └─────────────────────────────┘
```

## 三、数据面对比

### 3.1 Flannel 四种 backend

| Backend | 性能 | 封装开销 | 适用 |
|---------|------|----------|------|
| vxlan | ~70μs | 50 字节 | 云环境、跨子网 |
| host-gw | ~40μs | 0 字节 | 同 L2、裸金属 |
| ipip | ~60μs | 20 字节 | 跨子网、轻量 |
| udp | ~150μs | 大量 | 已不推荐 |

### 3.2 Calico 数据面

| 数据面 | 性能 | 封装 | 适用 |
|---------|------|------|------|
| 无封装 + BGP | ~30-50μs | 0 | 裸金属、BGP 网络 |
| IPIP | ~50-80μs | 20 字节 | 跨子网 |
| VXLAN | ~60-100μs | 50 字节 | 云环境 |
| eBPF | ~30-50μs | 0 | 4.19+ 内核 |

### 3.3 Cilium 数据面（eBPF）

```
唯一的数据面：eBPF
  - XDP（网卡驱动层）
  - TC（流量控制层）
  - sock_ops（socket 层）
  - kprobe（内核探针）

性能：
  - 跨节点：~25μs（最快）
  - 同节点：~5μs
  - 完全在内核态执行

特点：
  - 替换 kube-proxy
  - 哈希表查找 O(1)
  - 支持 L7 策略
  - 支持 WireGuard 加密
```

### 3.4 数据面对比总结

| 维度 | Flannel | Calico | Cilium |
|------|---------|--------|--------|
| 实现方式 | 用户态 daemon + 内核虚拟设备 | iptables/eBPF + 路由表 | eBPF 程序 |
| 内核态执行 | 部分（数据面） | iptables 或 eBPF | 完全 |
| 用户态上下文切换 | 每次包 1 次 | iptables 多次 | 0 次 |
| 哈希表查找 | 无 | iptables 线性 | O(1) |
| 大规模性能 | 差（etcd 瓶颈） | 良 | **优** |
| 灵活切换 | 多 backend | 多数据面 | 唯一（eBPF） |

## 五、关键技术原理对比

### 5.1 网络数据流对比

**Flannel 跨节点通信：**

```
Pod A → veth → cbr0 → 路由表
     → flannel.1（VXLAN 封装）
     → 物理网络
     → 目标节点 flannel.1（解封装）
     → cbr0 → veth → Pod B
```

**Calico 跨节点通信：**

```
Pod A → veth → cbr0 → 路由表（BIRD 注入）
     → eth0（裸机）
     → 物理网络（BGP 路由）
     → 目标节点 eth0
     → 路由表 → cbr0 → Pod B
```

**Cilium 跨节点通信：**

```
Pod A → 系统调用 send()
     → eBPF 钩子 sock_ops（内核态）
     → eBPF Map 查询（O(1)）
     → cilium_host → eth0
     → 物理网络
     → 目标节点 → cilium_host
     → eBPF 钩子 → cbr0 → Pod B
```

### 5.2 NetworkPolicy 实现对比

| 维度 | Calico | Cilium | Flannel |
|------|--------|--------|---------|
| K8s 标准 | ✅ 完全支持 | ✅ 完全支持 | ❌ 不支持 |
| 拒绝规则 | ✅ | ✅ | ❌ |
| 命名空间选择 | ✅ | ✅ | ❌ |
| 服务账户选择 | ✅ | ✅ | ❌ |
| ICMP 控制 | ✅ | ✅ | ❌ |
| L7 协议（HTTP/gRPC） | Enterprise | ✅ 原生 | ❌ |
| GlobalNetworkPolicy | ✅ | ✅ | ❌ |
| 性能（Policy 匹配） | iptables O(n) | eBPF O(1) | N/A |

### 5.3 关键技术对比

| 维度 | Flannel | Calico | Cilium |
|------|---------|--------|--------|
| 容器网络接口 | veth + bridge | veth + bridge | veth + eBPF |
| 跨主机隧道 | VXLAN/IPIP/host-gw/UDP | VXLAN/IPIP/无封装/BGP | eBPF（无隧道） |
| 路由协议 | 无（静态） | BGP（动态） | 无（BPF） |
| Service LB | kube-proxy | kube-proxy / Felix eBPF | cilium-agent eBPF |
| 连接跟踪 | 内核 conntrack | 内核 conntrack | eBPF Map |
| 策略实现 | 无 | iptables / nftables / eBPF | eBPF |
| 加密通信 | 无 | IPsec / WireGuard | WireGuard（原生） |

## 八、适用场景对比

| 场景 | 推荐 | 理由 |
|------|------|------|
| 开发测试 | **Flannel** | 简单、零策略 |
| 学习 K8s | **Flannel** | 容易理解 CNI 原理 |
| 小集群（<200 节点） | **Flannel** | 资源占用最低 |
| 中等生产（200-500 节点） | **Calico** | NetworkPolicy 完整、稳 |
| 大生产（500-2000 节点） | **Calico** | BGP 可对接物理网络 |
| 超大规模（2000+ 节点） | **Calico eBPF** 或 **Cilium** | 性能强 |
| 裸金属 + BGP 网络 | **Calico** | 无封装 + BGP 最优 |
| 云环境 | **Cilium** | eBPF + WireGuard |
| 需要可观测性 | **Cilium** | Hubble 业界最强 |
| 需要 L7 策略 | **Cilium** | 原生支持 HTTP/gRPC/Kafka |
| 服务网格 | **Cilium** | 替代 Istio 更轻量 |
| 多集群管理 | **Calico** 或 **Cilium** | 都有 ClusterMesh |
| 内核 < 4.19 | **Flannel** 或 **Calico iptables** | Cilium eBPF 需要新内核 |
| 严格安全合规 | **Calico** | 完整 NetworkPolicy |

## 九、部署方式对比

### 9.1 Flannel 部署

```bash
helm repo add flannel https://flannel-io.github.io/flannel
helm install flannel flannel/flannel \
  --namespace kube-flannel \
  --create-namespace
```

### 9.2 Calico 部署

```bash
kubectl apply -f https://raw.githubusercontent.com/projectcalico/calico/v3.27.0/manifests/operator.yaml
kubectl apply -f - <<EOF
apiVersion: operator.tigera.io/v1
kind: Installation
metadata:
  name: default
spec:
  calicoNetwork:
    ipPools:
    - blockSize: 26
      cidr: 10.244.0.0/16
    encapsulation: VXLANCrossSubnet
EOF
```

### 9.3 Cilium 部署

```bash
helm repo add cilium https://helm.cilium.io/
helm install cilium cilium/cilium \
  --namespace kube-system \
  --set kubeProxyReplacement=true \
  --set hubble.enabled=true \
  --set hubble.relay.enabled=true \
  --set hubble.ui.enabled=true
```

## 十、监控与排障对比

### 10.1 查看 CNI 状态

```bash
# Flannel
kubectl -n kube-flannel get pods
kubectl -n kube-flannel logs -l app=flannel
cat /etc/cni/net.d/10-flannel.conflist

# Calico
kubectl -n calico-system get pods
kubectl exec -n calico-system <calico-node-pod> -- calicoctl node status
kubectl exec -n calico-system <calico-node-pod> -- calicoctl bgp peers
kubectl get installation default -o yaml
kubectl get ippools -o yaml

# Cilium
kubectl -n kube-system get pods -l k8s-app=cilium
cilium status
hubble status
hubble observe
kubectl exec -n kube-system <cilium-pod> -- cilium bpf lb list
```

### 10.2 网络问题排障

```bash
# 所有 CNI 通用
kubectl get nodes -o wide
kubectl get pods -o wide
ip route show table all
iptables-save | head
```

### 10.3 CNI 切换注意事项

```
重要：CNI 切换会影响所有 Pod！

1. 所有 Pod 会重建
   - Pod IP 会变化
   - service ClusterIP 不变
   - 客户端重连即可

2. 切换期间网络中断
   - 短暂（30 秒 - 几分钟）
   - 提前通知业务方

3. 多 CNI 迁移路径：
   Flannel → Calico：calico policy-only 模式共存
   Calico → Cilium：建议一次性切换
   Cilium → Calico：calico installation 重装

4. 回滚方案：
   - 保留旧 CNI 配置
   - 切换 kubelet 配置指向旧 CNI
   - 重启 Pod
```

## 十一、迁移与升级

### 11.1 Flannel → Calico

```bash
# 1. 部署 Calico
kubectl apply -f calico.yaml

# 2. 标记 Flannel DaemonSet 不在节点上运行
kubectl -n kube-flannel patch ds kube-flannel --type=json \
  -p='[{"op":"replace","path":"/spec/template/spec/nodeSelector","value":{"kubernetes.io/os":"never"}}]'

# 3. 重启 Pod（会使用 Calico）
kubectl delete pods -A --all
```

### 11.2 Calico → Cilium

```bash
# 1. 删除 Calico
kubectl delete -f calico.yaml

# 2. 安装 Cilium（采用 Helm 一次性切换）
helm install cilium cilium/cilium --namespace kube-system \
  --set kubeProxyReplacement=true

# 3. 重启所有 Pod
kubectl delete pods -A --all
```

### 11.3 Cilium → Flannel

```bash
# 1. 卸载 Cilium
helm uninstall cilium -n kube-system

# 2. 安装 Flannel
helm install flannel flannel/flannel --namespace kube-flannel --create-namespace

# 3. 重启 Pod
kubectl delete pods -A --all
```

## 十二、决策树

```
Q1: 需要 NetworkPolicy 吗？
  ├─ 不需要 → Flannel（最简单）
  └─ 需要 ↓

Q2: 集群规模？
  ├─ < 200 节点 → Flannel 或 Calico
  ├─ 200-500 节点 → Calico
  └─ > 500 节点 ↓

Q3: 有物理网络 BGP？
  ├─ 是 → Calico（无封装 + BGP 最佳）
  └─ 否 ↓

Q4: 内核版本？
  ├─ < 4.19 → Calico iptables 模式
  └─ ≥ 4.19 ↓

Q5: 需要 L7 策略 / 服务网格 / 可观测？
  ├─ 是 → Cilium
  └─ 否 → Calico 即可

总结：
  - 简单场景：Flannel
  - 标准生产：Calico
  - 高端生产：Cilium
```

## 十三、核心要点速记

### 一句话定位

- **Flannel**：最简、零策略、学习/开发用
- **Calico**：生产最稳、NetworkPolicy 完整、配合 BGP 可对接物理网络
- **Cilium**：性能/可观测/服务网格一体化，新集群首选

### 决策速记

```
生产不知道选啥 → Calico
新集群能升内核 + 想要最强 → Cilium
学习/dev → Flannel
裸金属 + BGP 网络 → Calico
需要 L7/可观测 → Cilium
```

### 关键参数对比

| 参数 | Flannel | Calico | Cilium |
|------|---------|--------|--------|
| 数据面 | vxlan | vxlan/ipip/无封装/eBPF | eBPF |
| NetworkPolicy | ❌ | ✅ K8s 事实标准 | ✅ K8s + 扩展 |
| 可观测 | 无 | 弱 | Hubble（强） |
| 性能 | 中 | 高 | 最高 |
| BGP | ❌ | ✅ | ❌ |
| 内核要求 | 3.10+ | 3.10+ | 5.10+ |
| 资源占用 | 极低 | 中 | 中 |
| L7 策略 | ❌ | Enterprise | ✅ |

### 性能对比速记

```
跨节点延迟：
  Flannel vxlan：~70μs
  Calico iptables：~50μs
  Calico eBPF：~30μs
  Cilium eBPF：~25μs（最快）

Service LB（10000 service）：
  iptables：~50μs（性能下降）
  Cilium eBPF：~10μs（性能平稳）

Policy 匹配（10,000 条）：
  Calico iptables：~50-100μs
  Cilium eBPF：~10μs（10x 优势）
```

### 一句话选型

```
Flannel = 最简 CNI，无策略（开发学习）
Calico = 生产最稳，NetworkPolicy 完整（标准生产）
Cilium = eBPF 数据面，性能/可观测/L7 一流（高端生产）
```
