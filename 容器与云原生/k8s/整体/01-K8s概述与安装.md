# K8s 概述与安装 (Kubernetes Overview & Installation)

> 本章系统讲解 Kubernetes 的起源、特点、应用场景、各类安装方式与生产集群部署。

## 一、K8s 简介

### 1.1 起源

**Kubernetes** (K8s) 是 Google 开源的容器编排平台,前身是 Google 内部大规模集群管理系统 **Borg** 和 **Omega**。

```text
发展时间线:
   2003-2013: Google Borg (生产环境管理数十亿容器)
   2013      : Omega (Borg 的继任者)
   2014.06   : Google 发布 Kubernetes 1.0
   2015.07   : 成立 CNCF, K8s 成为首个项目
   2018      : K8s 从 CNCF 毕业
   现在      : 业界容器编排事实标准, 主导云原生
```

**三位创始人**:
- **Joe Beda** (前 Google)
- **Brendan Burns** (Google)
- **Craig McLuckie** (Google)

**名字由来**: Kubernetes 源自希腊语 κυβερνήτης (kubernétēs,意为"舵手/飞行员")。**K8s** 是中间的 8 个字母被省略的缩写。

### 1.2 核心特点

```text
1. 自动装箱 (Auto-scheduling)
   - 资源需求自动调度
   - 约束条件 (亲和/反亲和)
   
2. 自我修复 (Self-healing)
   - 容器崩溃自动重启
   - 节点故障自动迁移
   - 失败部署自动回滚
   
3. 水平扩展 (Horizontal Scaling)
   - 一键扩缩 Pod 副本
   - 自动 HPA (基于 CPU/内存/自定义指标)
   - 集群自动扩缩 (Cluster Autoscaler)
   
4. 服务发现与负载均衡
   - 内置 DNS (CoreDNS)
   - Service IP 自动分配
   - 多种负载均衡策略
   
5. 自动滚动升级与回滚
   - 一键升级
   - 灰度发布 (蓝绿/金丝雀)
   - 一键回滚到上一版本
   
6. 密钥与配置管理
   - ConfigMap (配置)
   - Secret (密钥)
   - 加密存储
   
7. 存储编排
   - 自动挂载存储系统
   - 本地/云存储/网络存储
   - PV/PVC 抽象
   
8. 批处理 (Batch)
   - Job (一次性任务)
   - CronJob (定时任务)
```

### 1.3 应用场景

| 场景 | 说明 |
|------|------|
| **微服务架构** | 服务发现、负载均衡、熔断、灰度 |

## 二、版本演进

### 版本历史

| 版本 | 发布时间 | 主要特性 |
|------|---------|---------|
| v1.0 | 2014.06 | 第一个 GA 版本 |
| v1.5 | 2017 | StatefulSet、PodDisruptionBudget |
| v1.6 | 2017 | RBAC 稳定 |
| v1.10 | 2018 | 外部 etcd、外部 DNS |
| v1.14 | 2019 | Windows 节点 GA |
| v1.16 | 2019 | CRD v1 GA |
| v1.20 | 2020 | Docker Shim 弃用 |
| v1.22 | 2021 | 移除 Dockershim,containerd 成为默认 |
| v1.24 | 2022 | Beta 版本不再支持 Dockershim |
| v1.27 | 2023 | Sidecar Containers GA |
| v1.28 | 2023 | nftables backend beta |
| v1.30 | 2024 | 性能优化、安全增强 |

### 版本支持策略

```text
- 上游版本: 最新 3 个次版本
- 例: 当前 v1.30 发布,则 v1.30、v1.29、v1.28 受支持
- Kubernetes 每 4 个月发布一个次版本
- 每个次版本约 9 个月(3 个版本 × 3 个月)维护期
- 之后升级到下个版本
```

### 3.2 minikube (本地开发)

```bash
# 安装 minikube
brew install minikube  # macOS
# 或
curl -LO https://storage.googleapis.com/minikube/releases/latest/minikube-linux-amd64
sudo install minikube-linux-amd64 /usr/local/bin/minikube

# 启动集群 (单节点)
minikube start --driver=docker --cpus=2 --memory=4g

# 验证
minikube status
kubectl get nodes

# 启动 Dashboard
minikube dashboard
```

### 3.3 kind (本地/CI 测试)

```bash
# 安装 kind
brew install kind  # macOS
# 或
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.20.0/kind-linux-amd64
chmod +x ./kind
mv ./kind /usr/local/bin/kind

# 创建集群
kind create cluster --name my-cluster

# 多节点集群
cat << EOF > kind-config.yaml
kind: Cluster
apiVersion: kind.x-k8s.io/v1alpha4
nodes:
- role: control-plane
- role: control-plane
- role: control-plane
- role: worker
- role: worker
EOF

kind create cluster --config kind-config.yaml --name ha-cluster

# 加载本地镜像
kind load docker-image myapp:1.0
```

### 3.4 k3s (轻量级 K8s)

```bash
# 一行命令安装
curl -sfL https://get.k3s.io | sh -

# 查看状态
sudo k3s kubectl get nodes

# 配置 kubectl
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config

# 卸载
/usr/local/bin/k3s-uninstall.sh
```

### 3.5 kubeadm (生产推荐)

#### 环境准备(所有节点)

```bash
# 1. 关闭 swap
sudo swapoff -a
sudo sed -i '/ swap / s/^\(.*\)$/#\1/g' /etc/fstab

# 2. 加载内核模块
cat << EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

# 3. 配置 sysctl
cat << EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system

# 4. 安装 containerd
sudo apt install -y containerd
sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl restart containerd

# 5. 安装 kubeadm/kubelet/kubectl
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl
curl -fsSL https://pkgs.k8s.io/core:/stable/v1.30/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg
echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable/v1.30/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl
```

#### 初始化 Master 节点

```bash
# 1. 初始化 (单 Master)
sudo kubeadm init \
  --apiserver-advertise-address=10.0.0.10 \
  --control-plane-endpoint=10.0.0.10 \
  --pod-network-cidr=192.168.0.0/16 \
  --service-cidr=10.96.0.0/12 \
  --kubernetes-version=v1.30.0 \
  --image-repository registry.aliyuncs.com/google_containers

# 2. 配置 kubectl
mkdir -p $HOME/.kube
sudo cp -f /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config

# 3. 验证
kubectl get nodes
kubectl get pods -n kube-system

# 4. 加入其他 Master (HA 模式)
sudo kubeadm init --control-plane ...
# 其他 Master 加入:
sudo kubeadm join 10.0.0.10:6443 --token xxx \
  --discovery-token-ca-cert-hash sha256:xxx \
  --control-plane

# 5. Worker 节点加入
sudo kubeadm join 10.0.0.10:6443 --token xxx \
  --discovery-token-ca-cert-hash sha256:xxx
```

#### 安装 CNI 网络插件

```bash
# Calico (推荐生产)
kubectl apply -f https://docs.projectcalico.org/manifests/calico.yaml

# 或 Flannel (轻量)
kubectl apply -f https://raw.githubusercontent.com/coreos/flannel/master/Documentation/kube-flannel.yml

# 验证
kubectl get pods -n kube-system
# 应该看到 calico/flannel Pod 都是 Running
```

#### 安装 Metrics Server

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

# 验证
kubectl top nodes
kubectl top pods -n kube-system
```

### 3.6 高可用集群(3 Master)

```bash
# 第一个 Master
sudo kubeadm init \

  --upload-certs \
```

## 四、Dashboard (Web UI)

### 安装 Dashboard

```bash
# 安装最新 Dashboard
kubectl apply -f https://raw.githubusercontent.com/kubernetes/dashboard/v2.7.0/aio/deploy/recommended.yaml

# 创建 admin 用户
cat << EOF | kubectl apply -f -
apiVersion: v1
kind: ServiceAccount
metadata:
  name: admin-user
  namespace: kubernetes-dashboard
---
apiVersion: v1
kind: Secret
type: kubernetes.io/service-account-token
metadata:
  name: admin-user-token
  namespace: kubernetes-dashboard
  annotations:
    kubernetes.io/service-account.name: admin-user
---
apiVersion: rbac.authorization.k8s.io/v1
kind: ClusterRoleBinding
metadata:
  name: admin-user
roleRef:
  apiGroup: rbac.authorization.k8s.io
  kind: ClusterRole
  name: cluster-admin
subjects:
- kind: ServiceAccount
  name: admin-user
  namespace: kubernetes-dashboard
EOF

# 获取 token
kubectl -n kubernetes-dashboard get secret admin-user-token -o jsonpath="{.data.token}" | base64 --decode

# 启动代理
kubectl proxy
# 访问 https://localhost:8001/api/v1/namespaces/kubernetes-dashboard/services/https:kubernetes-dashboard:/proxy/
```

## 五、第一个应用部署

### 部署 Nginx

```bash
# 创建 deployment
kubectl create deployment nginx --image=nginx:1.25

# 查看
kubectl get deployments
kubectl get pods -l app=nginx

# 暴露端口
kubectl expose deployment nginx --port=80 --type=NodePort

# 查看 Service
kubectl get service nginx

# 访问测试 (使用 NodePort)
# kubectl get nodes -o wide 查 IP
# curl http://<node-ip>:<nodeport>

# 清理
kubectl delete deployment nginx
kubectl delete service nginx
```

### 使用 YAML 部署

```yaml
# nginx-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.25
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 500m
            memory: 256Mi
```

```yaml
# nginx-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx
spec:
  type: ClusterIP
  selector:
    app: nginx
  ports:
  - port: 80
    targetPort: 80
```

```bash
# 部署
kubectl apply -f nginx-deployment.yaml
kubectl apply -f nginx-service.yaml

# 查看
kubectl get all -l app=nginx

# 端口转发本地测试
kubectl port-forward deployment/nginx 8080:80

# 删除
kubectl delete -f nginx-deployment.yaml
kubectl delete -f nginx-service.yaml
```

## 六、版本升级

### 升级 kubeadm 集群

```bash
# 1. 查看当前版本
kubectl version

# 2. 升级 kubeadm (Master 节点)
sudo apt-get update
sudo apt-get install -y kubeadm=1.30.0-1.30

# 3. 查看升级计划
sudo kubeadm upgrade plan

# 4. 应用升级
sudo kubeadm upgrade apply v1.30.0

# 5. 升级 kubelet 和 kubectl
sudo apt-get install -y kubelet=1.30.0-1.30 kubectl=1.30.0-1.30
sudo systemctl restart kubelet

# 6. Worker 节点升级(逐个)
# 先驱逐
kubectl drain <worker-node> --ignore-daemonsets

# 在 worker 节点升级
sudo apt-get install -y kubelet=1.30.0-1.30 kubeadm=1.30.0-1.30
sudo kubeadm upgrade node
sudo systemctl restart kubelet

# 解除保护
kubectl uncordon <worker-node>
```

## 核心要点速记

### K8s 是什么

- **Kubernetes** = 容器编排平台,源自 Google Borg
- K8s 缩写:K + 8 个字母 + s
- CNCF 第一个毕业项目
- 容器编排事实标准,市场份额 80%+

### 核心特点

```text
- 自动装箱 + 调度
- 自我修复 (重启/迁移/替换)
- 水平扩展 (HPA)
- 服务发现 + 负载均衡
- 滚动升级 + 回滚
- 密钥 + 配置管理
- 存储编排
- 批处理 (Job/CronJob)
```

### 安装选型

```text
本地开发:  minikube / kind / Docker Desktop
生产轻量:  k3s / KubeSphere
生产标准:  kubeadm (二进制)
托管服务:  EKS / GKE / AKS / ACK / TKE
```

### kubeadm 部署流程

```text
1. 准备环境 (swap off / 内核模块 / sysctl / containerd)
2. 安装 kubeadm/kubelet/kubectl
3. kubeadm init (Master)
4. 安装 CNI (Calico/Flannel)
5. 安装 Metrics Server
6. kubeadm join (其他节点)
7. 安装 Dashboard
8. 部署第一个应用
```

### 版本支持

- 当前最新 3 个次版本受支持
- 每 4 个月发版
- 建议生产用 N-1 版本(稳定)

### 生产环境最低配置

```text
Master 节点: 3 台 (HA), 2 CPU 4GB+
Worker 节点: 3+ 台, 4 CPU 16GB+
网络:        万兆, 同机房
存储:        SSD, 预留 100GB+ 给 docker/kubelet
```
