# 监控、日志与可观测性 (Observability)

> 本章系统讲解 K8s 集群的可观测性:监控指标 (Metrics)、日志 (Logs)、链路追踪 (Tracing)。

## 一、可观测性三大支柱

### 1.1 三大支柱

```text
可观测性 = Metrics + Logs + Traces

┌──────────────────┐
│   Metrics (指标)  │  数值化、可聚合、用于告警与趋势分析
│   - CPU/内存       │  例: container_cpu_usage_seconds_total
│   - QPS / 延迟     │  Prometheus + Grafana
└──────────────────┘

┌──────────────────┐
│   Logs (日志)      │  离散事件、用于问题排查
│   - 应用日志        │  例: 2026-08-18 10:00:00 ERROR ...
│   - 系统日志        │  EFK/PLG (Elasticsearch/Prometheus)
└──────────────────┘

┌──────────────────┐
│   Traces (链路追踪) │  请求在分布式系统中的完整路径
│   - 调用链          │  例: trace 100% / span 50ms
│   - 性能瓶颈定位     │  Jaeger / Zipkin / Tempo
└──────────────────┘
```

### 1.2 K8s 可观测性挑战

```text
1. Pod 是动态的 (IP 变化、漂移)
2. 容器是临时的 (日志丢失)
3. 资源是分布式的 (多个节点、多个容器)
4. 微服务调用链复杂

解决方案:
- Prometheus + Grafana (Metrics)
- Loki / EFK (Logs)
- Jaeger / Tempo (Traces)
- OpenTelemetry (统一采集)
```

## 二、Metrics (Prometheus + Grafana)

### 2.1 Prometheus 概述

**Prometheus** 是 CNCF 毕业项目,K8s 监控事实标准。

```text
Prometheus 特点:
1. 时序数据库 (TSDB)
2. Pull 模型 (主动拉取)
3. PromQL 查询语言
4. 强大的告警规则 (Alertmanager)
5. 与 K8s 完美集成
```

### 2.2 Prometheus 安装

```bash
# 添加仓库
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# 创建命名空间
kubectl create namespace monitoring

# 安装 kube-prometheus-stack (推荐,包含 Grafana)
helm install prometheus prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set prometheus.prometheusSpec.retention=30d \
  --set prometheus.prometheusSpec.storageSpec.volumeClaimTemplate.spec.resources.requests.storage=50Gi

# 查看
kubectl get pods -n monitoring
```

### 2.3 Prometheus 监控 K8s 架构

```text
┌──────────────────────────────────────┐
│ Prometheus (主)                       │
│   - 拉取各 exporter 指标            │
│   - 存储到 TSDB                     │
│   - 评估告警规则                     │
└─────────┬────────────────────────────┘
          │ pull (HTTP)
          ↓
┌──────────────────────────────────────┐
│ 各 Exporter / 监控组件                │
│   - node-exporter (节点)              │
│   - kube-state-metrics (K8s 资源)     │
│   - cAdvisor (容器, kubelet 内置)    │
│   - 应用 exporter (自定义)           │
└──────────────────────────────────────┘
```

### 2.4 核心 Exporter

| Exporter | 作用 | 部署 |
|---------|------|------|
| **node-exporter** | 节点指标 (CPU/内存/磁盘/网络) | DaemonSet,每节点一个 |
| **kube-state-metrics** | K8s 资源状态 | Deployment |
| **cadvisor** | 容器指标 | kubelet 内置 |
| **blackbox-exporter** | 黑盒探测 (HTTP/TCP/ICMP) | Deployment |
| **pushgateway** | 短任务指标推送 | Deployment |
| **应用 exporter** | 自定义应用指标 | Sidecar |

### 2.5 ServiceMonitor (CRD)

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: my-app-monitor
  namespace: monitoring
  labels:
    release: prometheus       # 匹配 Prometheus 选择器
spec:
  selector:
    matchLabels:
      app: my-app
  endpoints:
  - port: http                # Service 端口名
    path: /metrics            # 指标路径
    interval: 30s             # 拉取间隔
    scrapeTimeout: 10s
  namespaceSelector:           # 监控命名空间
    any: true
```

### 2.6 PodMonitor (CRD)

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PodMonitor
metadata:
  name: my-app-pod-monitor
  namespace: monitoring
  labels:
    release: prometheus
spec:
  selector:
    matchLabels:
      app: my-app
  podMetricsEndpoints:
  - port: metrics              # 容器端口名
    path: /metrics
    interval: 30s
```

### 2.7 关键 K8s 监控指标

```text
# 节点指标 (node-exporter)
node_cpu_seconds_total
node_memory_MemTotal_bytes
node_filesystem_avail_bytes
node_network_receive_bytes_total

# 容器指标 (cAdvisor)
container_cpu_usage_seconds_total
container_memory_usage_bytes
container_network_receive_bytes_total

# K8s 资源 (kube-state-metrics)
kube_pod_info
kube_pod_status_phase
kube_node_info
kube_deployment_status_replicas
kube_pod_container_resource_requests

# 应用指标 (自定义)
http_requests_total
http_request_duration_seconds
app_orders_total
```

### 2.8 PromQL 查询示例

```promql
# 节点 CPU 使用率 (%)
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 内存使用率
(1 - (node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes)) * 100

# Pod 重启次数
increase(kube_pod_container_status_restarts_total[1h])

# 每个命名空间的 Pod 数
count by(namespace) (kube_pod_info)

# Deployment 副本未就绪
kube_deployment_status_replicas_unavailable

# 99th 百分位延迟
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))
```

### 2.9 告警规则

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: k8s-alerts
  namespace: monitoring
  labels:
    release: prometheus
spec:
  groups:
  - name: k8s.rules
    rules:
    # 高 CPU 使用率
    - alert: HighCPUUsage
      expr: 100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100) > 80
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "High CPU usage on {{ $labels.instance }}"
        description: "CPU usage is {{ $value }}%"

    # Pod 频繁重启
    - alert: PodCrashLooping
      expr: rate(kube_pod_container_status_restarts_total[10m]) > 0
      for: 5m
      labels:
        severity: critical
      annotations:
        summary: "Pod {{ $labels.pod }} is crash looping"

    # 节点 NotReady
    - alert: NodeNotReady
      expr: kube_node_status_condition{condition="Ready",status="true"} == 0
      for: 5m
      labels:
        severity: critical

    # 磁盘空间不足
    - alert: DiskSpaceLow
      expr: (node_filesystem_avail_bytes{mountpoint="/"} / node_filesystem_size_bytes{mountpoint="/"}) * 100 < 10
      for: 10m
      labels:
        severity: warning
```

## 四、Logs (Loki + Promtail)

### 4.1 Loki 概述

**Loki** 是 Grafana Labs 推出的日志聚合系统,类似 Prometheus 但用于日志。

```text
Loki 特点:
1. 不索引全文,只索引 labels (类 Prometheus)
2. 与 Grafana 深度集成
3. 用 LogQL 查询
4. 轻量,水平扩展
5. 与 Prometheus 共享 dashboard
```

### 4.2 Loki + Promtail 架构

```text
┌──────────────┐    push     ┌─────────────┐
│  Promtail    │ ────────→  │    Loki     │
│  (DaemonSet) │             │  (存储)     │
└──────┬───────┘             └──────┬──────┘
       │                            │ query
       │ 读 /var/log / /var/lib/...  │
       ↓                            ↓
   ┌──────────────────────────────────┐
   │           Grafana                 │
   │  Logs / Metrics / Traces 统一面板 │
   └──────────────────────────────────┘
```

### 4.3 Loki 安装

```bash
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update

helm install loki grafana/loki-stack \
  --namespace logging \
  --create-namespace \
  --set promtail.enabled=true \
  --set loki.persistence.enabled=true \
  --set loki.persistence.size=50Gi
```

### 4.4 Promtail 配置

```yaml
# promtail values.yaml (Helm)
config:
  snippets:
    commonLabels:
      cluster: production

  pipelineStages:
  - docker: {}
  - cri: {}

scrapeConfigs:
- job_name: kubernetes-pods
  kubernetes_sd_configs:
  - role: pod
  relabel_configs:
  - source_labels: [__meta_kubernetes_pod_label_app]
    target_label: app
  - source_labels: [__meta_kubernetes_namespace]
    target_label: namespace
  - source_labels: [__meta_kubernetes_pod_name]
    target_label: pod
```

### 4.5 LogQL 查询示例

```logql
# 查询应用日志
{app="my-app", namespace="production"}

# 错误日志
{app="my-app"} |= "ERROR"

# 正则匹配
{app="my-app"} |~ "out of memory"

# 统计错误数
sum(rate({app="my-app"} |= "ERROR" [5m]))

# Top 10 错误信息
topk(10, sum by(message) (count_over_time({app="my-app"} |= "ERROR" [1h])))
```

## 五、EFK (Elasticsearch + Fluentd + Kibana) 备选

### 5.1 EFK 架构

```text
┌──────────────┐    push     ┌──────────────────┐
│  Fluentd     │ ────────→  │  Elasticsearch   │
│  (DaemonSet) │             │  (全文索引)       │
└──────────────┘             └────────┬─────────┘
                                       │
                                       ↓ query
                                  ┌─────────┐
                                  │  Kibana  │
                                  └─────────┘
```

### 5.2 EFK vs Loki 对比

| 维度 | EFK | Loki |
|------|-----|------|
| 全文搜索 | ✅ 强 | ❌ 弱 (只 label) |
| 资源占用 | 重 | 轻 |
| 运维复杂度 | 高 | 低 |
| 与 Grafana 集成 | 一般 | 极好 |
| 成本 | 高 | 低 |
| 推荐 | 复杂日志查询 | K8s 应用日志 |

## 六、Traces (Jaeger / Tempo)

### 6.1 Jaeger 概述

**Jaeger** 是 CNCF 毕业项目,源自 Uber,用于分布式链路追踪。

```text
Jaeger 特点:
1. OpenTracing / OpenTelemetry 兼容
2. 分布式上下文传播
3. 调用链可视化
4. 性能瓶颈定位
```

### 6.2 部署 Jaeger

```bash
# Jaeger Operator
helm install jaeger jaegertracing/jaeger-operator \
  --namespace observability --create-namespace

# 创建 Jaeger 实例
cat << EOF | kubectl apply -f -
apiVersion: jaegertracing.io/v1
kind: Jaeger
metadata:
  name: simplest
  namespace: observability
EOF
```

### 6.3 应用接入 Jaeger

```yaml
# OpenTelemetry Collector Config
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

exporters:
  jaeger:
    endpoint: jaeger-collector.observability:14250
```

应用代码 (Java):

```java
// OpenTelemetry SDK
OpenTelemetrySdk sdk = OpenTelemetrySdk.builder()
    .setTracerProvider(
        SdkTracerProvider.builder()
            .addSpanProcessor(BatchSpanProcessor.builder(
                OtlpGrpcSpanExporter.builder()
                    .setEndpoint("http://otel-collector:4317")
                    .build()).build())
            .build())
    .build();
```

### 6.4 Tempo (Grafana 推荐)

```text
Grafana Tempo 是新一代分布式追踪后端:
- 与 Grafana 深度集成
- 支持 Jaeger/Zipkin/OpenTelemetry 协议
- 对象存储后端 (S3/GCS)
- 与 Loki/Prometheus 联动 (Trace + Logs + Metrics)

安装:
  helm install tempo grafana/tempo
```

## 核心要点速记

### 可观测性三大支柱

```text
Metrics - Prometheus + Grafana
Logs    - Loki + Promtail (或 EFK)
Traces  - Jaeger / Tempo + OpenTelemetry
```

### K8s 监控栈

```text
kube-state-metrics → Prometheus → Grafana
Promtail (DaemonSet) → Loki → Grafana
OTel Collector → Tempo/Jaeger → Grafana
```

### 关键 Exporter

```text
node-exporter       - 节点指标
kube-state-metrics  - K8s 资源
cAdvisor           - 容器 (kubelet 内置)
blackbox-exporter   - 黑盒探测
应用 exporter       - 自定义
```

### PromQL 速查

```promql
sum(rate(http_requests_total[5m]))                       # QPS
histogram_quantile(0.99, sum(...))                       # P99
count by(namespace) (kube_pod_info)                      # 各命名空间 Pod
rate(kube_pod_container_status_restarts_total[10m])      # 重启率
```

### LogQL 速查

```logql
{app="my-app"}                # 某应用日志
{app="my-app"} |= "ERROR"     # 错误日志
{app="my-app"} |~ "regex"     # 正则
sum(rate({app="my-app"} |= "ERROR" [5m]))  # 错误率
```

### 监控分层

```text
基础设施 (node-exporter) → 容器 (cAdvisor) → K8s 资源 (kube-state-metrics) → 应用 (自定义)
                                    ↓
                              Prometheus 聚合
                                    ↓
                          Grafana 可视化 + Alertmanager 告警
```

### 黄金指标 (RED)

```text
Rate     - 每秒请求数 (QPS)
Errors   - 错误数 / 错误率
Duration - 响应时间 (P50/P99/P999)
```

### 黄金信号 (USE)

```text
Utilization - 资源使用率
Saturation  - 饱和度 (队列长度)
Errors      - 错误事件
```
