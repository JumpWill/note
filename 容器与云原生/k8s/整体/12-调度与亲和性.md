# 调度与亲和性 (Scheduling & Affinity)

> 本章系统讲解 K8s 的 Pod 调度机制:节点选择、亲和性、污点容忍、优先级、抢占等。

## 一、K8s 调度概述

### 1.1 调度流程

```text
Pod 创建 → kube-scheduler 调度 → 选定 Node → kubelet 启动

调度过程:
1. 预选 (Filtering): 排除不满足条件的节点
   - 资源需求
   - 节点选择器
   - 亲和/反亲和
   - 污点容忍
   
2. 打分 (Scoring): 为剩余节点打分
   - 资源利用均衡
   - 亲和性偏好
   - 已有 Pod 分布
   
3. 选定: 最高分节点
4. 绑定: 写 spec.nodeName
```

### 1.2 调度器配置

```yaml
# kube-scheduler-config (1.18+)
apiVersion: kubescheduler.config.k8s.io/v1beta3
kind: KubeSchedulerConfiguration
profiles:
- schedulerName: default-scheduler
  plugins:
    queueSort:
      enabled:
      - name: PrioritySort
    preFilter:
      enabled:
      - name: NodeResourcesFit
    filter:
      enabled:
      - name: NodeUnschedulable
      - name: NodeName
      - name: NodeAffinity
      - name: NodeResourcesFit
      - name: VolumeRestrictions
    score:
      enabled:
      - name: NodeResourcesFit
      - name: NodeAffinity
      - name: TaintToleration
```

## 二、节点选择器 (nodeSelector)

### 2.1 节点标签

```bash
# 给节点打标签
kubectl label nodes node1 disktype=ssd
kubectl label nodes node2 disktype=hdd
kubectl label nodes node1 zone=us-east-1a
kubectl label nodes node2 zone=us-east-1b

# 查看节点标签
kubectl get nodes --show-labels
```

### 2.2 nodeSelector

```yaml
spec:
  nodeSelector:
    disktype: ssd               # 必须匹配
    zone: us-east-1a            # 多条件 AND
```

简单但功能有限。

## 三、Node Affinity (节点亲和性)

### 3.1 概念

Node Affinity 是 nodeSelector 的增强版,支持:
- 必须满足 (required)
- 优先满足 (preferred)
- 多种操作符 (In, NotIn, Exists, DoesNotExist, Gt, Lt)

### 3.2 完整示例

```yaml
spec:
  affinity:
    nodeAffinity:
      # 硬要求 (调度失败则 Pending)
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          # 必须运行在 Linux
          - key: kubernetes.io/os
            operator: In
            values: ["linux"]
          # 不能在 us-east-1b
          - key: zone
            operator: NotIn
            values: ["us-east-1b"]
        # 第二个 term (OR 关系)
        - matchExpressions:
          # 或者是 arm64
          - key: kubernetes.io/arch
            operator: In
            values: ["arm64"]

      # 软偏好 (评分,不强制)
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 80                 # 1-100
        preference:
          matchExpressions:
          - key: disktype
            operator: In
            values: ["nvme-ssd"]    # 优先 NVMe SSD

      - weight: 20
        preference:
          matchExpressions:
          - key: zone
            operator: In
            values: ["us-east-1a"]
```

### 3.3 操作符

```text
In              - 在列表中
NotIn          - 不在列表中
Exists         - key 存在 (不管 value)
DoesNotExist   - key 不存在
Gt             - 大于 (数值)
Lt             - 小于 (数值)
```

## 四、Pod Affinity / Anti-Affinity

### 4.1 概念

根据**其他 Pod 的标签**决定调度,而非节点标签。

```text
适用场景:
- 把相关 Pod 调度到同一节点 (缓存亲和)
- 把相同 Pod 分散到不同节点 (高可用反亲和)
```

### 4.2 Pod Affinity (亲和)

```yaml
spec:
  affinity:
    podAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchLabels:
            app: cache             # 与 cache 应用同节点
            tier: backend
        topologyKey: kubernetes.io/hostname   # 同一节点
        namespaces:
        - production

      # 或 preferred
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app: db
          topologyKey: kubernetes.io/hostname
```

### 4.3 Pod Anti-Affinity (反亲和)

```yaml
spec:
  affinity:
    podAntiAffinity:
      # 硬要求: 不要与 cache 同节点
      requiredDuringSchedulingIgnoredDuringExecution:
      - labelSelector:
          matchLabels:
            app: cache
        topologyKey: kubernetes.io/hostname

      # 软偏好: 尽量分散到不同可用区
      preferredDuringSchedulingIgnoredDuringExecution:
      - weight: 100
        podAffinityTerm:
          labelSelector:
            matchLabels:
              app: web
          topologyKey: topology.kubernetes.io/zone
```

### 4.4 topologyKey

```text
常用的 topologyKey:
- kubernetes.io/hostname         # 单个节点
- topology.kubernetes.io/zone    # 可用区
- topology.kubernetes.io/region  # 地域
- 自定义标签                     # 节点机房等
```

### 4.5 实战:Web 三副本分散

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:1.25

      affinity:
        # 软反亲和: 尽量分散到不同节点
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchLabels:
                  app: web
              topologyKey: kubernetes.io/hostname
```

## 五、Taints 与 Tolerations (污点)

### 5.1 概念

```text
Taint (污点): 节点上的"拒绝标记"
Toleration (容忍): Pod 上"忍受"污点的声明

工作原理:
- 节点有 Taint → 默认 Pod 不会调度到该节点
- Pod 有 Toleration → 可以调度到该节点 (匹配污点)

使用场景:
1. 专用节点 (GPU、SSD)
2. 隔离环境 (master 节点不调度业务 Pod)
3. 节点维护 (cordon + drain)
```

### 5.2 Taint 操作

```bash
# 给节点打污点
kubectl taint nodes node1 key=value:NoSchedule

# 三种 effect:
# NoSchedule       - 硬拒绝,绝不调度
# PreferNoSchedule - 软拒绝,尽量不调度
# NoExecute       - 驱逐现有 Pod + 不调度新 Pod

# 去除污点
kubectl taint nodes node1 key=value:NoSchedule-

# 常用污点
kubectl taint nodes node1 node-role.kubernetes.io/master=true:NoSchedule
kubectl taint nodes node1 dedicated=gpu:NoSchedule
kubectl taint nodes node1 environment=production:PreferNoSchedule
```

### 5.3 Toleration 配置

```yaml
spec:
  tolerations:
  - key: "dedicated"
    operator: "Equal"
    value: "gpu"
    effect: "NoSchedule"

  # 容忍所有污点 (不推荐生产)
  - operator: "Exists"

  # 容忍 master 节点
  - key: "node-role.kubernetes.io/master"
    operator: "Exists"
    effect: "NoSchedule"
    tolerationSeconds: 300     # 5 分钟容忍时间
```

### 5.4 实战:GPU 节点

```bash
# GPU 节点打污点
kubectl taint nodes gpu-node-1 gpu=true:NoSchedule
```

```yaml
# GPU Pod 容忍
spec:
  containers:
  - name: ml-training
    image: tensorflow/tensorflow:latest-gpu
    resources:
      limits:
        nvidia.com/gpu: 1       # 申请 1 个 GPU

  tolerations:
  - key: "gpu"
    operator: "Equal"
    value: "true"
    effect: "NoSchedule"

  nodeSelector:
    gpu: "true"                 # 同时指定节点标签
```

### 5.5 节点维护 (cordon / drain)

```bash
# 1. cordon: 标记节点不可调度
kubectl cordon node1
# 节点状态变为 SchedulingDisabled
# 新 Pod 不会调度到该节点
# 现有 Pod 继续运行

# 2. drain: 驱逐 Pod (用于维护)
kubectl drain node1 --ignore-daemonsets
# - 驱逐所有非 DaemonSet Pod
# - 删除 EmptyDir 等本地数据
# - 等 Pod 优雅终止

# 3. uncordon: 恢复调度
kubectl uncordon node1
```

## 六、优先级与抢占

### 6.1 PriorityClass

```yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: high-priority
value: 1000000                  # 数值越高优先级越高
globalDefault: false
description: "High priority workloads"
```

```yaml
# Pod 使用
spec:
  priorityClassName: high-priority
```

### 6.2 内置 PriorityClass

```text
system-cluster-critical     - 3000000000
system-node-critical        - 2000000000
system-kube-controller      - 200000000
system-kube-scheduler       - 200000000
```

### 6.3 抢占 (Preemption)

```text
低优先级 Pod 可能被高优先级 Pod 抢占:
1. 高优先级 Pod 调度失败
2. 抢占低优先级 Pod
3. 被抢占的 Pod 优雅终止 (默认 30s)
4. 高优先级 Pod 调度成功

注意:
- 抢占通过 SIGTERM (30s grace period)
- 业务应用要能优雅处理 SIGTERM
- 默认开启,可在 PriorityClass 中禁用
```

## 七、Pod 拓扑分布约束 (Pod Topology Spread Constraints)

### 7.1 概念

K8s 1.18+ 引入,用于**更细粒度的 Pod 分布控制**(比 anti-affinity 更强)。

```yaml
spec:
  topologySpreadConstraints:
  # 规则 1: 尽量在多个节点
  - maxSkew: 1                     # 最大偏差
    topologyKey: kubernetes.io/hostname
    whenUnsatisfiable: ScheduleAnyway   # 即使不满足也调度
    labelSelector:
      matchLabels:
        app: web

  # 规则 2: 尽量在多个可用区
  - maxSkew: 1
    topologyKey: topology.kubernetes.io/zone
    whenUnsatisfiable: DoNotSchedule
    labelSelector:
      matchLabels:
        app: web
```

### 7.2 与 Anti-Affinity 对比

| 维度 | Anti-Affinity | Topology Spread |
|------|---------------|------------------|
| 粒度 | 二元 (同/不同) | 数值 (maxSkew) |
| 灵活度 | 低 | 高 |
| 多拓扑 | 单一 | 多 (节点 + 区域) |
| 推荐 | 简单场景 | 生产推荐 |

## 八、资源 QoS (服务质量)

### 8.1 QoS 等级

```text
K8s 根据 requests/limits 分配 QoS:

1. Guaranteed (保证)
   - 所有容器都设了 limits (cpu + memory)
   - limits == requests (强烈推荐生产关键服务)

2. Burstable (突发)
   - 设了 requests,但 limits > requests 或没设 limits

3. BestEffort (尽力)
   - 都没设 requests 和 limits

驱逐优先级 (内存压力时):
   BestEffort > Burstable > Guaranteed
```

### 8.2 资源限制建议

```yaml
# Guaranteed 配置 (生产关键服务)
resources:
  requests:
    cpu: 500m
    memory: 512Mi
  limits:
    cpu: 500m             # 严格限速 (CPU 节流)
    memory: 512Mi         # 严格限制 (OOM 风险)

# Burstable 配置 (一般服务)
resources:
  requests:
    cpu: 200m
    memory: 256Mi
  limits:
    cpu: 1000m            # 突发允许
    memory: 1Gi

# BestEffort 配置 (非关键/批处理)
# 不设 requests/limits
```

## 九、调度实战

### 9.1 多可用区高可用

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web-ha
spec:
  replicas: 6
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: web
        image: nginx:1.25

      affinity:
        # 硬反亲和: 同一 Node 不能有 2 个 web
        podAntiAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
          - labelSelector:
              matchLabels:
                app: web
            topologyKey: kubernetes.io/hostname

      topologySpreadConstraints:
      # 软分布: 尽量在不同 Zone
      - maxSkew: 1
        topologyKey: topology.kubernetes.io/zone
        whenUnsatisfiable: ScheduleAnyway
        labelSelector:
          matchLabels:
            app: web
```

### 9.2 节点维护完整流程

```bash
# 1. 标记节点不可调度
kubectl cordon node-1

# 2. 驱逐 Pod (会优雅终止)
kubectl drain node-1 --ignore-daemonsets --delete-emptydir-data
# --ignore-daemonsets: 忽略 DaemonSet
# --delete-emptydir-data: 删除 emptyDir 数据

# 3. 维护操作
ssh node-1 "yum update -y && reboot"

# 4. 节点恢复后,恢复调度
kubectl uncordon node-1

# 5. 验证
kubectl get nodes
kubectl get pods -o wide
```

### 9.3 自定义调度器

```yaml
# 使用自定义调度器
apiVersion: v1
kind: Pod
metadata:
  name: my-pod
spec:
  schedulerName: my-custom-scheduler
  containers:
  - name: app
    image: my-app:1.0
```

```bash
# 查看使用了哪个调度器
kubectl get pod my-pod -o jsonpath='{.spec.schedulerName}'

# 多调度器场景:
# - default-scheduler (默认)
# - my-custom-scheduler (业务调度)
# - spot-scheduler (抢占式实例)
```

## 十、调度性能与扩展性

### 10.1 大规模集群调度优化

```text
10,000+ 节点集群调度优化:

1. 调度器配置
   - percentageOfNodesToScore: 不要默认(会全集群评估)
   - 设置 5-10%, 大幅减少评估节点数

2. 减少非必要调度
   - 静态 Pod (mirror pods)
   - DaemonSet (无需调度)
   - 合理设置 replicas (避免过剩)

3. 预选 (Filtering) 优化
   - 简单 nodeSelector 优于复杂 Affinity
   - 减少不必要的 label 检查

4. 打分 (Scoring) 优化
   - LessAllocated 优先 (资源利用均衡)
   - BalancedAllocation
   - NodeAffinity 优先
```

### 10.2 Scheduler Profile

```yaml
# 多个调度器 Profile
apiVersion: kubescheduler.config.k8s.io/v1beta3
kind: KubeSchedulerConfiguration
profiles:
- schedulerName: default-scheduler

- schedulerName: spot-scheduler
  plugins:
    score:
      enabled:
      - name: NodeResourcesFit   # 优先选择空闲节点
```

## 核心要点速记

### 调度三大手段

```text
1. nodeSelector / NodeAffinity   - 节点级调度
2. Pod Affinity/Anti-Affinity    - Pod 级调度 (其他 Pod 位置)
3. Taints / Tolerations          - 节点拒绝 + Pod 容忍
```

### 调度策略优先级

```text
硬要求 (required) > 软偏好 (preferred)
nodeSelector / nodeAffinity > podAffinity > taints
```

### 实战选型

```text
- 节点池化 → nodeSelector
- 同 Pod 集中 → podAffinity
- 不同 Pod 分散 → podAntiAffinity (硬) / topologySpread (软)
- 专用节点 (GPU) → taints + tolerations
- 多可用区 → topologySpreadConstraints
```

### 节点维护三步

```text
1. cordon   - 标记不可调度
2. drain    - 驱逐现有 Pod
3. uncordon - 恢复调度
```

### 亲和性 vs 反亲和性 vs 拓扑分布

```text
nodeAffinity:
   选择满足条件的节点
podAffinity:
   与某 Pod 同节点 (缓存亲和)
podAntiAffinity:
   与某 Pod 不同节点 (高可用)
topologySpreadConstraints:
   Pod 均匀分布在拓扑域 (推荐)
```

### QoS 三等级

```text
Guaranteed - requests == limits (推荐生产)
Burstable  - requests < limits
BestEffort - 不设 requests/limits
```
