# K8s 故障排查与运维实战 (Troubleshooting)

> 本章系统讲解 K8s 集群常见故障的排查方法、运维工具与实战案例。

## 一、故障排查思路

### 1.1 排查流程

```text
故障现象
   ↓
检查 Pod 状态 (kubectl get pods)
   ↓
Pending? → 资源/调度问题
Running? → 检查应用
Failed? → 容器崩溃
CrashLoopBackOff → 重启循环
   ↓
查看 Pod 详情 (kubectl describe pod)
   ↓
查看 Events (关键!)
   ↓
查看日志 (kubectl logs)
   ↓
进入容器调试 (kubectl exec)
   ↓
检查 Node 状态
   ↓
检查 Control Plane 组件
```

### 1.2 必备工具

```bash
# kubectl (必备)
kubectl get/describe/logs/exec

# kubectx / kubens (多集群切换)
kubectx production
kubens production

# kube-ps1 (Shell 提示符)
source <(kube-ps1)
[PROD/staging] $

# k9s (TUI 工具)
k9s

# Stern (多 Pod 日志聚合)
stern "app-*" --tail 50

# kubectl-neat (清理 YAML)
kubectl neat get pod myapp -o yaml

# kubetail
kubetail -l app=myapp
```

## 二、Pod 常见故障

### 2.1 Pod Pending

**现象**: Pod 一直 Pending,无法调度

**排查**:

```bash
# 查看 Pod 详情 (关注 Events)
kubectl describe pod <pod-name>
```

**常见原因**:

| 原因 | 解决方法 |
|------|---------|
| 资源不足 | 加节点 / 调整 requests |
| 节点选择器不匹配 | 检查 nodeSelector / Affinity |
| 污点无法容忍 | 加 tolerations |
| PVC 未绑定 | 检查 PV 是否充足 |
| 镜像拉取失败 | 检查 imagePullSecrets |

### 2.2 Pod ImagePullBackOff

```bash
kubectl describe pod <pod-name>
# Events: Failed to pull image "myapp:1.0": rpc error: code = Unknown desc = Error response from daemon: pull access denied

# 检查项:
# 1. 镜像名拼写
kubectl get pod <pod-name> -o jsonpath='{.spec.containers[*].image}'

# 2. 私有仓库凭证
kubectl get secret <imagePullSecret>

# 3. 网络问题 (无法访问 Registry)
docker pull myapp:1.0

# 4. 配置私有 Registry
kubectl create secret docker-registry myregistry \
  --docker-server=registry.example.com \
  --docker-username=myuser \
  --docker-password=mypassword
```

### 2.3 Pod CrashLoopBackOff

```bash
# 1. 查看最近日志
kubectl logs <pod-name> --previous
kubectl logs <pod-name> --previous --tail 100

# 2. 常见原因:
# - 容器启动命令错误
# - 应用配置错误 (环境变量、配置文件)
# - 依赖服务未就绪 (DB, Redis)
# - 资源限制 (OOMKilled)
# - 健康检查失败 (livenessProbe)

# 3. 查看 OOMKilled
kubectl describe pod <pod-name>
# Last State: Terminated, Reason: OOMKilled
# 解决方法: 增加 memory limit

# 4. 进入容器调试 (添加新容器)
kubectl debug <pod-name> -it --image=busybox --target=<container-name>
```

### 2.4 Pod Running 但服务不通

```bash
# 1. 检查 readinessProbe
kubectl describe pod <pod-name>
# Conditions: Ready False

# 2. 端口转发本地测试
kubectl port-forward <pod-name> 8080:80

# 3. 检查 Service Endpoints
kubectl get endpoints <service-name>
# 应该显示 Pod IP

# 4. 检查 Service selector
kubectl get svc <service-name> -o yaml
# selector 应匹配 Pod labels

# 5. 测试 Pod 网络
kubectl exec -it <pod-name> -- curl http://target-service
```

### 2.5 Pod Pending (资源不足)

```bash
# 1. 检查节点资源
kubectl describe nodes | grep -A 5 "Allocated resources"

# 2. 检查 Pod requests
kubectl get pod <pod-name> -o jsonpath='{.spec.containers[*].resources.requests}'

# 3. 解决方案:
#    a. 加节点
#    b. 调整 Pod requests (降低)
#    c. 清理不需要的 Pod
#    d. 启用 HPA (HorizontalPodAutoscaler)
```

## 三、Node 故障

### 3.1 Node NotReady

```bash
# 1. 查看 Node 状态
kubectl get nodes
# NAME      STATUS     ROLES    AGE
# node-1    NotReady   worker   10d

# 2. 查看详情
kubectl describe node node-1
# Conditions: Ready False, Message: Kubelet stopped posting node status

# 3. 常见原因:
#    - kubelet 进程崩溃
#    - 节点网络问题
#    - 磁盘满 (kubelet 无法写 /var/lib/kubelet)
#    - 内存耗尽 (kubelet OOM)

# 4. 排查
ssh node-1
sudo systemctl status kubelet
sudo journalctl -u kubelet -f
df -h /var/lib/kubelet
free -h
```

### 3.2 节点磁盘满

```bash
# 1. 查看磁盘使用
kubectl exec -it <pod> -- df -h

# 2. 容器镜像占用
ssh node-1
docker system df
docker image prune -a

# 3. kubelet 日志占用
sudo journalctl --vacuum-size=100M

# 4. 容器日志占用
sudo find /var/log/containers -name "*.log" -size +100M -exec ls -lh {} \;
sudo find /var/log/pods -name "*.log" -size +100M -exec ls -lh {} \;

# 5. 清理已停止的容器
docker container prune
```

### 3.3 节点 OOM

```bash
# 1. 查看系统日志
dmesg | grep -i "out of memory"

# 2. 查看进程内存使用
ps aux --sort=-%mem | head

# 3. kubelet OOM 常见原因:
#    - 系统进程占用过多
#    - 容器密度过高
#    - 每个 Pod 内存 limit 设置过高

# 4. 解决方案:
#    - 减少每个节点 Pod 数
#    - 限制单 Pod 内存
#    - 加节点
```

### 3.4 节点 NotReady 恢复流程

```bash
# 1. 检查节点问题
ssh node-1
sudo systemctl status kubelet
sudo journalctl -u kubelet -n 100

# 2. 尝试重启 kubelet
sudo systemctl restart kubelet

# 3. 等待节点恢复
kubectl get nodes -w

# 4. 如果无法恢复,驱逐 Pod 到其他节点
kubectl drain node-1 --ignore-daemonsets --force

# 5. 修复节点后重新加入
kubectl uncordon node-1
```

## 四、网络故障

### 4.1 Service 无法访问

```bash
# 1. 检查 Service
kubectl get svc
# NAME         TYPE        CLUSTER-IP     PORT
# my-service   ClusterIP   10.96.10.50    80

# 2. 检查 Endpoints
kubectl get endpoints my-service
# 应显示 Pod IP,否则检查 selector

# 3. 测试 DNS 解析 (Pod 内)
kubectl run -it --rm --image=busybox --restart=Never test
# / # nslookup my-service
# / # nslookup my-service.default.svc.cluster.local

# 4. 测试 ClusterIP 连通性
# / # wget -O- http://my-service:80

# 5. 如果不通:
#    - 检查 Pod 状态
#    - 检查 NetworkPolicy
#    - 检查 kube-proxy / CNI
```

### 4.2 Pod 之间无法通信

```bash
# 1. 检查 NetworkPolicy
kubectl get networkpolicy -A

# 2. 检查 Pod label (selector 匹配)
kubectl get pod -l app=my-app --show-labels

# 3. 测试 Pod 到 Pod
kubectl exec -it pod-a -- curl http://pod-b:8080

# 4. 检查 CNI (Calico)
kubectl get pods -n kube-system | grep calico

# 5. 检查节点网络
kubectl exec -it pod-a -- ping <pod-b-ip>

# 6. 检查 Service ClusterIP 范围
#    ClusterIP range 是 10.96.0.0/12 (默认)
#    Pod CIDR 是 192.168.0.0/16 (默认)
#    不能重叠!
```

### 4.3 Ingress 502/504 错误

```bash
# 1. 查看 Ingress Controller 日志
kubectl logs -f <nginx-ingress-pod> -n ingress-nginx

# 2. 检查后端 Service
kubectl get svc <service-name>
kubectl get endpoints <service-name>

# 3. 端口转发测试后端
kubectl port-forward <pod-name> 8080:80
curl http://localhost:8080

# 4. 常见 502 原因:
#    - 后端 Pod 未运行
#    - Service selector 不匹配
#    - 健康检查失败
#    - 端口错误

# 5. 常见 504 原因:
#    - 后端响应超时
#    - nginx.ingress.kubernetes.io/proxy-read-timeout 太小
#    - 后端进程慢
```

## 五、存储故障

### 5.1 PVC Pending

```bash
# 1. 查看 PVC 状态
kubectl get pvc
# STATUS: Pending (持续不变)

# 2. 查看详情
kubectl describe pvc <name>
# Events: failed to provision volume with StorageClass

# 3. 常见原因:
#    - StorageClass 不存在
#    - provisioner 不可用
#    - 集群存储资源不足
#    - 配额不足

# 4. 检查 StorageClass
kubectl get storageclass
```

### 5.2 PV 文件系统只读

```bash
# Pod 日志: Read-only file system

# 1. 进入 Pod 检查
kubectl exec -it <pod> -- df -h

# 2. 常见原因:
#    - 磁盘满 → 删除数据
#    - PV 故障 → 切换到新 PV

# 3. 检查 Node 磁盘
ssh <node>
df -h
```

### 5.3 PV 数据丢失

```text
# 1. 检查是否使用了 hostPath 或 emptyDir
kubectl get pv -o yaml | grep type

# 2. hostPath: 数据存在节点本地,节点故障会丢
#    解决: 改用 NFS / cephFS / 云存储

# 3. emptyDir: Pod 删除即丢失 (正常行为)
```

## 六、Control Plane 故障

### 6.1 API Server 无响应

```bash
# 1. 检查 API Server Pod
kubectl get pods -n kube-system | grep apiserver
# 或
ssh master-1
crictl ps | grep kube-apiserver

# 2. 查看日志
sudo journalctl -u kubelet -f
sudo crictl logs <apiserver-container-id>

# 3. 检查静态 Pod 配置
ls /etc/kubernetes/manifests/

# 4. 静态 Pod 故障恢复
#    API Server 是 kubelet 直接管理的静态 Pod
#    修改 /etc/kubernetes/manifests/kube-apiserver.yaml
#    kubelet 会自动重启 API Server
```

### 6.2 etcd 故障

```bash
# 1. 检查 etcd Pod
kubectl get pods -n kube-system | grep etcd

# 2. 查看 etcd 状态
ETCDCTL_API=3 etcdctl endpoint status \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# 3. 多数 etcd 节点故障 → 集群不可写
#    解决: 恢复故障节点,或从备份恢复

# 4. etcd 数据损坏
#    解决: 从备份恢复
etcdctl snapshot restore /backup/etcd-xxx.db \
  --name=etcd-1 \
  --initial-cluster=... \
  --data-dir=/var/lib/etcd
```

### 6.3 证书过期

```bash
# 1. 查看证书过期时间
kubeadm certs check-expiration

# 输出:
# CERTIFICATE                EXPIRES                  RESIDUAL TIME   CERTIFICATE AUTHORITY
# admin.conf                 May 21, 2027 09:50      364d             ca
# apiserver                  May 21, 2027 09:50      364d             ca
# ...

# 2. 续期所有证书
kubeadm certs renew all
# 重启相关组件 (kubelet 会重启静态 Pod)

# 3. 手动续期
kubeadm certs renew apiserver
```

## 七、应用故障

### 7.1 OOMKilled

```bash
# 现象: 容器重启,describe 显示 OOMKilled

# 1. 查看内存使用
kubectl top pod <pod-name>

# 2. 解决方案:
#    a. 增加 memory limit (但不推荐无限增大)
#    b. 优化应用内存 (内存泄漏)
#    c. 加 JVM 内存参数 (Java 应用)
#    d. 加节点内存

# 3. JVM 应用特殊调优
env:
- name: JAVA_OPTS
  value: "-XX:MaxRAMPercentage=70.0 -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/tmp"

# 4. 健康检查发现内存增长
resources:
  limits:
    memory: 2Gi
  # OOMKilled 时退出码 137
```

### 7.2 健康检查失败

```bash
# 1. 现象: Pod 被 kill 但应用还在

# 2. livenessProbe 失败 → 重启容器
kubectl describe pod <pod-name>
# Events: Killing container with id ...: liveness probe failed

# 3. 解决方法:
#    - 增加 initialDelaySeconds (应用启动慢)
#    - 增加 failureThreshold
#    - 调整超时 timeoutSeconds
#    - 修复应用问题

livenessProbe:
  httpGet:
    path: /health
    port: 8080
  initialDelaySeconds: 60    # 应用启动需要 60s
  periodSeconds: 10
  timeoutSeconds: 5
  failureThreshold: 3         # 3 次失败才重启 (30s 容错)
```

### 7.3 配置错误

```bash
# 1. ConfigMap 错误
kubectl describe cm <name>
kubectl get cm <name> -o yaml

# 2. Secret 错误
kubectl get secret <name>
# base64 解码
echo "xxx" | base64 --decode

# 3. 应用配置查看
kubectl exec -it <pod> -- env | sort
kubectl exec -it <pod> -- cat /etc/config/app.yml

# 4. 配置热更新
kubectl edit cm <name>
# Volume 挂载约 30s 自动更新
```

## 八、运维工具与技巧

### 8.1 k9s (TUI 推荐)

```bash
# 安装
brew install k9s

# 运行
k9s

# 快捷键:
# :po    - 列出 Pod
# :svc   - 列出 Service
# :ns    - 切换 namespace
# /xxx   - 搜索
# d     - describe
# l     - logs
# e     - exec
# y     - yaml
# ?     - 帮助
```

### 8.2 Stern (多 Pod 日志)

```bash
# 安装
brew install stern

# 查看所有 Pod 日志 (匹配 pattern)
stern "app-*" --tail 50
stern "frontend" --since 10m

# 指定 namespace
stern "app-*" -n production

# 多 Pod 按时间排序
stern "app-*" --output json | jq -r '.message' | sort | uniq -c
```

### 8.3 kubectl 高级技巧

```bash
# 批量删除
kubectl delete pods -l app=bad
kubectl delete pods --field-selector=status.phase=Failed

# 强制删除卡住的 Pod
kubectl delete pod <pod> --grace-period=0 --force

# 调试 (1.18+)
kubectl debug <pod> -it --image=busybox

# 临时容器 (1.28+)
kubectl debug -it <pod> --image=busybox --target=<container>

# 端口转发
kubectl port-forward <pod> 8080:80

# 查看日志前 100 行
kubectl logs --tail=100 <pod>

# 实时跟踪多个 Pod
kubectl logs -f -l app=my-app --max-log-requests=5

# exec 到指定容器
kubectl exec -it <pod> -c <container-name> -- bash
```

## 九、紧急故障处理

### 9.1 节点宕机

```bash
# 1. 查看 Node 状态
kubectl get nodes

# 2. 强制驱逐故障节点上的 Pod
kubectl drain node-1 --ignore-daemonsets --force

# 3. 故障节点排查
ssh node-1
sudo systemctl status kubelet docker
dmesg | tail -50
df -h

# 4. 节点恢复后重新加入
kubectl uncordon node-1
```

### 9.2 etcd 故障恢复

```bash
# 1. 立即从备份恢复
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-xxx.db \
  --name=etcd-1 \
  --initial-cluster=etcd-1=https://...,etcd-2=https://...,etcd-3=https://... \
  --initial-advertise-peer-urls=https://10.0.0.11:2380 \
  --data-dir=/var/lib/etcd

# 2. 重启 etcd
sudo systemctl restart etcd

# 3. 重启 kube-apiserver (静态 Pod,kubelet 自动重启)
sudo systemctl restart kubelet

# 4. 验证
kubectl get nodes
```

### 9.3 集群完全崩溃

```bash
# 1. 不要慌张,etcd 备份通常完好
# 2. 重装 Master 节点
# 3. 恢复 etcd 备份
# 4. 加入 Worker 节点
# 5. 恢复应用 (从 Git + Velero)
```

### 9.4 故障检查 Checklist

```text
□ 所有 Node Ready?
□ API Server 响应?
□ etcd 健康?
□ 关键 Pod Running?
□ Service Endpoints 正确?
□ 网络策略正常?
□ 存储可访问?
□ Ingress Controller 正常?
□ 监控告警正常?
□ 最近一次备份?
□ 最近一次演练恢复?
```

## 核心要点速记

### 排查工具速查

```bash
kubectl get pods -A                    # 所有 Pod
kubectl describe pod <pod>             # 详情 + Events
kubectl logs <pod> --previous         # 上次重启日志
kubectl logs -f <pod> -c <container>  # 容器日志
kubectl exec -it <pod> -- bash        # 进入容器
kubectl debug -it <pod> --image=busybox  # 调试容器
kubectl get events --sort-by='.lastTimestamp'  # 集群事件
```

### 常见故障速查

```text
Pod Pending:
  → describe 看 Events
  → 资源不足 / 调度失败

CrashLoopBackOff:
  → logs --previous
  → 应用错误 / 配置错误

ImagePullBackOff:
  → 检查镜像名 / 凭证 / 网络

Service 不通:
  → get endpoints 检查 selector
  → 测试 ClusterIP 连通

PVC Pending:
  → get storageclass
  → 检查 StorageClass 和 provisioner

Node NotReady:
  → 节点 kubelet 状态
  → 磁盘 / 内存 / 网络

API Server 无响应:
  → 静态 Pod 日志
  → kubelet 状态
  → 必要时从 etcd 备份恢复
```

### 调试速记

```bash
# 网络调试
kubectl run -it --rm --image=nicolaka/netshoot --restart=Never test

# 文件系统调试
kubectl debug -it <pod> --image=busybox --target=<container>

# 进程调试
kubectl exec -it <pod> -- ps aux

# 网络连通
kubectl exec -it <pod> -- curl -v http://target

# DNS
kubectl exec -it <pod> -- nslookup my-service
```

### 紧急恢复优先级

```text
1. etcd 备份 (最关键)
2. 证书备份
3. K8s 资源备份 (Velero)
4. 应用数据备份
```
