# K8s 安全最佳实践 (Security Best Practices)

> 本章系统讲解 K8s 安全体系:认证、授权、网络策略、安全上下文、镜像安全、Secret 管理、运行时安全。

## 一、K8s 安全全景

### 1.1 安全四层防护

```text
┌─────────────────────────────────────────┐
│  4. 运行时安全 (Runtime Security)       │
│     - Falco / Tracee / AppArmor         │
│     - seccomp / SELinux                  │
├─────────────────────────────────────────┤
│  3. 镜像安全 (Image Security)            │
│     - 镜像签名验证 (Cosign / Notary)     │
│     - 镜像漏洞扫描 (Trivy / Clair)        │
│     - 最小化基础镜像 (Distroless)        │
├─────────────────────────────────────────┤
│  2. 网络隔离 (Network Isolation)         │
│     - NetworkPolicy                       │
│     - Service Mesh (mTLS)                │
├─────────────────────────────────────────┤
│  1. 访问控制 (Access Control)             │
│     - 认证 (Authentication)               │
│     - 授权 (RBAC)                          │
│     - 准入控制 (Admission Control)          │
└─────────────────────────────────────────┘
```

### 1.2 安全原则

```text
1. 零信任 (Zero Trust)
   - 默认拒绝所有,显式允许

2. 最小权限 (Least Privilege)
   - 只给需要的权限

3. 纵深防御 (Defense in Depth)
   - 多层防护,任何一层失败仍安全

4. 持续验证 (Continuous Verification)
   - 镜像签名、运行时检测
```

## 二、认证 (Authentication)

### 2.1 认证方式

```text
K8s 支持多种认证方式:

1. X.509 客户端证书 (默认, 用于组件和用户)
2. Bearer Token (ServiceAccount)
3. Bootstrap Token (节点引导)
4. OpenID Connect (OIDC) - 集成企业 IDP (推荐)
5. Webhook Token - 自定义认证
6. ServiceAccount Token (Pod 内访问 API Server)
```

### 2.2 X.509 客户端证书

```bash
# 创建用户证书 (OpenSSL)
mkdir -p certs && cd certs

# CA
openssl genrsa -out ca.key 2048
openssl req -x509 -new -nodes -key ca.key -days 3650 -out ca.crt \
  -subj "/CN=k8s-ca"

# 用户密钥
openssl genrsa -out alice.key 2048
openssl req -new -key alice.key -out alice.csr -subj "/CN=alice/O=developers"
openssl x509 -req -in alice.csr -CA ca.crt -CAkey ca.key -CAcreateserial \
  -out alice.crt -days 365

# 创建 kubeconfig
kubectl config set-credentials alice --client-certificate=alice.crt --client-key=alice.key
kubectl config set-context alice-context --cluster=k8s --user=alice
```

### 2.3 OIDC 集成 (推荐生产)

```yaml
# kube-apiserver 配置
spec:
  containers:
  - command:
    - kube-apiserver
    - --oidc-issuer-url=https://accounts.google.com
    - --oidc-client-id=kubernetes
    - --oidc-username-claim=email
    - --oidc-groups-claim=groups
    - --oidc-username-prefix=google:
```

```bash
# 用户使用 OIDC 登录
kubectl oidc login --issuer-url=https://accounts.google.com
```

```text
RBAC 核心:
```

## 四、准入控制 (Admission Control)

### 4.1 概念

```text
准入控制 = API 请求认证/授权之后,持久化之前的拦截器

作用:
- 修改资源 (添加默认字段)
- 验证资源 (拒绝非法)
- 限制资源 (Quota)

K8s 1.30+ 推荐启用:
- NodeRestriction
- PodSecurity (替代旧 PodSecurityPolicy)
- LimitRanger
- ServiceAccount
- DefaultStorageClass
- ResourceQuota
```

### 4.2 PodSecurity (替代 PSP)

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: restricted
    pod-security.kubernetes.io/audit: restricted
    pod-security.kubernetes.io/warn: restricted
```

三个等级:
- **privileged** - 允许所有 (无限制)
- **baseline** - 禁止特权容器、危险能力
- **restricted** - 最严格 (生产推荐)

### 4.3 准入控制 Webhook

```yaml
# 1. 部署 OPA Gatekeeper 或 Kyverno

# 2. 配置 ValidatingAdmissionWebhook
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: pod-must-have-labels
spec:
  failurePolicy: Fail
  rules:
  - apiGroups: [""]
    apiVersions: ["v1"]
    operations: ["CREATE", "UPDATE"]
    resources: ["pods"]
  validations:
  - expression: "object.metadata.labels.app"
    message: "Pod must have 'app' label"
```

### 4.4 OPA Gatekeeper 实战

```bash
# 安装 Gatekeeper
kubectl apply -f https://raw.githubusercontent.com/open-policy-agent/gatekeeper/master/deploy/gatekeeper.yaml

# 创建 ConstraintTemplate
apiVersion: templates.gatekeeper.sh/v1
kind: ConstraintTemplate
metadata:
  name: k8srequiredlabels
spec:
  crd:
    spec:
      names:
        kind: K8sRequiredLabels
      validation:
        openAPIV3Schema:
          properties:
            labels:
              type: object

# 创建 Constraint
apiVersion: constraints.gatekeeper.sh/v1beta1
kind: K8sRequiredLabels
metadata:
  name: pod-must-have-owner
spec:
  match:
    kinds:
    - apiGroups: [""]
      kinds: ["Pod"]
  parameters:
    labels:
    - owner
```

## 五、网络隔离 (NetworkPolicy)

(参见 [06-Service网络.md](06-Service网络.md) 详细文档)

### 5.1 默认拒绝所有

```yaml
# 1. 默认拒绝所有进出流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
---
# 2. 允许 DNS 解析 (所有 Pod 都需要)
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-dns
  namespace: production
spec:
  podSelector: {}
  policyTypes:
  - Egress
  egress:
  - to:
    - namespaceSelector: {}
    ports:
    - protocol: UDP
      port: 53
---
# 3. 允许应用流量
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-app-traffic
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: my-app
  policyTypes:
  - Ingress
  - Egress
  ingress:
  - from:
    - podSelector:
        matchLabels:
          app: nginx
    ports:
    - protocol: TCP
      port: 8080
```

### 5.2 微隔离最佳实践

```text
1. 默认拒绝 (deny-all)
2. 显式允许 (按需)
3. 命名空间隔离 (不同 NS 不同 Policy)
4. 入口流量限制 (Ingress)
5. 出口流量限制 (只允许必要外部服务)
6. K8s API 出口限制 (避免泄露元数据)
```

## 六、安全上下文 (SecurityContext)

### 6.1 Pod 级 SecurityContext

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-pod
spec:
  securityContext:
    # 容器以非 root 用户运行
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 3000
    fsGroup: 2000
    
    # SELinux
    seLinuxOptions:
      level: "s0:c123,c456"
      role: "object_r"
      type: "container_t"
    
    # 内核参数
    sysctls:
    - name: net.core.somaxconn
      value: "1024"
    
    # 补充组
    supplementalGroups: ["4000"]
    
    # Windows 选项
    windowsOptions:
      gmsaCredentialSpecName: my-gmsa

  containers:
  - name: app
    image: my-app:1.0
    securityContext:
      allowPrivilegeEscalation: false
      privileged: false
      readOnlyRootFilesystem: true
      runAsNonRoot: true
      runAsUser: 1000
      capabilities:
        drop:
        - ALL
        add:
        - NET_BIND_SERVICE    # 只添加必要的
      procMount:
        default: DefaultProcMount
```

### 6.2 容器安全三件套

```yaml
securityContext:
  allowPrivilegeEscalation: false   # 1. 禁止提权
  privileged: false                 # 2. 禁止特权模式
  readOnlyRootFilesystem: true       # 3. 根文件系统只读
  capabilities:
    drop: ["ALL"]                   # 删除所有 Linux capabilities
    add: ["NET_BIND_SERVICE"]        # 只添加必要的
```

### 6.3 安全上下文推荐配置

```yaml
# 生产标准安全配置
spec:
  containers:
  - name: app
    image: my-app:1.0
    
    # 资源限制
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 500m
        memory: 256Mi
    
    # 安全上下文
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      runAsNonRoot: true
      runAsUser: 1000
      capabilities:
        drop: ["ALL"]
        add: ["NET_BIND_SERVICE"]
    
    # 探针 (不用 root 不影响)
    livenessProbe:
      httpGet:
        path: /health
        port: 8080
    
    # 只读挂载敏感目录
    volumeMounts:
    - name: secrets
      mountPath: /etc/secrets
      readOnly: true
```

## 七、镜像安全

### 7.1 镜像扫描 (Trivy)

```bash
# 安装 Trivy
brew install trivy  # macOS
# 或 docker
docker run --rm -v /var/run/docker.sock:/var/run/docker.sock aquasec/trivy

# 扫描镜像
trivy image nginx:1.25

# 严重漏洞扫描
trivy image --severity HIGH,CRITICAL nginx:1.25

# 输出示例:
# ================================
# nginx:1.25 (debian 12.4)
# ================================
# Total: 5 (HIGH: 3, CRITICAL: 1)
#
# ┌───────────────┬──────────┬────────┬────────────────┐
# │    Library    │ Vuln ID  │ Status │  Severity      │
# ├───────────────┼──────────┼────────┼────────────────┤
# │ openssl       │ CVE-xxx  │ fixed  │  CRITICAL      │
# └───────────────┴──────────┴────────┴────────────────┘

# 与 K8s 集成 (扫描集群中运行的镜像)
trivy k8s --report summary cluster
```

### 7.2 镜像签名验证 (Cosign)

```bash
# 1. 安装 cosign
brew install cosign

# 2. 给镜像签名
cosign sign --key cosign.key myapp:1.0

# 3. 验证签名
cosign verify --key cosign.pub myapp:1.0

# 4. K8s 准入控制 (拒绝未签名镜像)
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: verify-image-signature
spec:
  rules:
  - operations: ["CREATE", "UPDATE"]
    apiGroups: [""]
    apiVersions: ["v1"]
    resources: ["pods"]
  validations:
  - expression: "request.object.spec.containers.all(c, has(c.image) && c.image.startsWith('registry.example.com/'))"
```

### 7.3 最小化基础镜像

```text
推荐使用:
1. Distroless (Google)
   - 没有 shell、package manager
   - 极小攻击面
   - gcr.io/distroless/java:11

2. Alpine (轻量 Linux)
   - ~5MB
   - 有 shell (注意安全)

3. Scratch (空镜像)
   - 0 字节
   - 仅用于静态编译的 Go 二进制

4. Chainguard Images (Wolfi)
   - CVE 接近零
   - 自动重建

例 (Dockerfile):
  # ❌ 不推荐
  FROM ubuntu:22.04
  
  # ✅ 推荐
  FROM gcr.io/distroless/java:11
  COPY target/myapp.jar /app.jar
  CMD ["/app.jar"]
```

## 九、运行时安全 (Runtime Security)

### 9.1 Falco 部署

```bash
# Falco - 云原生运行时安全工具 (CNCF)
helm repo add falcosecurity https://falcosecurity.github.io/charts
helm repo update

helm install falco falcosecurity/falco \
  --namespace falco --create-namespace \
  --set falco.json_output=true \
  --set falco.http_output.enabled=true \
  --set falco.http_output.url="http://falcosidekick:2801"
```

### 9.2 Falco 检测规则示例

```yaml
# 终端 shell 在容器内启动
- rule: Terminal shell in container
  desc: Detect shell activity in container
  condition: >
    spawned_process and container and
    proc.name in (bash, sh, zsh, csh, ksh, fish)
  output: "Shell spawned in container (user=%user.name command=%proc.cmdline)"
  priority: WARNING
  tags: [process, container]

# 容器内安装软件
- rule: Package management process in container
  condition: >
    spawned_process and container and
    proc.name in (apt, apt-get, yum, dnf, apk, pip, npm)
  output: "Package manager in container"
  priority: ERROR
  tags: [process, package]

# 敏感文件被访问
- rule: Sensitive file accessed
  condition: >
    open_read and container and
    fd.name in (/etc/shadow, /etc/passwd, /etc/sudoers)
  output: "Sensitive file accessed"
  priority: CRITICAL
```

### 9.3 AppArmor / seccomp

```yaml
# AppArmor 配置
container.apparmor.security.beta.kubernetes.io/<container-name>: runtime/default

# seccomp 配置
spec:
  securityContext:
    seccompProfile:
      type: RuntimeDefault    # 推荐
      # type: Localhost       # 自定义
      # localhostProfile: my-profile.json
```

## 十、API Server 加固

### 10.1 启用审计日志

```yaml
# /etc/kubernetes/audit-policy.yaml
apiVersion: audit.k8s.io/v1
kind: Policy
rules:
- level: Metadata
  resources:
  - group: ""
    resources: ["secrets", "configmaps"]

- level: RequestResponse
  verbs: ["create", "delete", "update"]
  resources:
  - group: ""
    resources: ["pods", "services"]

- level: None
  # 不记录只读请求
  verbs: ["get", "list", "watch"]
```

```bash
# 启动 kube-apiserver 时启用审计
--audit-policy-file=/etc/kubernetes/audit-policy.yaml
--audit-log-path=/var/log/kubernetes/audit/audit.log
--audit-log-maxage=30
```

### 10.2 API Server 标志

```yaml
# /etc/kubernetes/manifests/kube-apiserver.yaml
spec:
  containers:
  - command:
    - kube-apiserver
    # 认证
    - --client-ca-file=/etc/kubernetes/pki/ca.crt
    - --service-account-key-file=/etc/kubernetes/pki/sa.pub
    - --service-account-signing-key-file=/etc/kubernetes/pki/sa.key
    
    # 授权
    - --authorization-mode=Node,RBAC
    
    # 准入控制
    - --enable-admission-plugins=NodeRestriction,PodSecurity,ServiceAccount
    
    # 加密
    - --encryption-provider-config=/etc/kubernetes/encryption-config.yaml
    
    # 审计
    - --audit-policy-file=/etc/kubernetes/audit-policy.yaml
    - --audit-log-path=/var/log/kubernetes/audit/audit.log
    
    # 网络
    - --bind-address=0.0.0.0
    - --secure-port=6443
```

### 10.3 etcd 安全

```yaml
# /etc/kubernetes/manifests/kube-apiserver.yaml
spec:
  containers:
  - command:
    - kube-apiserver
    - --etcd-servers=https://etcd-1:2379,https://etcd-2:2379,https://etcd-3:2379
    - --etcd-cafile=/etc/kubernetes/pki/etcd/ca.crt
    - --etcd-certfile=/etc/kubernetes/pki/etcd/server.crt
    - --etcd-keyfile=/etc/kubernetes/pki/etcd/server.key
    - --encryption-provider-config=/etc/kubernetes/encryption-config.yaml  # Secret 加密
```

## 十一、安全最佳实践 Checklist

### 11.1 镜像安全

```text
□ 使用最小化基础镜像 (Distroless / Alpine)
□ 定期扫描漏洞 (Trivy / Clair)
□ 镜像签名验证 (Cosign)
□ 不在镜像中硬编码密钥
□ 不使用 :latest 标签
```

### 11.2 运行时安全

```text
□ 所有 Pod 设 securityContext
□ 禁止特权容器 (privileged: false)
□ 根文件系统只读 (readOnlyRootFilesystem: true)
□ 删除所有 capabilities
□ runAsNonRoot: true
□ 启用 seccomp / AppArmor
```

### 11.3 网络隔离

```text
□ 默认拒绝所有 NetworkPolicy
□ 显式定义允许规则
□ 命名空间间隔离
□ 限制 Pod 出口流量
□ Service Mesh (mTLS) 用于内部通信
```

### 11.4 访问控制

```text
□ 集成 OIDC (企业 IDP)
□ 不用默认 ServiceAccount
□ 最小权限 RBAC
□ 定期 audit
□ 限制 Secret 访问 (etcd 加密)
```

### 11.5 API Server 加固

```text
□ 启用审计日志
□ 启用准入控制 (PodSecurity / OPA)
□ Secret etcd 加密
□ API Server 不对外暴露 (走 LB)
□ 使用最新稳定版本
```

### 11.6 运行时检测

```text
□ 部署 Falco / Tracee
□ 检测异常进程
□ 检测敏感文件访问
□ 检测异常网络连接
□ 告警接 Prometheus Alertmanager
```

### 安全四层

```text
1. 访问控制 - 认证 + RBAC
2. 网络隔离 - NetworkPolicy
3. 镜像安全 - 漏洞扫描 + 签名
```

### 容器安全三件套

```yaml
allowPrivilegeEscalation: false
privileged: false
readOnlyRootFilesystem: true

```

### PodSecurity 等级

```text
privileged  - 允许所有 (测试)
baseline    - 基础防护

```

