# K8s 安全上下文（Security Context）

> 本章系统讲解 K8s SecurityContext 的原理、配置、PodSecurityStandards 准入控制与生产安全最佳实践。

## 一、为什么需要 SecurityContext

### 1.1 业务背景

```text
K8s 默认安全风险：

  1. Pod 默认以 root 运行（uid=0）
  2. 容器可获取 Linux capabilities（特权）
  3. 文件系统可任意写
  4. 进程可任意共享主机 namespace
  5. 镜像来源不可控
  6. 无资源限制
  7. 主机网络共享
  8. SELinux/AppArmor 默认关闭

真实事故：
  - 容器逃逸（container escape）
  - 镜像投毒（image poisoning）
  - 权限提升（privilege escalation）
  - 数据窃取
  - 拒绝服务（DoS）

合规要求：
  - PCI-DSS
  - GDPR
  - 等保 2.0（三级）
  - SOC 2
  - ISO 27001
```

### 1.2 SecurityContext 解决的核心问题

```text
SecurityContext 是 K8s 的核心安全机制：

  1. 身份控制
     - 运行用户（非 root）
     - 用户/组 ID（uid/gid）
     - fsGroup（卷权限）

  2. 权限控制
     - privileged（特权模式）
     - capabilities（Linux capabilities）
     - 限制 namespace（hostNetwork/hostPID）

  3. 资源控制
     - 资源 limits
     - 优先级类（PriorityClass）
     - 安全计算约束

  4. 文件系统控制
     - readOnlyRootFilesystem
     - seLinuxOptions
     - seccompProfile

  5. 进程控制
     - allowPrivilegeEscalation
     - procMount
     - runAsNonRoot
```

### 1.3 适用场景

```text
适合 SecurityContext 的场景：
  ✅ 多租户集群
  ✅ 金融/支付/医疗等合规场景
  ✅ 不可信的工作负载
  ✅ 共享开发集群
  ✅ 生产环境最佳实践

不适合：
  ❌ 单用户开发环境
  ❌ 内部测试集群（可用更宽松策略）
```

## 二、SecurityContext 核心概念

### 2.1 双重作用域

```text
SecurityContext 有两个层级：

  ┌────────────────────────────────────────┐
  │           Pod spec                      │
  │  ┌─────────────────────────────────┐  │
  │  │  securityContext:                │  │ ← Pod 级
  │  │  (Pod Security Standards)         │  │
  │  │  - runAsUser (uid)              │  │
  │  │  - runAsGroup (gid)             │  │
  │  │  - fsGroup (卷权限)            │  │
  │  │  - seLinuxOptions              │  │
  │  │  - runAsNonRoot                 │  │
  │  │  - supplementalGroups           │  │
  │  │  - sysctls                     │  │
  │  └─────────────────────────────────┘  │
  │  ┌─────────────────────────────────┐  │
  │  │  Container spec                 │  │
  │  │  ┌─────────────────────────┐  │  │
  │  │  │  spec.containers[0]:        │  │  │
  │  │  │  securityContext:           │  │ ← Container 级
  │  │  │  - runAsUser               │  │  （覆盖 Pod）
  │  │  │  - runAsGroup              │  │  │
  │  │  │  - allowPrivilegeEscalation │  │  │
  │  │  │  - capabilities             │  │  │
  │  │  │  - privileged              │  │  │
  │  │  │  - readOnlyRootFilesystem  │  │  │
  │  │  │  - allowPrivilegeEscalation │  │  │
  │  │  │  - seLinuxOptions          │  │  │
  │  │  │  - seccompProfile          │  │  │
  │  │  │  - runAsNonRoot            │  │  │
  │  │  │  - procMount               │  │  │
  │  │  └─────────────────────────┘  │  │
  │  └─────────────────────────────────┘  │
  └────────────────────────────────────────┘

  优先级：Container 级 > Pod 级
  合并行为：Container 级覆盖 Pod 级，其他字段合并
```

### 2.2 关键字段速查

```text
┌─────────────────────────────┬────────────────────────────────┐
│  字段                       │  说明                          │
├─────────────────────────────┼────────────────────────────────┤
│  runAsUser                  │  容器进程 UID                 │
│  runAsGroup                 │  容器进程 GID                 │
│  runAsNonRoot               │  强制非 root                  │
│  fsGroup                    │  卷的属组                     │
│  supplementalGroups        │  补充组                       │
│  privileged                 │  特权模式（危险）            │
│  allowPrivilegeEscalation  │  允许权限提升                  │
│  readOnlyRootFilesystem     │  根文件系统只读                │
│  capabilities.add/drop     │  增删 Linux capabilities      │
│  seLinuxOptions            │  SELinux 配置                 │
│  seccompProfile            │  seccomp 配置                 │
│  procMount                 │  /proc 挂载控制              │
│  sysctls                    │  内核参数                     │
└─────────────────────────────┴────────────────────────────────┘
```

## 三、用户与组控制

### 3.1 runAsUser / runAsGroup

```yaml
# Pod 级（所有容器生效）
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  securityContext:
    runAsUser: 1000              # UID
    runAsGroup: 3000             # GID
    fsGroup: 2000                # 卷属组
    supplementalGroups: [4000]   # 补充组
  containers:
  - name: app
    image: nginx
```

```yaml
# Container 级（覆盖 Pod）
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  securityContext:
    runAsUser: 1000
  containers:
  - name: app
    image: nginx
    securityContext:
      runAsUser: 2000           # 覆盖 Pod 级
      runAsGroup: 3000
```

### 3.2 runAsNonRoot

```yaml
# 强制以非 root 运行
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  securityContext:
    runAsNonRoot: true          # 镜像 USER 不是 root 才会启动
  containers:
  - name: app
    image: nginx
```

```bash
# 验证
kubectl get pod app -o yaml | grep -A 5 securityContext

# 如果镜像以 root 启动，会被 kubelet 拒绝
```

### 3.3 fsGroup 与卷权限

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  securityContext:
    fsGroup: 2000                # 卷的属组
  containers:
  - name: app
    image: nginx
    volumeMounts:
    - name: data
      mountPath: /data
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: pvc-app
```

```text
fsGroup 行为：
  - 当卷被挂载到容器时
  - 卷的所有文件会被设置为：
    - 组：fsGroup
    - 权限：g+w（如果 fsGroupChangePolicy = OnRootMismatch）
  - 容器内的进程如果在 fsGroup 中，可以写卷
```

## 四、权限与 Capabilities

### 4.1 privileged 模式

```yaml
# 特权模式：相当于 docker run --privileged
apiVersion: v1
kind: Pod
metadata:
  name: privileged-app
spec:
  containers:
  - name: app
    image: some-image
    securityContext:
      privileged: true         # ⚠️ 危险！获得所有 capabilities
```

```text
privileged: true 的能力：
  ✅ 访问所有设备（/dev/*）
  ✅ 修改网络配置
  ✅ 加载内核模块
  ✅ 挂载文件系统
  ✅ 修改系统时间
  ✅ 关闭 SELinux/AppArmor
  ❌ 容器逃逸风险极高

生产禁止使用 privileged，仅限：
  - 特殊系统级 Pod（如 kube-proxy、CNI、CSI）
  - 调试（受控环境）
```

### 4.2 capabilities 精细控制

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: nginx
    securityContext:
      capabilities:
        add:
          - NET_BIND_SERVICE      # 绑定 80 端口需要
        drop:
          - ALL                    # 移除所有
          # 上面 add 添加的是需要的
```

```text
常用 capabilities：
  NET_BIND_SERVICE      - 绑定低端口 (< 1024)
  NET_ADMIN              - 网络管理
  SYS_TIME               - 设置系统时间
  SYS_PTRACE             - 调试其他进程
  KILL                   - 杀死进程
  CHOWN                  - 修改文件属主
  DAC_OVERRIDE           - 绕过文件权限
  FSETID                - 设置文件 setuid
  FOWNER                 - 绕过文件属主权限
  MKNOD                 - 创建设备文件
  NET_RAW                - 使用 RAW socket
  SYS_ADMIN              - 危险：系统管理
  SYS_MODULE             - 危险：加载内核模块
  SYS_RAWIO              - 危险：原始 IO
  SYS_PTRACE             - 危险：调试

默认添加（不能 drop）：
  CHOWN
  DAC_OVERRIDE
  FSETID
  FOWNER
  MKNOD
  NET_RAW
  SETFCAP
  SETGID
  SETPCAP
  SETUID

最佳实践：
  capabilities:
    drop:
      - ALL
    add:
      - NET_BIND_SERVICE
```

### 4.3 allowPrivilegeEscalation

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: nginx
    securityContext:
      allowPrivilegeEscalation: false
```

```text
allowPrivilegeEscalation 控制：

  true（默认）：
    - 允许 setuid 文件提权
    - 允许 capability 提升

  false：
    - 禁止任何提权行为
    - 进程即使 setuid 也无法提权

生产推荐：
  - 全部设置 false
  - 防止意外的提权
```

## 五、文件系统安全

### 5.1 readOnlyRootFilesystem

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: nginx
    securityContext:
      readOnlyRootFilesystem: true  # 根文件系统只读
    volumeMounts:
    - name: tmp
      mountPath: /tmp                # /tmp 仍然可写
    - name: var-cache
      mountPath: /var/cache/nginx
```

```text
readOnlyRootFilesystem: true 行为：
  - 容器根文件系统（/）只读
  - 必须通过 volumeMount 显式声明可写路径
  - 防止容器内进程修改自身二进制
  - 防止攻击者植入恶意文件

最佳实践：
  - 所有生产容器开启
  - 仅暴露需要写的目录为 emptyDir 或 PV
  - /tmp、/var/log、/var/run 等必须 mount
```

### 5.2 完整文件系统安全配置

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  securityContext:
    # Pod 级
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 3000
    fsGroup: 2000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: my-app:1.0
    securityContext:
      # Container 级
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      privileged: false
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 3000
      capabilities:
        drop:
          - ALL
        add:
          - NET_BIND_SERVICE
      seccompProfile:
        type: RuntimeDefault
      seLinuxOptions:
        user: "system_u"
        role: "system_r"
        type: "container_t"
        level: "s0:c234,c567"
    volumeMounts:
    - name: tmp
      mountPath: /tmp
    - name: cache
      mountPath: /var/cache/app
    - name: log
      mountPath: /var/log/app
  volumes:
  - name: tmp
    emptyDir: {}
  - name: cache
    emptyDir: {}
  - name: log
    emptyDir: {}
```

## 六、SELinux 与 seccomp

### 6.1 SELinux Options

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  containers:
  - name: app
    image: nginx
    securityContext:
      seLinuxOptions:
        user: "system_u"            # SELinux 用户
        role: "system_r"            # SELinux 角色
        type: "container_t"         # SELinux 类型
        level: "s0:c234,c567"       # MLS 级别
```

```text
SELinux 模式：
  - Enforcing：强制执行（拒绝违规）
  - Permissive：仅记录，不拒绝（调试）
  - Disabled：完全关闭

在 K8s 中：
  - 节点 OS 必须开启 SELinux
  - 容器 runtime（containerd/CRI-O）支持 SELinux
  - 容器使用 container_t 类型
  - 挂载点使用 container_file_t 类型

如果 SELinux 阻止了容器：
  - 查看 AVC 拒绝日志：ausearch -m avc
  - 临时切换 Permissive 调试
  - 修复策略后切回 Enforcing
```

### 6.2 seccomp Profile

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  securityContext:
    seccompProfile:
      type: RuntimeDefault    # 使用容器 runtime 的默认 profile
  containers:
  - name: app
    image: nginx
    securityContext:
      seccompProfile:
        type: RuntimeDefault
```

```text
seccomp profile 类型：

  Unconfined：
    - 不限制任何系统调用
    - 仅调试使用

  RuntimeDefault（推荐）：
    - 使用容器 runtime 的默认 profile
    - containerd 默认约 250+ 系统调用
    - 平衡安全与兼容

  Localhost：
    - 自定义 profile
    - 挂载在节点的 /var/lib/kubelet/seccomp/ 目录
    - 路径如：/var/lib/kubelet/seccomp/my-profile.json

生产推荐：
  seccompProfile:
    type: RuntimeDefault
```

### 6.3 自定义 seccomp profile

```json
{
  "defaultAction": "SCMP_ACT_ERRNO",
  "architectures": ["SCMP_ARCH_X86_64"],
  "syscalls": [
    {
      "names": ["read", "write", "exit", "exit_group"],
      "action": "SCMP_ACT_ALLOW"
    },
    {
      "names": ["open", "openat"],
      "action": "SCMP_ACT_ALLOW"
    }
  ]
}
```

```bash
# 1. 创建 seccomp profile
sudo mkdir -p /var/lib/kubelet/seccomp
sudo cp my-profile.json /var/lib/kubelet/seccomp/

# 2. Pod 引用
apiVersion: v1
kind: Pod
spec:
  securityContext:
    seccompProfile:
      type: Localhost
      localhostProfile: my-profile.json
  containers:
  - name: app
    image: nginx
```

## 七、Pod Security Standards（PSA）

### 7.1 PSA 三个等级

```text
Pod Security Standards 三个等级（从最严格到宽松）：

  ┌─────────────────────────────────────────────┐
  │  Privileged（特权）                          │
  │  - 几乎无限制                                │
  │  - 仅用于系统级 Pod                         │
  │  - 风险：可绕过所有安全机制              │
  └─────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────┐
  │  Baseline（基线）                             │
  │  - 阻止已知提权                              │
  │  - 不限制普通 Pod                             │
  │  - 默认级别                                  │
  └─────────────────────────────────────────────┘

  ┌─────────────────────────────────────────────┐
  │  Restricted（受限，最严格）                  │
  │  - 强制最新安全最佳实践                     │
  │  - runAsNonRoot 强制                        │
  │  - 只读 rootfs 强制                          │
  │  - 所有 capabilities drop                    │
  │  - seccomp RuntimeDefault                    │
  └─────────────────────────────────────────────┘
```

### 7.2 PSA Baseline 规则

```text
Baseline 阻止的危险行为：

  1. 提权（Privilege Escalation）
     - ❌ privileged: true
     - ❌ hostNetwork / hostPID / hostIPC
     - ❌ allowPrivilegeEscalation: true
     - ❌ SYS_ADMIN / NET_ADMIN 等危险 capabilities

  2. 主机命名空间
     - ❌ hostNetwork: true
     - ❌ hostPID: true
     - ❌ hostIPC: true
     - ❌ hostPath（某些限制）

  3. 用户权限
     - ❌ runAsUser: 0（root）
     - 可 runAsNonRoot: false（不强制）

  4. 资源
     - ❌ 无限制的 capabilities
     - ❌ 不安全 seccomp（Unconfined）
     - ❌ 主机端口（HostPort）

  5. 文件系统
     - ❌ 危险 hostPath 路径
     - 可 readOnlyRootFilesystem: false（不强制）
```

### 7.3 PSA Restricted 规则

```text
Restricted 强制要求（比 Baseline 严格）：

  1. 用户必须非 root
     - ✅ runAsNonRoot: true（必须）
     - ✅ runAsUser != 0

  2. 只读文件系统
     - ✅ readOnlyRootFilesystem: true（必须）

  3. 最小 capabilities
     - ✅ capabilities.drop: ["ALL"]
     - 仅 NET_BIND_SERVICE 可加

  4. seccomp
     - ✅ seccompProfile.type: RuntimeDefault 或 Localhost
     - ❌ seccompProfile.type: Unconfined

  5. SELinux（可选）
     - 建议配置 seLinuxOptions

  6. 禁止危险行为
     - ❌ privileged
     - ❌ hostNetwork
     - ❌ hostPID
     - ❌ hostIPC
     - ❌ hostPath
     - ❌ hostPort
     - ❌ allowPrivilegeEscalation
```

### 7.4 启用 PSA（命名空间级别）

```bash
# 在命名空间打标签启用 PSA
kubectl label namespace production \
  pod-security.kubernetes.io/enforce=restricted \
  pod-security.kubernetes.io/enforce-version=latest \
  pod-security.kubernetes.io/audit=restricted \
  pod-security.kubernetes.io/audit-version=latest \
  pod-security.kubernetes.io/warn=restricted \
  pod-security.kubernetes.io/warn-version=latest

# 三种模式：
#   enforce：拒绝违规 Pod
#   audit：审计但不拒绝
#   warn：警告但不拒绝

# 验证
kubectl get ns production -o yaml | grep pod-security
```

### 7.5 替代：PodSecurityPolicy（已废弃，K8s 1.25+）

```text
⚠️ 重要：
  PodSecurityPolicy（PSP）已在 K8s 1.25 完全移除！

  替代方案：
    1. Pod Security Standards（PSA，官方推荐）
    2. OPA / Gatekeeper（策略引擎）
    3. Kyverno（K8s 原生策略引擎）
    4. KubeArmor（安全运行时）

  如有遗留 PSP，需要：
    1. 迁移到 Kyverno 或 OPA
    2. 或使用 Pod Security Admission（PSA）
```

## 八、K8s 安全最佳实践速记

### 8.1 Pod 级安全标准配置

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: secure-app
spec:
  automountServiceAccountToken: false   # 不挂载 SA token（减少攻击面）
  securityContext:
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 3000
    fsGroup: 2000
    seccompProfile:
      type: RuntimeDefault
  containers:
  - name: app
    image: my-app:1.0
    imagePullPolicy: IfNotPresent
    securityContext:
      allowPrivilegeEscalation: false
      readOnlyRootFilesystem: true
      privileged: false
      runAsNonRoot: true
      runAsUser: 1000
      runAsGroup: 3000
      capabilities:
        drop:
          - ALL
        add:
          - NET_BIND_SERVICE
      seccompProfile:
        type: RuntimeDefault
      seLinuxOptions:
        user: system_u
        role: system_r
        type: container_t
        level: s0:c234,c456
    resources:
      requests:
        cpu: 100m
        memory: 128Mi
      limits:
        cpu: 500m
        memory: 256Mi
    volumeMounts:
    - name: tmp
      mountPath: /tmp
    - name: cache
      mountPath: /var/cache/app
    - name: log
      mountPath: /var/log/app
    livenessProbe:
      httpGet:
        path: /healthz
        port: 8080
      initialDelaySeconds: 30
      periodSeconds: 10
    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
    securityContext:
      runAsNonRoot: true
      runAsUser: 1000
  serviceAccountName: app-sa
  automountServiceAccountToken: false
  volumes:
  - name: tmp
    emptyDir: {}
  - name: cache
    emptyDir: {}
  - name: log
    emptyDir: {}
```

### 8.2 Service Account 最佳实践

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: app-sa
  namespace: production
  annotations:
    # 禁用 token 自动挂载（减少攻击面）
    kubernetes.io/enforce-mountable-secrets: "true"
automountServiceAccountToken: false
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: app
spec:
  serviceAccountName: app-sa
  automountServiceAccountToken: false    # 关键：禁用 token 挂载
  containers:
  - name: app
    image: my-app:1.0
```

### 8.3 镜像安全

```bash
# 1. 使用受信镜像仓库
# 配置 imagePullSecrets
kubectl create secret docker-registry my-registry \
  --docker-server=registry.example.com \
  --docker-username=app \
  --docker-password=secret123

# 2. 启用镜像验证（Cosign）
cosign sign --key cosign.key my-app:1.0
cosign verify --key cosign.pub my-app:1.0

# 3. 镜像扫描（Trivy）
trivy image my-app:1.0

# 4. 策略：只用官方/内部 registry
imagePullPolicy: IfNotPresent
image: registry.example.com/myorg/app:1.0.0  # 明确 tag，不用 latest
```

### 8.4 NetworkPolicy（网络隔离）

```yaml
kind: NetworkPolicy

  name: default-deny
  namespace: production
spec:
  podSelector: {}               # 匹配所有 Pod
  policyTypes:
  - Ingress
  - Egress

```

```yaml
  name: allow-app
  namespace: production

  - Ingress
  - Egress

        matchLabels:
```

## 十、核心要点速记

### SecurityContext 双重作用域

```
Pod spec.securityContext     → Pod 级（所有容器共享）
Container spec.securityContext → Container 级（覆盖 Pod 级）
合并：Container 级覆盖 Pod 级，其他字段合并
```

### 必做项

```
✅ runAsNonRoot: true
✅ runAsUser: 1000（>0）
✅ readOnlyRootFilesystem: true
✅ allowPrivilegeEscalation: false
✅ capabilities.drop: [ALL]
✅ seccompProfile: RuntimeDefault
✅ resources.limits: 必须
```

### 禁止项

```
❌ privileged: true（除非系统级）
❌ runAsUser: 0（root）
❌ hostNetwork: true（生产）
❌ hostPID / hostIPC: true
❌ capabilities: [ALL]（不 drop）
❌ seccompProfile: Unconfined
```

### 完整推荐配置

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 1000
  runAsGroup: 3000
  fsGroup: 2000
  seccompProfile:
    type: RuntimeDefault
  seLinuxOptions:
    user: system_u
    role: system_r
    type: container_t
    level: s0:c234,c456
containers:
- name: app
  image: my-app:1.0
  securityContext:
    allowPrivilegeEscalation: false
    readOnlyRootFilesystem: true
    privileged: false
    runAsNonRoot: true
    runAsUser: 1000
    runAsGroup: 3000
    capabilities:
      drop: [ALL]
      add: [NET_BIND_SERVICE]
    seccompProfile:
      type: RuntimeDefault
    seLinuxOptions:
      user: system_u
      role: system_r
      type: container_t
      level: s0:c234,c456
```

### Pod Security Standards 三等级

```
Privileged → 无限制（仅系统级）
Baseline   → 阻止已知提权（默认推荐）
Restricted → 严格最佳实践（最高安全）
```

### 速记卡

- **SecurityContext** = Pod 级 + Container 级
- **runAsNonRoot**: 强制非 root
- **readOnlyRootFilesystem**: 只读根
- **capabilities.drop: [ALL]** + 按需 add
- **seccompProfile: RuntimeDefault**
- **PSA 三等级**: privileged / baseline / restricted
- **PSA 启用方式**: namespace label
- **PSP 已废弃**（K8s 1.25+）
- **automountServiceAccountToken: false** 减少攻击面
- **NetworkPolicy**: 默认 deny + 显式 allow
- **ServiceAccount**: 最小权限 + 隔离
