# MySQL 权限与安全 (MySQL Privileges & Security)

## 一、安全概述

### 安全威胁全景

- **未授权访问**:弱口令、暴露在公网、默认账户
- **权限越权**:账户被授予超过业务需要的权限
- **数据泄露**:明文传输、日志泄露、备份泄露
- **数据篡改**:SQL 注入、提权攻击
- **拒绝服务**:连接耗尽、慢查询、磁盘写满
- **审计缺失**:无法追溯谁做了什么
- **合规风险**:GDPR、个保法、PCI-DSS 等合规要求

### 安全基本原则

- **最小特权 (Least Privilege)**:只给业务必需的权限
- **纵深防御 (Defense in Depth)**:网络 + 主机 + 数据库 + 应用多层防护
- **失效安全 (Fail Safe)**:失败时进入安全状态
- **职责分离 (Separation of Duties)**:DBA、应用账号、审计账号分离
- **默认拒绝 (Default Deny)**:默认拒绝所有,按需放行
- **可审计 (Auditable)**:所有操作有迹可循

### MySQL 安全层次

| 层次 | 措施 | 说明 |
|------|------|------|
| 网络层 | 防火墙、绑定 IP、SSL/TLS | 限制谁能连 |
| 主机层 | 操作系统权限、SSH 密钥 | 谁能登机器 |
| 协议层 | 加密传输、协议版本 | 传输是否泄露 |
| 认证层 | 用户名/密码、密码策略 | 谁能进 MySQL |
| 授权层 | 权限粒度控制 | 能做什么 |
| 审计层 | 操作日志、查询日志 | 做了什么 |
| 数据层 | 字段加密、TDE | 数据本身加密 |

## 二、用户管理

### 1. 用户标识

MySQL 用户由 `用户名@主机` 组成,主机决定从哪来。

```sql
-- 用户 'app' 从 '192.168.1.%' 网段连接
'app'@'192.168.1.%'

-- 主机表示方法:
-- 'localhost'     本机 socket 连接
-- '127.0.0.1'     本机 TCP 连接
-- '192.168.1.10'  单一 IP
-- '192.168.1.%'   网段
-- '%'             任意主机(危险)
-- '%.example.com'  域名通配
```

### 2. CREATE USER 创建用户

```sql
-- 基本语法
CREATE USER 'username'@'host' IDENTIFIED BY 'password';

-- 指定密码哈希
CREATE USER 'username'@'host' IDENTIFIED WITH mysql_native_password BY 'password';

-- 使用 caching_sha2_password(MySQL 8.0 默认)
CREATE USER 'username'@'host' IDENTIFIED WITH caching_sha2_password BY 'password';

-- 5.7 之前可用 IDENTIFIED BY PASSWORD 传哈希值
CREATE USER 'app'@'%' IDENTIFIED BY 'App@2024!';

-- 创建后用户无任何权限
```

### 3. ALTER USER 修改用户

```sql
-- 修改密码
ALTER USER 'app'@'%' IDENTIFIED BY 'NewPass@2024';

-- 修改认证插件
ALTER USER 'app'@'%' IDENTIFIED WITH mysql_native_password BY 'Pass@123';

-- 锁定/解锁账户
ALTER USER 'app'@'%' ACCOUNT LOCK;
ALTER USER 'app'@'%' ACCOUNT UNLOCK;

-- 密码过期
ALTER USER 'app'@'%' PASSWORD EXPIRE;

-- 设置资源限制(每用户每小时查询数)
ALTER USER 'app'@'%' WITH MAX_QUERIES_PER_HOUR 1000
                      MAX_UPDATES_PER_HOUR 100
                      MAX_CONNECTIONS_PER_HOUR 50
                      MAX_USER_CONNECTIONS 5;
```

### 4. DROP USER 删除用户

```sql
-- 删除用户
DROP USER 'app'@'%';

-- 同时删除多个
DROP USER 'app'@'%', 'test'@'localhost';

-- 注意:不会自动撤销已授予的权限(虽然用户已不存在,授权记录仍在)
```

### 5. RENAME USER 重命名

```sql
RENAME USER 'old'@'%' TO 'new'@'%';
```

### 6. 用户信息存储

所有用户信息存储在 `mysql.user` 系统表(以及 `db`、`tables_priv`、`columns_priv`、`procs_priv` 等)。

```sql
-- 查看所有用户
SELECT user, host, plugin, authentication_string
FROM mysql.user;

-- 关键字段:
-- user              用户名
-- host              主机
-- plugin            认证插件(mysql_native_password / caching_sha2_password)
-- authentication_string  密码哈希
-- account_locked   是否锁定(Y/N)
-- password_expired 密码是否过期
-- password_last_changed 最后修改时间
-- password_lifetime 密码有效期(天)
-- max_connections   最大连接数
-- max_user_connections 单用户连接上限
```

### 7. 完整示例

```sql
-- 1. 创建应用账户
CREATE USER 'app_user'@'10.0.0.%'
  IDENTIFIED WITH caching_sha2_password BY 'App@2024!Strong'
  PASSWORD EXPIRE INTERVAL 90 DAY
  MAX_CONNECTIONS_PER_HOUR 1000
  MAX_USER_CONNECTIONS 20;

-- 2. 验证创建
SELECT user, host, plugin, account_locked
FROM mysql.user
WHERE user = 'app_user';

-- 3. 应用修改
ALTER USER 'app_user'@'10.0.0.%' IDENTIFIED BY 'New@2024!Pass';

-- 4. 锁定可疑账户
ALTER USER 'app_user'@'10.0.0.%' ACCOUNT LOCK;

-- 5. 删除测试账户
DROP USER 'test'@'%', 'root'@'%';
```

## 三、权限模型

### 1. 权限层级

MySQL 权限是分层的,从粗到细共 5 级:

| 层级 | 范围 | 存储表 |
|------|------|--------|
| 全局 | `*.*` 所有库所有表 | `mysql.user` |
| 库级 | `db.*` 指定库 | `mysql.db` |
| 表级 | `db.tbl` 指定表 | `mysql.tables_priv` |
| 列级 | 指定列 | `mysql.columns_priv` |
| 过程/函数 | 存储过程、函数 | `mysql.procs_priv` |

### 2. 全局权限 (`*.*`)

影响整个 MySQL 实例。

```sql
-- 授予所有权限(慎用)
GRANT ALL PRIVILEGES ON *.* TO 'admin'@'%';

-- 授予特定全局权限
GRANT RELOAD, SHUTDOWN, PROCESS ON *.* TO 'monitor'@'localhost';
GRANT SUPER ON *.* TO 'repl'@'10.0.0.%';  -- 复制账户
```

### 3. 库级权限 (`db.*`)

限制在某个数据库内。

```sql
-- 对 app_db 库所有权限
GRANT ALL PRIVILEGES ON app_db.* TO 'app_user'@'10.0.0.%';

-- 只读权限
GRANT SELECT ON report_db.* TO 'report_user'@'10.0.0.%';

-- DML 权限
GRANT SELECT, INSERT, UPDATE, DELETE ON order_db.* TO 'order_app'@'%';
```

### 4. 表级权限 (`db.table`)

精确到某一张表。

```sql
-- 单表权限
GRANT SELECT, INSERT ON app_db.users TO 'app_user'@'%';

-- 多张表
GRANT SELECT ON app_db.products TO 'app_user'@'%';
GRANT SELECT ON app_db.orders TO 'app_user'@'%';

-- 授予所有表 SELECT 权限(逐表,可使用脚本批量)
```

### 5. 列级权限

最细粒度,直接控制到列。

```sql
-- 授予某几列的权限
GRANT SELECT (id, name, email) ON app_db.users TO 'report'@'%';
GRANT UPDATE (email, phone) ON app_db.users TO 'app_user'@'%';

-- 注意:列级权限要写列名,语法上是 INSERT/UPDATE 等后面跟括号列名
GRANT INSERT (id, name, created_at) ON app_db.users TO 'app_user'@'%';

-- 查询列级权限
SELECT * FROM mysql.columns_priv;
```

### 6. 常用权限类别

| 权限 | 作用范围 | 说明 |
|------|----------|------|
| `SELECT` | 表/列 | 读 |
| `INSERT` | 表/列 | 插入 |
| `UPDATE` | 表/列 | 更新 |
| `DELETE` | 表 | 删除 |
| `CREATE` | 库/表/索引 | 创建 |
| `DROP` | 库/表 | 删除 |
| `ALTER` | 表 | ALTER TABLE |
| `INDEX` | 表 | CREATE/DROP INDEX |
| `REFERENCES` | 表 | 外键 |
| `GRANT OPTION` | 任意 | 是否能授权给他人 |
| `RELOAD` | 全局 | FLUSH 等 |
| `SHUTDOWN` | 全局 | 关闭 MySQL |
| `PROCESS` | 全局 | SHOW PROCESSLIST |
| `SUPER` | 全局 | KILL、SET GLOBAL 等(8.0 部分被取代) |
| `REPLICATION CLIENT` | 全局 | SHOW MASTER/SLAVE STATUS |
| `REPLICATION SLAVE` | 全局 | 从库连接主库读取 binlog |
| `FILE` | 全局 | LOAD DATA / SELECT ... INTO OUTFILE |
| `ALL [PRIVILEGES]` | 任意 | 除 GRANT OPTION 外所有权限 |

### 7. 查看权限

```sql
-- 查看自己的权限
SHOW GRANTS;

-- 查看其他用户的权限
SHOW GRANTS FOR 'app_user'@'10.0.0.%';

-- 查看具体权限记录
SELECT * FROM mysql.user WHERE user='app_user'\G
SELECT * FROM mysql.db WHERE user='app_user'\G
SELECT * FROM mysql.tables_priv WHERE user='app_user'\G
SELECT * FROM mysql.columns_priv WHERE user='app_user'\G
```

## 四、授权管理

### 1. GRANT 完整语法

```sql
GRANT
    priv_type [(column_list)]
    [, priv_type [(column_list)]] ...
    ON [object_type] priv_level
    TO user_or_role [, user_or_role] ...
    [WITH GRANT OPTION]
    [AS user_with_grant_option]
    [REQUIRE {NONE | SSL | X509 | tls_option}]
    [RESOURCE OPTION resource_option]
```

### 2. REVOKE 完整语法

```sql
REVOKE
    priv_type [(column_list)]
    [, priv_type [(column_list)]] ...
    ON [object_type] priv_level
    FROM user_or_role [, user_or_role] ...

-- 撤销 GRANT OPTION
REVOKE GRANT OPTION ON ... FROM 'user'@'host';
```

### 3. WITH GRANT OPTION

允许被授权者把权限再授权给其他人(慎用)。

```sql
-- A 授权 B,B 也能授权给 C
GRANT SELECT ON app_db.* TO 'dev'@'%' WITH GRANT OPTION;

-- 撤销时先撤销 GRANT OPTION,再撤销权限
REVOKE GRANT OPTION ON app_db.* FROM 'dev'@'%';
REVOKE SELECT ON app_db.* FROM 'dev'@'%';
```

### 4. 授权示例

```sql
-- 场景 1:只读报表用户
CREATE USER 'report'@'10.0.0.%' IDENTIFIED BY 'Report@2024';
GRANT SELECT ON report_db.* TO 'report'@'10.0.0.%';
GRANT SELECT (id, order_no, amount, status) ON order_db.orders TO 'report'@'10.0.0.%';

-- 场景 2:应用账户(DML)
CREATE USER 'app'@'10.0.0.%' IDENTIFIED BY 'App@2024!';
GRANT SELECT, INSERT, UPDATE, DELETE ON app_db.* TO 'app'@'10.0.0.%';
GRANT SELECT ON mysql.proc TO 'app'@'10.0.0.%';  -- 让应用能查存储过程列表

-- 场景 3:复制账户
CREATE USER 'repl'@'10.0.0.%' IDENTIFIED BY 'Repl@2024!';
GRANT REPLICATION SLAVE ON *.* TO 'repl'@'10.0.0.%';

-- 场景 4:监控账户
CREATE USER 'monitor'@'10.0.0.%' IDENTIFIED BY 'Mon@2024!';
GRANT PROCESS, REPLICATION CLIENT, SELECT ON *.* TO 'monitor'@'10.0.0.%';
GRANT SELECT ON performance_schema.* TO 'monitor'@'10.0.0.%';

-- 场景 5:备份账户
CREATE USER 'backup'@'localhost' IDENTIFIED BY 'Bkp@2024!';
GRANT SELECT, RELOAD, LOCK TABLES, REPLICATION CLIENT, SHOW VIEW,
      EVENT, TRIGGER ON *.* TO 'backup'@'localhost';

-- 场景 6:DBA 账户
GRANT ALL PRIVILEGES ON *.* TO 'dba'@'10.0.0.%' WITH GRANT OPTION;
```

### 5. 撤销权限

```sql
-- 撤销 SELECT
REVOKE SELECT ON app_db.* FROM 'app'@'10.0.0.%';

-- 撤销 INSERT
REVOKE INSERT ON app_db.* FROM 'app'@'10.0.0.%';

-- 撤销列级权限
REVOKE UPDATE (email) ON app_db.users FROM 'app'@'%';

-- 撤销 ALL(等价于逐一撤销每个权限,不包括 GRANT OPTION)
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'app'@'10.0.0.%';
```

### 6. 权限生效

```sql
-- 修改权限后必须刷新
FLUSH PRIVILEGES;

-- 或重启 MySQL
-- 或 mysqladmin flush-privileges

-- 8.0 起,部分场景会自动 reload
```

## 五、角色 (Roles, MySQL 8.0+)

### 1. 角色概念

角色是权限的集合,方便批量授权和回收。

```sql
-- 角色命名也是 user@host 形式
CREATE ROLE 'app_read', 'app_write', 'app_ddl';
```

### 2. CREATE ROLE / DROP ROLE

```sql
-- 创建角色
CREATE ROLE 'app_read', 'app_write', 'app_admin';

-- 删除角色
DROP ROLE 'app_read';
```

### 3. GRANT 角色权限

```sql
-- 给角色授权(角色当作用户对待)
GRANT SELECT ON app_db.* TO 'app_read';
GRANT SELECT, INSERT, UPDATE, DELETE ON app_db.* TO 'app_write';
GRANT ALL ON app_db.* TO 'app_admin';

-- 把角色授予用户
GRANT 'app_read' TO 'readonly_user'@'10.0.0.%';
GRANT 'app_read', 'app_write' TO 'app_user'@'10.0.0.%';
GRANT 'app_admin' TO 'dba_user'@'localhost' WITH ADMIN OPTION;
```

### 4. SET ROLE 激活角色

授权给用户后,默认未激活,需手动 SET ROLE。

```sql
-- 当前会话激活指定角色
SET ROLE 'app_read';

-- 激活所有已授权角色
SET ROLE ALL;

-- 激活除某角色之外的所有
SET ROLE ALL EXCEPT 'app_admin';

-- 不激活任何角色
SET ROLE NONE;
```

### 5. SET DEFAULT ROLE 默认激活

```sql
-- 设置用户登录默认激活的角色
SET DEFAULT ROLE 'app_read' TO 'app_user'@'10.0.0.%';

-- 默认激活所有已授权角色
SET DEFAULT ROLE ALL TO 'app_user'@'10.0.0.%';

-- 不默认激活任何角色
SET DEFAULT ROLE NONE TO 'app_user'@'10.0.0.%';

-- 持久化设置(写到 mysql.user,所有会话生效)
ALTER USER 'app_user'@'10.0.0.%' DEFAULT ROLE 'app_read', 'app_write';
```

### 6. 当前角色与权限查询

```sql
-- 查看当前会话已激活角色
SELECT CURRENT_ROLE();

-- 查看用户可用的所有角色
SELECT FROM_ROLES, TO_USER, TO_HOST
FROM mysql.role_edges
WHERE TO_USER = 'app_user';

-- 查看角色之间的继承关系
SELECT * FROM mysql.role_edges;
```

### 7. 撤销角色

```sql
-- 从用户撤销角色
REVOKE 'app_write' FROM 'app_user'@'10.0.0.%';

-- 从角色撤销权限
REVOKE INSERT, UPDATE ON app_db.* FROM 'app_write';
```

### 8. 完整流程示例

```sql
-- 1. 创建角色
CREATE ROLE 'app_read', 'app_write', 'app_dba';

-- 2. 给角色授权
GRANT SELECT ON app_db.* TO 'app_read';
GRANT SELECT, INSERT, UPDATE, DELETE ON app_db.* TO 'app_write';
GRANT ALL ON *.* TO 'app_dba' WITH GRANT OPTION;

-- 3. 创建用户
CREATE USER 'reader'@'10.0.0.%' IDENTIFIED BY 'Read@2024';
CREATE USER 'writer'@'10.0.0.%' IDENTIFIED BY 'Write@2024';

-- 4. 给用户授予角色
GRANT 'app_read' TO 'reader'@'10.0.0.%';
GRANT 'app_read', 'app_write' TO 'writer'@'10.0.0.%';

-- 5. 设置默认角色
SET DEFAULT ROLE ALL TO 'reader'@'10.0.0.%', 'writer'@'10.0.0.%';

-- 6. 验证
SHOW GRANTS FOR 'reader'@'10.0.0.%';
SHOW GRANTS FOR 'writer'@'10.0.0.%';

-- 7. 角色调整(只需改一次,所有用户自动生效)
REVOKE INSERT ON app_db.* FROM 'app_write';

-- 8. 清理
DROP ROLE 'app_dba';
REVOKE 'app_read' FROM 'reader'@'10.0.0.%';
```

### 9. mandatory_roles 强制角色

`mandatory_roles` 是所有用户强制拥有的角色,无需显式授权,默认激活。

```sql
-- 设置强制角色
SET PERSIST mandatory_roles = '`app_read`@`%`,`app_dba`@`%`';

-- 查看
SELECT * FROM performance_schema.global_variables
WHERE VARIABLE_NAME = 'mandatory_roles';
```

## 六、密码管理

### 1. validate_password 组件

MySQL 8.0 起使用 `validate_password` 组件(替代插件)。

```sql
-- 查看是否安装
SELECT * FROM mysql.component;

-- 安装组件(若未安装)
INSTALL COMPONENT 'file://component_validate_password';

-- 查看密码策略
SHOW VARIABLES LIKE 'validate_password%';
```

### 2. 密码策略级别

| 策略 | 值 | 要求 |
|------|------|------|
| LOW | 0 | 密码长度 >= `validate_password.length` |
| MEDIUM | 1 | LOW + 数字/大小写/特殊字符至少各 1 |
| STRONG | 2 | MEDIUM + 不能是字典词 |

```sql
-- 设置为强密码策略
SET GLOBAL validate_password.policy = 2;

-- 最小长度
SET GLOBAL validate_password.length = 12;

-- 数字最少个数
SET GLOBAL validate_password.number_count = 1;

-- 大小写字母最少个数
SET GLOBAL validate_password.mixed_case_count = 1;

-- 特殊字符最少个数
SET GLOBAL validate_password.special_char_count = 1;

-- 字典文件
SET GLOBAL validate_password.dictionary_file = '/path/dict.txt';
```

### 3. 密码过期

```sql
-- 单用户立即过期
ALTER USER 'app'@'%' PASSWORD EXPIRE;

-- 永不过期
ALTER USER 'app'@'%' PASSWORD EXPIRE NEVER;

-- N 天后过期
ALTER USER 'app'@'%' PASSWORD EXPIRE INTERVAL 90 DAY;

-- 全局默认过期天数
SET GLOBAL default_password_lifetime = 90;

-- 设置某用户使用全局默认值
ALTER USER 'app'@'%' PASSWORD EXPIRE DEFAULT;
```

### 4. 密码重用限制

```sql
-- 全局配置
SET PERSIST password_history = 5;            -- 不能用最近 5 个密码
SET PERSIST password_reuse_interval = 365;   -- 1 年内的密码不能用

-- 单用户覆盖
ALTER USER 'app'@'%' PASSWORD HISTORY 10;
ALTER USER 'app'@'%' PASSWORD REUSE INTERVAL 180 DAY;
```

### 5. 密码复杂度要求

```sql
-- 强密码建议:
-- 1. 长度 >= 12 位
-- 2. 包含大小写字母、数字、特殊字符
-- 3. 避免常见词、生日、连续数字
-- 4. 不同系统不同密码
-- 5. 定期更换(90 天)
-- 6. 使用密码管理器
```

### 6. 失败登录锁定(8.0.27+)

```sql
-- 全局设置
SET PERSIST connection_control_failed_connections_threshold = 5;
SET PERSIST connection_control_min_connection_delay = 60000;     -- 60s
SET PERSIST connection_control_max_connection_delay = 300000;    -- 300s

-- 安装组件
INSTALL COMPONENT 'file://component_connection_control';
```

## 七、权限验证流程

### 1. 完整流程图

```
客户端发起连接
     │
     ▼
┌─────────────────────┐
│ Step 1: 用户名/密码  │ ← 验证账户是否存在、密码是否正确、是否锁定
│ authentication      │   失败: Access denied for user
└─────────────────────┘
     │
     ▼ (认证通过)
┌─────────────────────┐
│ Step 2: 连接级权限   │ ← 全局权限(*.*)
│ global privileges   │   读 mysql.user
└─────────────────────┘
     │
     ▼ (无全局权限,继续细查)
┌─────────────────────┐
│ Step 3: 库级权限     │ ← db.*
│ db privileges       │   读 mysql.db
└─────────────────────┘
     │
     ▼ (无库级权限)
┌─────────────────────┐
│ Step 4: 表级权限     │ ← db.tbl
│ table privileges    │   读 mysql.tables_priv
└─────────────────────┘
     │
     ▼ (无表级权限)
┌─────────────────────┐
│ Step 5: 列级权限     │ ← 精确到列
│ column privileges   │   读 mysql.columns_priv
└─────────────────────┘
     │
     ▼ (通过 → 执行)
```

### 2. 验证要点

- 任何一个层级 `Y`(有权限)就立即放行
- 写操作额外检查:资源限制(`MAX_QUERIES_PER_HOUR` 等)
- 存储过程调用额外检查:`mysql.procs_priv` + `EXECUTE` 权限
- 视图查询额外检查:视图本身权限 + 底层表权限

### 3. 权限缓存

MySQL 在内存中缓存权限,`FLUSH PRIVILEGES` 强制重新加载。

```sql
-- 权限修改后必须刷新,否则其他连接可能看不到
FLUSH PRIVILEGES;
```

## 八、忘记 root 密码怎么办

### 场景 A:有 sudo 权限,知道 datadir

```bash
# 1. 停止 MySQL
sudo systemctl stop mysqld
# 或
sudo /etc/init.d/mysql stop

# 2. 以跳过授权方式启动
sudo mysqld_safe --skip-grant-tables --skip-networking &
# --skip-grant-tables  跳过所有权限检查
# --skip-networking    禁用远程连接(安全)

# 3. 直接登录(无需密码)
mysql -u root

# 4. 重新加载授权表并修改密码
FLUSH PRIVILEGES;
ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewRoot@2024!';

# 5. 退出
EXIT;

# 6. 停止 mysqld_safe
sudo kill $(pgrep mysqld_safe)
sudo kill $(pgrep mysqld)

# 7. 正常启动
sudo systemctl start mysqld

# 8. 验证
mysql -u root -p'NewRoot@2024!'
```

### 场景 B:使用 init-file 重置(8.0 推荐)

```bash
# 1. 停止 MySQL
sudo systemctl stop mysqld

# 2. 编写重置 SQL
echo "ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewRoot@2024!';" \
  > /tmp/mysql-init.sql
chmod 600 /tmp/mysql-init.sql  # 严控权限

# 3. 启动时指定 init-file
sudo mysqld --init-file=/tmp/mysql-init.sql &

# 启动完成后会自动执行 init-file 中的 SQL

# 4. 停止并正常启动
sudo kill $(pgrep mysqld)
sudo systemctl start mysqld

# 5. 删除 init-file(包含明文密码!)
sudo rm /tmp/mysql-init.sql
```

### 场景 C:docker / k8s 容器中

```bash
# docker
docker exec -it mysql /usr/bin/mysqld_safe --skip-grant-tables &
docker exec -it mysql mysql -u root -e "FLUSH PRIVILEGES; \
  ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewRoot@2024!';"

# k8s
kubectl exec -it mysql-pod -- mysql -u root -e "
  FLUSH PRIVILEGES;
  ALTER USER 'root'@'localhost' IDENTIFIED BY 'NewRoot@2024!';"
```

### 注意事项

- 操作前**先备份** mysql.user 等系统表
- 临时跳过授权会**暴露数据库**,确保物理或网络隔离
- `--skip-grant-tables` 在 MySQL 8.0 中需要 `--skip-networking` 配合或加 `FLUSH PRIVILEGES` 后立即改密码,否则会触发 `[ERROR] [MY-013127]` 警告
- 改完密码**立即恢复正常模式**
- 改完后**审计**安全日志,确认无异常登录

## 九、SSL/TLS 加密连接

### 1. 证书准备

```bash
# 1. 创建 CA 私钥与证书
openssl genrsa 2048 > ca-key.pem
openssl req -new -x509 -nodes -days 3650 \
  -key ca-key.pem -out ca.pem \
  -subj "/CN=MySQL-CA"

# 2. 创建服务器私钥与 CSR
openssl genrsa 2048 > server-key.pem
openssl req -new -key server-key.pem -out server-req.pem \
  -subj "/CN=mysql-server"
openssl x509 -req -in server-req.pem -CA ca.pem -CAkey ca-key.pem \
  -CAcreateserial -out server-cert.pem -days 3650

# 3. 创建客户端私钥与证书
openssl genrsa 2048 > client-key.pem
openssl req -new -key client-key.pem -out client-req.pem \
  -subj "/CN=mysql-client"
openssl x509 -req -in client-req.pem -CA ca.pem -CAkey ca-key.pem \
  -CAcreateserial -out client-cert.pem -days 3650

# 4. 设置权限
chmod 400 ca-key.pem server-key.pem client-key.pem
chown mysql:mysql ca.pem server-cert.pem server-key.pem
```

### 2. 服务器端配置

```ini
# /etc/my.cnf
[mysqld]
ssl-ca   = /etc/mysql/ssl/ca.pem
ssl-cert = /etc/mysql/ssl/server-cert.pem
ssl-key  = /etc/mysql/ssl/server-key.pem

# 强制要求加密(可选,8.0.16+)
require_secure_transport = ON
```

```bash

```

## 十二、数据加密

### 1. 字段加密(AES)

```sql
-- 加密
INSERT INTO users (name, id_card) VALUES (
  '张三',
  AES_ENCRYPT('310000199001011234', UNHEX(SHA2('MyKey@2024', 256)))
);

-- 解密
```

### 2. 透明数据加密 TDE(MySQL 5.7+ / 8.0)

```sql
-- keyring 管理
```

### 3. 备份加密

```bash
# mysqldump 本身不加密,需用 openssl 包装

  -pass pass:MyBkP@2024 > app_db.sql.enc
```

## 十四、安全最佳实践清单

### 1. 账户与认证

- 删除匿名账户:`DROP USER ''@'localhost'`
- 删除 `test` 数据库
- 重命名或强化 `root`(8.0 起 `root` 默认使用 `auth_socket`)
- 限制 root 远程登录:`root` 仅本地
- 为每个应用创建独立账户
- 不使用 `'%'` 通配主机,精确到 IP 或网段
- 强密码(12+ 位,大小写+数字+符号)
- 90 天强制更换
- 启用密码重用限制

- 应用账户最小权限(无 FILE、SUPER、SHUTDOWN、GRANT)
- 业务账户无 DDL 权限
- 用角色统一管理权限
- 关闭 `WITH GRANT OPTION`(DBA 除外)
- 定期审计授权:`SELECT * FROM mysql.user`

### 3. 网络与传输

- 不暴露 3306 到公网
- 强制 SSL/TLS:`require_secure_transport = ON`
- 防火墙限制来源 IP
- 启用协议版本检查

### 4. 审计与监控

- 开启 audit_log / Percona Audit
- 监控登录失败次数
- 监控异常时段访问
- 关键表(用户、订单、支付)单独审计
- 慢查询告警

### 5. 数据保护

- 敏感字段加密(AES_ENCRYPT)
- 整库合规加密(TDE)
- 备份文件加密
- 密钥独立管理(KMS)
- 不在代码中硬编码密码
- 不在日志中打印明文

### 6. 运维规范

- 操作系统用户 `mysql` 运行 mysqld
- 文件权限 600/700
- binlog、slow log、error log 定期清理
- 升级到最新稳定版
- 订阅安全公告(CVE)
- 数据库账号密码定期轮换

### 7. SQL 注入防护

- 应用层使用预编译 / 预处理
- ORM 参数化查询
- 输入校验(白名单)
- WAF 辅助

## 十五、权限管理脚本示例

## 核心要点速记

### 1. 安全层次

- **网络层** 不暴露 3306,SSL/TLS
- **认证层** 强密码 + validate_password
- **授权层** 最小权限 + 角色
- **审计层** audit_log + general_log
- **数据层** 字段加密 + TDE

### 2. 权限层级

- **全局** `*.*`  存 `mysql.user`
- **库级** `db.*`  存 `mysql.db`
- **表级** `db.tbl`  存 `mysql.tables_priv`
- **列级** `tbl(col)`  存 `mysql.columns_priv`
- **验证顺序** 全局 → 库级 → 表级 → 列级,命中即放行

### 3. GRANT/REVOKE 关键

- `GRANT` 一次性完成授权和入表
- `REVOKE` 撤销权限(必须显式撤销 `GRANT OPTION`)
- 改完必须 `FLUSH PRIVILEGES`
- `WITH GRANT OPTION` 慎用,DBA 限定

### 4. 角色 (8.0+)

- `CREATE ROLE` 建角色
- `GRANT role TO user` 把角色给用户
- `SET ROLE` 激活,`SET DEFAULT ROLE` 持久化
- `mandatory_roles` 全员强制
- 调整角色一次,所有用户生效

### 5. 密码

- `validate_password.policy = 2` 强策略
- `default_password_lifetime = 90` 90 天换
- `password_history = 5` 5 个内不重用
- 强密码:12+ 位 + 大小写 + 数字 + 符号

### 6. 忘 root 密码

- `--skip-grant-tables` 重置(8.0 需配 `--skip-networking`)
- `--init-file` 启动时执行 SQL(8.0 推荐)
- 改完立即恢复正常模式,删除 init-file

### 7. SSL/TLS

- 自签:openssl 三对密钥(CA/Server/Client)
- 服务端:`ssl-ca` `ssl-cert` `ssl-key`
- 客户端:`--ssl-mode=REQUIRED`
- 用户级:`ALTER USER ... REQUIRE SSL`
- 全局强制:`require_secure_transport = ON`

### 8. 审计

- Enterprise:`audit_log`
- 开源:Percona Audit Log Plugin
- 临时:`general_log`(生产慎用)
- 性能:`performance_schema`

### 9. SQL 注入

- 永远用 **PREPARE/参数化**
- 应用层 ORM 参数绑定
- 绝不用字符串拼接
- 账户不给 FILE / SUPER

### 10. 加密选型

- **字段** AES_ENCRYPT
- **整库** TDE(Enterprise)
- **传输** SSL/TLS
- **备份** openssl / xtrabackup
- **密钥** 独立 KMS,不要硬编码

### 11. 最佳实践

- 删匿名账户、test 库
