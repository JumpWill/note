# Redis 五大基础数据类型

## 一、String 字符串类型

String 是 Redis 中最简单、最基础、也是使用频率最高的类型。一个 key 对应一个 value,value 可以是字符串、整数或浮点数,最大长度 **512 MB**。Redis 把所有键值对都封装在 `redisObject` 中,即使是最简单的 String,在底层也对应 **int / embstr / raw** 三种编码之一。

### 1.1 常用命令

#### (1) SET / GET 最基本读写

```bash
# SET key value [EX s] [PX ms] [NX|XX] [KEEPTTL]
# 返回 OK 表示设置成功,nil 表示条件不满足(已存在 / 不存在)
SET username "will"
OK

GET username
"will"

# GET 不存在时返回 nil(批量输出 (nil))
GET not_exist_key
(nil)

# SET 一个空字符串
SET empty_str ""
OK

# SET 时设置过期时间(EX = seconds, PX = milliseconds)
SET session:abc "user_data" EX 3600
OK

TTL session:abc
(integer) 3600

# 检查 key 是否存在
EXISTS username
(integer) 1

# 删除 key
DEL username
(integer) 1

# 再次 EXISTS 返回 0
EXISTS username
(integer) 0
```

**时间复杂度**:SET / GET / DEL 都是 **O(1)**。

#### (2) APPEND 追加

```bash
SET msg "hello"
OK

APPEND msg " world"
(integer) 11

GET msg
"hello world"

# key 不存在时等价于 SET
APPEND new_key "first"
(integer) 5

GET new_key
"first"
```

**时间复杂度**:追加字符串长度级别 **O(N)**,N 为追加的字节数。

#### (3) STRLEN 取长度

```bash
SET greeting "你好,Redis"
OK

STRLEN greeting
(integer) 11          # UTF-8 字节数(不是字符数)

STRLEN not_exist
(integer) 0
```

> 注意:STRLEN 返回的是**字节数**而非字符数,中文 UTF-8 占 3 字节。

#### (4) INCR / DECR / INCRBY / DECRBY / INCRBYFLOAT 数值增减

```bash
# INCR / DECR 步长为 1
SET counter 10
OK

INCR counter
(integer) 11

INCR counter
(integer) 12

DECR counter
(integer) 11

# INCRBY / DECRBY 指定步长
INCRBY counter 100
(integer) 111

DECRBY counter 50
(integer) 61

# INCRBYFLOAT 浮点数
SET price 19.99
OK

INCRBYFLOAT price 0.5
"20.49"

INCRBYFLOAT price -10
"10.49"

# 整数类型用 INCRBYFLOAT 会变成字符串
OBJECT ENCODING price
"embstr"

# 对不存在的 key INCR 会初始化为 0 然后 +1
INCR new_counter
(integer) 1
```

**关键特性**:`INCR` 系列命令是 **原子操作**(Redis 单线程命令执行模型保证),无需担心并发竞争。

**时间复杂度**:全部 **O(1)**。

#### (5) GETRANGE / SETRANGE 字符串切片

```bash
SET article "Hello Redis World"
OK

# GETRANGE key start end(包含两端),支持负数(-1 = 倒数第 1 个字符)
GETRANGE article 0 4
"Hello"

GETRANGE article -5 -1
"World"

GETRANGE article 0 -1
"Hello Redis World"

# SETRANGE key offset value:从 offset 处开始覆盖
SETRANGE article 6 "Redis"
(integer) 17

GET article
"Hello Redis World"     # 从位置 6 开始覆盖成 "Redis"(恰好相同)

# 演示覆盖效果:换成 "Java"
SET msg2 "Hello World"
OK

SETRANGE msg2 6 "Java"
(integer) 11

GET msg2
"Hello Java"
```

**时间复杂度**:均为 **O(N)**,N 为字符串长度。

#### (6) SETNX / SETEX / PSETEX

```bash
# SETNX = SET if Not eXists,key 不存在才设置(原子)
SETNX lock:order:1001 "ownerA"
(integer) 1

SETNX lock:order:1001 "ownerB"
(integer) 0          # 已存在,失败

# SETEX = SET + EX(以秒为单位过期)
SETEX verify_code:138 300 "8842"
OK

TTL verify_code:138
(integer) 300

# PSETEX = SET + PX(以毫秒为单位过期)
PSETEX token:xyz 5000 "abc123"
OK

PTTL token:xyz
(integer) 5000
```

> Redis 2.6.12 之后官方推荐用 `SET key value NX EX 300` 替代 `SETNX + EXPIRE`(原子)。

#### (7) MSET / MGET 批量操作

```bash
# MSET / MGET 都是 O(N),N 为 key 个数,但比循环 SET/GET 少 N-1 次网络往返
MSET k1 v1 k2 v2 k3 v3
OK

MGET k1 k2 k3
1) "v1"
2) "v2"
3) "v3"

# MSETNX 原子批量 NX,任意 key 已存在则全部失败
MSETNX k3 new_v3 k4 v4
(integer) 0          # k3 已存在,k4 也未设置

GET k4
(nil)
```

#### (8) GETSET / GETDEL / GETEX

```bash
# GETSET 设置新值并返回旧值(2.6.9 后被 SET ... GET 取代)
SET name "will"
OK

GETSET name "tom"
"will"

GET name
"tom"

# GETDEL = GET + DEL(6.2+)
SET temp_key "data"
OK

GETDEL temp_key
"data"

EXISTS temp_key
(integer) 0

# GETEX = GET + 可选过期(6.2+),支持 EX/PX/EXAT/PXAT/PERSIST
SET cache:item 100
OK

GETEX cache:item EX 60
"100"

TTL cache:item
(integer) 60

# 取值并清除过期
GETEX cache:item PERSIST
"100"

TTL cache:item
(integer) -1
```

### 1.2 SET 命令的可选参数详解

SET 命令自从 **Redis 2.6.12** 起支持一组语义清晰的选项,堪称"分布式锁的基石":

```bash
SET key value [EX seconds | PX milliseconds]
         [NX | XX]
         [EXAT unix-time-seconds | PXAT unix-time-milliseconds]
         [KEEPTTL]
         [GET]
```

| 选项 | 含义 | 引入版本 |
|------|------|----------|
| `EX seconds` | 以秒为单位设置过期时间(等价 SETEX) | 2.6.12 |
| `PX milliseconds` | 以毫秒为单位设置过期时间(等价 PSETEX) | 2.6.12 |
| `NX` | **仅当 key 不存在**才设置(等价 SETNX) | 2.6.12 |
| `XX` | **仅当 key 已存在**才设置 | 2.6.12 |
| `EXAT ts` | 过期时间点(unix 秒时间戳) | 6.2 |
| `PXAT ts` | 过期时间点(unix 毫秒时间戳) | 6.2 |
| `KEEPTTL` | 设置新值时**保留旧 TTL**(6.0+ 改名,2.6.12 起为 SETNX 场景的默认) | 6.0 |
| `GET` | 返回旧值,key 不存在返回 nil | 6.2 |

**组合示例**:

```bash
# 1. 分布式锁的标准写法(NX + PX)
SET lock:order:1001 "uuid-001" NX PX 30000
OK

# 2. 已存在才覆盖(常用于 CAS 更新)
SET counter 100 XX EX 60
OK

# 3. 绝对时间过期(下午 6 点失效,适合定时任务场景)
SET daily:reset 1 EXAT 1731602400
OK

# 4. 保留旧 TTL(避免覆盖时把过期时间重置为永久)
SET cache:item new_value KEEPTTL
OK

# 5. 取旧值再设新值(原子 GETSET)
SET user:1 name "alice"
OK

SET user:1 name "bob" GET
"alice"          # 返回旧值
```

> **坑点**:SET 选项之间互斥,如 `NX` 与 `XX` 不能同时使用;`EX` 与 `PX` 也不能同时使用;若同时指定会返回语法错误。

### 1.3 应用场景

#### (1) 缓存(最典型场景)

```bash
# 读流程:先查 Redis,miss 再回源 DB 并回写 Redis
GET user:1001:profile
(nil)              # cache miss

# 业务代码(伪代码):
profile = redis.GET("user:1001:profile")
if profile is None:
    profile = db.query("SELECT * FROM users WHERE id=1001")
    redis.SET("user:1001:profile", json.dumps(profile), EX=3600)
return profile

# 写流程:更新 DB 后失效缓存(避免脏读)
db.update("UPDATE users SET name='tom' WHERE id=1001")
redis.DEL("user:1001:profile")           # 失效
```

#### (2) 计数器(原子 INCR)

```bash
# 文章阅读数 / 视频播放数 / 接口调用次数
INCR article:1001:views
(integer) 1

INCR article:1001:views
(integer) 2

# 批量自增(配合 Lua 保证复合计数原子)
EVAL "
  redis.call('INCR', KEYS[1])
  redis.call('INCRBY', KEYS[2], ARGV[1])
  return 1
" 2 views:total views:day:20260814 1

# 取当前值
GET article:1001:views
"2"
```

**业务代码示例(限流)**:

```python
import redis
import time

r = redis.Redis()

def rate_limit(user_id, limit=10, window=60):
    """滑动窗口限流(简化版,固定窗口)"""
    key = f"rate:user:{user_id}:{int(time.time()) // window}"
    count = r.incr(key)
    if count == 1:
        r.expire(key, window)
    if count > limit:
        return False, "too many requests"
    return True, count
```

#### (3) 分布式 ID

```bash
# 单机递增 ID(每秒可生成 8w+,分布式场景需配合 worker 编号避免冲突)
INCR global:order:id
(integer) 100001

INCR global:order:id
(integer) 100002

# 订单 ID = 时间戳 + 业务前缀 + 自增序号
# 100001 -> 20260814_ORD_100001
```

#### (4) Session / Token 存储

```bash
# 登录成功,写 Session(设置 30 分钟过期)
SET session:abc123 "{\"uid\":1001,\"name\":\"will\"}" EX 1800
OK

# 鉴权时读取,失效自动清理
GET session:abc123
"{\"uid\":1001,\"name\":\"will\"}"

# 主动登出
DEL session:abc123
(integer) 1
```

#### (5) 分布式锁(标准写法)

```python
import redis
import uuid
import time

r = redis.Redis()
LOCK_KEY = "lock:resource:1001"

def acquire_lock(ttl_ms=30000):
    """获取锁:SET NX PX"""
    token = str(uuid.uuid4())
    ok = r.set(LOCK_KEY, token, nx=True, px=ttl_ms)
    return token if ok else None

def release_lock(token):
    """释放锁:Lua 脚本保证原子(只有持有者才能释放)"""
    lua = """
    if redis.call('GET', KEYS[1]) == ARGV[1] then
        return redis.call('DEL', KEYS[1])
    else
        return 0
    end
    """
    return r.eval(lua, 1, LOCK_KEY, token)

# 使用
token = acquire_lock()
if token:
    try:
        do_critical_work()
    finally:
        release_lock(token)
```

#### (6) 限流(INCR + EXPIRE 固定窗口)

```bash
# 简单限流:每分钟最多 100 次
INCR rate:api:user:1001
(integer) 1

# 第一次 INCR 时设置过期
EXPIRE rate:api:user:1001 60
(integer) 1

# 业务逻辑
count = GET rate:api:user:1001
if int(count) > 100:
    return "rate limited"
```

### 1.4 底层编码

| 编码 | 触发条件 | 内存布局 | 大小上限 |
|------|----------|----------|----------|
| **int** | value 是整数且可用 long 表示(`8` 字节) | 直接存到 `ptr`(整数复用) | long 范围 |
| **embstr** | 字符串长度 ≤ **44 字节** | `redisObject + sdshdr` 一次 malloc | 44 B |
| **raw** | 字符串长度 > 44 字节 | `redisObject` 和 SDS 各一次 malloc | 512 MB |

```bash
SET small_int 100
OBJECT ENCODING small_int
"int"

SET tiny_str "hello"
OBJECT ENCODING tiny_str
"embstr"

SET big_str "this is a long string that exceeds 44 bytes for sure..."
OBJECT ENCODING big_str
"raw"

# 浮点数也是 embstr
SET float_val 3.14
OBJECT ENCODING float_val
"embstr"

# INCR 后整数溢出 / 类型改变不会自动降级
SET num 9999999999999999999
OBJECT ENCODING num
"embstr"          # 大整数用字符串表示
```

**embstr 与 raw 的临界值 = 44 字节**,因为:

```text
┌─────────────────────────────────────────────────────────┐
│ redisObject 16 字节 + sdshdr8 头 3 字节(len/alloc/flags)│
│   + \0 结束符 1 字节 + 64 位对齐填充                   │
│   = 19 字节固定开销,SDS 容量 = 64 - 19 = 45 字节       │
│   但要预留 \0,实际可存储字符串 = 44 字节               │
└─────────────────────────────────────────────────────────┘
```

**编码转换**:**int → embstr/raw**(整数被 `APPEND` / `INCRBYFLOAT` 等改成字符串后)、**embstr → raw**(APPEND 后长度超过 44 B 时,Redis 不会就地扩容而是重新分配 raw)。**注意不会自动降级**。

## 二、Hash 哈希类型

Hash 是**字段-值(field-value)**对的集合,适合存储**对象**。可以把 Hash 理解为"一个 key 对应一个迷你 Map"。field 和 value 都是字符串类型,单个 Hash 最多可包含 **2³² - 1** 个 field。

### 2.1 常用命令

#### (1) HSET / HGET / HMSET / HMGET

```bash
# HSET key field value [field value ...]
# 4.0 之前需用 HMSET,4.0 后 HSET 支持批量,返回新增 field 数
HSET user:1001 name "will" age 30 email "will@example.com"
(integer) 3

HGET user:1001 name
"will"

HMGET user:1001 name age email
1) "will"
2) "30"
3) "will@example.com"

# HGET 不存在的 field 返回 nil
HGET user:1001 phone
(nil)

# HMSET 已被废弃(4.0+),不推荐
```

#### (2) HDEL / HEXISTS / HLEN

```bash
HDEL user:1001 email
(integer) 1

HEXISTS user:1001 name
(integer) 1

HEXISTS user:1001 email
(integer) 0

HLEN user:1001
(integer) 2
```

#### (3) HGETALL / HKEYS / HVALS

```bash
HSET user:1001 name "will" age 30 city "shanghai"
(integer) 3

HGETALL user:1001
1) "name"
2) "will"
3) "age"
4) "30"
5) "city"
6) "shanghai"

HKEYS user:1001
1) "name"
2) "age"
3) "city"

HVALS user:1001
1) "will"
2) "30"
3) "shanghai"
```

> **大 Hash 慎用 HGETALL**:返回所有 field-value 会阻塞主线程且占用大带宽。生产环境推荐 `HSCAN` 迭代。

#### (4) HSETNX / HSTRLEN

```bash
# HSETNX 仅当 field 不存在才设置
HSETNX user:1001 name "tom"
(integer) 0          # name 已存在

HSETNX user:1001 phone "13800138000"
(integer) 1

HSTRLEN user:1001 phone
(integer) 11
```

#### (5) HINCRBY / HINCRBYFLOAT

```bash
# 商品库存、点赞数等
HSET product:5001 stock 100
(integer) 1

HINCRBY product:5001 stock -1
(integer) 99

HINCRBY product:5001 stock 10
(integer) 109

HINCRBYFLOAT product:5001 price 1.5
"101.5"
```

#### (6) HRANDFIELD(6.2+)

```bash
HSET user:1001 name "will" age 30 city "shanghai" job "dev" hobby "code"
(integer) 5

# 随机取 1 个 field(返回 field 名)
HRANDFIELD user:1001
"hobby"

# 随机取 1 个 field-value 对
HRANDFIELD user:1001 1 WITHVALUES
1) "age"
2) "30"

# 随机取 3 个 field,可重复(默认)
HRANDFIELD user:1001 3
1) "city"
2) "name"
3) "age"

# 不重复的随机 N 个
HRANDFIELD user:1001 3 WITHVALUES
1) "job"
2) "dev"
3) "city"
4) "shanghai"
5) "name"
6) "will"
```

### 2.2 应用场景

#### (1) 对象存储(替代多 String)

```bash
# 方案 A:用多个 String
SET user:1001:name "will"
SET user:1001:age 30
SET user:1001:email "will@example.com"

# 问题:
# 1. key 数量爆炸
# 2. 原子更新麻烦(需要 MULTI/EXEC 或 Lua)
# 3. 占用更多 redisObject(每个 key 都是 16 字节)

# 方案 B:用 Hash(推荐)
HSET user:1001 name "will" age 30 email "will@example.com"

# 优点:
# 1. 一次 HSET 设置多个字段,原子
# 2. 只占用 1 个 redisObject
# 3. HGETALL 一次取所有字段
# 4. HINCRBY 实现字段级原子增减
```

#### (2) 用户 Profile / 商品 SKU

```bash
# 商品规格多维度存储
HSET sku:8888 title "iPhone 15 Pro" price 7999 stock 50 brand "Apple" category "phone"
(integer) 5

HINCRBY sku:8888 stock -1
(integer) 49

# 取部分字段渲染商品详情页
HMGET sku:8888 title price stock
1) "iPhone 15 Pro"
2) "7999"
3) "49"
```

#### (3) 购物车(经典案例)

```python
import redis

r = redis.Redis()
CART_KEY = "cart:user:1001"

# 加入购物车
def add_to_cart(item_id, qty=1):
    r.hincrby(CART_KEY, item_id, qty)

# 删除商品
def remove_from_cart(item_id):
    r.hdel(CART_KEY, item_id)

# 修改数量
def update_qty(item_id, qty):
    r.hset(CART_KEY, item_id, qty)

# 查看购物车
def view_cart():
    return r.hgetall(CART_KEY)        # {item_id: qty}

# 清空
def clear_cart():
    r.delete(CART_KEY)

add_to_cart("sku:8888", 1)
add_to_cart("sku:7777", 2)
view_cart()
# {b'sku:8888': b'1', b'sku:7777': b'2'}
```

#### (4) 配置中心

```bash
# 集中式配置,运行时可热更新
HSET config:service:order max_retry 3 timeout_ms 5000 feature.switch "on" rate_limit 100
(integer) 4

# 服务启动时加载
HGETALL config:service:order
```

#### (5) 标签聚合

```bash
# 用户标签系统
HSET tag:user:1001 vip "gold" city "shanghai" age_range "25-30" active "high"
(integer) 4

# 标签筛选:HVALS + Lua / 业务层过滤
HVALS tag:user:1001
1) "gold"
2) "shanghai"
3) "25-30"
4) "high"
```

### 2.3 底层编码

| 编码 | 触发条件 | 适用 |
|------|----------|------|
| **listpack**(Redis 7.0+ 默认) | 同时满足:field 数 ≤ `hash-max-listpack-entries`(默认 128)且 value 字节 ≤ `hash-max-listpack-value`(默认 64) | 小 Hash |
| **hashtable** | 上述任一阈值超出 | 大 Hash |

```bash
# 小 Hash 用 listpack
HSET h_small f1 v1 f2 v2
OBJECT ENCODING h_small
"listpack"

# 超过 128 个 field,自动转 hashtable
# (这里用脚本批量写入演示)
EVAL "
  for i=1,200 do
    redis.call('HSET', KEYS[1], 'f'..i, 'v'..i)
  end
" 1 h_big
(nil)

OBJECT ENCODING h_big
"hashtable"

# 即使删除到 128 以下,也不会自动降级
HDEL h_big f1 f2 f3
(integer) 3

HLEN h_big
(integer) 197

OBJECT ENCODING h_big
"hashtable"          # 仍为 hashtable,不降级
```

**listpack 编码结构**:

```text
┌──────────────────────────────────────────────┐
│  entry: <encode-len><backlen><field><value> │
│  entry: <encode-len><backlen><field><value> │
│  ...                                         │
│  end: 0xFF                                   │
└──────────────────────────────────────────────┘
```

每个 entry 自包含长度信息,无需 prevlen 指针,避免级联更新。

## 三、List 列表类型

List 是**有序、可重复**的字符串序列,按插入顺序排序。Redis 的 List 底层采用 **quicklist**(双向链表 + listpack 节点),支持**双向操作**且实现**阻塞式**消费。最大元素数 **2³² - 1**。

### 3.1 常用命令

#### (1) LPUSH / RPUSH / LPOP / RPOP

```bash
# LPUSH 从左侧(头部)插入,RPUSH 从右侧(尾部)插入
LPUSH tasks "task1"
(integer) 1

LPUSH tasks "task0"
(integer) 2

RPUSH tasks "task2"
(integer) 3

# 一次插入多个
RPUSH tasks "task3" "task4" "task5"
(integer) 6

LRANGE tasks 0 -1
1) "task0"
2) "task1"
3) "task2"
4) "task3"
5) "task4"
6) "task5"

# LPOP / RPOP 弹出
LPOP tasks
"task0"

RPOP tasks
"task5"

LRANGE tasks 0 -1
1) "task1"
2) "task2"
3) "task3"
4) "task4"

# 6.2+ 可指定 count 一次弹出多个
LPOP tasks 2
1) "task1"
2) "task2"

LRANGE tasks 0 -1
1) "task3"
2) "task4"
```

#### (2) LLEN / LRANGE / LINDEX

```bash
LLEN tasks
(integer) 2

LRANGE tasks 0 -1
1) "task3"
2) "task4"

# 取下标 1(从 0 开始)
LINDEX tasks 1
"task4"

# 下标越界返回 nil
LINDEX tasks 10
(nil)

LRANGE tasks 0 0
1) "task3"
```

#### (3) LINSERT / LSET / LREM

```bash
RPUSH letters a b c d e
```

### 3.2 应用场景

#### (1) 消息队列(简易版)

```python
import redis
import json

r = redis.Redis()
QUEUE = "queue:emails"

# 生产者:RPUSH
def enqueue(email):
    r.rpush(QUEUE, json.dumps(email))

# 消费者:BLPOP 阻塞等待
def consume(timeout=5):
    result = r.blpop(QUEUE, timeout=timeout)
    if result:
        _, payload = result
        return json.loads(payload)
    return None
```

> Redis List 队列**不保证 ACK**,生产建议用 Stream(第 5 章)或专业 MQ。


#### (3) 微博/朋友圈时间线(FIFO 队列)


#### (4) 任务队列 + 死信(可靠队列模式)

```python
# LMOVE 实现"处理中"队列
WORK = "queue:working"
DONE = "queue:done"

def reserve_task(timeout=5):
    # 从主队列取出,放入 working 队列(原子)
    task = r.lmove("queue:tasks", WORK, "RIGHT", "LEFT")
    return task

def ack_task(task):
    # 处理完成后从 working 移除
    r.lrem(WORK, 1, task)

def requeue(timeout=30):
    # 兜底:把超时未 ack 的从 working 退回主队列
    while True:
        task = r.lmove(WORK, "queue:tasks", "LEFT", "RIGHT")
        if not task:
            break
```

## 四、Set 集合类型

Set 是**无序、不重复**的字符串集合。底层使用 **dict / intset**,提供交、并、差等集合运算,非常适合标签、共同好友、抽奖、UV 统计等场景。最大成员数 **2³² - 1**。

### 4.1 常用命令

#### (1) SADD / SMEMBERS / SREM / SISMEMBER

```bash
SADD tags:user:1001 "tech" "music" "movie" "sports"
(integer) 4

# 重复添加返回 0
SADD tags:user:1001 "tech"
(integer) 0

SMEMBERS tags:user:1001
1) "tech"
2) "music"
3) "movie"
4) "sports"

SISMEMBER tags:user:1001 "tech"
(integer) 1

SISMEMBER tags:user:1001 "cooking"
(integer) 0

SREM tags:user:1001 "sports"
(integer) 1

SCARD tags:user:1001
(integer) 3
```

```bash
"movie"

(integer) 2

SPOP tags:user:1001 1
1) "music"

# SRANDMEMBER 随机取但不删

2) "music"
```

## 五、ZSet 有序集合类型

Sorted Set(ZSet)是 Set 的"超集":每个 member 关联一个 **score(浮点数)**,按 score 升序排列,score 相同时按 member 字典序。底层采用 **skiplist + dict 双结构**,既能 O(log N) 范围查询,又能 O(1) 取 member 的 score。最大成员数 **2³² - 1**。

### 5.1 常用命令

#### (1) ZADD / ZSCORE / ZCARD

```bash
# ZADD key [NX|XX] [GT|LT] [CH] [INCR] score member [score member ...]
ZADD rank:game 100 "playerA" 95 "playerB" 88 "playerC"
(integer) 3

# 更新已有 member 的 score
ZADD rank:game 105 "playerA"
(integer) 0          # 0 = 更新,1 = 新增(可用 CH 选项改返回"变化的 member 数")

# GT/LT(6.2+):条件更新
ZADD rank:game GT 200 "playerA"      # 仅当新 score > 旧 score 才更新
(integer) 0

ZSCORE rank:game playerA
"200"

ZCARD rank:game
(integer) 3
```

**ZADD 关键选项**:

| 选项 | 含义 |
|------|------|
| `NX` | member 不存在才添加 |
| `XX` | member 已存在才更新 score |
| `GT` | 仅当新 score **大于**旧 score 才更新(6.2+) |
| `LT` | 仅当新 score **小于**旧 score 才更新(6.2+) |
| `CH` | 返回值改为"变化的 member 数"(新增 + 更新),默认返回"新增数" |
| `INCR` | 等价 ZINCRBY,返回新 score |

#### (2) ZINCRBY / ZRANGE / ZREVRANGE

```bash

3) "playerA"
4) "200"
5) "playerC"
6) "93"

1) "playerA"
2) "200"
3) "playerB"
4) "95"
5) "playerC"
6) "93"

# 取 Top 3

1) "playerA"
2) "200"
3) "playerB"
4) "95"
5) "playerC"
6) "93"
```

#### (3) ZRANGEBYSCORE / ZREVRANGEBYSCORE

```bash

3) "playerB"

5) "playerA"
6) "200"
```


### 5.2 跳表 + 哈希表双结构

ZSet 的底层结构是 **skiplist + dict(哈希表)的组合**,两者通过指针共享同一组成员:

```text
┌────────────────────────────────────────────────────────────┐
│ ZSet 对象                                                   │
│                                                            │
│  ┌──────────────────────────────┐  ┌───────────────────┐  │
│  │      zskiplist              │  │       dict        │  │
│  │  ┌──────┐                   │  │  key → score     │  │
│  │  │ head │ level 4           │  │  "alice" → 95   │  │
│  │  └──────┘                   │  │  "bob"   → 100  │  │
│  │     │                       │  │  ...             │  │
│  │     ▼                       │  │                   │  │
│  │  ┌──────┐  ┌──────┐  ┌──────┐│  │  O(1) 查 score   │  │
│  │  │ a 95 │→ │ c 88 │→ │ b100 ││  └───────────────────┘  │
│  │  └──────┘  └──────┘  └──────┘│                          │
│  │   level 3     level 1   level 2                         │
│  │                                                            │
│  │  ZRANGE / ZRANK / ZRANGEBYSCORE = O(log N)             │
│  │  ZSCORE = O(1)(走 dict)                                │
│  └──────────────────────────────┘                          │
└────────────────────────────────────────────────────────────┘
```

**skiplist 关键参数**:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 层数上限 `ZSKIPLIST_MAXLEVEL` | 32 | 实际很少超过 10 |
| 晋升概率 `ZSKIPLIST_P` | 0.25 | 每上一层概率 1/4,平衡空间与查询 |
| 跨度 `span` | — | 节点间跨越的节点数,用于 O(log N) 计算排名 |

```bash
# 验证编码
OBJECT ENCODING rank:game
"skiplist"

# 7.0+ 小 ZSet 也可能用 listpack(编码名显示为 listpack)
ZADD small_zset 1 a
OBJECT ENCODING small_zset
"listpack"          # 7.0+ 小 ZSet 默认
```

**Python 业务代码**:

```python
import redis

r = redis.Redis()
LB = "leaderboard:game1"

def add_score(player, score):
    r.zincrby(LB, score, player)

def top_n(n=10):
    return r.zrevrange(LB, 0, n - 1, withscores=True)

def player_rank(player):
    rank = r.zrevrank(LB, player)        # 0-based
    score = r.zscore(LB, player)
    return rank, score
```

#### (3) 滑动窗口限流

```python
def sliding_window(uid, window_ms=1000, limit=5):
    """滑动窗口:score = 时间戳(毫秒)"""
    key = f"rate:sliding:{uid}"
    now = int(time.time() * 1000)
    cutoff = now - window_ms

    pipe = r.pipeline()
    pipe.zremrangebyscore(key, 0, cutoff)   # 移除窗口外
    pipe.zcard(key)                          # 当前计数
    pipe.zadd(key, {str(uuid.uuid4()): now})
    pipe.expire(key, window_ms // 1000 + 1)
    results = pipe.execute()
    count = results[1]
    return count <= limit
```

```bash
# 取 Top 20
```

**决策口诀**:

```text
一值用 String,字段用 Hash,序列用 List。
不重且无序用 Set,排序不重用 ZSet。
```

**常见误区**:

| 误区 | 正确做法 |
|------|----------|
| 用 String + JSON 存整个对象 | 小字段多时改用 Hash(节省内存,支持字段级操作) |
| 用 List 做排行榜 | List 没有按 score 排序,改用 ZSet(`ZRANGE` O(log N) 而非 LRANGE O(N)) |
| 用 Set 做计数 | SCARD 计数耗时 O(1),但 Set 元素多时内存大,大量计数场景用 HyperLogLog |
| 用 ZSet 做消息队列 | ZSet 没有 ACK,生产用 Stream 或专业 MQ(见第 5 章) |
| 用 List 做去重 | List 允许重复,改用 Set |

## 九、核心要点速记

- **五大基础类型**:String / Hash / List / Set / ZSet,本质都是 `redisObject`(16 字节),通过不同编码适应场景
- **String 最大 512 MB**,编码按值长度和类型自动选择 **int / embstr / raw**
- **embstr 临界值 = 44 字节**(64 位对齐 - 19 字节头 - 1 字节 `\0`),小字符串优化为一次 malloc
- **SET 命令核心选项**:`NX` / `XX` / `EX` / `PX` / `EXAT` / `PXAT` / `KEEPTTL` / `GET`,互斥使用
- **INCR 系列原子计数**:Redis 单线程命令执行模型保证,无需额外加锁;支持整数与浮点
- **String 场景**:缓存(Session/Token)、计数器(阅读数/限流)、分布式锁(`SET NX PX` + Lua 释放)、分布式 ID
- **Hash 适用对象存储**:`user:1001 → {name, age, email}`,字段级 `HINCRBY` 实现购物车 / 库存
- **Hash 编码阈值**:成员 ≤ `hash-max-listpack-entries`(128)且 value ≤ `hash-max-listpack-value`(64) → listpack,否则 hashtable
- **List 底层 quicklist**:双向链表 + listpack 节点,`LPUSH` / `RPUSH` 头尾 O(1),`LRANGE` / `LINSERT` O(N)
- **List 阻塞消费**:`BLPOP` / `BRPOP` / `BLMOVE`(替代 BRPOPLPUSH),可用于消息队列 / 延迟处理
- **LTRIM 配合 LPUSH** 实现"只保留最近 N 条",如浏览历史 / 实时日志
- **Set 编码**:全整数且 ≤ `set-max-intset-entries`(512)→ intset,否则 hashtable;**intset 升级不降级**
- **Set 集合运算**:`SINTER` / `SUNION` / `SDIFF` 及其 STORE 版本,`SINTERCARD`(7.0+)只取基数
- **Set 场景**:标签、共同好友(`SINTER`)、抽奖(`SPOP`)、UV 去重(`SCARD`)、黑白名单
- **ZSet 双结构**:**skiplist(范围 / 排名 O(log N))+ dict(分数 O(1))**,共享同一组成员
- **ZSet 编码阈值**:成员 ≤ `zset-max-listpack-entries`(128)且 member ≤ `zset-max-listpack-value`(64) → listpack(7.0+ 默认);**高级命令触发后不会降级**
- **ZSet 关键命令**:`ZADD`(`NX/XX/GT/LT/CH/INCR`)、`ZRANGE`/`ZREVRANGE`、`ZRANGEBYSCORE`、`ZRANK`/`ZREVRANK`、`ZINCRBY`、`ZUNIONSTORE`/`ZINTERSTORE`
- **ZSet 场景**:排行榜(`ZREVRANGE 0 9`)、延迟队列(`ZRANGEBYSCORE 0 now`)、滑动窗口限流
- **底层编码转换**:listpack → hashtable / skiplist 是**单向**的,删除数据不会触发降级
- **OBJECT ENCODING** 查看当前编码;**OBJECT HELP** 查看用法
- **大集合慎用全量命令**:HGETALL、SMEMBERS、ZRANGE 0 -1 在大 key 上会阻塞主线程,生产用 HSCAN / SSCAN / ZSCAN 迭代
- **命令时间复杂度**:String 大部分 O(1);Hash 单字段 O(1),全量 O(N);List 头尾 O(1) 中间 O(N);Set 单元素 O(1),集合运算 O(N);ZSet 几乎都是 O(log N) 或 O(log N + M)
- **类型选择口诀**:**一值用 String,字段用 Hash,序列用 List,不重且无序用 Set,排序不重用 ZSet**
- **常见反模式**:用 String+JSON 存对象(改 Hash)、用 List 做排行榜(改 ZSet)、用 ZSet 做可靠队列(改 Stream)
- **版本演进**:7.0+ Hash / ZSet 默认 listpack 编码(原 ziplist 替代);6.2+ 新增 `GETDEL` / `GETEX` / `HRANDFIELD` / `ZADD GT/LT` / `LMOVE`;6.2 起 `BRPOPLPUSH` 弃用,改 `BLMOVE`
- **跨类型共性**:所有命令 O(N) 操作中的 N 均为元素个数,与 Redis 总 key 数无关;`TYPE` 命令可查看 key 类型;`OBJECT ENCODING` 查看底层编码
