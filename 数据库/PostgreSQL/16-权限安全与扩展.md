# PostgreSQL 权限、安全与扩展 (Privileges, Security & Extensions)

> 本章涵盖 PostgreSQL 的完整安全体系(用户/角色、权限模型、行级安全 RLS、密码认证、SSL/TLS 加密、审计、SQL 注入防护、防火墙)以及 PG 最强大的武器——**扩展生态**(包括 pgvector、PostGIS、pg_stat_statements、pgBackRest 等)。

## 一、PG 安全概述

### 1. 安全威胁全景

- **未授权访问**:弱口令、暴露在公网、默认账户(`postgres`)、trust 认证
- **权限越权**:账户被授予超过业务需要的权限(`SUPERUSER` 滥用)
- **数据泄露**:明文传输、备份泄露、日志泄露、`pg_stat_statements` 抓取
- **数据篡改**:SQL 注入、提权攻击、`COPY ... PROGRAM` 执行系统命令
- **拒绝服务**:连接耗尽、长事务、锁等待、慢查询、磁盘写满
- **审计缺失**:无法追溯谁做了什么、谁删了数据
- **合规风险**:GDPR、个保法、PCI-DSS、等保三级等合规要求

### 2. 安全基本原则

- **最小特权 (Least Privilege)**:只给业务必需的权限
- **纵深防御 (Defense in Depth)**:网络 + 主机 + 数据库 + 应用多层防护
- **失效安全 (Fail Safe)**:失败时进入安全状态(默认拒绝)
- **职责分离 (Separation of Duties)**:DBA、应用账号、审计账号分离
- **默认拒绝 (Default Deny)**:`pg_hba.conf` 默认 `reject`,按需 `md5`/`scram-sha-256`
- **可审计 (Auditable)**:所有操作有迹可循(`pgaudit`)

### 3. PG 安全层次

| 层次 | 措施 | 说明 |
|------|------|------|
| 网络层 | `listen_addresses`、防火墙、SSL/TLS | 限制谁能连 |
| 主机层 | 操作系统权限、SSH 密钥 | 谁能登机器 |
| 协议层 | SSL/TLS 加密 | 传输是否泄露 |
| 认证层 | `pg_hba.conf`、`scram-sha-256` | 谁能进 PG |
| 授权层 | 角色/权限、RLS、列级权限 | 能做什么 |
| 审计层 | `pgaudit`、`log_statement` | 做了什么 |
| 数据层 | `pgcrypto`、TDE(第三方) | 数据本身加密 |

### 4. PG 与 MySQL 安全模型差异

| 维度 | PostgreSQL | MySQL |
|------|------------|-------|
| 用户/角色 | `ROLE` 一统天下(`USER` 是带 LOGIN 的 ROLE) | `user@host` 二元组 |
| 行级安全 | **内置 RLS**(PG 杀手锏) | 需应用层实现 |
| 列级加密 | `pgcrypto` 扩展 | `AES_ENCRYPT` 函数 |
| 密码哈希 | `scram-sha-256`(默认)、`md5`、`password` | `caching_sha2_password`、`mysql_native_password` |
| 认证配置 | `pg_hba.conf`(集中) | 用户自带(`CREATE USER` 内) |
| Schema 隔离 | 原生 Schema(每库多 Schema) | 通过 `db.*` 控制 |
| 默认加密 | 10 默认 `scram-sha-256` | 8.0 默认 `caching_sha2_password` |

## 二、用户与角色管理

### 1. 角色概念

PG 中 `USER` 和 `ROLE` 本质相同,唯一的区别是:**`USER` 默认带 `LOGIN` 属性,`ROLE` 不带**。生产中**全部用 ROLE** 概念更准确。

```sql
-- 等价写法
CREATE USER app_user WITH PASSWORD 'App@2024';   -- 隐含 LOGIN
CREATE ROLE app_user LOGIN PASSWORD 'App@2024';  -- 显式 LOGIN

-- 纯角色(不能登录,只能被授予)
CREATE ROLE app_read;
```

### 2. CREATE ROLE / CREATE USER

```sql
-- 基础语法
CREATE ROLE name [ [ WITH ] option [ ... ] ];

-- 常用 option
--  SUPERUSER | NOSUPERUSER      超级用户
--  CREATEDB | NOCREATEDB        是否能建库
--  CREATEROLE | NOCREATEROLE    是否能建/改/删其他角色
--  LOGIN | NOLOGIN              是否能登录
--  REPLICATION | NOREPLICATION  用于流复制的专用属性
--  BYPASSRLS | NOBYPASSRLS      是否绕过行级安全
--  CONNECTION LIMIT n           最大并发连接数
--  IN ROLE role_name            把该角色加入其他角色(成员)
--  IN GROUP role_name           同 IN ROLE(旧语法)
--  ROLE role_name                把其他角色加入该角色(反向)
--  ADMIN role_name              同 ROLE,但能再授权
--  PASSWORD 'password'          设置密码
--  VALID UNTIL 'timestamp'      密码过期时间
--  INHERIT | NOINHERIT          是否自动继承父角色权限
```

```sql
-- 创建应用账户
CREATE ROLE app_order WITH LOGIN PASSWORD 'Ord3r@2024!';

-- 创建只读账户
CREATE ROLE report_ro WITH LOGIN PASSWORD 'R3ad@2024' CONNECTION LIMIT 10;

-- 创建 DBA 账户
CREATE ROLE dba_alice WITH LOGIN SUPERUSER PASSWORD 'Dba@2024!';

-- 创建角色继承(可登录,继承父角色权限)
CREATE ROLE app_owner INHERIT LOGIN PASSWORD 'Owner@2024';

-- 创建只到某时间有效的账户
CREATE ROLE temp_user WITH LOGIN PASSWORD 'Tmp@2024' VALID UNTIL '2026-12-31';

-- 创建可建库建角色但非超管
CREATE ROLE dev_lead WITH LOGIN CREATEDB CREATEROLE PASSWORD 'Lead@2024';
```

### 3. ALTER ROLE / ALTER USER

```sql
-- 修改密码
ALTER ROLE app_order WITH PASSWORD 'NewPwd@2025';

-- 加属性
ALTER ROLE app_order WITH CREATEDB;
ALTER ROLE app_order WITH CONNECTION LIMIT 50;

-- 改密码有效期
ALTER ROLE app_order VALID UNTIL '2027-12-31';
ALTER ROLE app_order VALID UNTIL 'infinity';  -- 永不过期

-- 改名
ALTER ROLE app_order RENAME TO app_order_v2;

-- 锁定(设置 NOLOGIN,等价于禁用)
ALTER ROLE app_order WITH NOLOGIN;

-- 解锁
ALTER ROLE app_order WITH LOGIN;
```

### 4. DROP ROLE / DROP USER

```sql
-- 删除角色
DROP ROLE app_order;

-- 删除多个
DROP ROLE temp_user, dev_test;

-- 若角色还有依赖(如拥有的对象),先转移
REASSIGN OWNED BY app_order TO postgres;  -- 把对象转给 postgres
DROP OWNED BY app_order;                   -- 删除角色在对象上的授权
DROP ROLE app_order;                       -- 最后删角色
```

### 5. SET ROLE / SET SESSION AUTHORIZATION

PG 的角色切换机制,**比 MySQL 的 `SET ROLE` 更强大**。

```sql
-- 当前会话以哪个角色身份
SELECT current_user, session_user, current_role;

-- SET ROLE:临时切换到另一角色(可来回切)
SET ROLE app_read;
SHOW ROLE;                    -- 显示当前 role

-- SET ROLE NONE 恢复
RESET ROLE;

-- SET SESSION AUTHORIZATION:切换 session_user(更彻底,影响 current_user)
SET SESSION AUTHORIZATION app_read;

-- 恢复
RESET SESSION AUTHORIZATION;

-- 应用场景:用低权限账户连接,执行中切到高权限账户完成运维
-- 通常通过 `SET ROLE <role>` + 角色成员关系授权实现
```

### 6. 完整示例

```sql
-- 1. 创建一个分层角色结构
-- 顶层:dba(超管)、app_owner(应用主)、report_ro(只读)
CREATE ROLE dba        WITH SUPERUSER LOGIN PASSWORD 'Dba@2024!';
CREATE ROLE app_owner  WITH LOGIN CREATEDB CREATEROLE PASSWORD 'Owner@2024';
CREATE ROLE report_ro  WITH LOGIN PASSWORD 'Report@2024';

-- 2. 业务角色(纯权限集合)
CREATE ROLE role_order_read;
CREATE ROLE role_order_write;
CREATE ROLE role_order_admin;

-- 3. 把业务权限赋给角色
GRANT CONNECT ON DATABASE order_db TO role_order_read, role_order_write;
GRANT USAGE ON SCHEMA public TO role_order_read, role_order_write;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO role_order_read;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO role_order_write;

-- 4. 让用户继承角色
GRANT role_order_read TO report_ro;
GRANT role_order_write TO app_owner;

-- 5. 应用登录后激活相应角色
-- \c - app_owner
-- SET ROLE role_order_write;

-- 6. 删除时清理顺序
REVOKE role_order_write FROM app_owner;
DROP OWNED BY role_order_write;
DROP ROLE role_order_write;
```

## 三、权限模型

PG 权限体系比 MySQL **丰富得多**:不仅有 DML/DDL 权限,还有 USAGE、REFERENCES、TRIGGER、EXECUTE、SET、ALTER、INDEX、DROP 等十几种对象权限,且支持**列级**与**行级**(RLS)。

### 1. 权限类别总览

| 权限 | 适用对象 | 说明 |
|------|----------|------|
| `SELECT` | 表/视图/列 | 读 |
| `INSERT` | 表/列 | 插入 |
| `UPDATE` | 表/列 | 更新 |
| `DELETE` | 表 | 删除 |
| `TRUNCATE` | 表 | 清空 |
| `REFERENCES` | 表/列 | 创建外键 |
| `TRIGGER` | 表 | 创建触发器 |
| `CREATE` | 数据库/Schema/表空间 | 创建对象 |
| `CONNECT` | 数据库 | 连接数据库 |
| `TEMPORARY` | 数据库 | 建临时表 |
| `USAGE` | 域/Foreign Data Wrapper/语言/Schema/序列/类型 | "使用"权 |
| `EXECUTE` | 函数/过程 | 调用 |
| `SET` | 配置参数 | SET param |
| `ALTER SYSTEM` | 配置参数 | ALTER SYSTEM |
| `ALTER` | 表/序列/数据库/函数等 | 修改 |
| `INDEX` | 表 | 建索引 |
| `DROP` | 任意 | 删除 |
| `MAINTAIN` | 表 | VACUUM/ANALYZE/REINDEX/CLUSTER/LOCK(14+) |
| `REFRESH` | 物化视图 | REFRESH |
| `RULE` | 表/视图 | CREATE RULE |
| `ALL PRIVILEGES` | 任意 | 所有上述权限(不含 GRANT OPTION) |

### 2. 系统权限(角色属性)

这些不是 GRANT 出来的,而是 `CREATE/ALTER ROLE` 时通过属性赋予:

| 属性 | 说明 |
|------|------|
| `SUPERUSER` | 跳过所有权限检查,慎用 |
| `CREATEDB` | 能 CREATE DATABASE |
| `CREATEROLE` | 能 CREATE/ALTER/DROP ROLE |
| `LOGIN` | 能像用户一样登录(可省略 `CREATE USER`) |
| `REPLICATION` | 用于流复制的专用角色属性 |
| `BYPASSRLS` | 绕过行级安全策略(RLS) |
| `INHERIT` | 自动继承父角色权限(默认) |
| `CONNECTION LIMIT n` | 最大并发连接数 |

```sql
-- 复制账户(专门用于流复制)
CREATE ROLE repl_user WITH REPLICATION LOGIN PASSWORD 'Repl@2024' CONNECTION LIMIT 10;

-- 监控账户
CREATE ROLE monitor WITH LOGIN PASSWORD 'Mon@2024';
GRANT pg_read_all_stats TO monitor;   -- PG 10+ 提供内置监控角色

-- DBA 账户
CREATE ROLE dba_bob WITH SUPERUSER LOGIN PASSWORD 'Dba@2024!';
```

### 3. 对象权限 GRANT 语法

```sql
GRANT { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER }
    [, ...] | ALL [ PRIVILEGES ] }
    ON { [ TABLE ] table_name [, ...]
         | ALL TABLES IN SCHEMA schema_name [, ...] }
    TO role_specification [, ...] [ WITH GRANT OPTION ]
    [ GRANTED BY role_specification ];

-- 表/列 上的细粒度
GRANT { { SELECT | INSERT | UPDATE | REFERENCES } ( column_name [, ...] )
    [, ...] | ALL [ PRIVILEGES ] ( column_name [, ...] ) }
    ON [ TABLE ] table_name [, ...]
    TO role_specification [, ...] [ WITH GRANT OPTION ];

-- Schema 上
GRANT { { CREATE | USAGE } [, ...] | ALL [ PRIVILEGES ] }
    ON SCHEMA schema_name [, ...]
    TO role_specification [, ...] [ WITH GRANT OPTION ];

-- 序列上
GRANT { { USAGE | SELECT | UPDATE }
    [, ...] | ALL [ PRIVILEGES ] }
    ON { SEQUENCE sequence_name [, ...]
         | ALL SEQUENCES IN SCHEMA schema_name [, ...] }
    TO role_specification [, ...] [ WITH GRANT OPTION ];

-- 数据库上
GRANT { { CREATE | CONNECT | TEMPORARY | MAINTAIN } [, ...] | ALL [ PRIVILEGES ] }
    ON DATABASE database_name [, ...]
    TO role_specification [, ...] [ WITH GRANT OPTION ];

-- 函数/过程
GRANT { EXECUTE | ALL [ PRIVILEGES ] }
    ON { { FUNCTION | PROCEDURE | ROUTINE } { function_name | ALL FUNCTIONS IN SCHEMA schema_name } [, ...] }
    TO role_specification [, ...] [ WITH GRANT OPTION ];

-- 语言
GRANT { USAGE | ALL [ PRIVILEGES ] }
    ON LANGUAGE lang_name [, ...]
    TO role_specification [, ...] [ WITH GRANT OPTION ];
```

### 4. REVOKE 语法

```sql
REVOKE [ GRANT OPTION FOR ]
    { { SELECT | INSERT | UPDATE | DELETE | TRUNCATE | REFERENCES | TRIGGER }
    [, ...] | ALL [ PRIVILEGES ] }
    ON { [ TABLE ] table_name [, ...]
         | ALL TABLES IN SCHEMA schema_name [, ...] }
    FROM { [ GROUP ] role_name | PUBLIC } [, ...]
    [ CASCADE | RESTRICT ];

-- 撤销授权能力(保留权限)
REVOKE GRANT OPTION FOR INSERT ON orders FROM app_user;

-- CASCADE 级联撤销
REVOKE SELECT ON ALL TABLES IN SCHEMA public FROM app_user CASCADE;
```

### 5. PUBLIC(默认权限)

`PUBLIC` 是一个伪角色,所有角色自动拥有 PUBLIC 上的权限。

```sql
-- 查看 PUBLIC 上的权限
SELECT grantee, privilege_type, table_schema, table_name
FROM information_schema.role_table_grants
WHERE grantee = 'PUBLIC';

-- 撤销 PUBLIC 上的 EXECUTE(防止任意用户调用危险函数)
REVOKE EXECUTE ON FUNCTION pg_read_file(text) FROM PUBLIC;

-- 常见安全做法:撤销 PUBLIC 的某些危险权限
REVOKE EXECUTE ON FUNCTION pg_read_file(text, bigint, bigint) FROM PUBLIC;
```

### 6. 查看权限

```sql
-- 查看某角色的所有权限(汇总视图)
SELECT grantee, table_schema, table_name, privilege_type
FROM information_schema.table_privileges
WHERE grantee = 'app_user';

-- 详细到列
SELECT grantor, grantee, table_schema, table_name, column_name, privilege_type
FROM information_schema.column_privileges
WHERE grantee = 'app_user';

-- Schema 权限
SELECT * FROM information_schema.usage_privileges WHERE grantee = 'app_user';

-- 数据库权限
SELECT * FROM information_schema.database_privileges WHERE grantee = 'app_user';

-- 用 psql 命令更简洁
-- \dp orders            -- 查看 orders 表权限
-- \dp *.*               -- 所有对象
-- \ddp                  -- 默认权限
```

## 四、Schema 权限管理

PG 的 Schema 是命名空间,**必须先有 `USAGE` 权限才能访问 Schema 内对象**,这是与 MySQL 的关键差异。

### 1. Schema 上的权限

| 权限 | 说明 |
|------|------|
| `CREATE` | 在该 Schema 中创建对象 |
| `USAGE` | "查找"该 Schema 中的对象(没 USAGE 即使有对象权限也访问不到) |

### 2. 完整示例

```sql
-- 创建 schema
CREATE SCHEMA app_data;
CREATE SCHEMA app_report;

-- 给 app_user 在 app_data 上所有权限
GRANT USAGE, CREATE ON SCHEMA app_data TO app_user;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app_data TO app_user;

-- 给 report_ro 在 app_report 上只读
GRANT USAGE ON SCHEMA app_report TO report_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA app_report TO report_ro;

-- 未来在 schema 里建的新表自动有权限
ALTER DEFAULT PRIVILEGES IN SCHEMA app_data
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_user;

-- ALTER DEFAULT PRIVILEGES 仅影响"在该 schema 后续创建的对象"
-- 必须由对象的 owner 执行(默认是当前用户)
```

### 3. PUBLIC 默认权限回收

```sql
-- 新建数据库默认对 PUBLIC 授予 CREATE on schema public(危险!)
-- 建议:从 PUBLIC 撤销
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
REVOKE ALL ON DATABASE mydb FROM PUBLIC;

-- 给特定用户保留
GRANT CREATE ON SCHEMA public TO app_user;
```

## 五、列级权限

PG 支持精确到列的 SELECT/INSERT/UPDATE/REFERENCES 控制。

```sql
-- 创建测试表
CREATE TABLE employees (
    id          SERIAL PRIMARY KEY,
    name        TEXT NOT NULL,
    salary      NUMERIC(10, 2),
    id_card     TEXT,
    department  TEXT
);

-- 只授予部分列的 SELECT
GRANT SELECT (id, name, department) ON employees TO report_ro;

-- INSERT 只能指定部分列(其余由默认值或 NOT NULL 兜底)
GRANT INSERT (id, name, department) ON employees TO hr_user;

-- UPDATE 只能更新部分列(工资列保密)
GRANT UPDATE (department) ON employees TO hr_user;

-- 完整查表需要至少 1 个列级权限 + 表级 SELECT
-- 实际查询:
-- SELECT name, department FROM employees;          -- OK
-- SELECT * FROM employees;                         -- ERROR: permission denied for table employees
-- SELECT salary FROM employees;                    -- ERROR: permission denied for column salary

-- 查看列权限
SELECT grantee, table_schema, table_name, column_name, privilege_type
FROM information_schema.column_privileges
WHERE table_name = 'employees';
```

## 六、行级安全(Row-Level Security, PG 杀手锏)

**RLS 是 PG 区别于 MySQL 的核心安全特性之一**,按 SQL 表达式过滤行,实现**多租户数据隔离**、**按用户隔离数据**等。

### 1. 启用 RLS

```sql
-- 创建表
CREATE TABLE orders (
    id          SERIAL PRIMARY KEY,
    tenant_id   INT NOT NULL,
    customer    TEXT,
    amount      NUMERIC(10, 2),
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 启用 RLS(默认拒绝所有)
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
ALTER TABLE orders FORCE ROW LEVEL SECURITY;  -- 强制 owner 也受 RLS 约束

-- 创建策略(Policy)
CREATE POLICY tenant_isolation ON orders
    USING (tenant_id = current_setting('app.tenant_id')::INT);

-- 验证:即使是有 ALL 权限的账户,也只能看到自己 tenant 的行
```

### 2. CREATE POLICY 完整语法

```sql
CREATE POLICY name ON table_name
    [ AS { PERMISSIVE | RESTRICTIVE } ]
    [ FOR { ALL | SELECT | INSERT | UPDATE | DELETE } ]
    [ TO { role_name | PUBLIC | CURRENT_USER | SESSION_USER } [, ...] ]
    [ USING ( using_expression ) ]
    [ WITH CHECK ( check_expression ) ];
```

| 子句 | 作用 |
|------|------|
| `AS PERMISSIVE` | 多个策略取 OR(默认) |
| `AS RESTRICTIVE` | 多个策略取 AND(必须全部满足) |
| `FOR ALL/SELECT/INSERT/UPDATE/DELETE` | 适用于哪些操作 |
| `USING` | 已有行的可见性检查(SELECT/UPDATE/DELETE) |
| `WITH CHECK` | 新增/更新行的合法性检查(INSERT/UPDATE) |

### 3. 多租户完整示例

```sql
-- 场景:每个用户属于一个 tenant,只能看自己 tenant 的数据

-- 1. 应用启动时设置 tenant_id
SET app.tenant_id = 1001;

-- 2. 应用连接账户
CREATE ROLE app_user WITH LOGIN PASSWORD 'App@2024';

-- 3. 表结构
CREATE TABLE orders (
    id          BIGSERIAL PRIMARY KEY,
    tenant_id   INT NOT NULL,
    customer    TEXT NOT NULL,
    amount      NUMERIC(10, 2),
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 4. 启用 RLS
ALTER TABLE orders ENABLE ROW LEVEL SECURITY;
ALTER TABLE orders FORCE ROW LEVEL SECURITY;

-- 5. 创建策略
-- SELECT/UPDATE/DELETE 用 USING 限制可见行
CREATE POLICY tenant_select ON orders
    FOR SELECT
    USING (tenant_id = current_setting('app.tenant_id', true)::INT);

-- INSERT 用 WITH CHECK 限制可插入行
CREATE POLICY tenant_insert ON orders
    FOR INSERT
    WITH CHECK (tenant_id = current_setting('app.tenant_id', true)::INT);

-- UPDATE 同时限制可见 + 限制可改(避免跨 tenant 改)
CREATE POLICY tenant_update ON orders
    FOR UPDATE
    USING (tenant_id = current_setting('app.tenant_id', true)::INT)
    WITH CHECK (tenant_id = current_setting('app.tenant_id', true)::INT);

-- 6. 授予基本权限(RLS 在权限基础上再加层过滤)
GRANT SELECT, INSERT, UPDATE, DELETE ON orders TO app_user;

-- 7. 测试
SET app.tenant_id = 1001;
INSERT INTO orders (tenant_id, customer, amount) VALUES (1001, 'Alice', 100);   -- OK
INSERT INTO orders (tenant_id, customer, amount) VALUES (2002, 'Bob', 200);     -- 违反 WITH CHECK,失败
SELECT * FROM orders;  -- 只看到 tenant_id=1001 的行

-- 8. 切换 tenant
SET app.tenant_id = 2002;
SELECT * FROM orders;  -- 只看到 tenant_id=2002 的行
```

### 4. PERMISSIVE vs RESTRICTIVE

```sql
-- PERMISSIVE:OR 关系(任一满足即通过)
-- RESTRICTIVE:AND 关系(必须全部满足)

-- 例:用户只能看自己创建的行,或被指派的行
CREATE POLICY own_orders ON orders
    AS PERMISSIVE
    FOR SELECT
    USING (created_by = current_user);

CREATE POLICY assigned_orders ON orders
    AS PERMISSIVE
    FOR SELECT
    USING (assigned_to = current_user);

-- 上述两个 PERMISSIVE 取 OR,看到自己创建 OR 被指派给自己的

-- 加一个 RESTRICTIVE:且只能在工作时间访问
CREATE POLICY work_hours ON orders
    AS RESTRICTIVE
    FOR SELECT
    USING (EXTRACT(HOUR FROM now()) BETWEEN 9 AND 18);
```

### 5. 跳过 RLS 的角色

```sql
-- 创建可绕过 RLS 的 DBA 角色
CREATE ROLE dba_bypass WITH LOGIN BYPASSRLS PASSWORD 'Dba@2024';

-- superuser 默认绕过 RLS
-- 临时绕过(需要 superuser)
SET LOCAL row_security = OFF;  -- 仅当前事务
```

## 七、角色继承

### 1. 基本继承

PG 的角色继承比 MySQL 早 5 年(MySQL 8.0 才引入),且更灵活。

```sql
-- 创建层级角色
CREATE ROLE dba_admin          SUPERUSER LOGIN PASSWORD 'Dba@2024';
CREATE ROLE app_owner          CREATEDB CREATEROLE LOGIN PASSWORD 'Owner@2024';
CREATE ROLE role_order_admin;       -- 业务表全权
CREATE ROLE role_order_write;       -- 业务表读写
CREATE ROLE role_order_read;        -- 业务表只读

-- 把权限授予业务角色
GRANT CONNECT ON DATABASE order_db TO role_order_read, role_order_write, role_order_admin;
GRANT USAGE ON SCHEMA public TO role_order_read, role_order_write, role_order_admin;

GRANT SELECT ON ALL TABLES IN SCHEMA public TO role_order_read;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO role_order_write;
GRANT ALL PRIVILEGES ON ALL TABLES IN SCHEMA public TO role_order_admin;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA public TO role_order_write, role_order_admin;

-- 用户继承业务角色(INHERIT 是默认行为)
GRANT role_order_read TO app_owner;        -- app_owner 自动有只读权限
-- 创建业务用户,继承角色
CREATE USER alice WITH LOGIN PASSWORD 'Alice@2024' IN ROLE role_order_write;
CREATE USER bob   WITH LOGIN PASSWORD 'Bob@2024'   IN ROLE role_order_read;
```

### 2. 多层级角色架构

```
dba_admin (superuser)
    │
    ├─ app_owner (CREATEDB/CREATEROLE, INHERIT)
    │       │
    │       ├─ role_order_admin (ALL)
    │       ├─ role_order_write (DML)
    │       └─ role_order_read (SELECT)
    │
    ├─ report_owner
    │       └─ role_report_read (SELECT 报表库)
    │
    └─ monitor
            └─ role_monitor_stats (监控视图)
```

### 3. SET ROLE 切换

```sql
-- app_owner 登录后默认有 role_order_read 权限(因为 INHERIT)
-- 想临时升级到 role_order_write(假设被授权了)
SET ROLE role_order_write;
SELECT current_user, current_role;

-- 切换回
RESET ROLE;

-- INHERIT 与 SET ROLE 组合使用
-- 默认 INHERIT 模式下,登录即拥有所有父角色权限
-- NOINHERIT 模式下,必须显式 SET ROLE 才能用
CREATE ROLE strict_user NOINHERIT LOGIN PASSWORD 'Str@2024';
GRANT role_order_read TO strict_user;
-- strict_user 登录后,需 SET ROLE role_order_read 才能读
```

## 八、密码与认证

### 1. 密码加密方式

| 方式 | 引入版本 | 安全性 | 说明 |
|------|----------|--------|------|
| `password` | 全部 | **低**(明文存 pg_authid) | 仅用于内部测试 |
| `md5` | 7.2 | 中 | 已被破解,建议升级 |
| `scram-sha-256` | 10 | 高 | **10+ 默认**,推荐生产 |

```sql
-- 全局设置默认加密方式
ALTER SYSTEM SET password_encryption = 'scram-sha-256';
SELECT pg_reload_conf();

-- 创建用户时显式指定
CREATE ROLE app_user WITH LOGIN PASSWORD 'SCRAM-SHA-256$xxxxx';
-- 或让 PG 自动用 password_encryption 配置加密

-- 查看已存储的密码哈希(需要 superuser)
SELECT rolname, rolpassword FROM pg_authid WHERE rolname = 'app_user';
-- 输出:ScRAM-SHA-256$4096:xxxxx$xxxx
```

### 2. 密码策略

PG 内置**无密码复杂度检查**(依赖外部或应用层控制),但可通过 `passwordcheck` 扩展或 `check_password` 函数实现。

```sql
-- 使用 contrib 扩展 passwordcheck(随 PG 自带,需启用)
-- shared_preload_libraries = 'passwordcheck'
-- 改 postgresql.conf 后重启,CREATE/ALTER ROLE 时自动校验

-- 改用更现代的 credcheck 扩展(社区)
-- CREATE EXTENSION credcheck;
-- SET credcheck.password_min_length = 12;
-- SET credcheck.password_complexity = 'lower:1,upper:1,digit:1,special:1';

-- 设置密码过期时间
ALTER ROLE app_user VALID UNTIL '2027-12-31';

-- 解除过期
ALTER ROLE app_user VALID UNTIL 'infinity';
```

### 3. pg_hba.conf 配置

PG 的认证控制**集中**在 `pg_hba.conf`(`pg_hba.conf` = PostgreSQL Host-Based Authentication)。

```conf
# TYPE  DATABASE        USER            ADDRESS                 METHOD       [OPTIONS]

# === 本地连接 ===
# TYPE: local(Unix socket)/host(TCP,SSL可选)/hostssl(必须SSL)/hostnossl(禁止SSL)
# DATABASE: 数据库名/all/sameuser/replication
# USER: all/具体角色/+角色名(任何以该角色为成员的)
# ADDRESS: CIDR/IP/host name(仅 host)
# METHOD: trust/peer/ident/md5/scram-sha-256/password/reject/ldap/cert/radius

# 1. postgres 用户仅本地 socket 访问
local   all             postgres                                peer

# 2. 应用账户走 scram-sha-256
host    order_db        app_user           10.0.0.0/24          scram-sha-256

# 3. 复制账户
host    replication     repl_user          10.0.0.0/24          scram-sha-256

# 4. 监控账户可读所有库(允许任意地址)
host    all             monitor            0.0.0.0/0            scram-sha-256

# 5. 开发网段可以 md5(向后兼容)
host    all             all                192.168.1.0/24       md5

# 6. 公网全拒
host    all             all                0.0.0.0/0            reject

# 改完生效
SELECT pg_reload_conf();
```

**METHOD 详解**:

| METHOD | 说明 | 安全性 |
|--------|------|--------|
| `trust` | 无需密码 | **危险**,仅本机调试 |
| `reject` | 拒绝连接 | 用于默认拒绝 |
| `peer` | 校验 OS 用户名与 PG 用户名一致 | 本机推荐 |
| `ident` | 类似 peer,但可通过 ident 服务映射 | 灵活 |
| `md5` | MD5 哈希密码(挑战-应答) | 中,已被破解 |
| `scram-sha-256` | SCRAM-SHA-256(挑战-应答) | **高,推荐** |
| `password` | 明文传密码 | **危险** |
| `cert` | SSL 客户端证书 | 高,生产可选 |
| `ldap` | 走 LDAP 服务器 | 集中认证 |
| `radius` | 走 RADIUS | 集中认证 |

## 九、SSL/TLS 加密连接

### 1. 证书准备

```bash
# 1. 创建 CA 私钥与证书(自签)
openssl genrsa -out ca.key 4096
openssl req -new -x509 -days 3650 -key ca.key -out ca.crt \
    -subj "/CN=PG-CA"

# 2. 创建服务器私钥与 CSR
openssl genrsa -out server.key 4096
openssl req -new -key server.key -out server.csr \
    -subj "/CN=pg-server"   # CN 必须等于客户端连接的 hostname/IP
openssl x509 -req -in server.csr -CA ca.crt -CAkey ca.key \
    -CAcreateserial -out server.crt -days 3650 \
    -sha256 -extfile <(echo "subjectAltName=DNS:pg-server,DNS:localhost,IP:10.0.0.10")

# 3. 创建客户端私钥与 CSR
openssl genrsa -out client.key 4096
openssl req -new -key client.key -out client.csr \
    -subj "/CN=pg-client"
openssl x509 -req -in client.csr -CA ca.crt -CAkey ca.key \
    -CAcreateserial -out client.crt -days 3650 -sha256

# 4. 设置权限(关键!)
chmod 600 server.key client.key ca.key
chown postgres:postgres server.crt server.key ca.crt
```

### 2. 服务器端配置

```ini
# postgresql.conf
ssl = on
ssl_cert_file = '/etc/postgresql/server.crt'
ssl_key_file  = '/etc/postgresql/server.key'
ssl_ca_file   = '/etc/postgresql/ca.crt'

# 加密套件
ssl_ciphers = 'HIGH:!aNULL:!MD5'
ssl_prefer_server_ciphers = on
ssl_min_protocol_version = 'TLSv1.2'
ssl_max_protocol_version = ''

# 绑定监听
listen_addresses = '10.0.0.10'
```

```conf
# pg_hba.conf,强制 SSL
# 强制所有连接必须 SSL
hostssl    all             all                0.0.0.0/0            scram-sha-256
# 禁止非 SSL
hostnossl  all             all                0.0.0.0/0            reject
```

```bash

sudo systemctl restart postgresql
```

## 十一、SQL 注入防护

### 1. SQL 注入示例

```sql
-- 危险代码(拼接)
-- 应用层:"SELECT * FROM users WHERE name='" + input + "'"
-- 输入: ' OR '1'='1
-- 实际执行:SELECT * FROM users WHERE name='' OR '1'='1'
-- 结果:返回所有用户

-- 危险代码(数值拼接)
-- "SELECT * FROM users WHERE id=" + input
-- 输入: 1; DROP TABLE users; --
-- 实际执行:SELECT * FROM users WHERE id=1; DROP TABLE users; --
-- 结果:删表
```

### 2. PREPARE / EXECUTE(预处理)

PG 原生支持服务端预编译语句,**参数与 SQL 完全分离**,从根上避免注入。

```sql
-- 准备语句
PREPARE user_query (INT, TEXT) AS
    SELECT * FROM users WHERE id = $1 AND status = $2;

-- 传参执行(参数永远是数据,不是 SQL)
EXECUTE user_query(1001, 'active');

-- 释放
DEALLOCATE user_query;
```

### 3. quote_literal / quote_nullable(转义函数)

PG 提供内置的转义函数,**作为补充手段**(不如 PREPARE)。

```sql
SELECT quote_literal('O''Brien');                 -- 'O''Brien'
SELECT quote_nullable(NULL);                       -- NULL
SELECT quote_ident('User Table');                  -- "User Table"

-- 动态 SQL 拼接时
EXECUTE 'SELECT * FROM users WHERE name = ' || quote_literal($1) USING 'Alice';
```

### 4. 应用层参数化查询(主流方案)

```python
# Python (psycopg2)
import psycopg2
cursor = conn.cursor()
cursor.execute(
    "SELECT * FROM users WHERE id = %s AND status = %s",
    (1001, 'active')   # 参数化,自动转义
)
```

```python
# Python (SQLAlchemy)
from sqlalchemy import text
stmt = text("SELECT * FROM users WHERE id = :uid AND status = :st")
result = conn.execute(stmt, {"uid": 1001, "st": "active"})
```

```java
// Java (JDBC)
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE id = ? AND status = ?");
ps.setInt(1, 1001);
ps.setString(2, "active");
ResultSet rs = ps.executeQuery();
```

```go
// Go (pgx)
rows, _ := conn.Query(ctx,
    "SELECT * FROM users WHERE id = $1 AND status = $2",
    1001, "active")
```

## 十三、安全最佳实践清单

### 1. 账户与认证

- 改 `postgres` 超级用户密码,**禁止远程登录**(`pg_hba.conf` 仅 `local` 允许)
- 删除无用账户:`DROP ROLE xxx`
- 每个应用创建独立角色
- 应用账户**无 SUPERUSER、CREATEROLE、CREATEDB、BYPASSRLS**
- 强密码(12+ 位,大小写 + 数字 + 符号),定期轮换
- 启用 `password_encryption = scram-sha-256`
- `pg_hba.conf` 用 `scram-sha-256`,禁 `trust`/`password`/`md5`

### 2. 权限控制

- 应用账户**最小权限**(无 SUPERUSER、CREATEROLE、CREATEDB)
- 业务账户无 DDL(`CREATE`/`DROP`/`ALTER`)
- 用角色统一管理权限(分层继承)
- 关闭 `WITH GRANT OPTION`(DBA 除外)
- 启用 RLS 做多租户/行级隔离
- 用 Schema 隔离模块(每模块一个 Schema)

### 3. 网络与传输

- `listen_addresses` 不要 `*`
- 不暴露 5432 到公网
- 强制 SSL/TLS(`pg_hba.conf` 全部 `hostssl`)
- 防火墙限制来源 IP
- 客户端用 `sslmode=verify-full`

### 4. 审计与监控

- 启用 `pgaudit` 做对象级审计
- `log_connections` / `log_disconnections` = on
- `log_min_duration_statement` 记录慢查询
- 监控登录失败(`log_line_prefix` 包含 `user=%u`)
- 关键表(`users`、`orders`、`payments`)单独审计

### 5. 数据保护

- 敏感字段加密(`pgcrypto.encrypt`)
- 备份文件加密
- 密钥独立管理(Vault/KMS)
- 不在代码中硬编码密码
- 不在日志中打印明文

### 6. SQL 注入防护

- 应用层用**预编译/参数化**(psycopg2、JDBC PreparedStatement)
- 绝不用字符串拼接
- 用 ORM(SQLAlchemy、Hibernate)默认参数化
- 输入校验(白名单)

### 7. 运维规范

- 用专用 OS 用户 `postgres` 跑 PG
- 私钥文件权限 600
- 日志定期清理(`logrotate`)
- 升级到最新稳定版
- 订阅 PG 安全公告
- 角色密码定期轮换

## 十五、扩展使用详解

### 1. pg_stat_statements(SQL 统计)

**必备扩展,生产第一站**。

```sql
-- 1. 配置
-- postgresql.conf
shared_preload_libraries = 'pg_stat_statements'
pg_stat_statements.max = 10000
pg_stat_statements.track = top    # top/none/all
pg_stat_statements.track_utility = on

-- 重启 PG

-- 2. 创建扩展
CREATE EXTENSION pg_stat_statements;

-- 3. 查询 TOP SQL(按总耗时)
SELECT
    substring(query, 1, 80) AS query,
    calls,
    round(total_exec_time::numeric, 2) AS total_ms,
    round(mean_exec_time::numeric, 2) AS mean_ms,
    rows,
    shared_blks_hit + shared_blks_read AS total_blks,
    round(100.0 * shared_blks_hit / NULLIF(shared_blks_hit + shared_blks_read, 0), 2) AS hit_pct
FROM pg_stat_statements
ORDER BY total_exec_time DESC
LIMIT 20;

-- 4. 重置统计
SELECT pg_stat_statements_reset();
```

### 2. pg_trgm(模糊匹配、相似度)

```sql
-- 启用
CREATE EXTENSION pg_trgm;

-- 创建带 trigram 索引的列

-- 模糊匹配(不依赖前缀)
SELECT * FROM users WHERE name ILIKE '%alice%';     -- 用普通索引慢
SELECT * FROM users WHERE name % 'alice';           -- 相似度匹配(gin_trgm_ops 加速)

-- 相似度函数

-- 计算 Levenshtein 距离
```

### 3. pgvector(AI 向量检索)

**2024-2025 最火扩展**,LLM/RAG 标配。

```bash
# 安装(以 PG 16 为例)
sudo apt install postgresql-16-pgvector
```

```sql
-- 启用
CREATE EXTENSION vector;

-- 向量列(3 维示例,实际 1536/OpenAI、1024/BGE、768/MPNet)
CREATE TABLE doc_chunks (
    id          BIGSERIAL PRIMARY KEY,
    content     TEXT NOT NULL,
    embedding   vector(1536) NOT NULL,    -- OpenAI text-embedding-3 模型
    metadata    JSONB,
    created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 插入
INSERT INTO doc_chunks (content, embedding)
VALUES ('PostgreSQL 是最强大的开源数据库', '[0.012, -0.034, 0.056, ...]');

-- 相似度搜索(cosine 距离)
SELECT id, content, embedding <=> '[0.012, -0.034, 0.056, ...]' AS distance
FROM doc_chunks
ORDER BY embedding <=> '[0.012, -0.034, 0.056, ...]'
LIMIT 5;

-- 内积距离(归一化向量等价 cosine)
SELECT id, content, embedding <#> '[0.012, -0.034, 0.056, ...]' AS neg_inner_product
FROM doc_chunks
ORDER BY embedding <#> '[0.012, -0.034, 0.056, ...]'
LIMIT 5;

-- L2 欧式距离
SELECT id, content, embedding <-> '[0.012, -0.034, 0.056, ...]' AS l2_dist
FROM doc_chunks
ORDER BY embedding <-> '[0.012, -0.034, 0.056, ...]'
LIMIT 5;

-- 索引(IVFFlat 或 HNSW)
CREATE INDEX idx_doc_chunks_embedding ON doc_chunks
    USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

CREATE INDEX idx_doc_chunks_embedding ON doc_chunks
    USING hnsw (embedding vector_cosine_ops);  -- PG 16+ 推荐

-- 过滤 + 向量检索
SELECT id, content
FROM doc_chunks
WHERE metadata->>'category' = 'database'
ORDER BY embedding <=> '[0.012, -0.034, 0.056, ...]'
LIMIT 5;
```

**距离算子对照**:

| 算子 | 距离 | 索引 operator class |
|------|------|---------------------|
| `<->` | L2 欧式 | `vector_l2_ops` |
| `<#>` | 负内积 | `vector_ip_ops` |
| `<=>` | 余弦 | `vector_cosine_ops` |
| `<+>` | L1 曼哈顿 | `vector_l1_ops` |

### 5. pgcrypto(加密函数)

```sql
def fib(n):
```

### 2. 性能与运维扩展优先级

| 优先级 | 扩展 | 安装时机 |
|--------|------|----------|
| **P0 必须** | pg_stat_statements、pgBackRest | 新装即装 |
| P1 强烈推荐 | pgaudit、auto_explain、pg_repack | 上线前装 |
| P2 按需 | pg_trgm、pgcrypto、uuid-ossp | 用到再装 |
| P3 高级 | pgvector、PostGIS、pg_cron | 项目需求 |

### 3. 扩展安装位置建议

```sql
-- 创建专用 schema
CREATE SCHEMA extensions;

-- 装到指定 schema
CREATE EXTENSION pg_trgm WITH SCHEMA extensions;
CREATE EXTENSION pg_stat_statements WITH SCHEMA extensions;

-- 设置搜索路径
ALTER ROLE app_user SET search_path = "$user", extensions, public, pg_catalog;

-- 验证
SHOW search_path;
```

## 核心要点速记

### 1. 安全层次

- **网络层** `listen_addresses` 不绑定公网,SSL/TLS
- **认证层** `scram-sha-256`,强密码
- **授权层** 角色 + 最小权限 + **RLS** 行级安全
- **审计层** `pgaudit` + `log_statement`
- **数据层** `pgcrypto` 字段加密

### 2. 角色与用户

- PG 中 `USER` 和 `ROLE` 本质相同,`USER` = 带 LOGIN 的 ROLE
- `SUPERUSER` 跳过所有权限检查,慎用
- `INHERIT` 默认开启,登录即继承父角色权限
- `SET ROLE` 临时切换;`RESET ROLE` 恢复
- `SET SESSION AUTHORIZATION` 切 session_user

### 3. 权限层级

| 层级 | 存储表 | 命令 |
|------|--------|------|
| 全局 | `pg_authid` | 角色属性(SUPERUSER 等) |
| 数据库 | `pg_database` | CONNECT/CREATE |
| Schema | `pg_namespace` | USAGE/CREATE |
| 表 | `pg_class` | SELECT/INSERT/UPDATE/DELETE/TRUNCATE/REFERENCES/TRIGGER |
| 列 | `pg_attribute` | 列级 GRANT SELECT(col1, col2) |
| 行 | RLS Policy | `CREATE POLICY` |
| 函数 | `pg_proc` | EXECUTE |

### 4. GRANT/REVOKE 关键

- `GRANT` 一次性完成授权
- `REVOKE GRANT OPTION FOR ...` 撤销再授权能力
- `CASCADE` 级联撤销,`RESTRICT` 严格模式
- `WITH GRANT OPTION` 慎用,DBA 限定
- `ALTER DEFAULT PRIVILEGES` 让未来对象自动有权限

### 5. 行级安全(RLS)

- `ALTER TABLE ... ENABLE ROW LEVEL SECURITY` 启用
- `ALTER TABLE ... FORCE ROW LEVEL SECURITY` 强制 owner 也遵守
- `CREATE POLICY ... USING(可见) WITH CHECK(可改)`
- `PERMISSIVE`(OR) vs `RESTRICTIVE`(AND)
- `BYPASSRLS` 角色属性绕过 RLS
- 多租户黄金方案

### 6. Schema 权限

- 必须先 `GRANT USAGE ON SCHEMA` 才能访问 Schema 内对象
- `GRANT CREATE ON SCHEMA` 才能在 Schema 内建对象
- 建议建独立 Schema 隔离业务模块
- 撤销 `PUBLIC` 的 `CREATE` 权限

### 7. 密码与认证

- `password_encryption = scram-sha-256`(10+ 默认)
- `pg_hba.conf` 控制认证方式,改完 `pg_reload_conf()`
- METHOD:`scram-sha-256`(推荐)/`md5`/`peer`/`cert`/`ldap`
- 用 `credcheck` 扩展做密码复杂度校验

### 8. SSL/TLS

- 自签:`openssl` 生成 CA + server + client 证书
- 服务端:`ssl = on`、`ssl_cert_file`、`ssl_key_file`
- `pg_hba.conf` 用 `hostssl` 强制 SSL
- 客户端:`sslmode=verify-full`(最严)

### 9. 审计

- 内置:`log_statement = 'all'`(简陋)
- 专业:**`pgaudit`**(对象/会话级)
- `pgaudit.log = 'write, ddl'`
- 角色级:`ALTER ROLE xxx SET pgaudit.log = '...'`
- 登录日志:`log_connections = on`

### 10. SQL 注入

- **PREPARE / EXECUTE**(服务端预编译)
- 应用层 **psycopg2 / JDBC PreparedStatement**(推荐)
- `quote_literal()`、`quote_ident()`(转义,补充)
- 应用账户无 SUPERUSER、COPY PROGRAM 权限

### 11. PG 扩展生态

| 类别 | 必装 |
|------|------|
| 监控 | **pg_stat_statements**、auto_explain |
| 安全 | pgaudit、pgcrypto |
| 运维 | **pgBackRest**、pg_repack |
| 功能 | **pgvector**、PostGIS、pg_trgm、ltree、hstore |
| 调度 | pg_cron、pg_partman |

### 12. 扩展管理

- 查看:`pg_available_extensions` / `pg_extension`
- 安装:`CREATE EXTENSION name [WITH SCHEMA xxx]`
- 升级:`ALTER EXTENSION name UPDATE`
- 删除:`DROP EXTENSION name [CASCADE]`
- 必须预加载:`shared_preload_libraries = 'pg_stat_statements,pgaudit,pg_cron'`
- 统一装到 `extensions` schema,设置 `search_path`

### 13. 最佳实践清单

- postgres 用户仅本地 socket 访问
- 应用账户无 SUPERUSER、CREATEROLE
- 用角色分层管理权限
- 启用 RLS 做多租户隔离
- 强 SSL/TLS(`sslmode=verify-full`)
- 启用 pgaudit 做对象审计
- 所有应用账户用参数化查询
- 不暴露 5432 到公网
- 敏感字段 pgcrypto 加密
- 必装 pg_stat_statements、pgBackRest
- 定期 `ANALYZE`、`VACUUM`、`REINDEX`
- 升级到最新稳定版,订阅 CVE
