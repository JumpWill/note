# PostgreSQL 分区表 (Partitioned Tables)

> 本章系统讲解 PostgreSQL 分区表:分区原理、与 MySQL 的差异、RANGE / LIST / HASH 三大分区类型、声明式分区语法、分区管理 DDL、分区索引与裁剪、pg_partman 自动分区、表继承对比、实战场景与最佳实践。

---

## 一、分区表概述

### 1.1 什么是分区

分区表是把**一张逻辑大表**按规则拆成**多张物理子表**。应用查询父表,数据库自动定位到对应物理子表(分区)执行。

```text
逻辑层(用户视角)
  ┌──────────────────────────────┐
  │  orders (一张表)             │
  └──────────────────────────────┘

物理层(数据库视角)
  ┌────────────┐ ┌────────────┐ ┌────────────┐
  │ orders_2024│ │ orders_2025│ │ orders_2026│
  └────────────┘ └────────────┘ └────────────┘
       p1             p2             p3
```

### 1.2 为什么要分区

| 收益         | 说明                                                       |
|--------------|------------------------------------------------------------|
| **查询加速** | 分区裁剪让查询只扫描相关分区                               |
| **维护提速** | 删旧数据 = `DROP PARTITION`,瞬间完成                       |
| **写入并发** | 各分区独立并行写入,锁粒度更细                             |
| **存储灵活** | 老分区可单独搬到 OSS / 压缩表空间                         |
| **统计准确** | 每分区独立 ANALYZE,统计信息更精准                         |

### 1.3 PG 分区 vs MySQL 分区

| 维度           | PostgreSQL                                | MySQL (InnoDB)                                |
|----------------|-------------------------------------------|-----------------------------------------------|
| **诞生版本**   | **PG 10 (2017)** 原生声明式分区           | MySQL 5.1 开始支持分区                        |
| **实现方式**   | 物理表继承 + 约束 + 元数据                | 仍是一个 .ibd,逻辑分区由引擎管理             |
| **分区类型**   | RANGE / LIST / HASH                       | RANGE / LIST / HASH / KEY / COLUMNS          |
| **子分区**     | 支持(PG 10+,子分区也声明式)             | 支持 (SUBPARTITION BY)                        |
| **全局索引**   | **不支持**,主键/唯一必须包含分区键       | 支持(分区表整体唯一索引)                    |
| **管理操作**   | DETACH / ATTACH / SPLIT / MERGE 灵活      | REORGANIZE PARTITION                          |
| **裁剪能力**   | 静态 + 动态裁剪                           | 主要 plan-time 裁剪                           |
| **运维生态**   | pg_partman 成熟                            | 内置即可,社区方案不多                        |

> **结论**:PG 10+ 新项目一律使用声明式分区;老项目用表继承的可逐步迁移。

## 二、分区类型总览

| 类型      | 适用场景                            | 分区列示例          | 数据分布     |
|-----------|-------------------------------------|---------------------|--------------|
| **RANGE** | 时间序列、数值区间                  | `created_at`        | 连续范围     |
| **LIST**  | 离散枚举(地区、类型)               | `region`            | 显式列出值   |
| **HASH**  | 均匀分布、无明显业务分界            | `user_id`           | 哈希取模     |

### 2.1 多级嵌套分区

```text
订单表 (按月 RANGE 分区)
  ├─ p_2025_01 (RANGE: 2025-01)
  │    ├─ p_2025_01_bj (LIST: region=beijing)
  │    └─ p_2025_01_sh (LIST: region=shanghai)
  └─ p_2025_02
```

## 三、声明式分区语法

### 3.1 三步创建分区表

```sql
-- 第 1 步:创建父表(只定义列和分区方式)
CREATE TABLE orders (
    order_id     BIGINT        NOT NULL,
    user_id      BIGINT        NOT NULL,
    created_at   TIMESTAMPTZ   NOT NULL,
    amount       NUMERIC(12,2) NOT NULL
) PARTITION BY RANGE (created_at);

-- 第 2 步:主键必须包含分区列
ALTER TABLE orders ADD PRIMARY KEY (order_id, created_at);

-- 第 3 步:创建各分区(每分区一张物理表)
CREATE TABLE orders_2025 PARTITION OF orders
    FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');
CREATE TABLE orders_2026 PARTITION OF orders
    FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');
```

### 3.2 三种分区方式语法

```sql
CREATE TABLE t_range (...) PARTITION BY RANGE (col_date);
CREATE TABLE t_list  (...) PARTITION BY LIST (col_enum);
CREATE TABLE t_hash  (...) PARTITION BY HASH (col_id);
```

### 3.3 DEFAULT 分区

```sql
CREATE TABLE orders_default PARTITION OF orders DEFAULT;
-- 不匹配任何显式分区的数据落这里,起到兜底作用,需定期拆分
```

## 四、RANGE 分区(最常用)

### 4.1 按时间分区

```sql
CREATE TABLE orders (
    order_id     BIGINT        NOT NULL,
    user_id      BIGINT        NOT NULL,
    created_at   TIMESTAMPTZ   NOT NULL,
    amount       NUMERIC(12,2) NOT NULL
) PARTITION BY RANGE (created_at);

CREATE TABLE orders_2025_01 PARTITION OF orders FOR VALUES FROM ('2025-01-01') TO ('2025-02-01');
CREATE TABLE orders_2025_02 PARTITION OF orders FOR VALUES FROM ('2025-02-01') TO ('2025-03-01');
-- ... 中间省略
CREATE TABLE orders_2025_12 PARTITION OF orders FOR VALUES FROM ('2025-12-01') TO ('2026-01-01');
CREATE TABLE orders_2026_01 PARTITION OF orders FOR VALUES FROM ('2026-01-01') TO ('2026-02-01');
CREATE TABLE orders_2026_02 PARTITION OF orders FOR VALUES FROM ('2026-02-01') TO ('2026-03-01');
CREATE TABLE orders_default PARTITION OF orders DEFAULT;

INSERT INTO orders (order_id, user_id, created_at, amount) VALUES
    (1, 1001, '2025-03-15 10:30:00+08', 199.00),
    (2, 1002, '2026-01-20 14:00:00+08', 520.00),
    (3, 1003, '2030-01-01 00:00:00+08',  99.00);  -- → DEFAULT
```

### 4.2 按数值范围分区

```sql
CREATE TABLE user_events (
    event_id  BIGINT NOT NULL,
    user_id   BIGINT NOT NULL,
    payload   JSONB
) PARTITION BY RANGE (user_id);

CREATE TABLE user_events_0    PARTITION OF user_events FOR VALUES FROM (0)       TO (1000000);
CREATE TABLE user_events_1    PARTITION OF user_events FOR VALUES FROM (1000000) TO (2000000);
CREATE TABLE user_events_2    PARTITION OF user_events FOR VALUES FROM (2000000) TO (3000000);
CREATE TABLE user_events_max  PARTITION OF user_events FOR VALUES FROM (3000000) TO (MAXVALUE);
```

### 4.3 验证分区裁剪

```sql
EXPLAIN (COSTS OFF) SELECT * FROM orders
WHERE created_at >= '2025-03-01' AND created_at < '2025-04-01';
-- 结果应只 Append orders_2025_03 一个分区
```

## 五、LIST 分区

### 5.1 按地区分区(电商分仓)

```sql
CREATE TABLE orders_region (
    order_id    BIGINT       NOT NULL,
    region      TEXT         NOT NULL,
    created_at  TIMESTAMPTZ  NOT NULL,
    amount      NUMERIC(12,2)
) PARTITION BY LIST (region);

CREATE TABLE orders_bj PARTITION OF orders_region FOR VALUES IN ('beijing','beijing_ch');
CREATE TABLE orders_sh PARTITION OF orders_region FOR VALUES IN ('shanghai','shanghai_ch');
CREATE TABLE orders_gz PARTITION OF orders_region FOR VALUES IN ('guangzhou');
CREATE TABLE orders_sz PARTITION OF orders_region FOR VALUES IN ('shenzhen');
CREATE TABLE orders_other PARTITION OF orders_region DEFAULT;  -- 兜底
```

### 5.2 按订单状态分区(冷热分离)

```sql
CREATE TABLE orders_status (
    id          BIGINT NOT NULL,
    status      TEXT   NOT NULL,
    created_at  TIMESTAMPTZ
) PARTITION BY LIST (status);

CREATE TABLE orders_hot  PARTITION OF orders_status FOR VALUES IN ('pending','paid','shipped');
CREATE TABLE orders_cold PARTITION OF orders_status FOR VALUES IN ('completed','cancelled');
```

## 六、HASH 分区

### 6.1 均匀分布(消除热点)

HASH 分区用**分区列的哈希值取模**决定数据落点,适合无业务分界但需分散写入的场景。

```sql
CREATE TABLE user_sessions (
    session_id  TEXT        NOT NULL,
    user_id     BIGINT      NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL,
    payload     JSONB
) PARTITION BY HASH (user_id);

-- 平均切 4 个分区
CREATE TABLE user_sessions_h0 PARTITION OF user_sessions FOR VALUES WITH (MODULUS 4, REMAINDER 0);
CREATE TABLE user_sessions_h1 PARTITION OF user_sessions FOR VALUES WITH (MODULUS 4, REMAINDER 1);
CREATE TABLE user_sessions_h2 PARTITION OF user_sessions FOR VALUES WITH (MODULUS 4, REMAINDER 2);
CREATE TABLE user_sessions_h3 PARTITION OF user_sessions FOR VALUES WITH (MODULUS 4, REMAINDER 3);

-- 查看分布是否均匀
SELECT tableoid::regclass AS partition, COUNT(*) FROM user_sessions GROUP BY 1;
```

### 6.2 扩容

HASH 扩容需要重新分配数据(可借助 `pg_partman` 或停机迁移)。

## 七、分区管理 (DDL)

### 7.1 ADD PARTITION

```sql
CREATE TABLE orders_2026_03 PARTITION OF orders
    FOR VALUES FROM ('2026-03-01') TO ('2026-04-01');
CREATE TABLE orders_cd PARTITION OF orders_region FOR VALUES IN ('chengdu');
```

### 7.2 DROP PARTITION

```sql
-- 直接 DROP 子表(瞬间,不走 VACUUM)
DROP TABLE orders_2025_01;
```

### 7.3 DETACH / ATTACH

```sql
-- 脱离成独立表,可单独维护/归档
ALTER TABLE orders DETACH PARTITION orders_2025_01;
ALTER TABLE orders_2025_01 SET TABLESPACE cold_tbs;
ALTER TABLE orders_2025_01 ADD COLUMN archived_by TEXT;

-- 挂载已存在的兼容表(常用于回灌)
CREATE TABLE orders_2024_archive (LIKE orders INCLUDING ALL);
ALTER TABLE orders ATTACH PARTITION orders_2024_archive
    FOR VALUES FROM ('2024-01-01') TO ('2025-01-01');
```

### 7.4 SPLIT / MERGE PARTITION (PG 14+)

```sql
-- 拆分分区
ALTER TABLE orders SPLIT PARTITION orders_2024_q1 INTO
    (PARTITION orders_2024_q1_1 FOR VALUES FROM ('2024-01-01') TO ('2024-02-15'),
     PARTITION orders_2024_q1_2 FOR VALUES FROM ('2024-02-15') TO ('2024-04-01'));

-- 合并相邻分区
ALTER TABLE orders MERGE PARTITIONS
    (orders_2025_01, orders_2025_02) INTO orders_2025_h1;
```

### 7.5 RENAME / 改属性

```sql
ALTER TABLE orders_2025_01 SET TABLESPACE fast_ssd;
ALTER TABLE orders_2025_01 RENAME TO orders_2025_jan;
ALTER TABLE orders_2025_01 SET (fillfactor = 90);
```

## 八、分区索引

### 8.1 父表索引(自动传播)

```sql
-- 在父表建索引,所有现有 / 未来分区自动拥有该索引
CREATE INDEX idx_orders_user_id ON orders (user_id);
CREATE INDEX idx_orders_region  ON orders (region);
CREATE UNIQUE INDEX uniq_orders_order_id ON orders (order_id, created_at);
```

### 8.2 分区独立索引

```sql
-- 只给热分区建特殊索引
CREATE INDEX idx_orders_amount ON orders_2025_12 (amount);
```

### 8.3 分区列必须包含在唯一约束 / 主键

```sql
-- ❌ 报错
ALTER TABLE orders ADD PRIMARY KEY (order_id);
-- ERROR: Partition column "created_at" must be part of the UNIQUE constraint.

-- ✅ 正确
ALTER TABLE orders ADD PRIMARY KEY (order_id, created_at);
```

> **原因**:PG 无全局唯一索引,只能靠分区约束 + 分区内唯一保证整体唯一。

## 九、分区裁剪 (Partition Pruning)

### 9.1 裁剪原理

```text
                  ┌────────────────────────────┐
                  │  WHERE created_at >= '...' │
                  │         AND created_at < '..' │
                  └────────────┬───────────────┘
                               ▼
            ┌──────────────────────────────────────────────┐
            │         分区裁剪 (优化器)                    │
            └────────────┬─────────────────────────────────┘
        ┌──────────────┬─┴──────┬─────────────────┐
        ▼              ▼        ▼                  ▼
   orders_2024     orders_2025 orders_2025       orders_default
   (扫描) ✓       (跳过) ✗    (扫描) ✓         (跳过) ✗
```

### 9.2 静态裁剪 (Plan-Time)

WHERE 是**常量**时,在生成执行计划时裁剪。

```sql
EXPLAIN SELECT * FROM orders WHERE created_at = '2025-03-15';   -- 命中电影院裁剪
EXPLAIN SELECT * FROM orders WHERE created_at = current_date;   -- 扫所有分区
```

### 9.3 动态裁剪 (Run-Time,PG 11+)

PG 11 引入 `enable_partition_pruning`,使参数化查询也能裁剪。

```sql
PREPARE q AS SELECT * FROM orders WHERE created_at >= $1 AND created_at < $2;
EXECUTE q('2025-03-01', '2025-04-01');  -- 动态裁剪也命中
```

### 9.4 不触发裁剪的反例

```sql
-- 函数在分区键上(优化器无法推导)
SELECT * FROM orders WHERE date_trunc('month', created_at) = '2025-03-01';

-- 类型转换 / OR 跨分区范围
SELECT * FROM orders WHERE created_at::text LIKE '2025-03%';
SELECT * FROM orders WHERE created_at < '2025-01-01' OR created_at > '2025-12-01';
```

### 9.5 关键参数

| 参数                       | 默认 | 说明                                       |
|----------------------------|------|--------------------------------------------|
| `enable_partition_pruning` | on   | 静态 + 动态裁剪总开关                     |
| `constraint_exclusion`     | on   | PG 10 之前的裁剪机制,已被取代             |

## 十、分区查询优化

### 10.1 Partition-wise JOIN (PG 11+)

当两表按相同分区键 / 范围连接时,优化器让对应分区之间单独 JOIN。

```sql
EXPLAIN
SELECT o.order_id, p.pay_amount
FROM orders    o
JOIN payments  p ON o.created_at = p.created_at AND o.order_id = p.order_id
WHERE o.created_at >= '2025-03-01' AND o.created_at < '2025-04-01';
-- 出现 Partitioned Join,每对分区单独执行
```

```text
orders_2025_03  ──JOIN──>  payments_2025_03
orders_2025_04  ──JOIN──>  payments_2025_04
orders_2025_05  ──JOIN──>  payments_2025_05
... (并行执行)
```

### 10.2 Partition-wise Aggregate (PG 11+)

```sql
SELECT date_trunc('month', created_at) AS m, COUNT(*) FROM orders GROUP BY 1;
-- 每个分区内部 GROUP BY,最后合并(Append)
```

## 十一、分区维护

### 11.1 自动创建分区

PG 本身**不内置自动建分区**,需要:
1. **应用层定时任务**(crontab + 调度器)
2. **pg_partman 扩展**(推荐,详见第十二章)
3. **自写 PL/pgSQL 函数** + `pg_cron`

### 11.2 旧分区归档(三种策略)

| 策略         | 操作                                       | 适用           |
|--------------|--------------------------------------------|----------------|
| **硬删**     | `DROP TABLE orders_2023`                   | 不再需要的历史 |
| **冷归档**   | DETACH → SET TABLESPACE cold_tbs           | 仍可能查的     |
| **导出归档** | DETACH → pg_dump → 单独存                  | 备份 / 合规    |

```sql
-- 自动归档 1 年前分区到冷表空间
DO $$
DECLARE r RECORD;
BEGIN
    FOR r IN
        SELECT inhrelid::regclass AS part_name
        FROM pg_inherits
        WHERE inhparent = 'orders'::regclass
          AND substring(inhrelid::regclass::text FROM '[0-9]{4}_[0-9]{2}')
              < to_char(CURRENT_DATE - INTERVAL '1 year', 'YYYY_MM')
    LOOP
        EXECUTE format('ALTER TABLE orders DETACH PARTITION %I', r.part_name);
        EXECUTE format('ALTER TABLE %I SET TABLESPACE cold_tbs', r.part_name);
    END LOOP;
END$$;
```

### 11.3 数据清理(批量删除)

```sql
-- ❌ 慢
DELETE FROM order_items WHERE created_at < now() - INTERVAL '6 months';

-- ✅ 秒级
ALTER TABLE order_items DETACH PARTITION order_items_2024_q3;
DROP TABLE order_items_2024_q3;
```

### 11.4 VACUUM / ANALYZE

```sql
VACUUM (ANALYZE) orders;          -- 父表操作级联所有分区
VACUUM (ANALYZE) orders_2025_01;  -- 单分区操作
```

## 十二、pg_partman 扩展

### 12.1 安装

```bash
git clone https://github.com/pgpartman/pg_partman.git
cd pg_partman && make install
psql -d mydb -c "CREATE EXTENSION pg_partman;"
```

### 12.2 创建按月分区的订单表

```sql
CREATE TABLE orders (
    order_id    BIGINT      NOT NULL,
    user_id     BIGINT      NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    amount      NUMERIC(12,2) NOT NULL
);

ALTER TABLE orders ADD PRIMARY KEY (order_id, created_at);

SELECT partman.create_parent(
    p_parent_table := 'public.orders',
    p_control     := 'created_at',
    p_type        := 'range',
    p_interval    := '1 month',   -- 按月分区
    p_premake     := 3            -- 预创建未来 3 个分区
);
```

### 12.3 自动维护任务

```sql
-- 手动执行一次
SELECT partman.run_maintenance('public.orders');

-- 用 pg_cron 每小时执行
SELECT cron.schedule(
    'partman-maintenance-orders',
    '0 * * * *',
    $$SELECT partman.run_maintenance('public.orders');$$
);
```

### 12.4 保留策略

```sql
UPDATE partman.part_config
SET retention            = '12 months',
    retention_keep_table = true       -- true=DETACH 保留,false=DROP
WHERE parent_table = 'public.orders';
```

### 12.5 完整示例:IoT 传感器数据

```sql
CREATE EXTENSION IF NOT EXISTS pg_partman;
CREATE EXTENSION IF NOT EXISTS pg_cron;

CREATE TABLE sensor_data (
    sensor_id   BIGINT      NOT NULL,
    ts          TIMESTAMPTZ NOT NULL,
    value       DOUBLE PRECISION,
    PRIMARY KEY (sensor_id, ts)
);

SELECT partman.create_parent(
    p_parent_table := 'public.sensor_data',
    p_control     := 'ts',
    p_type        := 'range',
    p_interval    := '1 hour',       -- 按小时
    p_premake     := 6               -- 预创建未来 6 小时
);

UPDATE partman.part_config
SET retention            = '7 days',
    retention_keep_table = false     -- 7 天前直接 DROP
WHERE parent_table = 'public.sensor_data';

SELECT cron.schedule(
    'partman-sensor_data',
    '*/15 * * * *',                  -- 每 15 分钟
    $$SELECT partman.run_maintenance('public.sensor_data');$$
);
```

### 12.6 常用函数

| 函数                                                  | 作用                          |
|-------------------------------------------------------|-------------------------------|
| `partman.create_parent(...)`                          | 创建分区表                    |
| `partman.run_maintenance(p_parent_table)`            | 跑一次维护                    |
| `partman.show_partitions(p_parent_table)`             | 列出所有分区                  |
| `partman.partition_data_time(p_parent_table)`         | 把存量数据迁到对应分区        |

## 十三、表继承 (INHERITS) vs 声明式分区

### 13.1 完整对比

| 维度             | 声明式分区 (Declarative)                 | 表继承 (INHERITS)                          |
|------------------|------------------------------------------|--------------------------------------------|
| **诞生**         | PG 10+                                   | PG 一直支持                                |
| **DDL**          | `PARTITION BY` + `PARTITION OF`          | `INHERITS (parent_table)`                  |
| **裁剪**         | 原生支持(快)                            | 需 `constraint_exclusion` + 手动 CHECK    |
| **约束自动传播** | 是                                       | 否,需手动写                                |
| **添加分区**     | `CREATE TABLE ... PARTITION OF`          | `CREATE TABLE ... INHERITS ...` + 约束    |
| **detach**       | 简单(`DETACH PARTITION`)               | 需 `NO INHERIT parent`                     |
| **分区列变更**   | 不能                                     | 灵活                                       |
| **唯一约束**     | 必须包含分区键                           | 完全自由,每子表独立                        |
| **跨分区外键**   | 不支持直接指向分区表                     | 可指向父表                                 |
| **多对多**       | 不支持                                   | 支持(每行可属于多个父表)                 |
| **性能**         | 高(原生优化器)                         | 低(每子表独立 plan)                       |
| **建议**         | **新项目首选**                          | 遗留系统 / 需要继承语义时用               |

### 13.2 表继承使用场景

```sql
-- 多态父表(每行可属于多个子类)
CREATE TABLE geo_location (id INT, geom GEOMETRY);
CREATE TABLE cities    INHERITS (geo_location);
CREATE TABLE countries INHERITS (geo_location);

-- 通用"按业务"分组
CREATE TABLE events_all (id BIGINT, payload JSONB);
CREATE TABLE events_login INHERITS (events_all);
CREATE TABLE events_pay   INHERITS (events_all);
```

## 十四、大表分区实战

### 14.1 订单表按月分区

```sql
-- 1. 创建父表
CREATE TABLE orders (
    order_id     BIGINT        NOT NULL,
    user_id      BIGINT        NOT NULL,
    created_at   TIMESTAMPTZ   NOT NULL DEFAULT now(),
    paid_at      TIMESTAMPTZ,
    status       TEXT          NOT NULL,
    amount       NUMERIC(12,2) NOT NULL,
    region       TEXT          NOT NULL,
    PRIMARY KEY (order_id, created_at)
) PARTITION BY RANGE (created_at);

-- 2. 生成月度分区(过去 6 个月 + 未来 3 个月)
DO $$
DECLARE
    start_month DATE := date_trunc('month', CURRENT_DATE);
    i INT;
BEGIN
    FOR i IN -6..3 LOOP
        EXECUTE format(
            'CREATE TABLE IF NOT EXISTS orders_%s PARTITION OF orders FOR VALUES FROM (%L) TO (%L)',
            to_char(start_month + (i || ' month')::INTERVAL, 'YYYY_MM'),
            (start_month + (i     || ' month')::INTERVAL)::date,
            (start_month + ((i+1) || ' month')::INTERVAL)::date
        );
    END LOOP;
END$$;

CREATE TABLE orders_default PARTITION OF orders DEFAULT;

-- 3. 索引
CREATE INDEX idx_orders_user   ON orders (user_id, created_at);
CREATE INDEX idx_orders_region ON orders (region, created_at);
CREATE INDEX idx_orders_status ON orders (status) WHERE status IN ('pending','paid');
```

### 14.2 日志表按天分区

```sql
CREATE TABLE app_logs (
    log_id   BIGINT      NOT NULL,
    ts       TIMESTAMPTZ NOT NULL DEFAULT now(),
    level    TEXT        NOT NULL,
    service  TEXT        NOT NULL,
    message  TEXT        NOT NULL
) PARTITION BY RANGE (ts);

ALTER TABLE app_logs ADD PRIMARY KEY (log_id, ts);

-- pg_partman 接管
SELECT partman.create_parent(
    p_parent_table := 'public.app_logs',
    p_control     := 'ts',
    p_type        := 'range',
    p_interval    := '1 day',
    p_premake     := 7
);

UPDATE partman.part_config
SET retention = '30 days', retention_keep_table = false
WHERE parent_table = 'public.app_logs';
```

### 14.3 性能对比(参考)

| 操作                      | 普通大表 (10 亿行) | 分区表 (按月)           | 加速比     |
|---------------------------|--------------------|-------------------------|------------|
| 按月范围 `SELECT`         | 全表扫描           | 单分区扫描              | 30~100x    |
| `DELETE` 6 个月前数据     | 几小时             | `DROP PARTITION` 秒级  | 10000x+    |
| `ALTER TABLE ADD COLUMN`  | 锁全表             | 改元数据(秒)           | 1000x+     |
| `VACUUM FULL`             | 几小时             | 单分区可并发            | 10x        |
| 高并发写入                | 单表热点页竞争     | 多分区并行              | 2~5x       |
| 点查(PK)                | 持平               | 持平(也无损)           | 持平       |

### 14.4 数据迁移

-- 小表直接 INSERT
CREATE TABLE orders_part (LIKE orders INCLUDING ALL);
INSERT INTO orders_part SELECT * FROM orders;

-- 大表用 pg_partman 后台批处理(每批 1 万行)

## 十五、分区最佳实践

### 15.1 粒度选择

| 业务场景           | 建议粒度 | 单分区行数大致区间     |
|--------------------|----------|------------------------|
| 订单 / 交易记录   | 按月     | 100 万 ~ 5000 万       |
| 日志 / 行为埋点   | 按天     | 100 万 ~ 5000 万       |
| IoT 传感器        | 按小时   | 100 万 ~ 1000 万       |
| 用户档案          | HASH     | 100 万 ~ 1000 万       |

**经验**:单分区 **5GB ~ 50GB** 是甜蜜区;**不超过 100GB / 分区**;**不要少于 100 万行 / 分区**;分区数 **50 ~ 200** 之间。

### 15.2 分区列选择

- ✅ 分区列必须**经常在 WHERE 里出现**
- ✅ 时间列适合时序数据
- ✅ 地区 / 类型适合 LIST 分区
- ⚠️ 用 HASH 时要谨慎(扩容难)

### 15.3 唯一约束限制

```sql
-- ❌ 报错
ALTER TABLE orders ADD UNIQUE (order_id);

-- ✅ 正确
ALTER TABLE orders ADD UNIQUE (order_id, created_at);
```

业务要 order_id 全局唯一时:**用 UUID** / **进分区键** / **应用层校验**。

### 15.4 运维反模式

| 反模式                                         | 后果                                          |
|------------------------------------------------|-----------------------------------------------|
| 分区列不在 WHERE 里                             | 全分区扫描                                     |
| 粒度过细(分小时)                              | 元数据膨胀                                     |
| DEFAULT 分区不维护                            | 数据全部落入 default                           |
| UPDATE 改分区键                                | PG 报错,partition key cannot be updated       |
| FOREIGN KEY 指向分区表                         | 不支持                                         |
| 不配 pg_partman                                | 每月漏建分区                                  |

### 15.5 心法口诀

```text
看查询,选分区键
粒度细,别过千
主键里,必有它
默认值,常维护
老分区,DROP 快
数据搬,OSS 摆
读冷热,分开怀
```

## 十六、核心要点速记

### 16.1 一句话记住 PG 分区

> **PG 10+ 声明式分区是事实标准**;按 RANGE / LIST / HASH 三大类,父表存元数据,每分区是独立物理表,DDL 在父表上自动级联。

### 16.2 三大分区类型速记

| 类型 | 一句话                  | 典型场景             |
|------|-------------------------|----------------------|
| RANGE| 连续范围(时间/数值)   | 订单 / 日志          |
| LIST | 离散枚举(地区/类型)  | 多分仓业务           |
| HASH | 哈希取模,均匀         | 高并发写入           |

### 16.3 创建分区表三步走

1. **父表**:`CREATE TABLE t (cols...) PARTITION BY RANGE/LIST/HASH (col)`
2. **主键**:必须包含分区列
3. **子表**:`CREATE TABLE t_yyyymm PARTITION OF t FOR VALUES ...`

### 16.4 关键限制

- 分区列必须在 **主键 / 唯一约束 / 索引键**里
- **FOREIGN KEY** 不能直接指向分区表
- **UPDATE 修改分区列**会被 PG 拒绝
- **DEFAULT 分区** 经常维护,否则数据全跑那里
- 各分区单独 **ANALYZE**,否则优化器估算不准
- 父表建索引 → 自动传到所有分区(包括后续 ATTACH)
- PG 14+ 支持 **SPLIT / MERGE PARTITION**

### 16.5 管理操作速记

| 操作             | 语法                                                | 说明                |
|------------------|-----------------------------------------------------|---------------------|
| 添加分区         | `CREATE TABLE p_xx PARTITION OF t FOR VALUES ...`   | 快速                |
| 删除分区         | `DROP TABLE p_xx`                                  | 瞬间,数据丢        |
| 脱离分区         | `ALTER TABLE t DETACH PARTITION p_xx`              | 变独立表            |
| 挂载分区         | `ALTER TABLE t ATTACH PARTITION p_xx FOR VALUES ...`| 重新纳管            |
| 拆分 (PG 14+)   | `ALTER TABLE t SPLIT PARTITION ...`                | 一拆为二            |
| 合并 (PG 14+)   | `ALTER TABLE t MERGE PARTITIONS ...`               | 多合为一            |
| 自动管理         | `pg_partman` + `pg_cron`                           | 工业级方案          |

### 16.6 性能加速速记

| 场景             | 加速比       |
|------------------|--------------|
| 删整月数据       | 10000x       |
| 范围查询         | 30~100x      |
| DDL(改列/索引) | 100~1000x    |
| VACUUM           | 10x+         |
| 高并发写入       | 2~5x         |
| 简单点查(PK)   | 持平         |

### 16.7 决策树

```text
表数据量 > 1000 万?
  ├─ 是 → 走分区
  │      ├─ 有时间维度? → RANGE(按月/天)
  │      ├─ 有离散枚举? → LIST(按地区/类型)
  │      ├─ 想均匀分布? → HASH
  │      └─ 都要?       → 二级嵌套分区
  └─ 否 → 单表足够
       │
       ▼
启用 pg_partman + 设置保留窗口 + 写分区列索引 + EXPLAIN 验证裁剪生效
```

### 16.8 与 MySQL 分区的核心差异

- PG 分区是**真正物理表**,MySQL 仍是一个 .ibd
- PG **不支持全局唯一索引**,分区列必须进主键
- PG 有 **DETACH / ATTACH / SPLIT / MERGE**,灵活性高
- PG 有 **pg_partman** 成熟生态,MySQL 偏运维自研
