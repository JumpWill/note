# 数据库和表操作 (Database & Table Operations)

> 本章覆盖 PostgreSQL 中最核心的 DDL(Data Definition Language)操作:数据库 / Schema / 表空间、模板数据库、表与列定义、各种约束(主键、外键、唯一、检查、**排他**)、ALTER TABLE、临时表、UNLOGGED 表、表继承、声明式分区、视图 / 物化视图、pg_dump / pg_restore,以及典型业务表的设计示例。

## 一、数据库操作

### 1. CREATE DATABASE

```sql
-- 最简形式
CREATE DATABASE mydb;

-- 完整形式(推荐生产使用)
CREATE DATABASE mydb
    OWNER = app_user
    ENCODING = 'UTF8'
    LC_COLLATE = 'en_US.UTF-8'
    LC_CTYPE = 'en_US.UTF-8'
    TEMPLATE = template1
    TABLESPACE = pg_default
    CONNECTION LIMIT = -1;   -- -1 表示无限制
```

**关键选项**:

| 选项              | 说明                                              |
|-------------------|---------------------------------------------------|
| `OWNER`           | 数据库所有者                                      |
| `ENCODING`        | 字符集(必须与模板兼容,通常 UTF8)               |
| `LC_COLLATE`      | 排序规则(库级,创建后**不可改**)                |
| `LC_CTYPE`        | 字符分类规则(同上,创建后**不可改**)            |
| `TEMPLATE`        | 模板,默认 `template1`                            |
| `TABLESPACE`      | 默认表空间                                        |
| `CONNECTION LIMIT`| 最大并发连接数,-1 无限制                         |

> **重要**:数据库级别的 `LC_COLLATE` / `LC_CTYPE` 在创建后**无法通过 ALTER 修改**,只能新建库用不同 locale。

### 2. 列出数据库

```sql
-- psql 元命令
\l
\l mydb

-- SQL 方式
SELECT datname, pg_size_pretty(pg_database_size(datname)) AS size
FROM pg_database;
```

### 3. ALTER DATABASE

```sql
-- 修改数据库名称(13+)
ALTER DATABASE mydb RENAME TO mydb_new;

-- 修改所有者
ALTER DATABASE mydb OWNER TO new_owner;

-- 修改默认表空间
ALTER DATABASE mydb SET TABLESPACE fast_ssd;

-- 修改连接数限制
ALTER DATABASE mydb CONNECTION LIMIT 100;

-- 设置会话级参数(只影响该库后续连接)
ALTER DATABASE mydb SET statement_timeout = '60s';
```

### 4. DROP DATABASE

```sql
DROP DATABASE mydb;                 -- 直接删除
DROP DATABASE IF EXISTS mydb;       -- 存在才删(推荐)
```

> **警告**:`DROP DATABASE` 会**删除库中所有对象**(表、视图、函数、序列等),且不可恢复,生产环境务必先 `pg_dump` 备份。

### 5. 切换数据库

```sql
-- psql 元命令
\c mydb
\connect mydb

-- 查看当前所在库
SELECT current_database();
```

## 二、模板数据库(Template Databases)

模板数据库是**新数据库的"原型"**,`CREATE DATABASE` 时通过复制模板来初始化。

### 1. 系统自带模板

```sql
SELECT datname, datistemplate, datallowconn
FROM pg_database WHERE datistemplate = true;
```

| 模板          | 特点                                                                 |
|---------------|----------------------------------------------------------------------|
| `template1`   | **默认模板**,可被修改,日常建库都用它                               |
| `template0`   | **干净模板**,不含用户对象;用于创建 locale 不同 / 编码不同的库       |

### 2. 两者的区别

```
template0                                  template1
   │                                            │
   │ 原始干净                                   │ 默认可改
   │ LC_COLLATE = 'C'                          │ LC_COLLATE = initdb 时的 locale
   │ 不含任何用户对象                           │ 可能含你自己加的扩展 / 表
   │ 不允许在它里面建对象                        │ 允许
   │                                            │
   └──────────── 用于"特殊 locale 建库" ────────┘
```

### 3. 使用场景

```sql
-- 场景 1:用 template1 建标准库(99% 的情况)
CREATE DATABASE mydb;

-- 场景 2:用 template0 建"不同 locale"的库(template1 的 locale 已固定)
CREATE DATABASE mydb_zh
    TEMPLATE = template0
    LC_COLLATE = 'zh_CN.UTF-8'
    LC_CTYPE   = 'zh_CN.UTF-8'
    ENCODING   = 'UTF8';

-- 场景 3:自定义模板(预装扩展/常用函数)
-- 1) 在 template1 中装扩展
\c template1
CREATE EXTENSION postgis;
CREATE EXTENSION pg_trgm;
-- 2) 之后 CREATE DATABASE 会自动包含这些扩展
CREATE DATABASE gis_app;  -- 自动有 postgis
```

> **生产建议**:`template0` 永远不要动。预装扩展建议**新建自定义模板库**,而不是污染 `template1`。

### 4. template0 的另一个用途:从损坏的 template1 恢复

```sql
-- 如果 template1 被玩坏了,可以基于 template0 重建
CREATE DATABASE template1_recovery TEMPLATE = template0;
-- 然后手动比对修复
```

## 三、Schema(模式)

PostgreSQL 的 Schema 是**数据库内部的命名空间**,一个数据库可以包含多个 Schema,每个 Schema 下有独立的表 / 视图 / 函数等。

### 1. Schema 与 Database 的关系

```
PostgreSQL 实例 (postgres)
   │
   ├── 数据库: mydb
   │       │
   │       ├── schema: public     (默认)
   │       │     ├── users
   │       │     ├── orders
   │       │     └── ...
   │       │
   │       └── schema: billing
   │             ├── invoices
   │             └── payments
   │
   └── 数据库: analytics
           └── schema: reports
```

### 2. CREATE SCHEMA

```sql
-- 最简形式
CREATE SCHEMA app;

-- 完整形式
CREATE SCHEMA IF NOT EXISTS billing
    AUTHORIZATION app_user;

-- 一条语句创建多个 schema
CREATE SCHEMA IF NOT EXISTS app;
CREATE SCHEMA IF NOT EXISTS app_internal;
CREATE SCHEMA IF NOT EXISTS app_logs;

-- 创建 schema 并授权
GRANT CREATE, USAGE ON SCHEMA app TO app_user;
GRANT USAGE ON SCHEMA app_internal TO app_user;
```

### 3. Schema 设计原则

```sql
-- 1) 用 schema 隔离业务模块(代替 MySQL 的"每个业务一个库")
CREATE SCHEMA crm;
CREATE SCHEMA erp;
CREATE SCHEMA report;

-- 2) 用 schema 做权限隔离
CREATE SCHEMA app_readonly;       -- 只读 schema
GRANT USAGE ON SCHEMA app_readonly TO readonly_user;

-- 3) 设置默认 search_path,简化 SQL
ALTER ROLE app_user SET search_path = app, public;
-- 这样 SELECT * FROM users 实际查 app.users
```

### 4. 跨 Schema 查询

```sql
-- 全限定名
SELECT * FROM billing.invoices;
SELECT * FROM report.daily_sales;

-- 设置 search_path(影响后续 SQL)
SET search_path TO billing, public;
SELECT * FROM invoices;            -- 解析为 billing.invoices

-- 查看当前 search_path
SHOW search_path;
```

### 5. Schema 的 DDL 操作

```sql
-- 重命名
ALTER SCHEMA app RENAME TO app_v2;

-- 修改所有者
ALTER SCHEMA app OWNER TO new_owner;

-- 删除(必须先清空里面的对象)
DROP SCHEMA app CASCADE;
```

## 四、表的创建(CREATE TABLE)

### 1. 完整语法骨架

```sql
CREATE TABLE [IF NOT EXISTS] table_name (
    column1 datatype [column_constraints],
    column2 datatype [column_constraints],
    ...
    [table_constraints]
)
[ INHERITS ( parent_table [, ...] ) ]
[ PARTITION BY { RANGE | LIST | HASH } ( column [, ...] ) ]
[ WITH ( storage_parameter [= value] [, ... ] ) ]
[ TABLESPACE tablespace_name ]
[ USING METHOD access_method ];
```

### 2. 完整示例

```sql
CREATE TABLE IF NOT EXISTS users (
    id           BIGINT        GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    username     VARCHAR(50)   NOT NULL UNIQUE,
    email        VARCHAR(100)  NOT NULL UNIQUE,
    password_hash TEXT         NOT NULL,
    age          SMALLINT      CHECK (age >= 0 AND age <= 150),
    status       SMALLINT      NOT NULL DEFAULT 1,
    bio          TEXT,
    created_at   TIMESTAMPTZ   NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at   TIMESTAMPTZ   NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT chk_status CHECK (status IN (0,1,2))
);
```

### 3. 常用数据类型速查

#### 数值类型

| 类型              | 存储   | 范围                                       |
|-------------------|--------|--------------------------------------------|
| `SMALLINT`        | 2 字节 | -32768 ~ 32767                            |
| `INTEGER`         | 4 字节 | -2^31 ~ 2^31-1                            |
| `BIGINT`          | 8 字节 | -2^63 ~ 2^63-1                            |
| `NUMERIC(p,s)`    | 变长   | 精确小数,适合金额(推荐)                  |
| `REAL`            | 4 字节 | 单精度浮点                                |
| `DOUBLE PRECISION`| 8 字节 | 双精度浮点                                |
| `SERIAL`          | 4 字节 | 1 ~ 2^31-1,自动生成(遗留用法)             |
| `BIGSERIAL`       | 8 字节 | 1 ~ 2^63-1,自动生成(遗留用法)             |

#### 字符串类型

| 类型              | 特点                                                      |
|-------------------|-----------------------------------------------------------|
| `CHAR(n)`         | 定长,尾部填空格                                           |
| `VARCHAR(n)`      | 变长,上限 n(**n 是字符数,不是字节数**)                  |
| `TEXT`            | 无限变长(无长度限制,推荐代替 MySQL 的 TEXT)             |

> PostgreSQL 没有 `TINYTEXT / MEDIUMTEXT / LONGTEXT`,长文本一律 `TEXT`。

#### 日期时间类型

| 类型           | 特点                                          |
|----------------|-----------------------------------------------|
| `DATE`         | 仅日期                                        |
| `TIME`         | 仅时间                                        |
| `TIMESTAMP`    | 时间戳(不带时区)                            |
| `TIMESTAMPTZ`  | **时间戳带时区**(强烈推荐,内部存 UTC)        |
| `INTERVAL`     | 时间间隔                                      |

> **强烈推荐 `TIMESTAMPTZ`**:`TIMESTAMP` 不带时区是 PG 常见坑,跨时区数据会乱。

#### 特殊类型

| 类型             | 用途                                       |
|------------------|--------------------------------------------|
| `BOOLEAN`        | true / false                              |
| `UUID`           | 通用唯一标识(需 uuid-ossp 或 pgcrypto)    |
| `JSON`           | 文本形式 JSON(保留重复键,无类型)         |
| `JSONB`          | **二进制 JSON**(推荐,支持索引)           |
| `ARRAY`          | 数组,如 `INTEGER[]`、`TEXT[]`             |
| `BYTEA`          | 二进制数据                                 |
| `INET` / `CIDR` | IP 地址                                    |
| `MONEY`          | 货币(不推荐,有精度问题)                  |

## 五、列定义详解

### 1. NOT NULL / NULL / DEFAULT

```sql
name VARCHAR(50) NOT NULL                   -- 必有值
nickname VARCHAR(50)                         -- 可空(默认 NULL)
score INTEGER DEFAULT 0                       -- 可空,默认 0
status SMALLINT NOT NULL DEFAULT 1           -- 必有值,默认 1
```

**为什么尽量用 NOT NULL**:

- NULL 在索引中需要额外标记,占用更多空间
- 含 NULL 的列做统计、比较很麻烦(`= NULL` 永远是 NULL,必须用 `IS NULL`)
- 业务上"无值"往往意味着默认值,不是真正的未知

### 2. CHECK 约束

```sql
CREATE TABLE product (
    id     BIGINT PRIMARY KEY,
    price  NUMERIC(10,2) NOT NULL CHECK (price >= 0),
    stock  INTEGER       NOT NULL CHECK (stock >= 0),
    status CHAR(1)       NOT NULL CHECK (status IN ('A','B','C'))
);

-- 表级命名 CHECK
CREATE TABLE orders (
    id     BIGINT PRIMARY KEY,
    amount NUMERIC(10,2) NOT NULL,
    CONSTRAINT chk_amount_positive CHECK (amount > 0)
);
```

### 3. GENERATED ALWAYS AS IDENTITY(PG 10+ 推荐的自增)

**从 PostgreSQL 10 开始,官方推荐用 `IDENTITY` 代替 `SERIAL`。**

```sql
-- 语法 1:ALWAYS(显式 INSERT id 会报错)
CREATE TABLE users (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    name TEXT
);
INSERT INTO users(name) VALUES ('alice');        -- OK,自动用 1
INSERT INTO users(id, name) VALUES (100,'bob');  -- 报错!

-- 语法 2:BY DEFAULT(允许手动指定,推荐)
CREATE TABLE orders (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    order_no TEXT
);
INSERT INTO orders(order_no) VALUES ('O001');       -- OK,自动用 1
INSERT INTO orders(id, order_no) VALUES (1000, 'X'); -- OK,显式 1000

-- 自定义:起始值、步长、缓存
CREATE TABLE t (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY
        (START WITH 1000 INCREMENT BY 1 CACHE 20) PRIMARY KEY
);
```

#### `IDENTITY` vs `SERIAL` 对比

| 维度               | `SERIAL`                          | `IDENTITY`                      |
|--------------------|-----------------------------------|---------------------------------|
| 标准              | PG 私有语法                       | **SQL 标准**                    |
| 序列归属          | 创建一个独立 SEQUENCE 对象        | **绑定列**,`DROP TABLE` 自动清理 |
| 权限              | 序列独立权限                      | **跟随表**                      |
| 列属性冲突        | 与 `DEFAULT nextval()` 同义       | 真正意义的"自增列"             |
| 复制 / 逻辑解码  | 行为可能不一致                    | **PG 10+ 推荐,行为一致**        |
| 推荐度            | 遗留系统                          | **新项目**                      |

```sql
-- 串行化(SERIAL)的写法(PG 10 之前唯一方式)
CREATE TABLE t_legacy (
    id SERIAL PRIMARY KEY,           -- 等价于 INTEGER + nextval()
    name TEXT
);
-- 本质:
--   CREATE SEQUENCE t_legacy_id_seq;
--   CREATE TABLE t_legacy (
--       id INTEGER NOT NULL DEFAULT nextval('t_legacy_id_seq'),
--       ...
--   );

-- 序列化(BIGSERIAL)
CREATE TABLE t_big (
    id BIGSERIAL PRIMARY KEY
);
```

### 4. 生成列(GENERATED ALWAYS AS STORED / VIRTUAL)

PostgreSQL 12+ 支持**生成列**,值由其他列计算得出。

```sql
-- STORED:物理存储(可加索引,推荐)
CREATE TABLE orders (
    id           BIGINT PRIMARY KEY,
    price        NUMERIC(10,2) NOT NULL,
    quantity     INTEGER       NOT NULL,
    total_amount NUMERIC(12,2) GENERATED ALWAYS AS (price * quantity) STORED
);

-- VIRTUAL:不存储,读取时计算(PG 12+ 新增,默认模式)
CREATE TABLE users (
    id      BIGINT PRIMARY KEY,
    first_name TEXT,
    last_name  TEXT,
    full_name  TEXT GENERATED ALWAYS AS (first_name || ' ' || last_name) VIRTUAL
);

-- 查看生成列
\d orders
```

| 模式      | 是否存储 | 是否可建索引 | 使用场景                  |
|-----------|----------|--------------|---------------------------|
| `STORED`  | 是       | **是**       | 频繁查询的计算列(推荐)   |
| `VIRTUAL` | 否       | 否           | 偶尔使用的展示列          |

### 5. COLLATE(排序规则)

PostgreSQL 的排序规则(collation)控制字符串比较规则。

```sql
-- 列级 COLLATE
CREATE TABLE users (
    name VARCHAR(50) COLLATE "en_US"      -- 标准美式字典序
        NOT NULL,
    code VARCHAR(50) COLLATE "C"          -- 按字节比较(速度快)
        NOT NULL
);

-- 表达式级 COLLATE(查询时覆盖)
SELECT * FROM users ORDER BY name COLLATE "C";

-- 数据库默认 collation
SHOW LC_COLLATE;

-- 查看可用 collation
SELECT collname FROM pg_collation;
```

| 场景                    | 推荐 COLLATE          |
|-------------------------|------------------------|
| 大多数业务             | 使用库默认(创建时定)   |
| 区分大小写的唯一性     | `"C"` 或 `"POSIX"`     |
| 中文排序               | `"zh_CN"`              |

## 六、临时表(TEMPORARY TABLE)

### 1. 语法

```sql
-- 会话级临时表(其他会话看不到,会话结束自动删)
CREATE TEMP TABLE tmp_user_stats (
    user_id      BIGINT,
    order_count  INTEGER,
    total_amount NUMERIC(10,2)
);

-- 基于查询结果
CREATE TEMP TABLE tmp_top_users AS
SELECT user_id, SUM(amount) AS total
FROM orders
WHERE created_at >= '2024-01-01'
GROUP BY user_id
HAVING SUM(amount) > 10000;
```

### 2. ON COMMIT(事务结束时)

```sql
-- ON COMMIT DELETE ROWS(默认,事务提交后清空)
CREATE TEMP TABLE tmp_session (
    id SERIAL PRIMARY KEY,
    data TEXT
) ON COMMIT DELETE ROWS;

-- ON COMMIT DROP(事务提交后整个表删掉)
CREATE TEMP TABLE tmp_tx (
    id INTEGER
) ON COMMIT DROP;

-- ON COMMIT PRESERVE ROWS(事务提交保留,会话结束才删)
CREATE TEMP TABLE tmp_retain (
    id INTEGER
) ON COMMIT PRESERVE ROWS;
```

### 3. PostgreSQL 临时表的特点

- 仅**当前会话**可见,其他会话看不到同名表
- **会话结束自动删除**
- 可与普通表同名(临时表优先级最高)
- 临时表的索引 / 触发器也是临时的
- 不写 WAL(无 WAL 写入,比普通表快)

> **临时表 vs CTE / 子查询**:临时表有统计信息,复杂多步骤查询用临时表比 CTE 性能更好。

## 七、UNLOGGED 表

**UNLOGGED 表 = 不写 WAL 的表**,写入速度极快,但**崩溃后数据丢失**(只保留表结构)。

```sql
CREATE UNLOGGED TABLE tmp_import (
    id   BIGINT,
    data TEXT
);

-- 批量导入比普通表快 5-10 倍
INSERT INTO tmp_import SELECT * FROM raw_csv_data;

-- 处理完后可以转成普通表(走一次 COPY 重建)
ALTER TABLE tmp_import SET LOGGED;
```

**使用场景**:

- 临时数据 / ETL 中间表
- 大批量导入临时区
- 不重要的会话级缓存
- 性能压测

**注意事项**:

- 崩溃 / 断电后**数据全没**(但表还在)
- **不能**做流复制 / 主备同步(不写 WAL)
- 不能做 PITR(Point-in-Time Recovery)

## 八、主键(PRIMARY KEY)

### 1. 基本用法

```sql
-- 列内定义
id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY

-- 表级定义(推荐,可命名)
CONSTRAINT pk_users PRIMARY KEY (id)

-- 复合主键
CONSTRAINT pk_order_items PRIMARY KEY (order_id, product_id)
```

### 2. 主键的特征

- **唯一且非空**
- **每张表只能有 1 个**
- 主键 = **默认聚簇索引**(数据按主键物理组织)
- 主键列**隐含 NOT NULL**

### 3. 主键设计原则

- 稳定不变(不被业务修改)
- 尽量短(主键会出现在所有二级索引叶子节点)
- 推荐:`IDENTITY` BIGINT、UUIDv7(有序 UUID,避免索引分裂)、雪花算法

```sql
-- 复合主键示例(订单明细)
CREATE TABLE order_items (
    order_id   BIGINT NOT NULL,
    product_id BIGINT NOT NULL,
    quantity   INTEGER NOT NULL,
    PRIMARY KEY (order_id, product_id)
);

-- UUIDv7 主键示例(需 pguuid 或 app 层生成)
CREATE EXTENSION pguuid;
CREATE TABLE events (
    id UUID DEFAULT pguuid_generate_v7() NOT NULL PRIMARY KEY,
    payload JSONB
);
```

## 九、外键(FOREIGN KEY)

### 1. 基本语法

```sql
CREATE TABLE orders (
    id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id  BIGINT NOT NULL,
    amount   NUMERIC(10,2) NOT NULL,
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id)
        REFERENCES users(id)
        ON DELETE RESTRICT
        ON UPDATE CASCADE
);
```

### 2. 完整参照动作

| 动作            | DELETE 时子表行为                  | UPDATE 时父表行为                  |
|-----------------|------------------------------------|------------------------------------|
| `CASCADE`       | 自动删除子表对应行                  | 自动更新子表外键值                  |
| `SET NULL`      | 子表外键列设为 NULL(需可空)       | 子表外键列设为 NULL                |
| `SET DEFAULT`   | 子表外键列设为 DEFAULT 值           | 子表外键列设为 DEFAULT 值           |
| `RESTRICT`      | **禁止**删除父表行(默认行为)      | **禁止**更新父表主键               |
| `NO ACTION`     | 检查推迟到事务结束(默认延迟模式)  | 同 RESTRICT,但检查延迟            |

### 3. 完整示例

```sql
-- CASCADE:博客删除 → 自动删评论
CREATE TABLE comments (
    id BIGINT PRIMARY KEY,
    post_id BIGINT NOT NULL,
    body TEXT,
    CONSTRAINT fk_comments_post
        FOREIGN KEY (post_id) REFERENCES posts(id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

-- SET NULL:用户注销 → 订单保留但 user_id 置空
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT,   -- 注意:允许 NULL
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE SET NULL
        ON UPDATE CASCADE
);

-- SET DEFAULT:员工离职 → 订单归属到"匿名员工"
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    employee_id BIGINT DEFAULT 1 NOT NULL,
    CONSTRAINT fk_orders_employee
        FOREIGN KEY (employee_id) REFERENCES employees(id)
        ON DELETE SET DEFAULT
        ON UPDATE CASCADE
);

-- RESTRICT(默认):有订单的用户不允许删除
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE RESTRICT
);

-- NO ACTION(默认延迟检查):在事务内可以暂时违反
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE NO ACTION
);
```

### 4. 延迟约束(DEFERRABLE)

PG 独有特性:**约束可设置为事务结束才检查**。

```sql
-- DEFERRABLE INITIALLY DEFERRED:事务内可暂时违反,提交时统一检查
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        DEFERRABLE INITIALLY DEFERRED
);

-- 用法:循环引用场景
BEGIN;
INSERT INTO users(id, ...) VALUES (1, ...);  -- 父表行未提交
INSERT INTO orders(user_id, ...) VALUES (1, ...);  -- 暂时违反
COMMIT;  -- 提交时一起检查,通过!
```

| 模式                                 | 行为                            |
|--------------------------------------|---------------------------------|
| `NOT DEFERRABLE`(默认)              | 每条语句立即检查                |
| `DEFERRABLE INITIALLY IMMEDIATE`    | 立即检查,但事务内可临时切换     |
| `DEFERRABLE INITIALLY DEFERRED`     | 事务结束才检查                  |

```sql
-- 事务内临时切换检查时机
SET CONSTRAINTS ALL DEFERRED;
-- 或
SET CONSTRAINTS fk_orders_user DEFERRED;
```

## 十、唯一约束(UNIQUE)

### 1. 基本用法

```sql
-- 列内定义
email VARCHAR(100) NOT NULL UNIQUE

-- 表级定义(可命名,推荐)
CONSTRAINT uk_users_email UNIQUE (email)

-- 复合唯一
CONSTRAINT uk_users_tenant_phone UNIQUE (tenant_id, phone)

-- 部分唯一(PG 特色:允许 NULL 不参与唯一性)
CREATE TABLE users (
    id   BIGINT PRIMARY KEY,
    email VARCHAR(100),
    phone VARCHAR(20),
    CONSTRAINT uk_users_email UNIQUE (email)       -- NULL 不冲突
    CONSTRAINT uk_users_phone UNIQUE (phone)       -- NULL 不冲突
);
```

### 2. 与主键的区别

| 维度         | PRIMARY KEY              | UNIQUE                   |
|--------------|--------------------------|--------------------------|
| 数量         | **1 个**                 | 多个                     |
| NULL        | 不允许                   | **允许**(且多个 NULL 不冲突) |
| 是否聚簇    | 是                       | 否                       |
| 用途         | 物理存储顺序 / 关联外键 | 业务唯一性                |

### 3. UNIQUE 索引的 NULL 处理

```sql
-- PG 中 NULL 视为"互不相等",所以 (NULL, NULL) 不冲突
INSERT INTO t(email) VALUES (NULL);    -- OK
INSERT INTO t(email) VALUES (NULL);    -- OK,不冲突
INSERT INTO t(email) VALUES ('a@x');   -- OK
INSERT INTO t(email) VALUES ('a@x');   -- 报错:违反唯一约束
```

## 十一、检查约束(CHECK)

### 1. 基本用法

```sql
-- 列级 CHECK
price NUMERIC(10,2) NOT NULL CHECK (price > 0)

-- 表级 CHECK(可命名,推荐)
CONSTRAINT chk_orders_amount CHECK (amount > 0 AND amount < 1000000)

-- 跨列 CHECK
CONSTRAINT chk_orders_paid CHECK (
    paid_amount <= total_amount AND paid_amount >= 0
)
```

### 2. 完整示例

```sql
CREATE TABLE products (
    id          BIGINT PRIMARY KEY,
    name        TEXT NOT NULL,
    price       NUMERIC(10,2) NOT NULL,
    cost_price  NUMERIC(10,2) NOT NULL,
    stock       INTEGER NOT NULL,
    status      CHAR(1) NOT NULL DEFAULT 'A',
    discount    NUMERIC(3,2),    -- 0.00 ~ 0.99

    CONSTRAINT chk_price_positive CHECK (price >= 0),
    CONSTRAINT chk_cost_le_price   CHECK (cost_price <= price),
    CONSTRAINT chk_stock_nonneg   CHECK (stock >= 0),
    CONSTRAINT chk_status_valid   CHECK (status IN ('A','B','C','D')),
    CONSTRAINT chk_discount_range CHECK (discount IS NULL OR (discount >= 0 AND discount < 1))
);
```

### 3. 添加 / 删除 CHECK

```sql
-- 添加
ALTER TABLE products
    ADD CONSTRAINT chk_name_length CHECK (length(name) >= 2);

-- 删除
ALTER TABLE products DROP CONSTRAINT chk_name_length;

-- 禁用 / 启用(用于批量导入)
ALTER TABLE products DISABLE TRIGGER ALL;
ALTER TABLE products DROP CONSTRAINT chk_price_positive;
-- 导入完成后
ALTER TABLE products ADD CONSTRAINT chk_price_positive CHECK (price >= 0) NOT VALID;
ALTER TABLE products VALIDATE CONSTRAINT chk_price_positive;  -- 渐进式校验存量数据
```

## 十二、排他约束(EXCLUDE,PG 特色)

**排他约束是 PostgreSQL 独有特性**,保证任意两行在指定列(或表达式)上不满足指定运算符(常用 `&&`、`=`、`~`)。

### 1. 语法

```sql
CONSTRAINT constraint_name
    EXCLUDE [ USING index_method ]
    ( exclude_element WITH operator [, ...] )
    [ WHERE ( predicate ) ]
```

### 2. 经典示例:会议室预订不冲突

```sql
-- 扩展(用于 GIST 索引范围类型)
CREATE EXTENSION btree_gist;

CREATE TABLE room_bookings (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    room_id     INTEGER     NOT NULL,
    during      tsrange     NOT NULL,    -- 时间区间
    booked_by   BIGINT      NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    -- 同一房间同一时间不能重复预订
    CONSTRAINT ex_room_no_overlap
        EXCLUDE USING GIST (
            room_id WITH =,
            during  WITH &&
        )
);

-- 测试
INSERT INTO room_bookings(room_id, during, booked_by)
VALUES (1, '[2026-08-14 10:00, 2026-08-14 12:00)', 100);

-- 这条会冲突报错!
INSERT INTO room_bookings(room_id, during, booked_by)
VALUES (1, '[2026-08-14 11:00, 2026-08-14 13:00)', 200);
-- ERROR: conflicting key value violates exclusion constraint "ex_room_no_overlap"
```

### 3. 其他典型用法

```sql
-- 1) 同一用户在同一时间不能重复登录
CREATE TABLE active_sessions (
    user_id    BIGINT NOT NULL,
    session_at TIMESTAMPTZ NOT NULL,
    CONSTRAINT ex_one_session_per_user
        EXCLUDE USING GIST (
            user_id WITH =,
            session_at WITH =
        )
);

-- 2) 部分排他(带 WHERE 条件)
CREATE TABLE employee_schedule (
    id      BIGINT PRIMARY KEY,
    emp_id  BIGINT,
    shift   tsrange,
    -- 启用(非删除)的排班才不允许冲突
    CONSTRAINT ex_no_shift_overlap
        EXCLUDE USING GIST (
            emp_id WITH =,
            shift WITH &&
        ) WHERE (shift IS NOT NULL)
);
```

> **核心价值**:用一条 EXCLUDE 约束替代应用层复杂的并发控制代码,数据库层面保证不冲突。

## 十三、表修改(ALTER TABLE)

### 1. 添加列

```sql

ALTER TABLE users ADD COLUMN avatar VARCHAR(255) DEFAULT '/default.png';
ALTER TABLE users ADD COLUMN age SMALLINT NOT NULL DEFAULT 0;

-- 添加列到指定位置(PG 不支持 AFTER,只能追加)
```

### 2. 删除列

```sql
ALTER TABLE users DROP COLUMN avatar;
ALTER TABLE users DROP COLUMN phone, DROP COLUMN nickname;
```

### 3. 修改列

```sql
-- 改类型 / 长度
ALTER TABLE users ALTER COLUMN username TYPE VARCHAR(100);

-- 改 NOT NULL
ALTER TABLE users ALTER COLUMN phone SET NOT NULL;
ALTER TABLE users ALTER COLUMN phone DROP NOT NULL;

-- 改默认值
ALTER TABLE users ALTER COLUMN status SET DEFAULT 1;
ALTER TABLE users ALTER COLUMN status DROP DEFAULT;

-- 重命名列
ALTER TABLE users RENAME COLUMN username TO user_name;

-- 改 COLLATE
ALTER TABLE users ALTER COLUMN username TYPE VARCHAR(50) COLLATE "C";
```

### 4. 添加 / 删除约束

```sql
-- 添加主键
ALTER TABLE orders ADD CONSTRAINT pk_orders PRIMARY KEY (id);

-- 添加外键
ALTER TABLE orders
    ADD CONSTRAINT fk_orders_user
    FOREIGN KEY (user_id) REFERENCES users(id);

-- 添加唯一约束
ALTER TABLE users ADD CONSTRAINT uk_email UNIQUE (email);

-- 添加 CHECK
ALTER TABLE products ADD CONSTRAINT chk_price CHECK (price >= 0);

-- 删除约束
ALTER TABLE users DROP CONSTRAINT uk_email;
ALTER TABLE orders DROP CONSTRAINT fk_orders_user;
```

### 5. 添加 / 删除索引

```sql
-- 添加索引
CREATE INDEX idx_users_status ON users(status);
ALTER TABLE users ADD CONSTRAINT uk_email UNIQUE (email);  -- 自动建唯一索引

-- 删除索引
DROP INDEX idx_users_status;
ALTER TABLE users DROP CONSTRAINT uk_email;
```

### 6. 重命名表

```sql
ALTER TABLE users RENAME TO app_users;
```

### 7. 移动表空间

```sql
ALTER TABLE users SET TABLESPACE fast_ssd;
```

### 8. 性能考虑

- PG 的 ALTER TABLE **不锁表**(PG 11 之前也基本无锁,大多数 DDL 在线)
- 修改列类型 / 加默认值是**元数据级**变更,瞬间完成
- 加外键 / CHECK 需要全表校验存量数据,**大表慢**

```sql
-- 大表加 NOT VALID 约束:先加,异步校验
ALTER TABLE huge_table ADD CONSTRAINT chk_x CHECK (x > 0) NOT VALID;
-- 业务空闲时段校验
ALTER TABLE huge_table VALIDATE CONSTRAINT chk_x;
```

## 十五、表继承(INHERITS,PG 特色)

**表继承 = 子表自动拥有父表的所有列和约束**,子表可以加自己的列。这是 PostgreSQL 的传统分区方式(PG 10 之前)。**注意:声明式分区表已替代大部分继承用法**,但继承本身仍用于通用"分类继承"。

### 1. 语法

```sql
-- 父表
CREATE TABLE vehicles (
    id           BIGINT PRIMARY KEY,
    brand        VARCHAR(50) NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP
);

-- 子表
CREATE TABLE cars (
    door_count   SMALLINT NOT NULL,
    fuel_type    VARCHAR(20)
) INHERITS (vehicles);

CREATE TABLE trucks (
    load_capacity NUMERIC(10,2) NOT NULL,
    axle_count    SMALLINT
) INHERITS (vehicles);
```

### 2. 查询父表

```sql
-- 默认查父表只返回父表数据
SELECT * FROM vehicles;          -- 只 vehicles
SELECT * FROM vehicles*;         -- 查 vehicles 和所有子表(后缀 *)

-- 也可显式查子表
SELECT * FROM ONLY vehicles;     -- 同 vehicles,排除子表
SELECT * FROM ONLY cars;
```

### 3. 继承特性

```
vehicles (父表)
   ├── cars (子表,继承 vehicles 列)
   ├── trucks (子表,继承 vehicles 列)
   └── motorcycles (子表)

- 子表自动拥有父表所有列
- 子表可加自己的列
- 子表上的 INSERT / UPDATE 不影响父表
- 父表上的 INSERT 不会进入子表
- 检查约束 / 唯一约束**不**自动继承到子表
- 主键 / 外键**不**继承
```

### 4. 继承 vs 分区

| 特性                | INHERITS(继承)            | PARTITION BY(声明式分区)            |
|---------------------|----------------------------|--------------------------------------|
| 标准化              | 传统方式                   | **PG 10+ 标准,推荐**                |
| 约束继承            | 否(需手动加到每张子表)    | 是(全局)                            |
| 主键 / 唯一约束    | 每张表独立                 | 全局唯一                           |
| 查询优化器          | 默认不加(需 `ONLY` 或 `*`)| 自动分区裁剪                        |
| 跨子表 UPDATE       | 需要复杂触发器             | 自动路由                           |
| 典型用途            | 通用"分类继承"            | **大表分区(时间 / 哈希)**           |

> **生产建议**:新项目用**声明式分区**,继承留给特殊业务(继承关系建模)。

## 十六、分区表(PARTITION BY,详见第 14 章)

### 1. 声明式分区语法

```sql
-- 父表(逻辑表,无数据)
CREATE TABLE orders (
    id          BIGINT GENERATED BY DEFAULT AS IDENTITY,
    order_no    TEXT NOT NULL,
    user_id     BIGINT NOT NULL,
    amount      NUMERIC(10,2) NOT NULL,
    created_at  TIMESTAMPTZ NOT NULL,
    PRIMARY KEY (id, created_at)   -- 分区键必须在主键里
) PARTITION BY RANGE (created_at);

-- 子分区
CREATE TABLE orders_2024q1 PARTITION OF orders
    FOR VALUES FROM ('2024-01-01') TO ('2024-04-01');

CREATE TABLE orders_2024q2 PARTITION OF orders
    FOR VALUES FROM ('2024-04-01') TO ('2024-07-01');

CREATE TABLE orders_default PARTITION OF orders DEFAULT;
```

### 2. 三种分区策略

```sql
-- RANGE(按范围,最常用:按时间)
PARTITION BY RANGE (created_at)

-- LIST(按枚举:按地区、状态)
PARTITION BY LIST (region)

-- HASH(按哈希均匀分布)
PARTITION BY HASH (user_id)
```

## 十七、表删除与清空

### 1. 三种方式对比

| 操作                | 类型     | 速度  | 回滚   | 自增 ID | 触发器 | 范围 |
|---------------------|----------|-------|--------|---------|--------|------|
| `DROP TABLE`        | DDL      | 最快  | 不支持 | 表没了  | -      | 表   |
| `TRUNCATE TABLE`    | DDL      | 快    | 不支持 | 重置为初始值 | 不触发 | 表   |
| `DELETE FROM`       | DML      | 慢    | 支持   | 保留    | 触发   | 行   |

### 2. DROP TABLE

```sql
DROP TABLE t;
DROP TABLE IF EXISTS t1, t2;
DROP TABLE t CASCADE;   -- 连同依赖对象(视图 / 外键)一起删
```

### 3. TRUNCATE

```sql
-- 最快清空表,本质是 DROP + CREATE
TRUNCATE TABLE users;
TRUNCATE TABLE users RESTART IDENTITY;   -- 重置 IDENTITY / SERIAL
TRUNCATE TABLE users, orders CASCADE;   -- 多表 + 级联
```

- TRUNCATE **不能**用于有外键引用的表(除非 `CASCADE`)
- 不触发 DELETE 触发器
- 不支持事务回滚

```sql
-- 在事务里也可以,但 COMMIT 后不可撤销
BEGIN;
TRUNCATE TABLE temp_data;
COMMIT;
```

### 4. DELETE

```sql
DELETE FROM users WHERE status = 0;
DELETE FROM users;                          -- 全表删除(慢!)
DELETE FROM users WHERE id < 100000 LIMIT 10000;  -- 分批删除
```

- 支持事务回滚
- 触发 DELETE 触发器
- 全表 DELETE 慢,产生大量 WAL

### 5. 实战建议

```sql
-- 大表清空:TRUNCATE
TRUNCATE TABLE log_2024;

-- 大表按条件清理:分批 DELETE
DO $$
DECLARE
    deleted INTEGER;
BEGIN
    LOOP
        DELETE FROM logs WHERE created_at < '2024-01-01' LIMIT 10000;
        GET DIAGNOSTICS deleted = ROW_COUNT;
        EXIT WHEN deleted = 0;
        PERFORM pg_sleep(0.1);  -- 让其他事务有机会
    END LOOP;
END $$;
```

## 十九、视图(View)

### 1. 普通视图

```sql
-- 创建
CREATE VIEW active_users AS
SELECT id, username, email
FROM users
WHERE status = 1;

-- 可更新视图(满足一定条件:单表 / 无聚合 / 无 DISTINCT)
CREATE VIEW v_users AS
SELECT id, username FROM users WHERE status = 1;

-- WITH CHECK OPTION:确保 UPDATE / INSERT 不违背视图条件
CREATE VIEW active_users AS
SELECT * FROM users WHERE status = 1
WITH CHECK OPTION;

-- 删除
DROP VIEW active_users;
DROP VIEW IF EXISTS active_users CASCADE;
```

**普通视图 = 存储 SQL,查询时执行**,不占额外空间,数据始终是最新的。

### 2. 物化视图(MATERIALIZED VIEW)

**物化视图 = 把查询结果物理存储**,查询速度快,但**数据可能陈旧**(需手动 REFRESH)。

```sql
-- 创建物化视图
CREATE MATERIALIZED VIEW daily_sales AS
SELECT
    date_trunc('day', created_at) AS day,
    user_id,
    COUNT(*)                       AS order_count,
    SUM(amount)                    AS total_amount
FROM orders
WHERE status >= 1
GROUP BY date_trunc('day', created_at), user_id
WITH DATA;   -- 创建时立即填充数据

-- 创建物化视图(不立即填充)
CREATE MATERIALIZED VIEW monthly_sales AS
SELECT ...
WITH NO DATA;
```

### 3. 物化视图的索引

```sql
-- 物化视图上**可以**建索引(普通视图不行)
CREATE UNIQUE INDEX uk_daily_sales
    ON daily_sales (day, user_id);

CREATE INDEX idx_daily_sales_day
    ON daily_sales (day);
```

### 4. 刷新物化视图

```sql
-- 完全刷新(清空再填充,慢)
REFRESH MATERIALIZED VIEW daily_sales;

-- 增量刷新(必须有唯一索引,只更新变化部分,快)
REFRESH MATERIALIZED VIEW CONCURRENTLY daily_sales;

-- 不存在则创建
REFRESH MATERIALIZED VIEW CONCURRENTLY daily_sales
    WITH NO DATA;
```

| 刷新方式                       | 锁表 | 速度 | 前提条件                         |
|--------------------------------|-------|------|----------------------------------|
| `REFRESH MATERIALIZED VIEW`    | 排他锁 | 慢   | 无                               |
| `REFRESH MATERIALIZED VIEW CONCURRENTLY` | 无锁  | 快   | 物化视图**必须有唯一索引** |

### 5. 物化视图完整示例

```sql
-- 1) 创建
CREATE MATERIALIZED VIEW top_products_monthly AS
SELECT
    p.id,
    p.name,
    date_trunc('month', o.created_at) AS month,
    SUM(oi.quantity)                   AS qty,
    SUM(oi.subtotal)                   AS revenue
FROM products p
JOIN order_items oi ON oi.product_id = p.id
JOIN orders o ON o.id = oi.order_id
WHERE o.status IN (2, 3)  -- 已发货 / 已完成
GROUP BY p.id, p.name, date_trunc('month', o.created_at)
WITH DATA;

-- 2) 建唯一索引(用于 CONCURRENTLY 刷新)
CREATE UNIQUE INDEX uk_top_products
    ON top_products_monthly (id, month);

-- 3) 查询
SELECT * FROM top_products_monthly
WHERE month = '2026-08-01'
ORDER BY revenue DESC
LIMIT 100;

-- 4) 定时刷新(用 pg_cron 或外部 cron)
SELECT cron.schedule('refresh-top-products', '0 2 * * *',
    $$REFRESH MATERIALIZED VIEW CONCURRENTLY top_products_monthly$$);
```

### 6. 删除物化视图

```sql
DROP MATERIALIZED VIEW daily_sales;
```

## 二十一、pg_dump / pg_restore 基础

### 1. pg_dump(导出)

```bash
# 导出整个库(默认纯文本 SQL)
pg_dump mydb > mydb.sql

# 自定义格式(压缩 + 并行恢复)
pg_dump -Fc mydb > mydb.dump

# directory 格式(并行导出 / 恢复)
pg_dump -Fd -j 4 -f mydb_dir mydb

# 只导表结构
pg_dump -s mydb > schema.sql

# 只导数据
pg_dump -a mydb > data.sql

# 导出特定表
pg_dump -t users -t orders mydb > partial.sql

# 排除表
pg_dump --exclude-table=log_* mydb > mydb_no_logs.sql
```

### 2. pg_restore(恢复)

```bash
# 恢复纯文本 SQL
psql mydb < mydb.sql

# 恢复自定义格式
pg_restore -d mydb mydb.dump

# 并行恢复(directory 格式)
pg_restore -d mydb -j 4 mydb_dir

# 先看 dump 包含什么
pg_restore --list mydb.dump | less

# 干净恢复(先删再建)
pg_restore -d mydb --clean --create mydb.dump
```

### 3. 跨服务器迁移(典型工作流)

```bash
# 1) 源服务器导出
pg_dump -Fc -Z 9 mydb > mydb.dump

# 2) 传到目标
scp mydb.dump target:/tmp/

# 3) 目标服务器创建空库
psql -c "CREATE DATABASE mydb;" postgres

# 4) 恢复
pg_restore -d mydb -j 4 mydb.dump

# 5) 验证
psql mydb -c "SELECT COUNT(*) FROM users;"
```

### 4. 备份策略

```bash
# 全量 + WAL 归档 = PITR(Point-in-Time Recovery)
# postgresql.conf
archive_mode = on
archive_command = 'cp %p /backup/wal/%f'
wal_level = replica

# 基础备份
pg_basebackup -D /backup/base -Ft -z -P

# 日常自动备份(crontab)
0 2 * * * pg_dump -Fc mydb > /backup/mydb-$(date +\%Y\%m\%d).dump
```

## 二十二、完整业务表设计示例

### 1. 用户表(users)

```sql
CREATE TABLE users (
    id              BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    username        VARCHAR(50)  NOT NULL UNIQUE,
    email           VARCHAR(100) NOT NULL UNIQUE,
    phone           VARCHAR(20)  UNIQUE,
    password_hash   TEXT         NOT NULL,
    nickname        VARCHAR(50),
    avatar          VARCHAR(255),
    gender          SMALLINT     NOT NULL DEFAULT 0
                    CHECK (gender IN (0,1,2)),
    birthday        DATE,
    status          SMALLINT     NOT NULL DEFAULT 1
                    CHECK (status IN (0,1,2)),
    last_login_at   TIMESTAMPTZ,
    last_login_ip   INET,
    profile         JSONB        NOT NULL DEFAULT '{}'::jsonb,
    created_at      TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT chk_phone_format CHECK (phone ~ '^\d{11}$')
);

COMMENT ON TABLE  users           IS '用户表';
COMMENT ON COLUMN users.username  IS '用户名';
COMMENT ON COLUMN users.email     IS '邮箱';
COMMENT ON COLUMN users.status    IS '状态:0-禁用 1-正常 2-锁定';

CREATE INDEX idx_users_status_created ON users(status, created_at);
CREATE INDEX idx_users_profile_gin    ON users USING GIN (profile);
```

### 2. 商品分类表(product_categories,树形 + 排他约束)

```sql
CREATE TABLE product_categories (
    id          BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    parent_id   BIGINT       NOT NULL DEFAULT 0,
    name        VARCHAR(100) NOT NULL,
    slug        VARCHAR(100) NOT NULL UNIQUE,
    level       SMALLINT     NOT NULL CHECK (level BETWEEN 1 AND 5),
    sort_order  INTEGER      NOT NULL DEFAULT 0,
    status      SMALLINT     NOT NULL DEFAULT 1 CHECK (status IN (0,1)),
    created_at  TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP
);

COMMENT ON TABLE product_categories IS '商品分类表(树形)';

CREATE INDEX idx_categories_parent ON product_categories(parent_id, status);
```

### 3. 商品表(products)

```sql
CREATE TABLE products (
    id            BIGINT       GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sku           VARCHAR(50)  NOT NULL UNIQUE,
    name          VARCHAR(200) NOT NULL,
    category_id   BIGINT       NOT NULL,
    brand_id      BIGINT,
    price         NUMERIC(10,2) NOT NULL CHECK (price >= 0),
    cost_price    NUMERIC(10,2) NOT NULL DEFAULT 0 CHECK (cost_price >= 0),
    stock         INTEGER      NOT NULL DEFAULT 0 CHECK (stock >= 0),
    sales         INTEGER      NOT NULL DEFAULT 0,
    status        SMALLINT     NOT NULL DEFAULT 1
                  CHECK (status IN (0,1,2)),
    description   TEXT,
    tags          TEXT[]       NOT NULL DEFAULT '{}',
    attrs         JSONB        NOT NULL DEFAULT '{}'::jsonb,
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_products_category
        FOREIGN KEY (category_id) REFERENCES product_categories(id)
        ON DELETE RESTRICT,
    CONSTRAINT chk_cost_le_price CHECK (cost_price <= price)
);

COMMENT ON TABLE products IS '商品表';

CREATE INDEX idx_products_category ON products(category_id, status);
CREATE INDEX idx_products_brand    ON products(brand_id);
CREATE INDEX idx_products_tags     ON products USING GIN (tags);
CREATE INDEX idx_products_attrs    ON products USING GIN (attrs);
```

### 4. 订单表(orders,声明式分区)

```sql
CREATE TABLE orders (
    id            BIGINT       GENERATED BY DEFAULT AS IDENTITY,
    order_no      VARCHAR(32)  NOT NULL,
    user_id       BIGINT       NOT NULL,
    total_amount  NUMERIC(12,2) NOT NULL CHECK (total_amount >= 0),
    paid_amount   NUMERIC(12,2) NOT NULL DEFAULT 0 CHECK (paid_amount >= 0),
    status        SMALLINT     NOT NULL DEFAULT 0
                  CHECK (status IN (0,1,2,3,4,5)),
    pay_method    SMALLINT     CHECK (pay_method IN (1,2,3)),
    paid_at       TIMESTAMPTZ,
    shipped_at    TIMESTAMPTZ,
    completed_at  TIMESTAMPTZ,
    remark        VARCHAR(500),
    created_at    TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at    TIMESTAMPTZ  NOT NULL DEFAULT CURRENT_TIMESTAMP,

    PRIMARY KEY (id, created_at),    -- 分区键必须在主键里

    CONSTRAINT fk_orders_user
        FOREIGN KEY (user_id) REFERENCES users(id)
        ON DELETE RESTRICT
) PARTITION BY RANGE (created_at);

-- 分区
CREATE TABLE orders_2024q1 PARTITION OF orders
    FOR VALUES FROM ('2024-01-01') TO ('2024-04-01');
CREATE TABLE orders_2024q2 PARTITION OF orders
    FOR VALUES FROM ('2024-04-01') TO ('2024-07-01');
CREATE TABLE orders_2024q3 PARTITION OF orders
    FOR VALUES FROM ('2024-07-01') TO ('2024-10-01');
CREATE TABLE orders_2024q4 PARTITION OF orders
    FOR VALUES FROM ('2024-10-01') TO ('2025-01-01');
CREATE TABLE orders_default PARTITION OF orders DEFAULT;

-- 唯一约束(分区表必须包含分区键)
CREATE UNIQUE INDEX uk_orders_order_no ON orders(order_no, created_at);

CREATE INDEX idx_orders_user_status ON orders(user_id, status, created_at);

```

### 5. 订单明细表(order_items)

CREATE TABLE order_items (

    product_id    BIGINT       NOT NULL,

### 6. 会议室预订表(room_bookings,EXCLUDE 约束)

```sql
CREATE EXTENSION IF NOT EXISTS btree_gist;

CREATE TABLE room_bookings (
    id           BIGINT   GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    room_id      INTEGER  NOT NULL,
    booked_by    BIGINT   NOT NULL,
    during       tsrange  NOT NULL,
    title        VARCHAR(200) NOT NULL,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_room_bookings_user
        FOREIGN KEY (booked_by) REFERENCES users(id) ON DELETE CASCADE,

    -- 同一房间同一时间不能重复预订(EXCLUDE 是 PG 杀手锏)
    CONSTRAINT ex_room_no_overlap
        EXCLUDE USING GIST (
            room_id WITH =,
            during   WITH &&
        ),

    CONSTRAINT chk_during_valid CHECK (lower(during) < upper(during))
);

COMMENT ON TABLE room_bookings IS '会议室预订表';

CREATE INDEX idx_room_bookings_during ON room_bookings USING GIST (during);
```

## 二十三、设计最佳实践

### 1. 表设计原则

- **每张表必须有主键**
- **字段尽量 NOT NULL**,少用 NULL,业务"无值"用默认值
- **金额用 `NUMERIC`**,不用 `REAL` / `DOUBLE PRECISION`
- **时间戳用 `TIMESTAMPTZ`**,不用 `TIMESTAMP`(无时区)
- **大文本用 `TEXT`**,不用 `VARCHAR(无穷)`
- **每个字段加 COMMENT ON COLUMN**,便于维护
- **`created_at` / `updated_at` 几乎必备**

### 2. 命名规范

```sql
-- 表名:小写 + 下划线 + 复数
users, orders, order_items, product_categories

-- 主键:id (BIGINT GENERATED BY DEFAULT AS IDENTITY)
-- 外键:{关联表}_id (user_id, order_id, product_id)
-- 时间字段:{action}_at (created_at, paid_at, shipped_at)
-- 布尔 / 状态:is_{x} 或 status (SMALLINT + CHECK)
-- 索引:idx_{col1}_{col2} 普通
--      uk_{col} 唯一
--      pk_{col} 主键
-- 约束:chk_{col}_{rule} 检查
--      fk_{table}_{ref_table} 外键
--      ex_{rule} 排他
```

### 3. 字符集与存储

```sql
-- 全链路 UTF8 + 推荐 locale
-- 服务端 initdb -E UTF8 --locale=en_US.UTF-8
-- 库级 ENCODING='UTF8' LC_COLLATE='en_US.UTF-8'

-- 大文本一律 TEXT
-- 金额一律 NUMERIC
-- IP 用 INET 类型
-- 主键 BIGINT(避免 SERIAL 的 INT 上限)
```

### 4. 常用扩展(必装)

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;        -- 加密 / UUID
CREATE EXTENSION IF NOT EXISTS uuid-ossp;       -- UUID 函数
CREATE EXTENSION IF NOT EXISTS pg_trgm;         -- 模糊搜索 / 相似度
CREATE EXTENSION IF NOT EXISTS btree_gist;      -- GIST 索引标量类型
CREATE EXTENSION IF NOT EXISTS citext;          -- 不区分大小写 TEXT
CREATE EXTENSION IF NOT EXISTS hstore;          -- 键值存储
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;  -- SQL 统计
```

## 二十四、核心要点速记

- **PostgreSQL DDL 三件套**:`CREATE / ALTER / DROP`,对象覆盖**数据库 / Schema / 表 / 索引 / 视图 / 序列**
- **数据库的 `LC_COLLATE` / `LC_CTYPE` 创建后不可改**,因此创建时要选好 locale
- **模板数据库**:`template1`(默认可改)、`template0`(干净模板,用于不同 locale)
- **Schema = 数据库内的命名空间**,一个库可多个 Schema,合理设计可代替 MySQL 的"每个业务一个库"
- **生成列**:`GENERATED ALWAYS AS (...) STORED`(可索引)、`VIRTUAL`(不存储)
- **`IDENTITY` vs `SERIAL`**:`IDENTITY` 是 SQL 标准,序列绑定表,PG 10+ 推荐;`SERIAL` 是遗留用法
- **`COLLATE`**:控制字符串排序,默认按库 locale,可列级覆盖,索引与 ORDER BY 都要注意
- **`EXCLUDE` 排他约束是 PG 杀手锏**:会议室预订、时间区间、唯一组合等场景,数据库层面杜绝冲突
- **外键的 5 种参照动作**:`CASCADE / SET NULL / SET DEFAULT / RESTRICT / NO ACTION`
- **延迟约束 `DEFERRABLE INITIALLY DEFERRED`**:事务结束才检查,适合循环引用 / 复杂导入
- **唯一约束允许多个 NULL**(MySQL 不允许),这是 PG 的"宽容"行为
- **CHECK 约束**从 PG 7.x 一直强制执行(比 MySQL 早得多)
- **`UNLOGGED` 表**:不写 WAL,写入极快,**崩溃数据丢失**,用于临时区 / 批量导入
- **`TEMP` 表**:仅会话可见,会话结束自动删,`ON COMMIT` 控制事务结束行为
- **表继承(INHERITS)**:传统分区方式,**新项目用声明式分区**
- **声明式分区**:`PARTITION BY RANGE / LIST / HASH`,分区键必须在主键里,详见第 14 章
- **`ALTER TABLE` 大部分在线**:改类型 / 加默认值是元数据级,瞬间完成;**加外键 / CHECK 大表慢,可用 `NOT VALID` 渐进**
- **表空间(TABLESPACE)**:把热数据放 SSD,冷数据放机械盘,迁移用 `ALTER TABLE ... SET TABLESPACE`
- **`DROP` / `TRUNCATE` / `DELETE`**:DDL 不可回滚 / DDL 清表重置 IDENTITY / DML 支持事务
- **查询元数据三件套**:`\d`(快速)、`information_schema`(标准 SQL)、`pg_catalog`(最全)
- **普通视图 = 存储 SQL**,物化视图 = **物理存储查询结果**(可建索引,需 `REFRESH`)
- **`REFRESH MATERIALIZED VIEW CONCURRENTLY`**:增量刷新无锁,**必须有唯一索引**
- **`pg_dump -Fc` + `pg_restore -j`**:标准备份 / 恢复,大库用并行恢复
- **`TIMESTAMPTZ` > `TIMESTAMP`**:跨时区数据用带时区的时间戳,内部存 UTC
- **`JSONB` > `JSON`**:二进制 JSON,支持 GIN 索引,推荐代替纯文本 JSON
- **`NUMERIC` > `REAL / DOUBLE`**:金额一律精确小数
- **排他约束 `EXCLUDE`**:会议室 / 时间段不冲突的唯一非冲突解决方案,代码层并发控制可以简化为一条 DDL
