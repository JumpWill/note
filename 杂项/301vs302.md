# 301 vs 302 重定向

## 一、基本定义

| 状态码 | 名称 | 含义 |
| ------ | ---- | ---- |
| **301** | Moved Permanently | 资源**永久**移动,搜索引擎将旧 URL 的权重转移到新 URL |
| **302** | Found(原 Moved Temporarily) | 资源**临时**移动,搜索引擎继续抓取旧 URL |

```text
301:  GET /old → 301 Location: /new    (永久)
302:  GET /old → 302 Location: /new    (临时)
```

---

## 二、RFC 定义与历史

| 状态码 | RFC | 原始含义 |
| ------ | --- | -------- |
| 301 | RFC 2616 | "The requested resource has been assigned a new permanent URI" |
| 302 | RFC 2616 | "The requested resource resides temporarily under a different URI" |

**注**:302 在 HTTP/1.0 时叫 "Moved Temporarily",HTTP/1.1 改名 "Found",但浏览器对两者的处理**保持一致**(临时)。

---

## 三、核心差异:缓存行为

这是 301 与 302 在浏览器中**最关键**的区别。

### 1. 浏览器对 301 的处理

```text
GET /old
  ↓
301 Location: /new
  ↓
浏览器:
  1. 缓存 /old → /new 的映射(强缓存,**默认长期有效**)
  2. 后续请求 /old 时,**不再发请求**,直接走缓存跳转到 /new
```

**关键**:浏览器会**永久缓存**这个重定向,直到**缓存被清除**(用户清缓存 / 浏览器重启 / 配置变更)。

### 2. 浏览器对 302 的处理

```text
GET /old
  ↓
302 Location: /new
  ↓
浏览器:
  1. **不缓存** 重定向关系(或仅短暂缓存)
  2. 后续每次请求 /old,都会**重新发请求**到服务器
  3. 服务器再返回 302(可能再跳到别的地址)
```

**关键**:浏览器每次都发请求,**不长期缓存**。

---

## 四、行为对比表

| 行为 | 301 | 302 |
| ---- | --- | --- |
| **浏览器缓存重定向** | **永久缓存**(默认长期) | **不缓存 / 短期** |
| **后续请求 /old** | 不发请求,直接走缓存跳转 | 每次都发请求 |
| **地址栏显示** | 更新为新地址 | 通常显示新地址(取决于浏览器) |
| **后退按钮** | 不能再退到 /old | 可以退到 /old |
| **刷新** | 用新地址重新请求 | 用新地址重新请求 |
| **POST 请求** | RFC:应变成 GET(浏览器实际行为不一) | RFC:应变成 GET(浏览器实际行为不一) |
| **搜索引擎** | 转移权重到新 URL | 保留旧 URL,继续抓取 |
| **历史记录** | 不记录 /old | 记录 /old |

## 五、浏览器实际行为详解

### 1. Chrome / Edge / Safari(Chromium 系)

#### 301 行为

```text
T1: 浏览器请求 https://example.com/old
    服务器返回 301 Location: https://example.com/new
    → 浏览器跳转到 /new,地址栏变成 /new
    → 浏览器**缓存** /old → /new 的映射到 .well-known 缓存目录

T2: 用户再次访问 https://example.com/old
    → 浏览器**不发起任何网络请求**
    → 直接读缓存,跳转到 https://example.com/new
    → 地址栏变成 /new
```

#### 302 行为

```text
T1: 浏览器请求 https://example.com/old
    服务器返回 302 Location: https://example.com/new
    → 浏览器跳转到 /new

T2: 用户再次访问 https://example.com/old
    → 浏览器**重新发起请求** https://example.com/old
    → 服务器再次返回 302 → /new
    → 浏览器跳转到 /new
```

**关键差异**:302 每次都重新问服务器。

### 2. Firefox

行为与 Chrome 类似,但**地址栏策略略有不同**:

- 301 后地址栏**保留为新地址**
- 302 后地址栏**保留为新地址**(但内部 /old 仍可访问)

### 3. 地址栏与回退行为对比

```text
301 后:
  - 用户输入 /old → 地址栏跳到 /new
  - 用户按"后退" → **不能回到 /old**(历史记录不存 /old)
  - /old 在地址栏输入 → 立刻变成 /new

302 后:
  - 用户输入 /old → 地址栏跳到 /new
  - 用户按"后退" → 回到 /old(浏览器记忆)
  - 再次访问 /old → 仍然跳到 /new
```

## 六、HTTP 协议层面:POST + 301/302 的特殊行为

RFC 2616 规定:

- **301 / 302**:浏览器**应**把 POST 请求改为 GET(避免重复提交)
- **307 / 308**:浏览器**应**保持原方法(POST 仍是 POST)

```text
POST /old  body=...
  ↓
服务器返回 301 Location: /new
  ↓
RFC: 浏览器应该把 POST 变成 GET,请求 /new

POST /old  body=...
  ↓
服务器返回 307 Location: /new
  ↓
浏览器:保留 POST,请求 /new,body 不变
```

**实际行为**(Chromium 系):

- 301 / 302 都会把 POST 变成 GET
- 但 301 浏览器**会更激进**地缓存跳转,后续不会重发

## 七、搜索引擎(SEO)视角

| 维度 | 301 | 302 |
| ---- | --- | --- |
| **PageRank 转移** | **是**(新 URL 继承) | **否**(旧 URL 保留) |
| **索引** | 新 URL 取代旧 URL | 两 URL 都索引 |
| **抓取预算** | 集中到新 URL | 分散到两个 URL |
| **旧 URL 失效时间** | "永久" | 临时(可恢复) |

**SEO 实践**:

- **域名切换 / URL 永久变更** → **301**(权重转移)
- **A/B 测试 / 灰度** → **302**(权重不转移,试验性)
- **临时维护页** → **302**(搜索引擎不索引维护页)
- **移动端跳转** → 一般用 **302**(避免权重分散)

## 八、实际应用场景

### 1. 301 适用场景

```text
✓ 域名迁移(老域名 → 新域名)
✓ HTTP → HTTPS 永久跳转
✓ 网址结构调整(URL 改版)
✓ 多个域名合并到一个主域名
✓ 永久废弃某个页面
```

### 2. 302 适用场景

```text
✓ 临时维护(暂时跳转到维护页)
✓ A/B 测试(根据条件跳不同版本)
✓ 灰度发布(部分用户跳新版本)
✓ 防止 URL 提交重复内容
✓ 设备适配(临时跳移动版)
```

## 九、典型陷阱

### 1. 误用 302 导致 SEO 权重分散

```text
错误:永久迁移却用 302
→ 搜索引擎继续抓旧 URL
→ 新旧 URL 同时存在
→ 权重分散,排名下降

正确:永久迁移用 301,搜索引擎把权重集中到新 URL
```

### 2. 误用 301 导致 AB 测试无效

```text
错误:临时灰度跳新版本用 301
→ 浏览器永久缓存跳转
→ 后端灰度规则失效(老用户都被永久跳走)

正确:灰度用 302,浏览器每次重新请求,后端可动态调整规则
```

### 3. 缓存层与重定向冲突

```nginx
# 错:反代层缓存 301 / 302 响应
proxy_cache_valid 200 10m;
proxy_cache_valid 301 10m;       # ❌ 缓存了 301 跳转
proxy_cache_valid 302 10m;       # ❌ 缓存了 302 跳转

# 对:301 长期缓存(浏览器也缓存),302 不缓存
proxy_cache_valid 200 10m;
proxy_cache_valid 301 1h;        # 配合浏览器,缩短跳转生效时间
# 302 不缓存(让后端动态决定)
```

### 4. POST 请求丢失 body

```text
表单提交 POST /submit
  ↓
服务端返回 302 Location: /thanks
  ↓
浏览器把 POST 变成 GET /thanks(body 丢失)

→ 用 307 保持方法不变(POST + body 保留)
```

### 5. 浏览器跳转缓存过期

```text
错误:某 URL 临时跳转到新 URL(302)
但浏览器缓存了 302 响应
→ 即便服务端撤销跳转,客户端仍跳转

解决:
1. 设置 Cache-Control: no-store 避免浏览器缓存
2. 或改用 307 + 服务器动态决策
```

### 6. CDN 缓存 301 vs 302

```text
CDN 默认缓存 301(永久)
但 302 不缓存(让源站控制)

→ 配置 CDN 时需注意:
  - 301 可设较短 TTL(避免源站改了但 CDN 还跳老地址)
  - 302 默认透传不缓存
```

## 十、307 / 308 的引入

HTTP/1.1 引入 307 和 308,**保留请求方法**:

| 状态码 | 名称 | 含义 |
 | ------ | ---- | ---- |
| **307** | Temporary Redirect | **临时重定向,保留方法**(POST 仍为 POST) |
| **308** | Permanent Redirect | **永久重定向,保留方法** |

```text
301 vs 308:
  301: POST /old → 变成 GET /new
  308: POST /old → 仍是 POST /new

302 vs 307:
  302: POST /old → 变成 GET /new
  307: POST /old → 仍是 POST /new
```

**使用建议**:

- API 永久迁移且需要保留 method → **308**
- 表单提交后跳转保留 method → **307**
- 简单页面跳转 → 301 / 302

## 十一、实战配置

### 1. Nginx 301 / 302 配置

```nginx
# 301 永久跳转
server {
    listen 80;
    server_name old.example.com;
    return 301 https://new.example.com$request_uri;
}

# 302 临时跳转
location /maintain {
    return 302 https://maintain.example.com;
}

# 308 永久跳转保留 POST
location /api/v1/ {
    return 308 https://api.example.com/v2/;
}

# 307 临时跳转保留 POST
location /upload/ {
    return 307 /upload-backup/;
}
```

### 2. 避免浏览器过度缓存 301

```nginx
# 想让 301 在 1 天后失效,可在响应中加短缓存
location /old/ {
    return 301 https://new.example.com$request_uri;
    add_header Cache-Control "max-age=86400";      # 1 天
    expires 1d;
}
```

### 3. 区分 301 与 302 在 Nginx 反代中的缓存策略

```nginx
upstream backend {
    server 10.0.0.1:8080;
}

server {
    location / {
        proxy_pass http://backend;
        proxy_cache my_cache;

        # 301 缓存 1 小时(浏览器和 CDN 都会缓存 301 长期)
        proxy_cache_valid 301 1h;

        # 302 不缓存(让后端每次动态决定)
        proxy_cache_valid 200 302 10m;
    }
}
```

### 4. CDN 上的配置

```nginx
# CDN 边缘节点:301 短期缓存 + 302 不缓存
location / {
    add_header Cache-Control "max-age=300";        # 5 分钟
    proxy_pass http://origin;
}
```

### 5. 浏览器开发者工具查看

```text
F12 → Network 标签:
  Status: 301 / 302
  Headers → Location: 新地址
  右键 → Clear Browser Cache(清除浏览器缓存)
```

清除缓存后,301 会重新请求服务器;302 本来就不缓存,也会重新请求。

## 十二、决策表

| 场景 | 推荐 |
| ---- | ---- |
| 域名永久迁移 | **301** |
| HTTP → HTTPS 永久跳转 | **301** |
| 多个域名合并 | **301** |
| URL 永久改版 | **301** |
| 临时维护页面 | **302** |
| A/B 测试 | **302** |
| 灰度发布 | **302** |
| 设备临时适配 | **302** |
| API 永久迁移且保留 method | **308** |
| 表单提交后跳转保留 method | **307** |

## 十三、要点速记

- **301 = 永久,302 = 临时**
- **301 浏览器永久缓存跳转**,302 不缓存(每次重新请求)
- **301 跳转后用户无法"后退"到原地址**(历史被替换),302 可以
- **SEO**:301 转移权重,302 保留旧 URL
- **301 / 302 都会把 POST 变成 GET**,307 / 308 保留方法
- **误用 302**:永久迁移权重不集中
- **误用 301**:灰度失效,浏览器永久跳走
- **307 / 308**:HTTP/1.1 引入,保留 method
- **CDN 行为**:301 缓存(默认),302 不缓存(透传)
- **生产配置**:301 可加短 `Cache-Control` 控制生效时间
- **Nginx 配置**:`return 301 ...` / `return 302 ...` / `return 307 ...` / `return 308 ...`
- **判断方法**:F12 看 Network 状态码 + 多次访问 /old 是否真发请求
- **SEO 黄金法则**:永久变更用 301,临时跳转用 302
- **API 设计**:迁移用 308,临时 307,避免 POST 变 GET
- **浏览器内部**:Chrome / Firefox / Safari 对 301 缓存策略相似,都永久缓存直到手动清理
- **回退按钮**:301 后回退 = 跳到 /old 的上一页,302 后回退 = 回到 /old
- **搜索引擎会跟踪 302**,但保留旧 URL;若 302 持续半年以上,Google 可能视为永久
