# 容器命令对比 (Docker / Podman / nerdctl / ctr / crictl / kubectl)

> 本文档系统对比 Docker 与各种容器工具的命令差异，帮助快速在不同工具间切换。

## 一、容器工具生态总览

### 1.1 工具定位对比

```text
┌─────────────────────────────────────────────────────────────────┐
│              容器生态                                              │
│                                                                  │
│  ┌──────────────────────────────────────────────────────┐      │
│  │              用户接口（CLI 工具）                      │      │
│  │                                                       │      │
│  │  Docker       Podman       nerdctl                    │      │
│  │  (通用)      (通用/rootless) (Docker 兼容)            │      │
│  └───────┬────────────┬────────────┬──────────────────┘      │
│          │            │            │                          │
│  ┌───────▼────────────▼────────────▼──────────────────┐      │
│  │              高层运行时（High-level Runtime）          │      │
│  │                                                       │      │
│  │  containerd         CRI-O        runc/crun           │      │
│  │  (CNCF)             (K8s 默认)   (OCI Runtime)       │      │
│  └───────┬────────────┬────────────┬──────────────────┘      │
│          │            │            │                          │
│  ┌───────▼────────────▼────────────▼──────────────────┐      │
│  │              调试/管理工具（CLI）                    │      │
│  │                                                       │      │
│  │  ctr            crictl          kubectl            │      │
│  │  (containerd)   (K8s 节点)     (K8s 集群)        │      │
│  └──────────────────────────────────────────────────────┘      │
│                                                                  │
│  ┌──────────────────────────────────────────────────────┐      │
│  │              Linux 内核                                │      │
│  │         (cgroup + namespace + capabilities)              │      │
│  └──────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
```

### 1.2 工具定位速记

```
ctr      = containerd 的"手术刀"（底层调试）
crictl   = Kubernetes 的"听诊器"（K8s 节点排障）
nerdctl  = Docker 的"平替"（日常开发）
docker   = 通用容器工具（最广泛）
podman   = Docker 替代品（兼容 + rootless）
kubectl  = K8s 集群管理
```

### 1.3 工具特性对比

| 工具 | 维护方 | 兼容性 | Rootless | K8s 集成 | 主要用途 |
|------|--------|--------|----------|-----------|----------|
| **Docker** | Docker Inc. | 标准 | 支持 | 需 K8s | 通用容器 |
| **Podman** | Red Hat | Docker 兼容 | 原生支持 | 部分 | Docker 替代 |
| **nerdctl** | containerd | Docker 兼容 | 支持 | 间接 | containerd CLI |
| **ctr** | CNCF | 低级 | 不支持 | 直接 | containerd 调试 |
| **crictl** | CNCF | K8s 专用 | 不支持 | 直接 | K8s 节点排障 |
| **kubectl** | CNF/CNCF | K8s 专用 | 支持 | 原生 | K8s 资源管理 |

## 二、镜像操作对比

### 2.1 镜像搜索

```bash
# Docker
docker search nginx

# Podman
podman search nginx

# nerdctl
nerdctl search nginx

# Skopeo（专为镜像设计）
skopeo search docker://nginx
```

### 2.2 镜像拉取

```bash
# Docker
docker pull nginx:1.25
docker pull registry.example.com/myorg/myapp:1.0

# Podman
podman pull nginx:1.25
podman pull registry.example.com/myorg/myapp:1.0

# nerdctl
nerdctl pull nginx:1.25
nerdctl pull registry.example.com/myorg/myapp:1.0

# ctr（语法特殊）
ctr images pull docker.io/library/nginx:1.25
ctr images pull --user admin --pass xxx registry.example.com/myorg/myapp:1.0

# crictl（专用语法）
crictl pull nginx:1.25
```

### 2.3 镜像列表

```bash
# Docker
docker images
docker image ls

# Podman
podman images
podman image ls

# nerdctl
nerdctl images
nerdctl image ls

# ctr
ctr images list

# crictl
crictl images
```

### 2.4 镜像构建

```bash
# Docker
docker build -t myapp:1.0 .
docker build -f Dockerfile.dev -t myapp:dev .

# Podman（语法兼容）
podman build -t myapp:1.0 .
podman build -f Dockerfile.dev -t myapp:dev .

# nerdctl（支持 BuildKit）
nerdctl build -t myapp:1.0 .
nerdctl build -f Dockerfile.dev -t myapp:dev .

# BuildKit（独立工具）
buildctl build -t myapp:1.0 --frontend dockerfile --local context=. --local dockerfile=.
```

### 2.5 镜像推送

```bash
# Docker
docker login registry.example.com
docker push registry.example.com/myorg/myapp:1.0

# Podman
podman login registry.example.com
podman push registry.example.com/myorg/myapp:1.0

# nerdctl
nerdctl login registry.example.com
nerdctl push registry.example.com/myorg/myapp:1.0

# Skopeo
skopeo login registry.example.com
skopeo copy docker://myapp:1.0 docker://registry.example.com/myorg/myapp:1.0
```

### 2.6 镜像删除

```bash
# Docker
docker rmi nginx:1.25
docker image rm nginx:1.25
docker image prune -a              # 清理悬空镜像

# Podman
podman rmi nginx:1.25
podman image rm nginx:1.25
podman image prune -a

# nerdctl
nerdctl rmi nginx:1.25
nerdctl image prune -a

# ctr
ctr images remove docker.io/library/nginx:1.25
ctr images prune

# crictl
crictl rmi nginx:1.25
```

### 2.7 镜像保存与加载

```bash
# Docker
docker save -o nginx.tar nginx:1.25
docker load -i nginx.tar

# Podman
podman save -o nginx.tar nginx:1.25
podman load -i nginx.tar

# nerdctl
nerdctl save -o nginx.tar nginx:1.25
nerdctl load -i nginx.tar

# Skopeo
skopeo copy docker-daemon://nginx:1.25 docker-archive:/tmp/nginx.tar
skopeo copy docker-archive:/tmp/nginx.tar docker-daemon://nginx:1.25
```

### 2.8 镜像检查

```bash
# Docker
docker image inspect nginx:1.25
docker history nginx:1.25

# Podman
podman image inspect nginx:1.25
podman history nginx:1.25

# nerdctl
nerdctl inspect nginx:1.25

# Skopeo
skopeo inspect docker://nginx:1.25
```

### 2.9 镜像打标签

```bash
# Docker
docker tag myapp:1.0 registry.example.com/myorg/myapp:v1.0

# Podman
podman tag myapp:1.0 registry.example.com/myorg/myapp:v1.0

# nerdctl
nerdctl tag myapp:1.0 registry.example.com/myorg/myapp:v1.0

# Skopeo（通过 copy）
skopeo copy docker://myapp:1.0 docker://registry.example.com/myorg/myapp:v1.0
```

## 三、容器运行对比

### 3.1 启动容器

```bash
# Docker（最常用）
docker run -d --name web -p 8080:80 nginx:1.25
docker run -it --rm ubuntu bash
docker run -d --name db \
  -e POSTGRES_PASSWORD=xxx \
  -v /data/db:/var/lib/postgresql/data \
  postgres:15

# Podman（语法基本一致）
podman run -d --name web -p 8080:80 nginx:1.25
podman run -it --rm ubuntu bash

# nerdctl（基本一致）
nerdctl run -d --name web -p 8080:80 nginx:1.25
nerdctl run -it --rm ubuntu bash

# ctr（语法差异大）
ctr containers create docker.io/library/nginx:1.25 web
ctr task start web
ctr container info web

# crictl（K8s 风格）
crictl run -d --name web nginx:1.25
```

### 3.2 容器列表

```bash
# Docker
docker ps                 # 运行中
docker ps -a              # 全部
docker ps -q              # 仅 ID
docker ps --filter "status=running"

# Podman
podman ps
podman ps -a

# nerdctl
nerdctl ps
nerdctl ps -a

# ctr
ctr containers list
ctr tasks list

# crictl
crictl ps
crictl ps -a
```

### 3.3 容器启动/停止/重启

```bash
# Docker
docker start web
docker stop web
docker restart web

# Podman
podman start web
podman stop web
podman restart web

# nerdctl
nerdctl start web
nerdctl stop web
nerdctl restart web

# ctr
ctr task start web
ctr task kill web      # ctr 用 kill 模拟 stop

# crictl
crictl start <container-id>
crictl stop <container-id>
```

### 3.4 进入容器

```bash
# Docker
docker exec -it web bash
docker exec -it web sh
docker exec -u root -it web bash

# Podman
podman exec -it web bash
podman exec -it web sh

# nerdctl
nerdctl exec -it web bash

# ctr（需要 task pid）
ctr task exec --exec-id web bash
# 或通过 PID
ctr task exec -t --exec-id web bash

# crictl（专用）
crictl exec -it <container-id> bash
```

### 3.5 容器日志

```bash
# Docker
docker logs web
docker logs -f web              # 跟踪
docker logs --tail 100 web      # 最后 100 行
docker logs --since 1h web      # 最近 1 小时

# Podman
podman logs web
podman logs -f web

# nerdctl
nerdctl logs web
nerdctl logs -f web

# ctr
# ctr 没有专门的 logs 命令
# 用 journalctl 查看 containerd 日志
journalctl -u containerd -f

# crictl
crictl logs <container-id>
crictl logs -f <container-id>
```

### 3.6 查看容器详情

```bash
# Docker
docker inspect web
docker stats               # 实时资源
docker stats web

# Podman
podman inspect web
podman stats

# nerdctl
nerdctl inspect web
# nerdctl 无 stats（用 docker stats 或 crictl stats）

# ctr
ctr containers info web
ctr container info web

# crictl
crictl inspect <container-id>
crictl stats              # 实时资源
```

### 3.7 删除容器

```bash
# Docker
docker rm web
docker rm -f web            # 强制删除
docker container prune       # 清理停止的容器

# Podman
podman rm web
podman rm -f web
podman container prune

# nerdctl
nerdctl rm web
nerdctl rm -f web
nerdctl container prune

# ctr
ctr containers remove web

# crictl
crictl rm <container-id>
crictl rmp <container-id>     # pod 删除
```

## 四、容器资源限制对比

### 4.1 内存和 CPU 限制

```bash
# Docker
docker run -d \
  --memory 512m \
  --memory-swap 1g \
  --cpus 1.5 \
  --cpuset-cpus "0,1" \
  nginx

# Podman（语法一致）
podman run -d \
  --memory 512m \
  --memory-swap 1g \
  --cpus 1.5 \
  --cpuset-cpus "0,1" \
  nginx

# nerdctl（语法一致）
nerdctl run -d \
  --memory 512m \
  --memory-swap 1g \
  --cpus 1.5 \
  --cpuset-cpus "0,1" \
  nginx

# ctr（需要特殊参数）
ctr containers create \
  --memory-limit 536870912 \
  --cpu-quota 150000 \
  nginx

# crictl（语法接近 K8s）
crictl run --memory 536870912 --cpu-quota 150000 nginx
```

### 4.2 块 IO 限制

```bash
# Docker
docker run -d \
  --device-read-bps /dev/sda:50mb \
  --device-write-bps /dev/sda:30mb \
  --device-read-iops /dev/sda:500 \
  --device-write-iops /dev/sda:300 \
  nginx

# Podman（语法一致）
podman run -d --device-read-bps /dev/sda:50mb nginx

# nerdctl（语法一致）
nerdctl run -d --device-read-bps /dev/sda:50mb nginx

# ctr / crictl
# 不支持直接限制，需要通过 cgroup 操作
```

### 4.3 进程数限制（PID）

```bash
# Docker
docker run -d --pids-limit 200 nginx

# Podman（语法一致）
podman run -d --pids-limit 200 nginx

# nerdctl（语法一致）
nerdctl run -d --pids-limit 200 nginx

# ctr / crictl
# 不支持直接限制
```

### 5.1 端口映射

```bash

# nerdctl（语法一致）

# ctr

  --port-mapping 8080:80 \
  nginx
```

```bash

# nerdctl（语法一致）
nerdctl run -n bridge nginx
nerdctl run --network host nginx

# ctr / crictl
# 通过 CNI 插件配置
```

### 5.3 自定义网络

### 5.4 DNS 与主机名

```bash
# Podman（语法一致）
podman volume create mydata

# nerdctl（语法一致）

```

### 6.2 绑定挂载

```bash
# Docker
docker run -d \
  -v /host/path:/container/path \
  -v /host/path:/container/path:ro \
  --mount type=bind,source=/host,target=/container \
  nginx

# Podman（语法一致）
podman run -d \
  -v /host/path:/container/path:ro \
  nginx

# nerdctl（语法一致）
nerdctl run -d \
  -v /host/path:/container/path:ro \
  nginx

# ctr（需要特殊处理）
ctr containers create \
  --mount type=bind,src=/host,dst=/container,options=rbind:ro \
  nginx

# crictl（K8s 风格）
crictl run \
  --mount type=bind,src=/host,dst=/container,options=rbind:ro \
  nginx
```

### 6.3 tmpfs 挂载

```bash
# Docker

podman run -d --tmpfs /tmp nginx

# nerdctl（语法一致）
nerdctl run -d --tmpfs /tmp:rw,size=100m nginx
```

### 6.4 数据卷容器（Docker 特色）

```bash
# Docker 特色

# Podman 也支持

nerdctl run --volumes-from data-container app
```

## 十一、容器编排相关对比

### 11.1 Compose / Pod

```yaml
# docker-compose.yml
services:
  web:
    image: nginx:1.25
    ports:
      - "8080:80"
    depends_on:
      - db
    networks:
      - backend
  
  db:
    image: postgres:15
    environment:
      POSTGRES_PASSWORD: secret
    networks:
      - backend

networks:
  backend:
```

```bash
# Docker Compose
docker compose up -d
docker compose ps
docker compose logs
docker compose down

# Podman Compose（兼容 compose v3）
podman compose up -d
podman compose ps

# nerdctl（不直接支持 compose，需要 kompose 转换）
kompose convert -f docker-compose.yml
nerdctl compose up

# K8s（用 kubectl）
kubectl apply -f deployment.yaml
kubectl get pods
kubectl logs -f pod-name
```

### 11.2 K8s vs Docker 命令对比

```bash
# 概念映射
Docker                  K8s
─────────────────────────────────────
docker run              kubectl run / create deployment
docker ps               kubectl get pods
docker stop             kubectl delete pod
docker logs             kubectl logs
docker exec            kubectl exec
docker inspect          kubectl describe
docker network ls       kubectl get networkpolicies
docker volume ls       kubectl get pv,pvc
docker-compose         kubectl apply -f

# 具体命令对比
# 启动 nginx
docker run -d nginx                  kubectl run nginx --image=nginx
docker ps                             kubectl get pods
docker logs nginx                     kubectl logs deploy/nginx
docker exec -it nginx bash           kubectl exec -it nginx -- bash
docker rm nginx                       kubectl delete deploy nginx

# 镜像管理（K8s 中由节点维护）
docker pull nginx                    # K8s kubelet 自动拉取
docker images                        kubectl get pods -o jsonpath='{.items[*].spec.containers[*].image}'
```

### 11.3 Swarm 模式（Docker 特色）

```bash
# Docker Swarm
docker swarm init
```

## 十八、迁移与转换

### 18.1 从 Docker 迁移到 Podman

```bash
# 1. 安装 podman
yum install -y podman
apt install -y podman

# 2. 别名替换（可选）
alias docker=podman

# 3. 大多数命令完全兼容
docker run -d nginx    →   podman run -d nginx
docker ps              →   podman ps

# 4. 不同点处理
# Docker 特有（Podman 不支持）：
docker swarm        →   K8s
docker compose      →   podman compose（基本兼容）
docker context      →   podman context
docker buildx       →   podman build（部分功能）
```

### 18.2 从 Docker 迁移到 K8s

```bash
# 1. 用 kompose 转换
kompose convert -f docker-compose.yml

# 2. 生成 K8s 资源
ls *.yaml
# deployment.yaml, service.yaml, ...

# 3. 应用到 K8s
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml

# 4. 验证
kubectl get pods
kubectl get svc
```

### 18.3 从 Docker 迁移到 nerdctl

```bash
# 1. 安装 containerd + nerdctl
apt install -y containerd.io
apt install -y nerdctl

# 2. 配置 containerd
containerd config default > /etc/containerd/config.toml

# 3. 启动 containerd
systemctl start containerd

# 4. 使用 nerdctl
nerdctl run -d nginx
nerdctl ps

# 5. 完全兼容 Docker CLI
# 大部分 docker run 命令可直接替换为 nerdctl run
```

## 十九、容器运行时底层对比

### 19.1 运行时架构对比

```text
Docker 架构：
┌─────────────────────────────────────┐
│         dockerd (守护进程)             │
│  - REST API                          │
│  - 镜像管理                          │
│  - 容器管理                          │
│  - 网络管理                          │
└──────────────┬───────────────────────┘
               │ gRPC
┌──────────────▼───────────────────────┐
│         containerd                   │
└──────────────┬───────────────────────┘
               │ OCI Runtime Spec
┌──────────────▼───────────────────────┐
│            runc                       │
└─────────────────────────────────────┘

containerd 架构（直接使用）：
┌─────────────────────────────────────┐
│         containerd                   │
│  - CRI 插件                          │
│  - gRPC API                          │
└──────────────┬───────────────────────┘
               │ OCI Runtime Spec
┌──────────────▼───────────────────────┐
│            runc / crun               │
└─────────────────────────────────────┘

Podman 架构（无守护进程）：
┌─────────────────────────────────────┐
│         podman (直接调用)             │
└──────────────┬───────────────────────┘
               │ OCI Runtime Spec
┌──────────────▼───────────────────────┐
│        runc / crun / conmon          │
└─────────────────────────────────────┘
```

### 19.2 守护进程对比

```text
有守护进程：
  - Docker（dockerd）
  - containerd
  - CRI-O

无守护进程（直接调用）：
  - Podman（conmon 是容器监控）
  - nerdctl（需要 containerd 运行）
  - runc（纯 CLI 工具）

客户端-服务端：
  Docker    = 客户端 → dockerd → containerd → runc
  Podman    = 客户端 → runc（直接）
  nerdctl   = 客户端 → containerd → runc
  ctr       = 客户端 → containerd → runc（直接）
  crictl    = 客户端 → kubelet → containerd → runc
```

### 一句话总结

```
ctr      = containerd 底层调试
crictl   = K8s 节点排障专用
nerdctl  = Docker 命令兼容 CLI
docker   = 通用容器标准
podman   = Docker 替代品，兼容

大多数命令在 Docker/Podman/nerdctl 之间通用。
ctr/crictl 用于底层调试，需要了解 containerd/K8s 架构。
K8s 是更高层次的编排系统，使用 kubectl 管理。
```

### 迁移路径速记

```
Docker → Podman
  1. 安装 Podman
  2. 创建别名 alias docker=podman
  3. 大多数命令无需修改

Docker → K8s
  1. 用 kompose 转换 docker-compose.yml
  2. 调整 deployment 配置
  3. 用 kubectl apply 部署

Docker → nerdctl
  1. 安装 containerd + nerdctl
  2. 配置 containerd
  3. 大多数 docker run 命令可直接替换
```
