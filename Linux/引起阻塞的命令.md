# 容易引起阻塞的 Linux 命令

排查 / 写脚本时需要警惕的命令：会"卡住 / hang 住 / 静默等待 / 影响共享资源 / 触发硬件故障"的命令。文档说明**现象 + 为什么 + 怎么替代**。

## 1. 高 I/O 等待 / 卡顿的命令

### 1.1 `cat` / `tail -f` 巨型文件

```bash
tail -f /var/log/nginx/access.log
```

- 不会停，会一直读盘 + 跟着写
- 普通 `tail -f` 不占 IO，但配合 grep/awk 会卡

**替代**：`less +F` / `journalctl -f`

### 1.2 `cat /dev/zero` / `cat /dev/urandom`

```bash
cat /dev/urandom > file
```

- 死循环写，磁盘占满
- CPU 100%

**替代**：

```bash
dd if=/dev/urandom of=rand.bin bs=1M count=100
head -c 100M /dev/urandom > rand.bin
```

### 1.3 `dd` 大块写而不带 `oflag=direct` / `status=progress`

```bash
dd if=/dev/zero of=/tmp/file bs=1M count=10000
```

- 默认走 page cache，IO 报告假象
- 容易导致监控误判

**替代**：加 `oflag=direct conv=fsync status=progress`

### 1.4 `find /` 大范围搜索

```bash
find / -type f -name '*.log'
```

- 跨 mount + 大目录慢
- 触发 mtime / atime inode 读

**替代**：

```bash
find / -xdev -type f -name '*.log'     # 不跨 mount
locate '*.log'                          # mlocate / plocate
fd '*.log'                               # Rust 替代
```

## 2. 会消耗全部内存 / 文件描述符

### 2.1 `cat huge_file | grep ... | sort | uniq`

```bash
cat huge.log | grep error | sort | uniq -c | sort -rn
```

- 一边全文件读入管道
- 同时打开 4 个进程
- 文件描述符 / pipe buffer 容易占满

**替代**：

```bash
grep error huge.log | sort | uniq -c | sort -rn
# 不显式 cat；grep 直接打开
```

### 2.2 `du -h /` 全盘扫描

```bash
du -h /data/*
du -sh /*
```

- 全盘扫描，IO 严重
- 在 NFS / 网络盘上特别慢

**替代**：

```bash
du -sh /data
du --max-depth=1 /data/* | sort -h
```

### 2.3 `ls -la /` / `find /` 触发 metadata 巨量访问

- inode / dentry 缓存被换出
- 系统响应整体下降

**替代**：限制 depth、`-xdev`、仅查具体子目录

## 3. 阻塞输入 / 等待终端输入

### 3.1 `read` 没有重定向

```bash
read -p "Continue? " ans
```

- 没有输入会阻塞
- 脚本中容易 deadlock

**替代**：

```bash
read -t 10 -p "Continue? " ans || echo timeout
read -p "OK" ans < /dev/null    # 立即返回
```

### 3.2 `more` / `less` 等待 q 退出

```bash
service foo status | more      # more 会卡
```

**替代**：`cat` / `less -E` / 管道到 grep

### 3.3 `mail` / `crontab -e` 编辑器卡

- `crontab -e` 不退出编辑器 → cron 不生效
- `mail` 不退出 → 邮件不收尾

**替代**：

```bash
EDITOR=vim crontab -e
EDITOR=nano crontab -e
```

### 3.4 `fdisk` / `cfdisk` / `mkfs` 等未确认

- 误操作易毁盘
- 不要在远程、自动化中跑

**替代**：`parted` / 自动脚本中加 `--script` 模式

## 4. 挂起 / 中断时易卡

### 4.1 `kill -9 PID` 仍卡

```bash
kill -9 PID
# 进程状态 = Z (zombie) 或 D (uninterruptible sleep)
```

- 不可中断睡眠（IO / 内核态）无法被信号打断
- 在 `uninterruptible sleep (D)` 的进程只能等 IO 完成

**排查**：

```bash
cat /proc/PID/wchan
ps -o stat,command -p PID
# 看是否在 'flush-253:0' / 'nfs:rpc_wait'
```

### 4.2 SSH 长时间不响应

- keepalive 失败
- TCP 拥塞

**预防**：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3
# ~/.ssh/config
ServerAliveInterval 30
ServerAliveCountMax 3
```

### 4.3 反向 NAT / 防火墙挂起

```bash
curl -m 30 https://example.com    # 必须设超时
```

避免无限期等待。

## 5. 触发 OS / 资源限制的命令

### 5.1 `ulimit -n 999999`

```bash
ulimit -n 999999     # 进程 fd 上限无限制，会耗尽系统资源
```

**安全**：

```bash
ulimit -n 65535     # 合理上限
ulimit -u 4096      # 进程数
```

### 5.2 `mkfs` 不带 `-t`

```bash
mkfs /dev/sdb       # 不指定 fs 时交互问
```

远程 / 自动化会卡。

**替代**：

```bash
mkfs.ext4 -F /dev/sdb     # -F 强制
```

### 5.3 `fsck` 强制跑大盘

```bash
fsck /dev/sda       # 远程 / 大盘上 = 卡死 + 高风险
```

- 100TB 文件系统 fsck 可能数小时

**预防**：用 `e2fsck -n` 只读 / `xfs_repair -n`

### 5.4 `cryptsetup luksOpen`

- 无 LUKS header 时假文件会卡
- 不带 `-v` 时无反馈

**预防**：`-v` 显示 + `cryptsetup isLuks /dev/sdX` 检查

### 5.5 `lvresize` 不带 `-f`

- 默认会问 y/N
- 远程脚本卡

**替代**：`-f` 强制

## 6. 资源 deadlock / 危险操作

### 6.1 `rm -rf /` 或误路径

```bash
rm -rf /*           # 删除系统
rm -rf /usr /etc    # 灾难
```

- 没有"回收站"
- 一旦执行不可逆

**防御**：

```bash
alias rm='rm -i'    # 加 -i 强制问
safe-rm              # 黑名单
```

### 6.2 `dd of=/dev/sda` 覆盖系统

```bash
dd if=foo of=/dev/sda       # 把整个盘覆写
```

- 必须 100% 确认 target 设备

### 6.3 `chmod -R 000 /`

```bash
chmod -R 000 /var           # 系统权限乱
```

### 6.4 `rm /proc/<pid>/mem`

```bash
echo x > /proc/$(pidof bash)/mem
```

- 直接 panic
- 已被内核禁止

### 6.5 `kill -STOP 1`

```bash
kill -STOP 1          # 冻结 PID 1（systemd/init）
```

- 系统停止响应
- 仅 console 可恢复

### 6.6 `mv /` 改名

```bash
mv / /usr/old
```

- kernel panic

### 6.7 `killall`

```bash
killall -9 ssh       # kill 所有同名进程
```

- 包括你自己

**替代**：

```bash
pkill -f 'sshd'
pgrep ssh | xargs kill
```

## 7. 锁 / 并发阻塞

### 7.1 `flock` / `lockfile` 卡死

```bash
flock /tmp/foo.lock -c cmd
```

- 锁不释放会阻塞所有等待者

**预防**：

```bash
flock -n -w 5 /tmp/foo.lock -c cmd
# 加 -n 非阻塞 / -w 5 超时 5 秒
```

### 7.2 `dpkg` / `apt` 同时跑

```bash
apt install -y foo &
apt install -y bar &
```

- 锁文件 `/var/lib/dpkg/lock-frontend`
- 后跑的那一个阻塞

### 7.3 `apt autoremove` 删除运行依赖

```bash
apt autoremove          # 删除无人引用的包
```

- 可能删掉仍被旧进程加载的 .so
- 旧进程 `dlopen` 时卡死 / 段错误

**预防**：先用 `debian-goodies / checkrestart` 校验

## 8. 等待 IO / 网络的常见命令

### 8.1 `mount -t nfs host:/path /mnt`

- nfs 远程不可达时阻塞
- 长时间无响应
- 关 nfs 端口后进程卡 D 状态

**预防**：

```bash
mount -t nfs -o timeo=10,retrans=3,_netdev host:/path /mnt
```

### 8.2 `ping` / `traceroute` 长超时

```bash
ping 1.2.3.4 -c 1000    # 默认无 timeout
```

**预防**：

```bash
ping -W 1 -c 3 host
timeout 5 ping host
```

### 8.3 `tcpdump` 长跑

```bash
tcpdump -i any -w /tmp/pcap       # 累计巨大文件
```

- 写盘慢 + 长时间占用

**预防**：

```bash
tcpdump -i any -G 600 -w 'pcap_%s'      # 10 分钟切片
tcpdump -i any -c 1000
```

### 8.4 `wget` / `curl` 大文件

```bash
wget https://...
```

- 网络不稳时阻塞
- 默认不超时

**预防**：

```bash
curl --max-time 600 -C - URL      # 续传
wget --timeout=600 URL
```

## 9. 高 / 危险用法

### 9.1 `kill -9` 杀自己

```bash
kill -9 $$            # 杀自己
kill -9 $PPID
```

- 子进程 / init 异常
- /tmp 等清理脚本消失

### 9.2 `:() { :|:& }; :`（fork 炸弹）

```bash
:() { :|:& }; :
```

- fork 自己
- 系统死机

**预防**：

```bash
ulimit -u 4096      # 限制用户进程数
```

### 9.3 `nohup` / `disown`

```bash
nohup foo &      # 父进程退出后还在
```

- 不显式 detach 容易留 zombie

### 9.4 `disown -h` vs `&` 的差别

```bash
foo &              # 后台
disown foo         # 不挂 HUP 信号
```

### 9.5 `screen` / `tmux` 残留

```bash
screen             # 进入
^A d              # detach
```

- 长期 detach 容易忘记
- `screen -ls` / `tmux ls` 看

## 10. shell 脚本相关

### 10.1 `command > file` 不带 `set -e`

```bash
command > file       # 可能 false 但不报错
```

- 没 `set -e` / `set -o pipefail` 时静默
- 进程继续出错

### 10.2 `kill $!` 杀错 pid

```bash
sleep 100 &
PID=$!
kill $PID            # 正常
kill -9 $!           # 父进程 ID 也是 $!
```

### 10.3 `source` / `.` 找不到文件

```bash
. /etc/profile.d/foo.sh       # 找不到静默 / no error
```

**预防**：

```bash
. /etc/profile.d/foo.sh || { echo missing; exit 1; }
```

### 10.4 `set -e` 子 shell 不继承

```bash
( set -e; false ) ; echo OK    # OK 仍输出
```

- `set -e` 仅对当前 shell

### 10.5 `xargs` 单引号 / 引号

```bash
echo "foo bar" | xargs echo      # 拆分错误
```

**预防**：

```bash
echo "foo bar" | xargs -d '\n'
find . -print0 | xargs -0
```

## 11. 写脚本时的"挂死"组合

| 组合 | 风险 |
| ---- | ---- |
| `ssh remote cmd <code>&#124;</code> grep ...` | ssh 不返回 → grep 等 |
| `mysql -e 'sql'` | network 卡 |
| `docker exec` 卡死 | 容器 syscall 卡 |
| `redis-cli -h host` 卡 | 网络断 |
| `kubectl exec` 卡 | API server hang |
| `nc -l 1234` 卡 | 等客户端连 |
| `find / -name '*' <code>&#124;</code> xargs rm` | 误删 |

## 12. 应对策略 / 一般原则

1. **永远设超时**：所有网络 / IO 命令加 `timeout` / `-m` / `--max-time`
2. **后台加 nohup / tmux**：避免 SSH 退出导致进程死
3. **避免用 root 跑通配**：谨慎 `rm -rf *` / `find / | xargs rm`
4. **监控阻塞**：`/proc/*/wchan`、`uninterruptible sleep`、strace stuck
5. **拆目录 / 拆范围**：大数据用 `parted / slice / xdev`
6. **管道首步不要 cat**：`<command> | grep ... | sort` 不必 `<file> | grep`
7. **测试脚本在容器**：`docker run -it --rm alpine` 内试跑

## 13. 卡死排查清单

```bash
# 1. 整系统 CPU 高？哪个进程？
top -o %CPU
uptime
mpstat 1 5

# 2. 整系统 IO 高？哪台盘？
iostat -xz 1 5
iotop
cat /proc/pressure/io

# 3. 系统锁
sysctl kernel.unprivileged_userns_clone
dmesg | tail -30

# 4. 单进程卡死
cat /proc/PID/wchan
cat /proc/PID/syscall
strace -p PID
strace -ff -p PID -o /tmp/strace.log

# 5. D 状态卡死
ps -eo stat,pid,comm | grep '^D'
ps -eo stat,pid,etime,comm | awk '$1=="D" {print}'

# 6. 进程在死等系统调用
perf top -p PID
bcc / bpftrace

# 7. SSH / docker / kubectl 卡
strace -p $(pidof sshd)
strace -p $(pidof dockerd)
```

## 14. 一句话总结

```text
容易卡死的命令：高 I/O 扫描 / 大文件读 / 远程等待 / 锁等待 / 误删
通用规则：永远 timeout + nohup + set -euo pipefail
诊断：cat /proc/PID/wchan + strace + iostat + D 进程
```
