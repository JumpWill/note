# 09 - eBPF 性能与限制

> eBPF 不是「在内核里跑任何 C 代码」。它有严格的边界，理解边界才能写出生产可用的程序。

## 限制维度速览

```
                    ┌──────────────────────┐
                    │  eBPF 程序能做什么？ │
                    └──────────────────────┘
                              │
              ┌───────────────┼───────────────┐
              ▼               ▼               ▼
        安全性保证        资源限制        API 限制
              │               │               │
   verifier 全面检查    指令数/栈/Maps    受限 helper
   保证不 crash 内核    不可超过上限     受限类型
```

## 1. Verifier 限制

> Verifier 是 eBPF 的「门卫」，三个核心保证：
> 1. **类型安全**：不会越界
> 2. **控制流终止**：不会死循环
> 3. **可预测资源**：栈、helper 调用有界

### 1.1 指令复杂度上限

| 版本 | 指令上限 |
|------|---------|
| ≤ 5.2 | 4096 |
| ≥ 5.3 | 100 万 |
| ≥ 6.0 | 大幅放宽，但仍有约束 |

### 1.2 循环：5.2 前完全禁止

```c
// 错：直到 5.2 都拒
for (int i = 0; i < 10; i++) {
    buf[i] = i;
}

// 对：展开
buf[0] = 0;
buf[1] = 1;
buf[2] = 2;
// ...
buf[9] = 9;

// 或者 #pragma unroll
#pragma unroll
for (int i = 0; i < 10; i++) {
    buf[i] = i;
}

// 或者用辅助函数（用 verifier 友好的 helper）
#pragma unroll
for (int i = 0; i < 256; i++) {
    if (bpf_probe_read_kernel(&buf[i], 1, src + i) < 0) break;
}
```

### 1.3 有界循环（5.3+）

```c
// 5.3+ 接受，verifier 会追踪迭代次数
#pragma unroll
for (int i = 0; i < 1024; i++) {  // 必须有明确上界
    if (i >= len) break;          // verifier 跟踪 break 条件
    process(buf[i]);
}
```

规则：
- 循环次数必须**编译期已知**
- 内部必须有**条件终止**（verifier 看得懂）
- `pragma unroll` 强制展开

### 1.4 栈限制：512 字节

```c
// 错：栈溢出
struct huge { char data[1024]; };   // 1024 > 512
SEC("kprobe/do_sys_open")
int h(struct pt_regs *ctx) {
    struct huge x;  // R10 偏移 1024，但栈只有 512
    return 0;
}
// → "negative offset from stack pointer"
```

**解决方案**：
1. 用 map 分配（per-CPU array 适合）
2. 减小结构大小
3. 分多次处理

```c
// 对：栈上只放指针，结构在 map 里
struct {
    __uint(type, BPF_MAP_TYPE_PERCPU_ARRAY);
    __uint(max_entries, 1);
    __type(key, u32);
    __type(value, struct huge);  // 100KB 也可以
} scratch SEC(".maps");

SEC("kprobe/do_sys_open")
int h(struct pt_regs *ctx) {
    u32 key = 0;
    struct huge *p = bpf_map_lookup_elem(&scratch, &key);
    if (!p) return 0;
    // 用 p
    return 0;
}
```

### 1.5 内存访问：必须先检查再访问

```c
// 错：
struct foo *p = ...;
int x = p->a;  // verifier 不知 p 是否可访问

// 对：
if (p != NULL) {        // 防止 NULL
    if (p->valid) {     // 防止野指针
        int x = p->a;
    }
}
```

详细规则（强烈建议读内核源码 `kernel/bpf/verifier.c`）：

1. **NULL 检查**：`if (p != NULL)`
2. **边界检查**：包尾 `(void *)eth + 1 > end`
3. **对齐检查**：某些 read 要求对齐
4. **类型保护**：非直接 type cast

### 1.6 最大尾调用数

```c
// tail call 最大 33 次（内核常量）
#define MAX_TAIL_CALL_CNT 33
```

多于 33 次，verifier 拒绝。

### 1.7 嵌套调用深度

```c
// 子程序（BPF 子调用）最大深度
// Linux < 5.7:    8
// Linux ≥ 5.7:    256  (BPF_MAX_SUBPROG_DEPTH 提升)
// 实际工程中很少触及
```

## 2. 程序类型限制

每种程序类型有特定的「上下文」和「允许的 helper」。

```c
// 错：在 tracepoint 中调用 bpf_redirect
SEC("tracepoint/syscalls/sys_enter_openat")
int h(struct trace_event_raw_sys_enter *ctx) {
    bpf_redirect(1, 0);   // 拒：不在网络上下文中
    return 0;
}

// 对：仅在 TC/XDP 调用
```

## 3. 类型限制

### 3.1 内置类型

```
char   u8    u16   u32   u64
int    s8    s16   s32   s64
bool   const
```

### 3.2 不允许的特性

```c
// 错：
float f;          // 无浮点（5.18 部分放开但有限）
long double ld;   // 同上
void *p[10];      // 不能有全局数组（除非在 .data/.bss）

goto fail;        // 不能跨函数（但局部 goto 某些版本支持）
longjmp();        // 禁

// 对：
u32 arr[10];       // 限制大小
```

### 3.3 字符串处理

```c
// 无 strlen，要自己写
size_t n = 0;
#pragma unroll
for (int i = 0; i < 256; i++) {
    if (buf[i] == '\0') { n = i; break; }
}

// 或用 helper
long bpf_probe_read_str(void *dst, u32 size, const char *src);
```

## 4. 性能数据

### 4.1 一次 XDP 程序耗时

```
网卡 DMA → XDP → 丢包
                │
                └─ 30-50 ns (无 JIT)
                   15-25 ns (JIT 后)
```

### 4.2 一次 kprobe 程序耗时

```
函数入口 → 触发 kprobe → bpf 程序
                            │
                            └─ 200-500 ns（含上下文保存）
```

### 4.3 ringbuf vs perf_event_array

| 维度 | perf_event | ringbuf |
|------|-----------|---------|
| 共享模式 | 每 CPU + 跨页 | 共享环形 |
| 拷贝次数 | 2 次 | 1 次（零拷贝） |
| 延迟 | ~1 μs | ~150 ns |
| 内核版本 | 任意 | 5.8+ |

### 4.4 perf

```bash
# 用 perf 测 eBPF 程序耗时
sudo perf stat -e 'cycles:ppp' ./my_prog  # 启用 precise_ip

# 测全局：pmu-stat 启硬件采样
sudo bpftrace -e 'hardware:cpu-cycles:1000000 { @[comm] = count(); }'
```

## 5. 内存占用

### 5.1 各数据结构上限

| 对象 | 上限 |
|------|------|
| 程序字节码 | 100 万条 |
| 程序栈 | 512 字节 |
| 子调用深度 | 8 |
| tail call 深度 | 33 |
| maps 数 | sysctl `vm.max_map_count`（默认 65536） |
| 单 map 大小 | 受 max_entries 限制 |
| ringbuf | `max_entries` 控制（page 倍数） |

### 5.2 系统参数调优

```bash
# /etc/sysctl.conf
vm.max_map_count = 262144      # 提升 map 数量
kernel.perf_event_max_stack = 10000
kernel.perf_event_mlock_kb = 65536   # 提升 perf 内存
```

## 6. JIT 性能

### 6.1 关闭 JIT 测 fallback 性能

```bash

```

### 6.2 启用 JIT（默认）

```bash

# 2 = debug，会保留原 eBPF 字节码

...（x86 汇编）
```

## 7. 避免 Verifier 失败的技巧

### 7.1 提前结束检查

```c
// 不好的写法
struct foo *p = bpf_map_lookup_elem(&m, &k);
if (!p) return -1;  // verifier 跟踪 fail

// 好的写法：使用 bpf_map_lookup_elem 的 NULL 检查
struct foo *p = bpf_map_lookup_elem(&m, &k);
if (p && p->valid) {
    // 主流程
}
return 0;  // 统一返回
```

### 7.2 使用 BPF_CORE_READ

```c
// 不安全的访问
u32 v = t->pid;

// 安全的（runtime 检查 + CO-RE）
u32 v = BPF_CORE_READ(t, pid);
```

### 7.3 state pruning

Verifier 会做 path pruning，每个分支独立跟踪。**条件互斥**的分支更容易过：

```c
// 差：64 个分支并列，verifier 复杂度高
if (cond1) ...
if (cond2) ...
if (cond3) ...

// 好：分而治之
if (!cond1 || !cond2 || !cond3) return 0;
// 主流程
```

### 7.4 state + instruction 计数

```c
// 给 verifier「提示」，让它知道这不是复杂状态机
SEC("classifier")
int h(struct __sk_buff *skb) {
    if (skb->len == 0) return TC_ACT_OK;     // 提前退出
    // 一些读取 ...
    if (skb->protocol != expected) return TC_ACT_OK;  // 提前退出
    // 主流程
    return TC_ACT_SHOT;
}
```

## 8. 常见错误列表

| 错误 | 原因 | 解决 |
|------|------|------|
| `R0 invalid mem access` | 返回值类型不对 | 检查 helper 返回类型 |
| `stack overflow` | 栈用太多 | 用 map 分配 |
| `loop may run forever` | 死循环 | 加 `pragma unroll` 或 break |
| `invalid helper call` | 程序类型不匹配 | 换 SEC |
| `permission denied` | 没特权 | `sudo` 或 CAP_BPF |
| `kernel version not supported` | 内核太老 | 升级内核 |
| `neg offset from stack` | 栈偏移负数 | 调整顺序 |
| `type mismatch` | 类型不匹配 | 检查 `__type` 定义 |

## 9. 在生产中管理复杂度

### 9.1 sub-program 拆分

```c
// 顶层 SEC("xdp")
static __always_inline int parse(struct xdp_md *ctx, struct pkt *p) {
    // 100 行
    return 0;
}

static __always_inline int process(struct pkt *p) {
    // 200 行
    return 0;
}

SEC("xdp")
int main(struct xdp_md *ctx) {
    struct pkt p = {};
    if (parse(ctx, &p)) return XDP_PASS;
    return process(&p);
}
```

> 关键：`__always_inline` 让子函数不创建新 frame，verifier 跟踪得到。

### 9.2 拆分到多个程序（tail call）

```c
struct progs SEC(".maps") = {
    __uint(type, BPF_MAP_TYPE_PROG_ARRAY);
    __uint(max_entries, 4);
};

SEC("xdp")
int main(struct xdp_md *ctx) {
    // 解析阶段：跳到 stage1
    bpf_tail_call_static(ctx, &progs, 0);
    return XDP_PASS;
}

SEC("xdp/0")
int stage0(struct xdp_md *ctx) { ... }
```

### 9.3 复用主流代码（libbpf + 头文件）

```c
// common.h
#ifndef __EBPF_COMMON_H
#define __EBPF_COMMON_H

#include "vmlinux.h"
#include <bpf/bpf_helpers.h>
#include <bpf/bpf_core_read.h>
#include <bpf/bpf_tracing.h>

#define MAX_ENTRIES 10240

struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, MAX_ENTRIES);
    __type(key, u32);
    __type(value, u64);
} global_count SEC(".maps");

#endif
```

## 11. 设计建议

1. **小而精**：单程序 < 1000 行，复杂逻辑拆多程序
2. **优先标准 helper**：自定义逻辑用 sub-program 模拟
4. **测试**：用 veristat 跑 benchmark
5. **fallback**：内核不支持时降级为模块或用户态
6. **观察**：`bpftool prog show --pretty` 看 verifier 复杂度
