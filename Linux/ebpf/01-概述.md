# 01 - eBPF 概述

## 什么是 eBPF

**eBPF（Extended Berkeley Packet Filter）** 是 Linux 内核中的一套运行时注入技术，允许将自定义程序安全地加载到内核中执行，而无需修改内核源码或加载内核模块。

> 通俗理解：内核里跑了一段「小程序」，这段程序被严格审查（Verifier）确保不会把内核搞崩，然后以 JIT 编译后的本地指令在内核上下文里高速运行。

### 一句话定义

> **eBPF = 内核态事件触发 + 安全沙箱执行 + 用户态观测控制**

## 发展历史

| 阶段 | 年份 | 事件 |
|------|------|------|
| BPF 诞生 | 1992 | BSD Packet Filter，用于 tcpdump 抓包 |
| 沉寂期 | 1992-2012 | 32 位指令集，仅 2 个寄存器，功能极弱 |
| 重生 | 2013 | Alexei Starovoitov 提交扩展提案，加入 64 位、11 个寄存器、maps |
| Linux 合并 | 2014 | Linux 3.18 引入 eBPF，仅限 kprobe |
| 全面爆发 | 2016-2020 | XDP（4.8）、perf event（4.9）、TC（4.9）、ringbuf（5.8） |
| 当代 | 2021+ | BTF、CO-RE、kfunc、struct_ops、token 鉴权全面落地 |

## 与传统内核模块的对比

| 维度 | 内核模块 | eBPF |
|------|----------|------|
| 安全性 | 一个 bug 可直接 panic | Verifier 全程验证，保证不 crash 内核 |
| 重启内核 | 是 | 否，运行时热加载 |
| 内核版本兼容 | 需重新编译 | CO-RE 一次编译到处运行 |
| 性能 | 与内核代码相同 | JIT 后几乎原生，但有 5 层限制 |
| 编程语言 | C + 内核头文件 | 受限 C + BTF，标准库受限 |
| 调试 | kgdb、printk | printk、bpftool、bpf_dbg |

## 典型应用场景

### 1. 网络加速

- **Facebook Katran**：在 XDP 层做 L4 负载均衡，单机数千万 PPS
- **Cilium**：完全用 eBPF 替代 iptables，k8s Service 性能提升 10 倍以上
- **Cloudflare**：DDoS 缓解，XDP drop 早于协议栈

### 2. 安全性

- **Falco**：运行时威胁检测，监控 syscall、文件、进程
- **Tetragon（Cilium 子项目）**：内核级策略 + 阻断，能 kill 任意 syscall
- **Tracee（Aqua）**：基于 eBPF 的运行时安全

### 3. 可观测性

- **Pixie（New Relic）**：k8s 应用性能，自动追踪，无侵入
- **bcc 工具集**：90+ 一键诊断工具（execsnoop、tcpconnect、生物 latency）
- **bpftrace**：类似 awk 的高级追踪 DSL

### 4. 性能分析

- **bpftrace + offcputime**：找出进程被调度器踢出 CPU 的耗时
- **biolatency、biosnoop**：块设备延迟分析
- **funclatency**：任意函数耗时直方图

## 一个直观的例子

假设想统计每秒打开文件的次数，传统方式：

```c
// 内核模块：需要重新编译内核，宕机风险大
static int my_open(struct inode *inode, struct file *file) {
    printk("file opened\n");
    return 0;
}
module_init(...);
```

eBPF 方式（5 行解决）：

```c
SEC("tracepoint/syscalls/sys_enter_openat")
int trace_openat(struct trace_event_raw_sys_enter *ctx) {
    bpf_printk("file opened\n");
    return 0;
}
```

```bash
$ bpftrace -e 't:syscalls:sys_enter_openat { @[comm] = count(); }'
```

## 核心优势总结

1. **零重启**：运行时注入，业务不感知
2. **零侵入**：不改内核源码，应用不改一行
3. **安全可控**：Verifier 保证，内核不会因为你的 eBPF 程序崩
4. **高性能**：JIT 编译后接近原生 C
5. **跨版本**：CO-RE + BTF 一次编译到处跑
6. **生态完整**：从工具链到生产级项目一应俱全

## eBPF 的"代价"

- **有限循环**：< 5.3 完全禁止；5.3+ 支持有界循环（verifier 跟踪 trip count）+ `#pragma unroll`；5.17+ 提供 `bpf_loop()` helper
- **栈限制**：512 字节，需要小心大结构
- **指令上限**：< 5.3 时 4096，5.3+ 提升到 100 万
- **受限语言**：禁止部分 C 特性（如可变长数组、跨函数 goto 等）
- **内核版本要求**：建议 5.4+，新特性往往需要最新内核
