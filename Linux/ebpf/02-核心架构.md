## 四大核心组件

### 1. eBPF 程序（Program）

> 内核中实际执行的代码，字节码格式

```c
// 最小 eBPF 程序
SEC("tracepoint/syscalls/sys_enter_openat")
int handle_openat(struct trace_event_raw_sys_enter *ctx) {
    return 0;
}
```

特点：
- 由 LLVM/Clang 编译成 eBPF 字节码（也是一种 ELF）
- 内核里的 Verifier 逐条指令检查
- 通过后 JIT 编译为机器码（x86/ARM64），原生速度执行
- 程序通过 `bpf()` syscall 注册到内核

### 2. eBPF Maps

> 程序与用户态、内核各程序之间共享数据的「共享内存」

```c
// C 定义
struct {
    __uint(type, BPF_MAP_TYPE_HASH);
    __uint(max_entries, 1024);
    __type(key, u32);
    __type(value, u64);
} my_map SEC(".maps");

// 在程序中使用
u32 key = 1;
u64 value = 100;
bpf_map_update_elem(&my_map, &key, &value, BPF_ANY);

// 在用户态读取（用 skeleton）
struct my_prog_bpf *skel = my_prog_bpf__open_and_load();
int fd = bpf_map__fd(skel->maps.my_map);
u64 val;
bpf_map_lookup_elem(fd, &key, &val);
```

详见 [06-Maps详解](06-Maps详解.md)

### 3. eBPF Helpers

> eBPF 程序调用内核提供的辅助函数（200+ 个）

按类别分组：

| 类别 | 例子 |
|------|------|
| Map 操作 | `bpf_map_lookup_elem`、`bpf_map_update_elem`、`bpf_map_delete_elem` |
| 时间 | `bpf_ktime_get_ns`、`bpf_ktime_get_boot_ns` |
| 进程 | `bpf_get_current_pid_tgid`、`bpf_get_current_comm` |
| 网络 | `bpf_redirect`、`bpf_skb_store_bytes`、`bpf_l4_csum_replace` |
| 调试 | `bpf_trace_printk`（已废弃，推荐 ringbuf） |
| 上下文 | `bpf_get_func_arg`、`bpf_probe_read` |

详见 [08-Helpers与API](08-Helpers与API.md)

### 4. Hook 点（挂载点）

> eBPF 程序挂载到的内核事件触发点

```
内核事件流   ──→   eBPF 程序被触发   ──→   决定行为
                    │                         │
                    ↓                         ↓
              读取上下文(ctx)            XDP_DROP / XDP_PASS
              读 map 数据                TC_ACT_*
              调用 helper               bpf_override_return
                                       修改包内容
```

主流 Hook 点（30+ 种）详见 [03-程序类型](03-程序类型.md)

## 内核态/用户态交互流程

### 完整生命周期

```
┌────────────────────────────────────────────────────────────────┐
│ 1. 编写 eBPF C 代码                                              │
│    └─→ clang -target bpf 编译成 .o                               │
├────────────────────────────────────────────────────────────────┤
│ 2. 用户态加载                                                    │
│    libbpf/bpftool:                                              │
│      bpf_object__open() → bpf_object__load()                    │
│      - 读取 ELF                                                │
│      - 调整 relocater                                          │
│      - 通过 bpf() syscall 上传到内核                            │
├────────────────────────────────────────────────────────────────┤
│ 3. 内核验证 (Verifier)                                          │
│      - 指令合法性                                               │
│      - 控制流终止性                                             │
│      - 内存访问范围                                             │
│      - 栈使用量                                                │
│      - Helper 参数合法性                                        │
├────────────────────────────────────────────────────────────────┤
│ 4. JIT 编译                                                     │
│      bpf_jit_compile() → 机器码写入只读内存                       │
├────────────────────────────────────────────────────────────────┤
│ 5. 挂载                                                          │
│      bpf_prog_attach() / setsockopt / link create               │
├────────────────────────────────────────────────────────────────┤
│ 6. 触发执行                                                     │
│      内核事件触发 eBPF 程序                                      │
├────────────────────────────────────────────────────────────────┤
│ 7. 用户态观测                                                    │
│      - ringbuf perf_event                                       │
│      - map 数据                                                 │
│      - /sys/kernel/debug/tracing                                │
└────────────────────────────────────────────────────────────────┘
```

### 完整代码示例

```c
// minimal.c — 一个最简 eBPF 程序
#include <linux/bpf.h>
#include <bpf/bpf_helpers.h>

char LICENSE[] SEC("license") = "GPL";

// 1. 定义 map：用户态写入"配置"，程序读取
struct {
    __uint(type, BPF_MAP_TYPE_ARRAY);
    __uint(max_entries, 1);
    __type(key, u32);
    __type(value, u32);
} cfg_map SEC(".maps");

// 2. eBPF 程序：tracepoint 触发时执行
SEC("tracepoint/syscalls/sys_enter_openat")
int trace_openat(struct trace_event_raw_sys_enter *ctx) {
    u32 key = 0;
    u32 *enabled = bpf_map_lookup_elem(&cfg_map, &key);
    if (!enabled || !*enabled)
        return 0;

    // 通过 ringbuf 发送事件到用户态
    bpf_printk("file opened by pid %d\n", bpf_get_current_pid_tgid() >> 32);
    return 0;
}
```

```c
// minimal.c — 用户态加载器
#include <bpf/bpf.h>
#include <bpf/libbpf.h>

struct cfg_map {
    __u32 enabled;
};

int main() {
    // 1. 打开编译后的 ELF
    struct bpf_object *obj = bpf_object__open("minimal.bpf.o");
    if (libbpf_get_error(obj)) return 1;

    // 2. 加载到内核（触发 verifier）
    if (bpf_object__load(obj)) return 1;

    // 3. 获取程序 fd 并挂载
    struct bpf_program *prog = bpf_object__find_program_by_name(obj, "trace_openat");
    struct bpf_link *link = bpf_program__attach(prog);
    if (libbpf_get_error(link)) return 1;

    // 4. 写 map：启用探测
    int cfg_fd = bpf_object__find_map_fd_by_name(obj, "cfg_map");
    struct cfg_map cfg = { .enabled = 1 };
    bpf_map_update_elem(cfg_fd, &(u32){0}, &cfg, BPF_ANY);

    // 5. 主循环：从 ringbuf 读事件
    sleep(60);

    bpf_link__destroy(link);
    bpf_object__close(obj);
    return 0;
}
```

## 关键设计：Verifier（验证器）

> **核心安全保证**：内核对你的 eBPF 代码做静态分析，证明其：
> 1. 不会 panic 内核
> 2. 一定会终止（没有死循环）
> 3. 不会越界访问内存
> 4. 不会调用危险指令

### Verifier 看的不是 C 代码，而是字节码

```
你的 C 代码 → clang → eBPF 字节码 → Verifier
                                  ↓
                            ┌──────────────┐
                            │  控制流图     │
                            │  类型状态     │
                            │  范围约束     │
                            └──────────────┘
                                  ↓
                            允许 / 拒绝
```

### 一个典型拒绝

```c
SEC("kprobe/do_sys_open")
int check_open(struct pt_regs *ctx) {
    char filename[256];
    bpf_probe_read_str(filename, sizeof(filename), (void *)PT_REGS_PARM1(ctx));
    bpf_printk("open: %s\n", filename);
    return 0;
}
```

编译/加载报错：

```
Verifier output:
; bpf_probe_read_str+0x12
R1 25: type=inv size=0
; bpf_probe_read_str+0x32
invalid read from stack R1 off=0+0 size=256
```

原因：Verifier 无法证明 256 字节读不会越界。

## 性能数据

| 操作 | 耗时 |
|------|------|
| 编译 1 个 eBPF 程序 | < 1s |
| 加载 + Verifier | 1-100ms（取决于复杂度） |
| JIT 编译 | < 1ms |
| 一次 eBPF 程序触发（XDP） | 30-50 ns |
| 一次 eBPF 程序触发（kprobe） | 200-500 ns |
| ringbuf 发送 64B 事件 | 80-150 ns |
| ringbuf 用户态读取 | 200ns per event |
