# 11 - eBPF 调试技巧

> 内核里跑 eBPF 程序调试起来不轻松。本章汇总实战经验。

## 调试三板斧

```
                eBPF 调试
                    │
       ┌────────────┼────────────┐
       ▼            ▼            ▼
    编译期         加载期         运行时
       │            │            │
   -Wall -Werror   verifier    trace_pipe
   static check    log         ringbuf
   clang -g        map info    bpftool
```

## 1. 编译期调试

### 1.1 让 verifier 报错更友好

```bash
# 编译时 -O2 改成 -O0/-O1 调试
clang -O0 -g -target bpf -D__TARGET_ARCH_x86 -c prog.bpf.c -o prog.bpf.o
```

注意：太复杂的源码可能被 verifier 拒，调试时反而**先用 -O0** 验证逻辑。

### 1.2 打印伪字节码

```bash
llvm-objdump -d prog.bpf.o
```

输出示例：

```
prog.bpf.o:        file format elf64-bpf

Disassembly of section xdp:

0000000000000000 <xdp_prog>:
       0:	bf 16 00 00 00 00 00 00	r6 = r1
       3:	79 61 08 00 00 00 00 00	r1 = *(u64 *)(r6 + 8)
       4:	...
```

### 1.3 bpftool 看 verifier 信息

```bash
# 加载并启用 verifier 详细 log
sudo libbpf-tools/load_fail_dump
```

在 Makefile 加 LIBBPF_LOG_LEVEL：

```makefile
LIBBPF_LOG_LEVEL ?= warn
# 编译 -DDEBUG
```

## 2. 加载期调试：Verifier Log

### 2.1 获取完整 verifier log

```c
// 用户态加载器：libbpf 自动输出 verifier log
struct bpf_object_open_opts opts = {
    .kernel_log_buf = malloc(LOG_BUF_SIZE),
    .kernel_log_size = LOG_BUF_SIZE,
    .kernel_log_level = 1,   // 详细级别
};
```

```bash
# 或 bpftool
$ sudo bpftool prog load prog.bpf.o /sys/fs/bpf/prog
# 失败时会打印 verifier log
```

### 2.2 解读示例

```
; bpf_map_update_elem+0x12
r1 = 0
; BPF Program
0: r6 = r1
1: r1 = 0
2: *(u32 *)(r10 - 4) = r1
3: r1 = r10
4: r1 += -4
5: call bpf_map_lookup_elem  // R1 = map, R2 = key
; BPF return: 0x0
6: if r1 == 0 goto +1
; 中间删去
7: r0 = *(u64 *)(r1 + 0)  // 取 value（这里出问题）
invalid mem access 'inv'
```

### 2.3 常见 verifier 错误速查

| 错误信息 | 原因 | 解决 |
|---------|------|------|
| `invalid mem access` | 越界或 NULL | 加 NULL 检查 |
| `type mismatch` | 类型不匹配 | 检查 helper 参数 |
| `stack limit exceeded` | 栈溢出 | 减小栈变量或用 map |
| `back-edge` (loop) | 死循环 | `pragma unroll` |
| `R0 invalid value` | 返回值未设 | 改写函数最后赋值 |
| `min/max too big` | 数值范围太大 | 缩小变量范围 |

### 2.4 bpftool 启用全局 verifier 模式

```bash
# /proc/sys/kernel/bpf_stats_enabled
echo 1 | sudo tee /proc/sys/kernel/bpf_stats_enabled

# verifier 收集所有程序统计
sudo bpftool prog show --pretty
```

## 3. 运行时调试：trace_pipe

### 3.1 使用 printk

```c
SEC("kprobe/do_sys_open")
int h(struct pt_regs *ctx) {
    char buf[256] = {};
    bpf_probe_read_user_str(buf, sizeof(buf), (char *)PT_REGS_PARM1(ctx));
    bpf_printk("DEBUG: pid=%d filename=%s\n", bpf_get_current_pid_tgid() >> 32, buf);
    return 0;
}
```

读取：

```bash
sudo cat /sys/kernel/debug/tracing/trace_pipe
```

> ⚠️ `bpf_trace_printk` 有限制（fmt 串最多 512 字节；5 个参数）；**生产建议用 ringbuf**。

## 4. ringbuf 调试：抓取事件

```bash
# 内核角度看 ringbuf 数据
sudo bpftool map dump id 10

# 或编写调试工具
cat > ringbuf_dump.bpf.c <<EOF
SEC("tracepoint/syscalls/sys_enter_openat")
int h(struct trace_event_raw_sys_enter *ctx) {
    /* 复用你的 event 结构 */
    struct event *e = bpf_ringbuf_reserve(&rb, sizeof(*e), 0);
    if (!e) return 0;
    e->pid = bpf_get_current_pid_tgid() >> 32;
    bpf_ringbuf_submit(e, 0);
    return 0;
}
EOF
```

## 5. 用户态调试

### 5.1 gdb 跟踪用户态加载器

```bash
gdb -args ./minimal bpf.o
```

libbpf 加载器会输出详细信息：

```
libbpf: failed to find BTF for map 'my_map'
libbpf: map 'my_map': at sec ".maps", offset 0
libbpf: failed to load program 'h_openat': Invalid argument(-22)
```

### 5.2 verbose 加载

```c
struct bpf_object_open_opts opts = {};
opts.kernel_log_buf = malloc(8192);
opts.kernel_log_size = 8192;
opts.kernel_log_level = 1;  // 0 = disabled

struct bpf_object *obj = bpf_object__open_file("prog.bpf.o", &opts);
```

### 5.3 BPF object pinning 调试

```bash
# 在文件系统上 dump
sudo bpftool prog dump xlated pinned /sys/fs/bpf/my_prog

# 看程序的所有 helper 调用
sudo bpftool prog dump xlated id 42 | grep 'call'
```

## 6. 特定类型的常见问题

### 6.1 XDP 调试

```bash
# 看 XDP 是否成功加载
ip link show dev eth0
# 输出 "xdp" 或 "xdpdrv" 行

# 卸载
sudo ip link set dev eth0 xdp off

# 错误信息
dmesg | tail
```

### 6.2 TC 调试

```bash
# 看 clsact 是否激活
sudo tc qdisc show dev eth0

# 加载 TC 程序
sudo tc filter add dev eth0 ingress bpf direct-action obj xdp.o sec classifier

# 查统计
sudo tc -s filter show dev eth0 ingress

# 卸载
sudo tc filter del dev eth0 ingress
```

### 6.3 tracepoint 调试

```bash
# 检查 tracepoint 是否存在
ls /sys/kernel/debug/tracing/events/syscalls/sys_enter_openat

# 查看格式（帮助写 ctx->args）
sudo cat /sys/kernel/debug/tracing/events/syscalls/sys_enter_openat/format
```

### 6.4 kprobe 调试

```bash
# 检查内核函数是否存在
sudo grep "T do_sys_open\b" /proc/kallsyms

# 注意：CONFIG_KALLSYMS_ALL=y 才能看到全部
```

## 13. 常见调试误区

### 13.1 别只盯着 verifier log

```c
// 错：以为编译过就万事大吉
SEC("xdp") int h(...) { return XDP_PASS; }  // 啥也不做，但编译过
```

要加 **测试断言**：

```c
SEC("xdp")
int h(struct xdp_md *ctx) {
    bpf_printk("DEBUG: hit my_prog\n");  // 至少证明程序被调用
    return XDP_PASS;
}
```

### 13.2 ringbuf 容量太小丢事件

```c
// 错：max_entries = 4KB，高吞吐下大量丢失
struct { __uint(type, BPF_MAP_TYPE_RINGBUF); __uint(max_entries, 4 * 1024); }

// 对：至少 256KB
struct { __uint(type, BPF_MAP_TYPE_RINGBUF); __uint(max_entries, 256 * 1024); }
```

### 13.3 perf_event_array 跨用户态共享问题

```c
// perf_event_array 在多线程消费者下不安全
// 优先用 ringbuf
```

### 13.4 BTF 信息不全

```bash
# 发行版内核可能没开启 BTF
ls /sys/kernel/btf/vmlinux  # 存在吗？

# Ubuntu 提示：安装 linux-modules-extra-$(uname -r)
sudo apt install linux-modules-extra-$(uname -r)
```

### 13.5 ringbuf 用户态 poll 频率

```c
// 错：100ms poll，事件堆积
ring_buffer__poll(rb, 100);

// 对：阻塞 + adaptive
while (!stop) {
    ring_buffer__poll(rb, 100);  // 这是合适的
}
```

### 13.6 不要在 hot path 里用 `bpf_printk`

```c
// 错：每秒百万次 printk
SEC("tracepoint/syscalls/sys_enter_open") int h(...) {
    bpf_printk("open\n");  // 严重影响性能
    return 0;
}

// 对：用 ringbuf 或关闭日志
```

## 14. 调试一个完整示例

```bash
# 步骤1: 确认探针存在
sudo ls /sys/kernel/debug/tracing/events/syscalls/sys_enter_openat

# 步骤2: 用 bpftrace 验证逻辑
sudo bpftrace -e 't:syscalls:sys_enter_openat { @[comm] = count(); }'

# 步骤3: 编译并加载 BPF 程序
make
sudo ./minimal &
PROGRAM_PID=$!

# 步骤4: 验证输出
sudo cat /sys/kernel/debug/tracing/trace_pipe | head -5

# 步骤5: 看 verifier 信息
sudo bpftool prog show id $(bpftool prog show | grep handle_openat | awk '{print $1}' | tr -d :)

# 步骤6: 检查 map 数据
sudo bpftool map show
sudo bpftool map dump id <map_id>

# 步骤7: 如果有 bug，用 dmesg
dmesg | tail -30

# 步骤8: 修改 → 重新编译 → 再跑
sudo kill $PROGRAM_PID
make clean && make
sudo ./minimal
```

## 15. 调试脑图

```
程序不工作
   │
   ├─ 加载失败
   │   ├─ verifier 拒绝 → 看 verifier log
   │   │   ├─ 类型错误 → 检查 helper 参数
   │   │   ├─ 越界     → 加边界检查
   │   │   ├─ 循环     → pragma unroll
   │   │   └─ 栈溢出   → 改用 map
   │   └─ 权限错误 → sudo
   │
   ├─ 加载成功但不触发
   │   ├─ SEC 名字错
   │   ├─ 挂载方式错（TC filter / XDP）
   │   └─ 探针不存在
   │
   ├─ 触发但输出错
   │   ├─ 数据没传过来 → 看 map / ringbuf
   │   ├─ 字段对齐错   → check struct layout
   │   └─ 字符串截断   → 增加 buf 大小
```
