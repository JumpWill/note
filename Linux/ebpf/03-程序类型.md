# 03 - eBPF 程序类型详解

> Linux 内核目前有 **30+ 种** 程序类型，每种对应不同的挂载点和上下文。选错类型是初学者最常见的坑。

## 全景分类

```
                              eBPF 程序类型
                                    │
        ┌──────────────┬────────────┼──────────────┐
        │              │            │              │
     网络层         内核追踪      用户态追踪       其他
        │              │            │              │
     XDP             kprobe       uprobe         LSM
     TC(clsact)      tracepoint   uretprobe      struct_ops
     socket filter   perf_event   USDT           tracing
     sk_msg          raw_tp       ...            ...
     sock_ops
     sk_reuseport
     lwt_seg6
```

## 1. 网络类

### XDP（eXpress Data Path）

**最热门的网络类程序类型**。在网卡驱动收到包后、内核协议栈之前处理。

```
网卡驱动 ─→ XDP ─→ 协议栈
              │
              ├─ XDP_PASS: 正常上送协议栈
              ├─ XDP_DROP: 直接丢弃（DDoS）
              ├─ XDP_TX:   原路返回（限流）
              ├─ XDP_REDIRECT: 重定向到其他网卡/CPU
              └─ XDP_ABORTED: 异常（触发 trace）
```

**示例：丢包过滤器**

```c
SEC("xdp")
int drop_tcp_syn(struct xdp_md *ctx) {
    void *data = (void *)(long)ctx->data;
    void *end = (void *)(long)ctx->data_end;

    struct ethhdr *eth = data;
    if ((void *)(eth + 1) > end) return XDP_PASS;

    if (eth->h_proto != bpf_htons(ETH_P_IP)) return XDP_PASS;

    struct iphdr *ip = (void *)(eth + 1);
    if ((void *)(ip + 1) > end) return XDP_PASS;

    if (ip->protocol != IPPROTO_TCP) return XDP_PASS;

    struct tcphdr *tcp = (void *)(ip + 1);
    if ((void *)(tcp + 1) > end) return XDP_PASS;

    if (tcp->syn && !tcp->ack) {
        bpf_printk("drop SYN from %x\n", ip->src);
        return XDP_DROP;
    }
    return XDP_PASS;
}
```

**加载方式**：

```bash
ip link set dev eth0 xdp obj xdp_drop.o sec xdp verbose
# 或 native 模式（驱动支持时性能最佳）
ip link set dev eth0 xdpdrv obj xdp_drop.o sec xdp
```

**典型开源应用**：[Facebook Katran](https://github.com/facebookincubator/katran)（L4 LB）、Cloudflare DDoS 缓解

### TC（Traffic Control）

在内核流量控制子系统挂载，**比 XDP 慢但能改包**，且支持对出包（egress）。

```
网卡 ─→ ingress ─→ TC clsact ─→ 协议栈
                          │
                          ├─ TC_ACT_OK: 放行
                          ├─ TC_ACT_SHOT: 丢弃
                          ├─ TC_ACT_REDIRECT: 重定向
                          ├─ TC_ACT_STOLEN: 接管
                          └─ TC_ACT_QUEUED: 入队
```

**示例：限速**

```c
SEC("classifier/ingress")
int tc_drop_high_pps(struct __sk_buff *skb) {
    u64 now = bpf_ktime_get_ns();
    u32 key = 0;
    u64 *last = bpf_map_lookup_elem(&rate_map, &key);
    if (!last) return TC_ACT_OK;

    if (now - *last < 1000000)  // 1ms 内只过 1 个包
        return TC_ACT_SHOT;

    *last = now;
    return TC_ACT_OK;
}
```

**典型开源应用**：Cilium 几乎所有网络功能都用 TC 实现

### Socket Filter

挂载在 socket 层，过滤发给本进程或从本进程发出的包。

```c
SEC("socket")
int sock_filter(struct __sk_buff *skb) {
    if (skb->protocol == bpf_htons(ETH_P_IP))
        return skb->len;  // 返回 > 0 表示接收
    return 0;
}
```

### Socket Maps（sk_msg / sock_ops）

- **sock_ops**：TCP 连接建立、状态机变化时触发。**用于透明代理、负载均衡**
- **sk_msg**：发送消息时触发
- **sk_reuseport**：SO_REUSEPORT 选择连接

```c
// Cilium 的 sock_ops 实现 k8s Service
SEC("sockops")
int bpf_sockops(struct bpf_sock_ops *skops) {
    // ... redirect 连接到本地代理
    return 1;
}
```

## 2. 内核追踪类

### kprobe / kretprobe

在内核函数入口/返回处动态插入追踪点。

```c
SEC("kprobe/do_sys_open")
int trace_open_entry(struct pt_regs *ctx) {
    // ctx 是 pt_regs，包含所有寄存器
    char filename[256];
    bpf_probe_read_user_str(filename, sizeof(filename), (void *)PT_REGS_PARM1(ctx));
    bpf_printk("open: %s\n", filename);
    return 0;
}

SEC("kretprobe/do_sys_open")
int trace_open_ret(struct pt_regs *ctx) {
    long ret = PT_REGS_RC(ctx);  // 返回值
    bpf_printk("open returned: %ld\n", ret);
    return 0;
}
```

> ⚠️ kprobe 依赖内核函数名，**内核版本升级可能改名**。所以生产建议用 tracepoint 或 BTF + kfunc

### tracepoint（静态追踪点）

`tracepoint` 是内核源码中**静态埋点**的追踪点，跨版本稳定。

```c
SEC("tracepoint/syscalls/sys_enter_openat")
int trace_openat(struct trace_event_raw_sys_enter *ctx) {
    // ctx->args[0] 是第一个参数
    const char *filename = (const char *)ctx->args[0];
    bpf_printk("openat: %s\n", filename);
    return 0;
}
```

查看所有 tracepoint：

```bash
ls /sys/kernel/debug/tracing/events/syscalls/sys_enter_openat/
cat /sys/kernel/debug/tracing/events/syscalls/sys_enter_openat/format
```

### raw_tracepoint

更轻量的 tracepoint，性能更好（不需要 fmt 解析）。

```c
SEC("raw_tracepoint/sys_enter")
int raw_tp(struct bpf_raw_tracepoint_args *ctx) {
    // ctx->args[0..n] 直接是原始参数
    return 0;
}
```

### perf_event

挂载在 PMU 硬件事件或采样事件上。

```c
SEC("perf_event")
int on_cpu(struct bpf_perf_event_data *ctx) {
    u64 cpu = bpf_get_smp_processor_id();
    bpf_printk("CPU %d busy\n", cpu);
    return 0;
}
```

### bpf_probe_read / bpf_core_read

**注意**：在 5.4+ 内核，`bpf_probe_read` 已被 `bpf_probe_read_kernel` 和 `bpf_probe_read_user` 取代（避免歧义）。

## 3. 用户态追踪类

### uprobe / uretprobe

在用户态函数入口/返回处插入追踪。

```c
SEC("uprobe/usr/bin/bash:readline")
int trace_bash(struct pt_regs *ctx) {
    char buf[256];
    bpf_probe_read_user(buf, sizeof(buf), (void *)PT_REGS_PARM1(ctx));
    bpf_printk("bash command: %s\n", buf);
    return 0;
}
```

加载：

```bash
bpftrace -e 'uprobe:/usr/bin/bash:readline { printf("%s\n", arg0); }'
```

### USDT（User-level Statically Defined Tracing）

类似 tracepoint，但用户态程序自己埋的探针。

```bash
# 给你的程序埋 USDT
dtrace -n 'probe provider_name { ... }' ./your_app
```

## 4. 安全与 LSM

### LSM（Linux Security Module）

Linux Security Module 钩子，eBPF 替代 AppArmor / SELinux。

```c
SEC("lsm/file_open")
int BPF_PROG(restrict_open, struct file *file, int ret) {
    char comm[16];
    bpf_get_current_comm(comm, sizeof(comm));

    // 阻止 nginx 读 /etc/shadow
    if (bpf_strcmp(comm, "nginx") == 0 &&
        file->f_path.dentry->d_name.name[0] == 's')
        return -EPERM;

    return 0;
}
```

**典型应用**：[Tetragon](https://github.com/cilium/tetragon) - 实时安全阻断

## 5. 现代程序类型（5.x 内核）

### BPF_PROG_TYPE_TRACING

5.x 新增，多个 tracepoint 合并，最常用。

```c
SEC("tp_btf/sys_enter_openat")
int trace_openat(struct trace_event_raw_sys_enter *ctx) {
    return 0;
}
```

### BPF_PROG_TYPE_SYSCALL

5.14+ 可用，syscall 追踪的最优选。

### struct_ops（5.6+）

在内核结构体上注册自定义操作，如 TCP congestion control。

```c
SEC("struct_ops/tcp_congestion_ops")
int BPF_PROG(my_congestion, struct sock *sk) {
    // 自定义 TCP 拥塞控制
    return 0;
}

SEC(".struct_ops")
struct tcp_congestion_ops my_ops = {
    .init     = (void *)my_init,
    .cong_ctrl = (void *)my_congestion,
};
```

### kfunc（5.18+）

调用内核导出的 kfunc，扩展性最强，**和 BPF 共享 BTF 类型**。

```c
extern int bpf_task_acquire(struct task_struct *p) __ksym;

SEC("tp_btf/task_newtask")
int trace_newtask(struct task_struct *task) {
    bpf_task_acquire(task);  // 调用内核导出函数
    return 0;
}
```

## 6. 程序类型选择决策树

```
是否观测网络包？
├─ 是
│  ├─ 包最早就丢 → XDP（最早期）
│  ├─ 需要改包内容 → TC
│  ├─ 关联到 socket → socket / sock_ops
│  └─ TCP 状态变化 → sock_ops
└─ 否
   ├─ 是观测内核态？
   │  ├─ 函数入口/出口 → kprobe
   │  ├─ 内核埋点 → tracepoint（稳定）/ raw_tracepoint（轻量）
   │  └─ 硬件事件 → perf_event
   ├─ 是观测用户态？
   │  ├─ 用户态函数 → uprobe
   │  └─ 用户态埋点 → USDT
   ├─ 是安全策略？
   │  └─ LSM hook
   └─ 是替换内核行为？
      ├─ TCP 协议 → struct_ops
      └─ 调用内核函数 → kfunc
```

## 7. 程序类型与 ctx 上下文对照表

| 类型 | ctx 类型 | 用途 |
|------|---------|------|
| XDP | `struct xdp_md` | 网卡入口 |
| TC | `struct __sk_buff` | 收发包 |
| socket | `struct __sk_buff` | socket 过滤 |
| sock_ops | `struct bpf_sock_ops` | TCP 状态 |
| sk_msg | `struct sk_msg_md` | 发送消息 |
| sk_reuseport | `struct sk_reuseport_md` | 端口选择 |
| kprobe | `struct pt_regs *` | 函数入口 |
| tracepoint | 由 `trace_event_raw_*` 定义 | 静态埋点 |
| raw_tracepoint | `struct bpf_raw_tracepoint_args *` | 轻量 tracepoint |
| perf_event | `struct bpf_perf_event_data *` | 性能事件 |
| uprobe | `struct pt_regs *` | 用户态函数 |
| LSM | 由 hook 类型决定 | 安全 |
| struct_ops | 协议相关 | 替换内核行为 |
| tracing | `struct bpf_tracing_link_ctx *`（5.18+） | 现代追踪 |
