# Linux 文件类型

Linux 系统里"一切皆文件"，但文件不是同一种"文件"。它们在 inode 元数据的 type 字段被区分，ls 命令展示出来的前缀字符（`- / d / l / c / b / p / s`）就是文件类型的速记。内核通过 inode 的 `i_mode & S_IFMT` 判定类型，不同类型对应不同的打开 / 读写 / 寻址语义。

## 1. 七种基础类型

| 类型 | ls 前缀 | 用途 |
| ---- | ------- | ---- |
| **regular file** | `-` | 普通文件，存储实际数据 |
| **directory** | `d` | 目录，文件名到 inode 的映射 |
| **symbolic link** | `l` | 软链接，存储目标路径 |
| **character device** | `c` | 字符设备，按字节流访问 |
| **block device** | `b` | 块设备，按块访问、可寻址 |
| **pipe / FIFO** | `p` | 命名管道，进程间通信 |
| **socket** | `s` | 套接字文件，进程通信 |

> 块设备 / 字符设备 / 命名管道 / 套接字 统称 **special file**（特殊文件）。

注意 ls 在某些平台上还显示 `=` 表示 door（Solaris）。现代 Linux 不常见。

## 2. inode 类型字段

### 2.1 S_IFMT 位

内核用 `inode->i_mode` 字段的高 4 位表示类型（`<sys/stat.h>`）：

| 类型宏 | 数值（八进制） | 含义 |
| ------ | -------------- | ---- |
| `S_IFREG` | 0100000 | regular file |
| `S_IFDIR` | 0040000 | directory |
| `S_IFLNK` | 0120000 | symlink |
| `S_IFCHR` | 020000 | char device |
| `S_IFBLK` | 060000 | block device |
| `S_IFIFO` | 010000 | FIFO / pipe |
| `S_IFSOCK` | 0140000 | socket |

判断：

```c
if ((inode->i_mode & S_IFMT) == S_IFDIR) {
    // 目录
}
```

### 2.2 获取文件信息

```bash
stat /etc/passwd
```

```text
File: /etc/passwd
  Size: 1234         Filetype: regular file
  Mode: (0644/-rw-r--r--)
...
```

`stat -c '%F' file` 输出人类可读类型：

```bash
$ stat -c '%F' /etc/passwd
regular file

$ stat -c '%F' /var
directory

$ stat -c '%F' /bin/ln
symbolic link
```

## 3. 详细说明

### 3.1 普通文件 (regular file, `-`)

- 最常见：文本、二进制、文档、图片…
- 通过字节偏移 `lseek()` / `read()` / `write()`
- 可以删除（若 link count = 0 + 无打开 handle）
- 没有特殊语义

### 3.2 目录 (directory, `d`)

- 内部是一张"文件名 → inode 号"的哈希表
- 内容保存在目录自身的 data blocks 中
- 操作命令：`cd / ls / mkdir / rmdir`
- 程序 API：`opendir() / readdir() / closedir()`
- 目录不能删自己；只能在空时删（rmdir / rm -rf）

硬链接只能针对同文件系统的目录项：

```bash
ln /etc /tmp/etclink       # 不允许：cross-device / 目录
```

LINUX 有保护模式 `protected_hardlinks` / `protected_symlinks`。

### 3.3 软连接 / 符号链接 (symbolic link, `l`)

- 文件内容是目标路径字符串（"链接 → /some/where"）
- 可以跨文件系统
- 可以链接到不存在的目标（"dangling symlink"，操作时 ENOENT）
- 删除软链只是删 inode，不影响目标

```bash
ln -s /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default
```

软连接权限位无效（看查 ls 显示 `lrwxrwxrwx`），实际权限由目标决定。

### 3.4 硬链接 vs 软链

| 维度 | 硬链接 | 软链接 |
| ---- | ------ | ------ |
| inode | 同 inode | 新 inode |
| 跨文件系统 | ❌ | ✔ |
| 链接目录 | ❌（内核限制） | ✔ |
| 失效 | 必须 inode 释放才"链接消失" | 目标删除即失效 |
| 权限 / 链接计数 | 都变化 | 不变 |
| 删除影响 | 只在 link=0 时释放 inode | 立即删链接 inode |

### 3.5 字符设备 (character device, `c`)

- 按字符流写入 / 读取
- 内核驱动实现 `open / read / write / release` ops
- 例子：

```text
crw-rw---- 1 root tty     4,   1 /dev/tty1
crw------- 1 root root   10,  61 /dev/kmsg
crw-rw-rw- 1 root root    1,   3 /dev/null
```

主 / 次设备号：major / minor 标识驱动与设备。

```bash
ls -l /dev | head -30
stat /dev/null
```

应用：

- 终端 `tty`
- 串口 `/dev/ttyS0`
- `null / zero / random / urandom / kmsg / mem`

### 3.6 块设备 (block device, `b`)

- 按固定大小块（512 / 4K）随机寻址
- 支持缓存、IO 调度、文件系统
- 例子：硬盘 / U 盘 / 磁盘阵列

```text
brw-rw---- 1 root disk    8,   0 /dev/sda
brw-rw---- 1 root disk  259,   0 /dev/nvme0n1
```

### 3.7 命名管道 (named pipe / FIFO, `p`)

- 文件系统里有名字的管道
- 用于进程间通信（"先把数据塞进 FIFO，对方 read"）
- 半双工，加锁可避免多人写混乱
- 用 `mkfifo`：

```bash
mkfifo /tmp/mypipe
ls -l /tmp/mypipe
echo "hello" > /tmp/mypipe             # 阻塞，直到对端 read
cat /tmp/mypipe                        # 阻塞等到写入
```

适合：

- shell 流式串联
- 一写一读结构

### 3.8 套接字 (socket, `s`)

- 命名 unix domain socket（AF_UNIX）有自己的 inode + 文件名
- 用 `socket()` 创建 + `bind()` 到 path
- 进程间通信，比 TCP/IP 轻

```text
srwxrwxr-x 1 mysql mysql     0 /var/run/mysqld/mysqld.sock
srwxrwxrwx 1 root  root      0 /var/run/docker.sock
```

查看网络套接字使用 `ss` / `netstat`（不计入文件系统，仅内核 socket 抽象），不走 inode。

### 3.9 可执行 / 链接文件

常见特殊情况：

- ELF 可执行：**普通文件** + x 权限位 + `readelf -h` 才能看
- 静态 / 共享库：普通文件 + 共享库名后缀
- namespace：仍是普通文件，由 `unshare()` 创建
- mount namespace、cgroup、chroot 看到的是内核虚拟文件系统，不是"普通文件"

## 4. 工具与方法

### 4.1 ls -l 看类型

```bash
ls -l /etc | head
drwxr-xr-x  88 root root  4096 Jan  1 10:00 etc
-rw-r--r--   1 root root    123 Jan  1 10:00 passwd
lrwxrwxrwx   1 root root    12 Jan  1 10:00 hosts -> /etc/hosts
```

### 4.2 find 加 `-type`

```bash
find / -type f -name "*.log"
find / -type d -name "site*"
find / -type l -name "current"
find /tmp -type p
find /var/run -type s
```

| 选项 | 匹配 |
| ---- | ---- |
| `-type f` | 普通文件 |
| `-type d` | 目录 |
| `-type l` | symlink |
| `-type c` | char device |
| `-type b` | block device |
| `-type p` | FIFO |
| `-type s` | socket |

### 4.3 stat 多格式

```bash
stat -c '%F %n' /etc
stat -c '%F %n' /etc/passwd
stat -c '%F %n' /usr/bin/ln
```

### 4.4 file 命令（详细）

```bash
file /bin/ln
file -s /dev/sda
file -L /usr/bin/python
```

`file` 通过 magic 文件识别，对 ELF / 脚本 / 压缩文件 / 图片等。

### 4.5 直接读 magic 文件

```bash
hexdump -C /bin/ln | head
xxd /var/run/docker.sock | head
```

观察实际 magic number。

## 5. 文件系统内的运作

### 5.1 ext4 / inode

inode 元数据（见 inode.md）包含类型 / mode / link count / size / block map /
xattr / generation。

```bash
stat /etc
```

### 5.2 symlink 在 ext4

- 普通 symlink：inode 中存 inline target（≤ 60 bytes），不占额外数据块
- 长 symlink：存一个 60 bytes 起点 + block pointer

```bash
readlink /usr/bin/gzip          # 输出 /bin/gzip
ls -l /bin                      # 验证 links 数
```

### 5.3 Unix Domain Socket 与文件系统

`/var/run/docker.sock` 是 socket 但仍是文件系统中的文件（s 开头）。

```bash
ss -lpn 'src = /var/run/docker.sock' | head
lsof -U | grep docker.sock
```

### 5.4 设备号

```bash
ls -l /dev/null /dev/sda /dev/tty
stat /dev/null | grep Inode
```

设备号关系：

```text
128  major:
  1 / 1     -- /dev/mem
  4 / 1     -- /dev/tty
  10 / 61   -- kmsg
  8 / 0     -- sda
  259 / 0   -- nvme
```

## 6. Linux 与 Windows 文件类型差异

| 维度 | Linux | Windows |
| ---- | ----- | ------- |
| 分类 | 7 类 inode 类型 | 二进制 / 文本 |
| 区分方式 | 字符设备 / 块设备 / symlink | 文件扩展名 |
| 大小写 | 区分 | 不区分 |
| 路径分隔 | `/` | `\` |
| 软硬链接 | ✔ 软 + 硬 | ❌（只有 shortcut） |
| 特殊文件目录 | `/dev /proc /sys /run /tmp` | 特殊目录 |

注意：`/dev/null /dev/zero /dev/random` 在 Windows 中不可对应，要用 `nul` / 模拟。

## 7. 实际场景

### 7.1 找文件类型

```bash
# 找出所有套接字
find / -type s

# 找出所有软链
find / -type l -name "*.service"
```

### 7.2 处理 dangling symlink

```bash
find /usr -xtype l -print
find /usr -xtype l -delete
```

### 7.3 检查命名管道

```bash
find /tmp -type p
```

### 7.4 清理 /dev 占位

```bash
udevadm info /dev/sda
mknod /tmp/mydev c 99 99     # 仅示例，实际不会这么做
```

### 7.5 文件类型与权限

文件类型与权限无关：

- 看 ls 第一字符
- 权限看 rwx / setuid / sticky

### 7.6 容器内 / Dockerfile

容器内文件类型与 host 完全相同。volumes / bind mount 时主要校验：

```bash
ls -la /data
find / -type s               # 找 socket
```

## 8. 延伸：不同文件系统的"文件类型"

| 类型 / 文件系统 | ext4 | xfs | btrfs | tmpfs | procfs | sysfs |
| --------------- | --- | --- | ----- | ----- | ------ | ----- |
| 普通文件 | ✔ | ✔ | ✔ | ✔ | ❌（多数） | ❌ |
| 目录 | ✔ | ✔ | ✔ | ✔ | ✔ | ✔ |
| 软链 | ✔ | ✔ | ✔ | ✔ | ❌ | ❌ |
| 设备文件 | ❌ | ❌ | ❌ | ❌ | ❌ | ❌ |
| FIFO | ✔ | ✔ | ✔ | ✔ | ❌ | ❌ |
| Socket | ✔ | ✔ | ✔ | ✔ | ❌ | ❌ |

总结：

- **真实文件系统**（ext4 / xfs / btrfs）：7 种都支持
- **tmpfs**：所有"客户端"类型都能创，设备文件无意义
- **procfs / sysfs**：内核生成的虚拟文件，多为 read-only

## 9. 一句话总结

```text
Linux 文件类型 = inode 元数据 4 位掩码
ls 看一个字符（-/d/l/c/b/p/s）
find -type 分类快速筛查
```
