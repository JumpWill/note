# Linux 信号机制详解

## 一、信号概述

### 1.1 什么是信号

**信号**（Signal）是 Linux 内核向进程发送的**异步通知机制**，用于处理异常事件或进程间通信。

**信号特点：**

- 异步（随时可能到达）
- 预定义（固定含义）
- 编号 1-64（传统信号）
- 实时信号（RT signals）

**常见信号速记：**

- `SIGKILL`（9）— 必杀，不可捕获
- `SIGTERM`（15）— 优雅退出
- `SIGINT`（2）— Ctrl+C
- `SIGHUP`（1）— 终端断开
- `SIGSTOP`（19）— 必停
- `SIGCONT`（18）— 继续

### 1.2 信号来源

**硬件异常：**

- 除零 → `SIGFPE`
- 段错误 → `SIGSEGV`
- 总线错误 → `SIGBUS`
- 非法指令 → `SIGILL`

**用户操作：**

- Ctrl+C → `SIGINT`
- Ctrl+\ → `SIGQUIT`
- Ctrl+Z → `SIGTSTP`（停止）

**进程操作：**

- `kill` 命令 → 默认 `SIGTERM`
- `kill -9` → `SIGKILL`
- `abort()` → `SIGABRT`

**内核发送：**

- 子进程退出 → `SIGCHLD`
- 管道关闭 → `SIGPIPE`
- 内存不足 → `SIGKILL`（OOM）
- CPU 时间超限 → `SIGXCPU`

### 2.2 三大类信号

**1. 传统信号（Standard Signals）**

- 编号 1-31
- POSIX 标准定义
- 主要用于进程控制

**2. 实时信号（Real-Time Signals）**

- 编号 `SIGRTMIN` 至 `SIGRTMAX`（通常 32-64）
- 携带数据（`sigval_t`）
- 排队有序
- 不会丢失

**3. 进程控制专用**

- `SIGCHLD` — 子进程状态变化
- `SIGSTOP` — 不可捕获的停止
- `SIGKILL` — 不可捕获的终止
- `SIGCONT` — 继续

### 2.3 不可捕获信号

这三种信号**进程无法忽略或处理**：

- `SIGKILL`（9）— 必杀，内核强制终止
- `SIGSTOP`（19）— 必停，进程暂停
- `SIGCONT`（18）— 继续（与 STOP 对应）

特性：

- 进程无法注册 handler
- 进程无法忽略
- 进程无法阻塞
- 内核直接处理

### 2.4 核心转储信号（Core Dump）

默认动作是 **Core** 的信号（产生 core dump）：

- `SIGQUIT`（3）— Ctrl+\ 退出
- `SIGILL`（4）— 非法指令
- `SIGTRAP`（5）— 跟踪
- `SIGABRT`（6）— abort
- `SIGBUS`（7）— 总线错误
- `SIGFPE`（8）— 浮点异常
- `SIGSEGV`（11）— 段错误
- `SIGXCPU`（24）— CPU 超限
- `SIGXFSZ`（25）— 文件大小超限
- `SIGSYS`（31）— 系统调用错

**Core dump 配置：**

```bash
ulimit -c unlimited
echo "/tmp/core.%e.%p" > /proc/sys/kernel/core_pattern
```

## 三、特权信号详解

### 3.1 SIGKILL（9）— 必杀信号

**SIGKILL 详解：**

特性：

- 不能被捕获
- 不能被忽略
- 不能被阻塞
- 内核强制立即终止
- 不给进程清理机会

**用途：**

- 进程无响应时强制终止
- `kill -9 PID`
- OOM Killer 触发
- 系统管理紧急情况

**风险：**

- 数据丢失（未刷盘）
- 资源未释放（文件、socket）
- 锁未释放
- 日志未刷写

**示例：**

```bash
kill -9 1234
kill -KILL 1234
kill -SIGKILL 1234
```

**SIGKILL 的陷阱：**

**场景 1：kill -9 导致数据损坏**

- 应用正在写文件，没 flush
- 数据库事务没提交
- 缓存数据丢失

**场景 2：父进程被 SIGKILL 后，子进程变孤儿**

- 子进程被 init（PID 1）收养
- 需要清理

**场景 3：父进程在管道中，读端被 SIGKILL**

- 写端收到 `SIGPIPE`

**场景 4：OOM Killer 触发 SIGKILL**

- 系统内存耗尽
- 内核选一个进程杀
- 通常是占用最多的

**最佳实践：**

1. 永远先尝试 `SIGTERM`（给应用清理机会）
2. 等几秒
3. 才用 `SIGKILL`

### 3.2 SIGSTOP（19）— 必停信号

**SIGSTOP 详解：**

特性：

- 不能被捕获
- 不能被忽略
- 进程被立即停止
- 不能被恢复（除非 `SIGCONT`）

**与 `SIGTSTP`（20）的区别：**

- `SIGSTOP`：不可捕获，强制停止
- `SIGTSTP`：可捕获，软停止（Ctrl+Z）

**状态：** `T`（stopped）进程状态

**用途：**

- 调试（暂停进程查看内存）
- 进程切换（上下文）
- 抢占时间片

**示例：**

```bash
kill -STOP 1234
kill -CONT 1234
```

**注意：**

- 暂停的进程不响应任何信号
- 只有 `SIGKILL` 才能杀死
- 或 `SIGCONT` 恢复

### 3.3 SIGCONT（18）— 继续信号

**SIGCONT 详解：**

特性：

- 可捕获
- 默认动作：继续执行
- 恢复 `SIGSTOP`/`SIGTSTP` 暂停的进程

**用途：**

- 恢复后台进程
- 配合 `SIGSTOP` 用于调试

**示例：**

```bash
kill -CONT 1234
```

### 3.4 SIGTERM（15）— 优雅终止

**SIGTERM 详解：**

特性：

- 可捕获
- 默认动作：终止
- 给应用清理机会
- 最常用的"正常"终止信号

**应用应该做的：**

1. 注册 `SIGTERM` handler
2. 收到信号后：
   - 停止接受新连接
   - 等待处理中的请求
   - 关闭数据库连接
   - 刷新日志
   - 释放资源
3. `exit(0)`

**默认行为（无 handler）：**

- 进程直接退出
- 不做清理

**示例：**

```bash
kill -15 1234
kill -TERM 1234
systemctl stop myapp
docker stop myapp
```

**SIGTERM 与 SIGKILL 的对比：**

|特性|SIGTERM(15)|SIGKILL(9)|
|---|---|---|
|可捕获|是|否|
|可忽略|是|否|
|可阻塞|是|否|
|默认动作|Term(终止)|Term(终止)|
|给清理机会|是(推荐)|否|
|可被 handler|是|否|

**最佳实践：**

1. 总是先发 `SIGTERM`
2. 等待 grace period（10s 默认）
3. 应用没退，才发 `SIGKILL`

### 3.5 SIGINT（2）— 中断信号

**SIGINT 详解：**

来源：

- 用户按 Ctrl+C
- 终端驱动发送
- tty 接收到的中断字符

**默认动作：** Term（终止）

**可捕获：** 是

**应用场景：**

- 交互式程序：中断当前操作
- 后台程序：通常不处理
- 批处理：优雅停止

**示例：**

```bash
Ctrl+C
```

```c
/* 自定义处理 */
trap 'echo "Got SIGINT"; exit' SIGINT
```

### 3.6 SIGHUP（1）— 挂起信号

**SIGHUP 详解：**

名称来源：_"Hang UP"_（挂断电话）

**传统含义：**

- 终端连接断开
- 用户登出

**现代用途：**

- 守护进程重新加载配置（daemon reload）
- 通知进程控制终端已断开

**常见 daemon 的 SIGHUP 处理：**

- nginx：重新加载配置
- sshd：重新读取配置
- apache：graceful restart
- syslog：重新打开日志文件

**示例：**

```bash
kill -HUP 1234
kill -1 1234
```

守护进程收到 `SIGHUP` 后通常重新加载配置，不会终止进程。

### 3.7 SIGCHLD（17）— 子进程状态变化

**SIGCHLD 详解：**

**触发条件：**

- 子进程终止
- 子进程停止（`SIGSTOP`）
- 子进程继续（`SIGCONT`）
- 子进程退出（status 变化）

**默认动作：** Ign（忽略）

**用途：**

- 父进程回收子进程
- 异步通知子进程结束
- 实现 `wait()` 系统调用

**实现方式：**

- `wait()`：阻塞，直到子进程结束
- `waitpid()`：等待指定子进程
- 异步：注册 `SIGCHLD` handler

**代码示例：**

```c
void sigchld_handler(int sig) {
    int status;
    waitpid(-1, &status, WNOHANG);
    /* 回收子进程，避免僵尸 */
}

int main() {
    signal(SIGCHLD, sigchld_handler);
    fork();
    /* ... */
}
```

如果不处理 `SIGCHLD`：

- 子进程退出后变僵尸
- 占用进程表 slot
- 大量子进程后系统无响应

### 3.8 其他重要信号

**`SIGPIPE`（13）— 管道关闭**

- 场景：写入管道，读端已关闭
- 默认动作：Term
- 处理：通常应该捕获，关闭 socket

**`SIGUSR1`（10）/ `SIGUSR2`（12）— 用户自定义**

- 默认动作：Term
- 用途：进程间通信
- 例子：nginx 用 `SIGUSR1` 重新打开日志

**`SIGALRM`（14）— 定时器**

- 来源：`alarm()` / `setitimer()`
- 默认动作：Term
- 用途：定时操作

**`SIGIO` / `SIGPOLL`（29）— I/O 事件**

- 来源：套接字或文件描述符就绪
- 默认动作：Term（早期）/ Ign
- 用途：异步 I/O

**`SIGURG`（23）— 紧急数据**

- 来源：TCP 紧急数据到达
- 默认动作：Ign
- 用途：带外数据（out-of-band）

**`SIGWINCH`（28）— 终端窗口大小变化**

- 来源：终端大小变化
- 默认动作：Ign
- 用途：应用程序调整 UI

## 四、信号传递机制

### 4.1 信号发送流程

**发送信号流程：**

1. 进程 A 调用 `kill(pid, sig)` 系统调用
2. 内核检查权限（同 UID 或 `CAP_KILL`）
3. 内核找到目标进程
4. 内核设置目标进程的 signal pending 标志
5. 系统调用返回（异步）
6. 目标进程返回用户态前，内核检查 signal pending
7. 内核调用 signal handler 或执行默认动作
8. 信号处理完成，进程继续执行

### 4.2 信号在内核中的表示

进程描述符（`task_struct`）中的信号相关字段：

- `sigset_t blocked`：阻塞的信号
- `sigset_t pending`：待处理信号
- `struct sighand_struct *sighand`：信号 handler 表

### 4.3 信号的默认动作

- **Term（Terminate）**：进程终止
- **Core（Core dump）**：进程终止，生成 core dump
- **Ign（Ignore）**：忽略信号
- **Stop（Stop）**：停止进程
- **Cont（Continue）**：继续

## 五、信号处理

### 5.1 signal() 系统调用（简单方式）

```c
#include <signal.h>

void handler(int sig) {
    printf("Caught signal %d\n", sig);
}

int main() {
    signal(SIGINT, handler);  /* 注册 handler */
    signal(SIGINT, SIG_IGN);  /* 忽略 */
    signal(SIGINT, SIG_DFL); /* 默认动作 */

    while (1) {
        pause();
    }
    return 0;
}
```

### 5.2 sigaction() 系统调用（推荐方式）

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

volatile sig_atomic_t got_signal = 0;

void handler(int sig, siginfo_t *info, void *ucontext) {
    got_signal = 1;
    /* 可以获取更多信息 */
    printf("Signal %d from PID %d, code %d\n",
           sig, info->si_pid, info->si_code);
}

int main() {
    struct sigaction sa;
    sa.sa_sigaction = handler;        /* handler 函数 */
    sa.sa_flags = SA_SIGINFO;         /* 启用 siginfo */
    sigemptyset(&sa.sa_mask);
    sigaddset(&sa.sa_mask, SIGTERM);  /* 处理时阻塞这些 */

    sigaction(SIGUSR1, &sa, NULL);

    while (!got_signal) {
        pause();
    }
    printf("Got SIGUSR1\n");
    return 0;
}
```

### 5.3 信号处理函数限制

**信号处理函数（handler）中应该只做：**

- 设置全局标志
- 写无锁的 `volatile` 变量
- 重新设置信号（`signal`）
- 写入原子操作

**信号处理函数中不应该做：**

- `malloc` / `free`
- `printf`（可能死锁，线程不安全）
- 访问复杂数据结构
- 调用不可重入函数
- 长时间阻塞操作

**原因：** 信号处理随时打断主程序，主程序可能在任何状态，复杂操作可能导致数据不一致。

**Async-Signal-Safe 函数列表（可安全在 handler 中调用）：**

- `_Exit()`
- `read()` / `write()`
- `open()` / `close()`
- `stat()` / `fstat()` / `lstat()`
- `lseek()`
- `getpid()` / `getuid()` / `getgid()`
- `kill()` / `pause()` / `sleep()` / `alarm()`
- `time()` / `gettimeofday()`
- `writev()` / `readv()`
- `sigaction()` / `sigreturn()` / `waitpid()` / `fork()`

### 5.4 信号的阻塞与解除

```c
#include <signal.h>

/* 阻塞所有信号 */
sigset_t mask;
sigfillset(&mask);
sigprocmask(SIG_BLOCK, &mask, NULL);

/* 临界区代码 */
/* 此时信号 pending，但不执行 */

/* 解除阻塞（会触发 pending 的信号） */
sigprocmask(SIG_UNBLOCK, &mask, NULL);

/* sigsuspend() 原子地修改 mask 并等待信号 */
sigemptyset(&mask);
sigsuspend(&mask);  /* 等待任何信号 */

/* sigprocmask 与 sigsuspend 的区别：
   sigprocmask: 修改 mask
   sigsuspend:   临时修改 mask + 等待信号 */
```

### 5.5 进程与线程的信号

Linux 中线程是轻量级进程：

- 信号可以发给特定线程（`pthread_kill`）
- 也可以发给进程（`kill`）
- 发给进程的信号：任意线程处理
- 发给特定线程：`pthread_kill` 指定线程处理

**多线程程序中信号处理：**

1. `pthread_sigmask`：每个线程独立阻塞
2. 默认：主线程处理进程信号
3. 可用 `pthread_kill` 定向发送

## 六、信号实战应用

### 6.1 优雅关闭模式

```c
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <stdbool.h>

static volatile sig_atomic_t shutdown_requested = false;

void handle_sigterm(int sig) {
    shutdown_requested = true;
}

int main() {
    /* 注册 SIGTERM handler */
    struct sigaction sa;
    sa.sa_handler = handle_sigterm;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = 0;
    sigaction(SIGTERM, &sa, NULL);
    sigaction(SIGINT, &sa, NULL);

    /* 启动服务 */
    printf("服务启动\n");

    /* 主循环 */
    while (!shutdown_requested) {
        /* 处理请求... */
        sleep(1);
    }

    /* 优雅清理 */
    printf("收到终止信号，开始清理\n");

    /* 关闭 socket */
    /* 关闭数据库连接 */
    /* 刷新缓存 */
    /* 关闭文件 */

    printf("清理完成，退出\n");
    return 0;
}
```

### 6.2 多进程服务器信号处理

```c
#include <signal.h>
#include <unistd.h>

/* 处理 SIGCHLD，避免僵尸进程 */
void handle_sigchld(int sig) {
    int status;
    pid_t pid;

    /* 非阻塞回收所有子进程 */
    while ((pid = waitpid(-1, &status, WNOHANG)) > 0) {
        /* 处理结束的子进程 */
        if (WIFEXITED(status)) {
            printf("子进程 %d 退出，状态：%d\n",
                   pid, WEXITSTATUS(status));
        }
    }
}

int main() {
    /* 注册 SIGCHLD handler */
    struct sigaction sa;
    sa.sa_handler = handle_sigchld;
    sigemptyset(&sa.sa_mask);
    sa.sa_flags = SA_RESTART | SA_NOCLDSTOP;
    sigaction(SIGCHLD, &sa, NULL);

    /* 创建 worker 子进程 */
    for (int i = 0; i < 4; i++) {
        if (fork() == 0) {
            /* worker 进程 */
            worker_main();
        }
    }

    /* 主进程等待 */
    while (1) {
        sleep(60);
    }
}
```

### 6.3 定时器信号 SIGALRM

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

void timer_handler(int sig) {
    static int count = 0;
    printf("定时器触发：%d 次\n", ++count);
}

int main() {
    signal(SIGALRM, timer_handler);

    /* 启动定时器：1 秒后第一次触发，之后每 1 秒 */
    struct itimerval itv;
    itv.it_value.tv_sec = 1;     /* 第一次触发时间 */
    itv.it_value.tv_usec = 0;
    itv.it_interval.tv_sec = 1;  /* 之后间隔 */
    itv.it_interval.tv_usec = 0;
    setitimer(ITIMER_REAL, &itv, NULL);

    while (1) pause();
}
```

### 6.4 kill 命令详解

```bash
# 默认发送 SIGTERM
kill 1234

# 发送 SIGKILL
kill -9 1234
kill -KILL 1234

# 发送 SIGINT（Ctrl+C）
kill -2 1234

# 发送 SIGHUP（重读配置）

# 1) SIGHUP   2) SIGINT   3) SIGQUIT  4) SIGILL   5) SIGTRAP

# 按名称杀
pkill nginx

# 按用户杀

# 查看并杀
pgrep -l nginx
pkill -v nginx

# 进程树
pstree -p 1234
```

### 6.5 系统调用与信号

慢系统调用被信号中断的行为：

- `errno = EINTR`（Interrupted system call）
- 受影响的调用：`read()`、`write()`、`accept()`、`connect()`、`select()`、`poll()`、`epoll_wait()`、`sleep()`、`pause()`

**处理方式 1：重试**

```c
while ((n = read(fd, buf, size)) == -1 && errno == EINTR);
```

**处理方式 2：SA_RESTART 标志**

```c
struct sigaction sa;
sa.sa_flags = SA_RESTART;  /* 系统调用自动重启 */
sigaction(SIGINT, &sa, NULL);
```

## 七、信号安全实践

### 7.1 信号处理安全

**错误示例：handler 中调用非 async-signal-safe 函数**

```c
void bad_handler(int sig) {
    printf("Got signal %d\n", sig);  /* printf 不是 async-safe */
    malloc(100);                       /* malloc 可能死锁 */
    log_to_file("signal.log", ...);   /* 写文件可能死锁 */
}
```

**正确示例：只做最少的事情**

```c
volatile sig_atomic_t signal_received = 0;

void good_handler(int sig) {
    signal_received = 1;
    /* 在主程序中检查并处理 */
}

int main() {
    signal(SIGUSR1, good_handler);

    while (!signal_received) {
        do_work();
    }

    /* 这里是安全的（不在 handler 中） */
    printf("Signal received\n");
    log_to_file("signal.log", ...);
    return 0;
}
```

### 7.2 信号处理中的常见错误

**错误 1：不可重入函数**

```c
void handler(int sig) {
    FILE *fp = fopen("log.txt", "a");  /* fopen 不安全 */
    fprintf(fp, "Got signal\n");
    fclose(fp);
}
```

**错误 2：长时间阻塞**

```c
void handler(int sig) {
    sleep(10);  /* handler 中 sleep 会阻塞其他信号 */
}
```

**错误 3：死锁**

```c
void handler(int sig) {
    pthread_mutex_lock(&mutex);  /* 如果主线程持有锁，死锁 */
    /* ... */
    pthread_mutex_unlock(&mutex);
}
```

**错误 4：非原子访问**

```c
int flag = 0;
void handler(int sig) { flag = 1; }  /* int 写入不原子 */
void main() { if (flag) { ... } }     /* 读取可能看到中间状态 */

/* 正确：使用 volatile sig_atomic_t */
volatile sig_atomic_t flag = 0;
void handler(int sig) { flag = 1; }
void main() { if (flag) { ... } }
```

### 7.3 信号使用最佳实践

1. **默认用 `sigaction()` 而不是 `signal()`**
   - `signal()` 行为不可移植
   - `sigaction()` 是 POSIX 标准

2. **handler 只设置标志**
   - 复杂处理在主程序中做
   - 用 `volatile sig_atomic_t` 标志

3. **处理慢系统调用的 EINTR**
   - 重试或 `SA_RESTART`
   - 检查 `errno`

4. **阻塞信号保护临界区**
   - `sigprocmask()`
   - `sigsuspend()` 配合

5. **父进程处理 `SIGCHLD`**
   - `waitpid()` 回收子进程
   - `WNOHANG` 非阻塞

6. **优雅关闭先 `SIGTERM` 后 `SIGKILL`**
   - 留 grace period
   - 10-30 秒

7. **关键资源用 volatile + 锁**
   - `volatile sig_atomic_t` 标志
   - `sigprocmask` 保护访问

## 八、信号核心要点速记

### 三大不可捕获信号

- `SIGKILL`（9）— 必杀，立即终止
- `SIGSTOP`（19）— 必停，立即停止
- `SIGCONT`（18）— 继续，恢复执行

### 五大常用信号

- `SIGTERM`（15）— 优雅终止（推荐）
- `SIGINT`（2）— 中断（Ctrl+C）
- `SIGHUP`（1）— 重读配置
- `SIGUSR1` / `SIGUSR2` — 用户自定义
- `SIGCHLD`（17）— 子进程状态变化

### 默认动作分类

- **Term**（终止）— 大多数信号
- **Core**（核心转储）— 异常信号（`SIGSEGV`、`SIGABRT` 等）
- **Ign**（忽略）— `SIGCHLD`、`SIGURG`、`SIGWINCH`
- **Stop**（停止）— `SIGSTOP`、`SIGTSTP`
- **Cont**（继续）— `SIGCONT`

### 关键命令

```bash
kill PID              # 发送 SIGTERM
kill -9 PID           # 发送 SIGKILL
kill -HUP PID         # 重新加载配置
kill -STOP PID        # 暂停进程
kill -CONT PID        # 继续进程
pkill name           # 按名称杀
killall name         # 按名称杀所有
```

### 处理 EINTR 模式

**模式 1：重试**

```c
while (read(fd, buf, n) == -1 && errno == EINTR);
```

**模式 2：SA_RESTART**

```c
sa.sa_flags = SA_RESTART;
sigaction(SIGINT, &sa, NULL);
```

**模式 3：信号驱动 IO**

```c
/* 使用 epoll + 信号处理 */
```

### 信号安全规则

**handler 中允许：**

- 设置 `volatile sig_atomic_t` 标志
- 写入原子变量
- 调用 `_exit()`（不是 `exit`）
- 重新设置信号
- 写无锁数据结构
- 唤醒阻塞操作（write to pipe）

**handler 中禁止：**

- `malloc` / `free`
- `printf` / `fprintf`
- `pthread_mutex_lock`
- 任何阻塞调用
- 调用非 async-safe 函数

### 一句话总结

**信号 = 进程异步通知机制。`SIGKILL`/`SIGSTOP` 不可捕获（内核强），`SIGTERM` 可捕获，应做优雅关闭。Handler 只设标志，复杂逻辑在主程序。多线程程序用 `pthread_kill` 定向发送。**
