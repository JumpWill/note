# 进程的状态

Linux 进程的状态分为 **两大类：活着的 / 死了的**。`ps` / `top` / `cat /proc/<pid>/status` 中的 `State` 列就是这些标识。

## 1. 总览：状态字符表

| 字符 | 状态 | 含义 | 类别 |
| --- | --- | --- | --- |
| **R** | Running | 正在运行 / 就绪（在 run queue 中等待 CPU） | 活着 |
| **S** | Interruptible sleep | 可中断睡眠，等待 IO / 信号 | 活着 |
| **D** | Uninterruptible sleep | 不可中断睡眠（内核在等 IO 完成） | 活着 |
| **T** | Stopped | 暂停（被 `SIGSTOP` / debugger） | 活着 |
| **t** | Tracing stop | 被 ptrace 调试中（`gdb attach`） | 活着 |
| **I** | Idle | 内核态空闲线程（v3.13+） | 活着 |
| **X** | Dead | 进程已经不可见（瞬时态，几乎看不到） | 死了 |
| **Z** | Zombie / defunct | 进程已退出，等待父进程 wait() | 死了 |

> 新版内核还有 `W` (Waking / paging)，`P` (Parked)，但实战很少见。

## 2. 活着：R / S / D / T

### 2.1 R（Running / on run queue）

```text
进程状态 R
  │
  ├─ 真正在 CPU 上执行：手握 CPU
  │
  └─ 在 run queue 等 CPU：操作系统随时可调度
```

- 进程要么正在被 CPU 执行，要么在 ready queue 里等着
- CPU 调度窗口里，task 在 R 上的累计时间 = 进程占用 CPU 时间

### 2.2 S（Interruptible Sleep）

```text
S（可中断睡眠）
  │
  ├─ 等待网络 / 磁盘 / 锁 / 信号
  │
  └─ 可被信号唤醒，ctrl+c / kill -15 都能 kill
```

- 大多数情况下进程都是 S（等待 IO / 用户输入）
- `cat /proc/<pid>/status` 显示 `State: S (sleeping)`

### 2.3 D（Uninterruptible Sleep）—— 重点

```text
D（不可中断睡眠）
  │
  └─ 内核态 IO 等待（设备层正在响应不过来）
     │
     └─ 不可以被信号唤醒！
        不能用 ctrl+c 也不能用 kill -9 杀
        必须等内核做完这次 IO 才能退出
```

- **典型原因**：
  - 磁盘 IO 拥塞
  - NFS / 远程存储卡死
  - 内核层 driver bug
  - iSCSI / SAN 延迟

- **观察**：

```bash
ps -eo stat,pid,etime,comm | awk '$1 ~ /D/ {print}'
```

`D` 长时间不退出通常意味着"卡死"。

### 2.4 T（Stopped）

- 被 `SIGSTOP` / `SIGTSTP` / `Ctrl+Z` 暂停
- debugger (`gdb`) 设置断点后也会让进程进入 `t`
- `kill -SIGCONT <pid>` 恢复

### 2.5 t（Tracing stop）

- 被 ptrace 调试（`gdb attach` / `strace -p`）
- 几乎等同于 T 的含义

### 2.6 I（Idle）

- Linux 内核 3.13+ 引入
- 仅在内核态空闲线程（kworker）出现
- 平均负载统计中 I 不计入 load average

## 3. 死了：Z / X

### 3.1 Z（Zombie）

```text
子进程死亡
  │
  ├─ 内核释放：内存 / 文件 / IO 等所有资源
  │
  └─ 保留：pid + 退出状态 / 一些运行信息
      ↓
      等待父进程 wait() / waitpid() 来读取
      ↓
      父进程读取后 → 子进程彻底消失
```

**僵尸进程是 OS 的一种优化机制**：

- 一个进程死掉之后，会把其占用的 CPU、内存资源都释放掉
- 但会保留进程的状态信息（pid 号、退出状态等）
- 这些保留下来的信息是 OS 给父进程准备的
- 每个进程死掉之前都会进入僵尸进程的状态
- 僵尸进程通常由父进程来回收

```bash
# 看僵尸
ps -o stat=,pid=,comm= -p <pid>     # Z
# 找父进程
ps -o ppid= -p <pid>

# 父进程没 wait 时怎么办？
#  1) 父进程修复：加 SIGCHLD handler / wait()
#  2) 重启父进程：Zombie 由 init / systemd 接管并 wait
```

### 3.2 X（Dead）

- 进程已经"不可见"，瞬时态，几乎看不到
- 内核回收阶段的最后一刻

## 4. 状态修饰字符（第二列 STAT）

`ps -l` 输出除了第一列的状态（R / S / D ...），还有修饰位：

| 字符 | 含义 |
| --- | --- |
| `<` | 低优先级进程 |
| `N` | 高优先级（nice 值负） |
| `+` | 前台运行的进程（与 tty 关联） |
| `s` | session leader（会话首进程） |
| `l` | 多线程（multi-threaded） |
| `L` | 页面锁定（page locked in memory） |
| `T` | 暂停（stopped） |

```text
S      → 普通后台
S+     → 前台运行（可 ctrl+c）
R<     → 高优先级在 CPU 上跑
Ssl    → 会话首进程 + 多线程（典型 sshd / init）
```

## 5. 状态之间的关系

```text
                 fork()
 父进程 ────────────────────────────────────► 子进程
                                          │
  D │ R │ S │ T (t) │ Z          状态变化
   │
   ▼ 系统调用返回
   ▼
   R  <──────  S  ─────► D
   │           │           │
   │           │           └── IO 慢
   │           │                │
   │           │           唤醒 → R
   │           │
   │     SIGTERM/SIGSTOP
   │           │
   │           ▼
   │           T ──SIGCONT──► R
   │
   └── exit() / _exit() ─────►  Z（瞬时）
                                 │
                                 └── 父 wait() ──► X（消失）
```

## 6. 看进程状态：4 个命令

### 6.1 `ps`

```bash
ps aux
ps -ef
ps -eo pid,ppid,stat,etime,comm
ps -L -p <pid>         # 进程内的线程 + stat
ps -eo stat=,etime=,comm= | awk '$1 ~ /D/'
```

### 6.2 `top`

```bash
top -H          # 按线程（PID 列变成 LWP / TID）
top -o %CPU      # 按 CPU 排
top -o %MEM
```

### 6.3 /proc/<pid>/status

```bash
cat /proc/<pid>/status
# Name:   foo
# State:  S (sleeping)
# Tgid:   1234
# Ngid:   0
# Pid:    1234
# PPid:   1
# TracerPid:      0
# Uid:    1000    1000    1000    1000
# Gid:    1000    1000    1000    1000
# FDSize: 64
# Threads:        12
# ...
```

### 6.4 /proc/<pid>/wchan

```bash
cat /proc/<pid>/wchan
# flush-253:0      ← 磁盘刷盘
# nfs:rpc_wait     ← NFS 等待
# inet_csk_accept  ← 网络 accept
# pipe_wait        ← 管道读等待
```

- `0` 表示"在用户态 / running"
- 非 0 都是内核函数名

## 7. 实战：典型状态排查

### 7.1 D 状态卡死

```bash
ps -eo stat,pid,etime,comm | awk '$1 ~ /D/ {print}'
#  D 12345  03:12  mysqld

# 看 wchan
cat /proc/12345/wchan
# flush-253:1

# iostat 看 IO
iostat -xz 1 5
```

- D 状态不能 kill，只有等 IO 完成
- 长时间 D → 物理存储问题 / NFS 卡死 / 内核 bug

### 7.2 大量 Z

```bash
ps -eo stat=,comm= | grep '^Z' | wc -l
# 5

# 找父进程
ps -eo pid,ppid,stat=,comm=
```

- 父进程没 wait() 子进程，僵尸越来越多
- 父进程修复或重启（僵尸会被 init 回收）

### 7.3 T / t（暂停）

```bash
ps -eo pid,stat,comm | grep 'T \|t '
kill -CONT <pid>             # 恢复
kill -STOP <pid>             # 暂停
```

- `Ctrl+Z` 把前台任务送到后台 T
- `kill -STOP` 也 T

### 7.4 进程死循环

```bash
top -H -p <pid>             # 线程视角
perf top -p <pid>            # on-CPU 栈
```

## 8. 一句话总结

```text
进程状态：
  R    正在 / 即将跑 CPU
  S    可中断睡眠（大多数时候都在这）
  D    不可中断睡眠，等 IO 不能 kill
  T/t  暂停 / 调试暂停
  I    内核空闲线程
  X    死亡瞬时
  Z    僵尸（待父 wait）
常用观察：ps / top / /proc/<pid>/status / wchan
```
