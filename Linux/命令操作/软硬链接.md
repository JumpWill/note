# Linux 硬链接与软链接

Linux 文件系统里"文件名 + inode + 数据块"在 inode.md 已经讲过；这里说**多文件指向同一 inode** 的两种形式：硬链接（hard link）与符号链接（symbolic link / symlink）。

```text
硬链接:
  /path/A  ─┐
             ├──► inode 123 ──► 数据块
  /path/B  ─┘       │

软链接 / 符号链接:
  /path/A  ──► inode 456 ──► 路径字符串 "/path/B"
                              ▼
                          inode 123 ──► 数据块
```

## 1. 概览对比

| 维度 | 硬链接（hard link） | 软链接（symbolic link） |
| ---- | ------------------ | ------------------------ |
| inode | 同一个 inode | 新 inode |
| 内容 | 直接指向数据 | 存"目标路径"字符串 |
| 跨文件系统 | ❌ | ✔ |
| 链接目录 | ❌（内核 protected_hardlinks） | ✔ |
| 链接名独立性 | 同 inode，等价 | 通过路径再解析 |
| 删除一个 | 仅 link count −1 | 软链本身被删 |
| 链接目标删除 | 不影响（链接仍可用） | 软链 dangling，访问 ENOENT |
| 权限位 | 真实显示 | 显示 `lrwxrwxrwx` |
| inode 资源 | 几乎不额外占用 | 占用 1 个 inode（vs 60B 内联存储） |
| 大小 | 与源文件相同 | 一段字符串 |
| 替代 | NTFS hard link、macOS Finder 替身 | Windows Shortcut / symlink |
| 反向遍历 | `find / -inum N` | `readlink / -name symlink` |
| 备份工具感知 | `cp -l / rsync --link` | 跟随或 `-P` |

## 2. 硬链接（hard link）

### 2.1 含义

新建一个**目录项（dirent）**，使其指向**已存在的 inode**。本质是同一份数据，多个名字。

```text
mkdir -p /data
echo "hello" > /data/orig
ln /data/orig /data/alt       # 创建硬链接

ls -li /data/
1234567 -rw-r--r-- 2 root root 6 /data/alt
1234567 -rw-r--r-- 2 root root 6 /data/orig
         ↑
         同一 inode，link count = 2
```

`1234567` 是 inode 号，相等；`-rw-...-r--` 链接计数显示为 2；两个文件名等价访问。

### 2.2 创建

```bash
ln SOURCE LINK              # 默认硬链接
ln -s ...                  # 软链接（见下）

ln foo bar                 # foo 指向相同 inode
ln -P src link             # 强制跟踪：创建硬链跟随符号链接
ln -f src link             # 强制覆盖
ln -i src link             # 询问
ln -T src link             # 把 link 当文件名（不作为目录路径解释）
ln -v src link             # verbose
ln -b                      # 备份已存在的 target
ln -t DIR src...           # 目标目录
```

### 2.3 增 / 删

```bash
# 创建
echo "x" > /tmp/a
ln /tmp/a /tmp/a2          # a 与 a2 是同一份
stat /tmp/a /tmp/a2

# 删除原文件
rm /tmp/a
cat /tmp/a2                # 仍能读
```

`unlink` 命令（同 unlink(2) 系统调用）：

```bash
unlink /tmp/a2             # 相当于 rm，但只能删单文件
```

### 2.4 链接数追踪

```bash
find / -xdev -samefile /etc/hostname   # 找出同一 inode 的全部硬链接
find / -inum 1234567 -ls
find / -links 2 -type f                 # 链接数 = 2
find / -links +1 -size +10M            # 链 ≥ 1 的 > 10M 文件
```

`nlink` 字段在 `stat` 中：

```bash
stat /etc/passwd
#  显示 ... Links: 1 ...
```

### 2.5 系统中的硬链接

- 同一目录的 `.` 和 `..`
- `<file>` 与 `<file>.bak` 在 rsync / cp -l 备份中
- `sendmail` / `/usr/sbin/sendmail.sendmail` 等版本控制
- `alternatives` 系统：`/etc/alternatives/python3` 是真实文件，硬链接到多版本

```bash
ls -li /etc/alternatives/python*
```

### 2.6 跨设备 / 目录硬链接限制

```bash
# 跨 fs 报错
touch /tmp/a
ln /tmp/a /mnt/b/x         # Operation not permitted / Invalid cross-device link

# 链接目录
mkdir /tmp/d
ln /tmp/d /tmp/d2
# 默认 ln: failed to create hard link '/tmp/d2': Operation not permitted
```

原因：

- 跨文件系统 inode 号不同 / 不共享
- 链接目录会形成目录环，`. / ..` 引用难处理

Linux 保护机制：

- `fs.protected_hardlinks = 1`：非特权用户只能链接"自己拥有" 的文件
- `fs.protected_symlinks = 1`：防止在某些情形下跟随符号

### 2.7 软 / 硬链行为对比实例

```bash
echo "data" > /tmp/x
ln /tmp/x /tmp/x.hard
ln -s /tmp/x /tmp/x.soft

# 删除原文件
rm /tmp/x

echo "x.hard 可读："
cat /tmp/x.hard     # OK
echo "x.soft 状态："
ls -la /tmp/x.soft  # 失效 (broken symlink)
cat /tmp/x.soft     # No such file or directory
```

硬链接 = 入口；软链接 = 名字。

## 3. 符号链接（symlink）

### 3.1 含义

软链接是**单独 inode**，文件内容是"目标路径"字符串。内核在路径解析时自动追链：

```text
/path/link -> "/path/target"  (max_path 4096 chars in ext4)
```

### 3.2 创建

```bash
ln -s TARGET LINK              # 创建软链接
ln -s .../target link
ln -snf TARGET LINK           # 强制覆盖 (不询问)

ln -s /usr/local/bin/python3 /usr/bin/python3
ln -snf /opt/app-2.0 /opt/app       # 切换版本
```

常用选项：

| 选项 | 含义 |
| --- | ---- |
| `-s` | 创建符号链接 |
| `-f` | 强制覆盖 |
| `-n` | 把 LINK 当普通文件 (不作为目录) |
| `-T` | 同上 |
| `-i` | 询问 |
| `-r` | 软链接本身，可以同相对路径 |

### 3.3 读、追踪、修改

```bash
readlink /tmp/x.soft            # 显示 target
readlink -f /tmp/x.soft         # 解析所有链 + 绝对路径
readlink -e /tmp/x.soft        # 不可解析则报错
readlink -m /tmp/x.soft        # 模拟绝对路径(不强制存在)
readlink -n /tmp/x.soft        # 末尾 NUL 输出
realpath /tmp/x.soft           # 同 readlink -e
```

修改 target：

```bash
# 方法 1：删除并重建
ln -snf /new/path link

# 方法 2：直接修改（要求 GNU coreutils 8.32+）
# 不支持原地编辑

# 方法 3：用 sed -i 替换（需重建）
```

```bash
# 系统级：批量切换版本
ln -snf python3.10 /usr/bin/python3
```

### 3.4 追链命令

```bash
readlink -f dir/file
realpath dir/file
stat -L file                  # 追链，显示目标状态
ls -L dir                     # 追链
ls -H dir                     # 半追链
cp -L ...                     # 复制时追踪为普通文件
cp -P ...                     # 复制时保持链（默认行为）
```

### 3.5 dangling / broken

```bash
# 列出失效链
find / -xtype l 2>/dev/null
find / -type l ! -exec test -e {} \; -print 2>/dev/null
```

批量清：

```bash
find /opt -xtype l -delete    # ext4 / xfs 同支持
```

### 3.6 系统中的符号链接

```bash
ls -l /usr/bin/python*         # 软链
ls -l /usr/lib/x86_64-linux-gnu/ld-linux-x86-64.so.*   # 内含路径
ls -l /etc/init.d/             # /etc/rc?.d/ 接 /etc/init.d/
ls -l /var/run -> /run        # Ubuntu 18+ 链接回 /run
ls -l /etc/systemd/system/dbus.service   # multi-user.target dependency
```

### 3.7 absolute vs relative

```bash
# 推荐：绝对路径
ln -s /opt/app-1.2.3 /opt/current

# 相对：可移植但易错
cd /opt
ln -s app-1.2.3 current        # link 处于同目录时可
```

迁移 / 重定位时相对链可能断裂，CI / 容器中推荐 absolute。

### 3.8 链接路径存储

ext4 中：

```text
short symlink (max 60 bytes):
  - 目标 inline 在 inode 中
long symlink:
  - inode 指向数据块
```

- ext4：路径最长 4096 字节
- btrfs：不限
- limit 内联存储：节省 block

### 3.9 跨文件系统软链

```bash
ln -s /mnt/nfs/data /local/data-link
cat /local/data-link           # 自动追链过 NFS

# 链接"目录"
ln -s /opt/app-2.0 /opt/app
ls /opt/app                    # 解到 /opt/app-2.0
```

## 4. inode / link count 视角

### 4.1 ls -li 输出解读

```text
12345 -rw-r--r-- 2 root root 6 Apr  1 12:00 /etc/hosts
12346 lrwxrwxrwx 1 root root 9 Apr  1 12:00 /usr/bin/python -> python3
         ↑     ↑  ↑
         权限  链  ID
         数字=链数
```

| 字段 | 含义 |
| --- | ---- |
| inode | 同一行的 inode 相等 |
| mode | 如 `lrwxrwxrwx` |
| nlink | 硬链接数 |
| size | 普通文件字节数；软链 = 路径长度 |
| 文件类型第 1 字符 | `-` 普通 / `l` 链接 / `d` 目录 / `p` pipe / etc. |

### 4.2 stat 输出

```bash
stat /etc/hosts
# Inode: 12345   Links: 1

stat /usr/bin/python3
# Inode: 12346   Links: 1
```

### 4.3 nlink 字段更新

| 行为 | nlink 是否变化 |
| --- | --- |
| `cp file copy` | 否（独立 inode） |
| `ln file link` | +1 |
| `rm file` | −1，若降为 0 才释放 |
| `mv file` | 否（rename 只改 dirent） |
| 跨目录 `mv` | 不变（同 fs） |
| `cp -l src dst` | +1（硬链） |

### 4.4 find 按 nlink 找

```bash
find /tmp -type f -links +1
find /var -type f -links 1     # 仅原文件
find / -type l ! -links 1     # 任意链
find / -samefile /path/of/file
```

## 5. 备份 / 部署场景

### 5.1 rsync 用硬链做增量备份

```bash
# 完整备份 / backup/0
rsync -a /data/ /backup/0/

# 增量 / backup/1：硬链到 0 中未变文件，新文件复制
rsync -a --link /data/ /backup/1/

# 优点：空间 ~ 一次完整，但保留 2 份"完整"历史
du -sh /backup/0 /backup/1
```

### 5.2 cp -l

```bash
cp -l file link                # 创建硬链接
cp -al src dst                 # 递归硬链
```

### 5.3 软链做版本切换

```bash
ln -snf /opt/app-v1.2 /opt/app
ln -snf /opt/app /etc/profile.d/app.sh  # 决定版本
```

新版本部署：

```bash
mkdir -p /opt/app-v1.3
ln -snf /opt/app-v1.3 /opt/app          # 原子切换
```

容器镜像运维常用 such as `latest` `stable` 标签。

### 5.4 current / stable 多版本

```bash
ls -l /usr/bin/python
# /usr/bin/python -> /usr/bin/python3 -> python3.10
ls -l /usr/bin/python3
ls -l /usr/bin/python3.10
```

`/etc/alternatives` 系统做版本管理：

```bash
update-alternatives --display python
update-alternatives --config python
```

## 6. 系统内部例子

### 6.1 链接 vs 真实文件

```bash
ls -li /bin
ls -li /usr                     # 多数 distro 是镜像 / 多 fs
ls -li /var/run                 # Ubuntu 软链 /run
ls -li /usr/lib                 # 多为真实目录
```

### 6.2 系统服务软链

```text
/lib/systemd/system/syslog.service
  -> /lib/systemd/system/rsyslog.service  (部分系统)
```

```bash
find /etc/systemd /lib/systemd -type l -name '*.wants/*.service'
find /etc/init.d -type l -ls
```

### 6.3 fs.protected_hardlinks

```bash
sysctl fs.protected_hardlinks
sysctl fs.protected_symlinks
```

决定非特权用户是否能跨目录链接、追链等。生产建议开启。

## 7. 常见错误与排查

### 7.1 软链路径错误

```bash
ln -s /old/path /tmp/link
ls -la /tmp/link
file /tmp/link
```

```text
link -> /old/path
```

如果 `/old/path` 不存在：`ls -la` 看见链；`cat /tmp/link` 失败 ENOENT。

### 7.2 软链 vs 真实文件的 `rm`

```bash
ln -s /etc/passwd /tmp/passwd-link
rm /tmp/passwd-link             # 删的是链，源不动
rm /etc/passwd /tmp/passwd-link   # 删两个名字
```

不会"跨过"软链进到原目录。

### 7.3 跨设备硬链接

```bash
mount | grep /tmp
stat /dev/shm                   # tmpfs
ln /tmp/a /dev/shm/a            # 报错
```

### 7.4 inode 满了

硬链接不耗 inode，因为它就是原 inode；软链接 = 1 个 inode + tiny inlined content。所以"软链大批量"会占 inode（见 inode.md 中的"inodes 耗尽"排查）。

### 7.5 backup 工具的硬链支持

- `tar -h` 跟随符号链接成普通文件
- `tar --hard-dereference` 跟随硬链
- `cp -P` 默认，保持软链接
- `cp -L` 跟随
- `rsync --no-links` 跳出硬链

### 7.6 容器 / overlay

```bash
docker exec CONTAINER ls -l /etc/hosts
```

容器 rootfs 由 overlay 组成，链接行为部分破坏：

- `ln` 在容器内创建的是 overlay 文件
- 跨层链接不一定可见
- 备份 / 迁移要 `-R` 才保留

### 7.7 rsync 硬链断开

```bash
rsync -aH src/ dst/
```

`-H` 保留硬链；不带会展开成独立 inode 文件。

## 8. 命令汇总

### 8.1 创建

| 命令 | 用途 |
| --- | --- |
| `ln s t` | 硬链 |
| `ln -s t l` | 软链 |
| `ln -snf t l` | 强覆软链 |
| `ln -i t l` | 询问 |
| `cp -l s t` | 创建硬链 |
| `rsync -l` / `--link` | 同步时创建硬链 |

### 8.2 查询

| 命令 | 用途 |
| --- | --- |
| `ls -li file` | 查 inode + 链接数 |
| `stat file` | 详情 |
| `readlink link` | 显示 target |
| `readlink -f link` | 解析目标绝对路径 |
| `realpath link` | 同上 |
| `file link` | "symbolic link to /..." |
| `find / -inum N` | 同 inode 全文件 |
| `find / -samefile f` | 同 inode 全文件 |
| `find / -type l` | 全软链 |
| `find / -xtype l` | 失效软链 |

### 8.3 修改 / 删除

| 命令 | 用途 |
| --- | --- |
| `rm file` | 减链接数（普通） |
| `rm link` | 删硬链 |
| `unlink link` | 删单个文件 / 链 |
| `ln -snf new old` | 重定向软链 |
| `mv s t` | rename（同一 fs 不变 inode） |

### 8.4 找链接

```bash
# 找出 inode 12345 的全文件
find / -xdev -inum 12345

# 找出同名链接 / 链接目录
find / -name '*.tmp' -links +1

# 找出失效软链
find / -xtype l 2>/dev/null

# 删除所有失效软链
find /opt -xtype l -delete

# 反向：找出指向同一数据的所有硬链
find / -xdev -type f -samefile /etc/hosts
```

## 9. 一句话总结

```text
硬链接 = 同一个 inode 多入口（同设备、不能跨、删名字 ≠ 删数据）
软链接 = 新 inode 内容是路径字符串（可跨、可挂、可失效）
判定 ls -li / stat：硬链 inode 相同 / 软链 size 是路径长度
软件版本切换：ln -snf；增量备份：rsync --link
```
