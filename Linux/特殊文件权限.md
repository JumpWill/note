# Linux 特殊文件权限 (setuid / setgid / sticky bit)

Linux 文件权限位有 12 位（3 组 octal）：基础 9 位（owner / group / other: r / w / x）+ 3 个"特殊位"。

```text
                    owner                group                other
                  r w x                r w x                r w x
                  + setuid  +          + setgid  +          + sticky
                                   
传统位（执行前查）  ↓      ↓              ↓                  ↓
                                                  4        2        1
```

| 名称 | 缩写 | 八进制位 | 显示形态 |
| ---- | ---- | -------- | -------- |
| **setuid（Set User ID）** | SUID | 4xxx（第 4 个八进制位） | `rwsr-xr-x` 中的 `s`（owner `x` 位） |
| **setgid（Set Group ID）** | SGID | 2xxx | `rwxr-sr-x` 中的 `s`（group `x` 位） |
| **sticky bit** | t | 1xxx | `rwxrwxrwt` 中的 `t`（other `x` 位） |

## 1. 概念与作用

### 1.1 SUID（Set User ID on execution）

可执行文件被设置 SUID 时：

- 用户执行该文件时，进程**实际 UID 不取用户，而取文件 owner**
- 典型用途：以文件 owner 身份提权运行（passwd / sudo / ping 等）

```text
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ...   # owner x 位是 s = SUID
```

```text
alice $ /usr/bin/passwd     # 改 /etc/shadow
alice $ id -u               # 现实是 alice
但 passwd 写入 /etc/shadow 却是 root 在做（owner is root）
```

### 1.2 SGID（Set Group ID on execution）

- 文件被设置 SGID 时，进程实际 GID = file group，权限位受 group 权限位约束
- 目录被设置 SGID 时，新建的子文件 / 子目录继承该目录的 group（project 协作常用）

```text
$ ls -l /usr/bin/crontab
-rwxr-sr-x  root crontab ...   # group x 位是 s = SGID

$ ls -ld /var/lib/shared
drwxrws--- shared team       # 在 shared 目录下新建文件，组自动 = team
```

### 1.3 sticky bit

- **目录**被设置 sticky 时：**只有文件 owner / 目录 owner / root** 能在该目录删 / 改 / 重新链接文件
- 防止公共目录被互相 delete / rename
- **文件**被设置 sticky 时，Linux 自身**几乎无作用**（历史是 file 共享者放内存中），常见仅做"标记"

```text
$ ls -ld /tmp
drwxrwxrwt root root  ...    # 任何用户可写，但只能删自己的
```

```bash
mkdir /tmp/public
chmod 1777 /tmp/public       # sticky + 777
```

## 2. 三种符号

### 2.1 数字 rwx 位

- 4 = SUID 位
- 2 = SGID 位
- 1 = sticky 位
- 0–7 普通 rwx

### 2.2 设置方法

```bash
chmod u+s file               # SUID
chmod g+s file               # SGID
chmod +t dir                 # sticky
chmod 4755 file              # SUID + rwxr-xr-x
chmod 2755 file              # SGID + rwxr-xr-x
chmod 1755 dir               # sticky + rwxr-xr-x
chmod 7550 file              # SUID+SGID+sticky + 050 (--x...)
chmod 7666 file              # rw-rw-rw-，无任何特殊位
```

### 2.3 显示形态

| 状态 | owner x | 形态 |
| --- | --- | --- |
| 无 SUID / SUID 但 owner 无 x | - | `-rwSr-xr-x` 大写 `S` |
| SUID + owner 有 x | 正常 | `-rwsr-xr-x` 小写 `s` |
| 同理 SGID 在 group 位 | | |
| 同理 sticky 在 other 位 | 末位 `t`（无 x 时 `T`） | |

## 3. SUID 经典例子

| 程序 | 文件 owner | 目的 |
| --- | --- | --- |
| `/usr/bin/passwd` | root | 改 `/etc/shadow` |
| `/usr/bin/mount` | root | 调用 `mount(2)` 内核态 |
| `/usr/bin/umount` | root | 同上 |
| `/usr/bin/ping` | root / cap_net_raw | 打开 ICMP raw socket |
| `/usr/bin/su` | root | 鉴权切换 |
| `/usr/bin/sudo` | root | 受控提权 |
| `/usr/bin/chsh` | root | 改 /etc/passwd 中 shell 字段 |
| `/usr/bin/newgrp` | root | 改变组身份 |
| `/usr/bin/find` | 不一定 | 不常见 |

### 3.1 列举所有 SUID

```bash
find / -perm -4000 -type f 2>/dev/null
find / -perm /u+s 2>/dev/null
```

### 3.2 找出 SGID

```bash
find / -perm -2000 -type f 2>/dev/null
find / -perm /g+s 2>/dev/null
```

### 3.3 找出 SUID 且 owner 不是 root

```bash
find / -perm -4000 -type f ! -user root 2>/dev/null
```

疑似入侵痕迹排查时这是关键一步。

### 3.4 设置 SUID

```bash
chmod u+s /usr/local/bin/myscript
chmod 4755 /usr/local/bin/myscript
```

## 4. SGID 在目录中的作用

新建文件 / 目录时，若该目录带 SGID：

- new file / dir 的 group = parent dir 的 group
- 不需要每次手动 `chgrp`

```bash
mkdir -p /opt/project
chgrp team /opt/project
chmod 2775 /opt/project
# team 组成员在 /opt/project 下创建文件自动属于 team
```

新目录同样继承 SGID：

```bash
ls -ld /opt/project/sub
# drwxrwsr-x ...
```

如果希望"inheritable SGID" 还能对新目录生效，需要：

```bash
# ext4：chattr +d /  setfattr -n security.SGI  (mac 默认)
chmod g+s                    # 设
chmod -R g+s                 # 已有目录递归
```

POSIX 行为：

- SGID 目录内新建的子目录继承 SGID
- 文件继承（仅权限位，不含模式继承）

## 5. sticky bit 的运用

### 5.1 /tmp

```bash
ls -ld /tmp
# drwxrwxrwt root root ...    t 位
```

效果：用户 `alice` 写的 `wongfoo.txt`，只有 alice / root 可以 rm；任何用户都可读。

```bash
mkdir -p /var/cache/work
chmod 1777 /var/cache/work
chown root:root /var/cache/work
```

### 5.2 用户主目录

```text
/home/alice
drwx------  alice alice      0700
```

非 sticky；他人不能 cd。

### 5.3 应用上传目录

很多 web 服务上传目录被设 1777。

## 6. 数值记忆法

```text
chmod ABCD file
           ↑
           D = special 位：
              4 SUID
              2 SGID
              1 sticky
              5 4+1 SUID + sticky
              7 4+2+1 SUID+SGID+sticky

典型组合：
4755  -rwsr-xr-x   SUID 可执行
2750  drwxr-s---   SGID + 750
1750  drwxr-x--T   sticky + 750
6750  drwsr-s---   SUID+SGID + 750
```

## 7. 实践中的潜在风险与防控

### 7.1 SUID 程序滥用

```text
真正 SUID 风险：
1. 路径注入：当 SUID 程序 spawn 子进程时，PATH 不受控造成子程序被替换
2. 库注入：LD_PRELOAD 等
3. 自解压 EXECVE / argv 滥用
```

缓解：

- 不用 SUID 写服务，用 capability（cap_dac_override, cap_net_bind_service 等）
- 容器 / namespace 中减少 SUID 可执行
- 工具：Lynis / Bastille / docker bench

### 7.2 find 命令

```bash
# find 自身可能带 SUID，谨慎使用
find / -exec /tmp/attacker.sh \;    # 不安全问题
```

正确做法：用绝对路径：

```bash
find / -exec /usr/bin/rm {} \;
```

### 7.3 writable + SUID = 💀

```bash
ls -l /usr/local/bin/myscript
-rwsrwxrwx root root myscript     # 可写 + SUID = 必查
```

任何用户改内容，下次执行即拥有 root。可用以下查找：

```bash
find / -perm -4000 -type f -perm /200 -print        # SUID + group writable
find / -perm -4000 -type f -perm /002 -print        # SUID + other writable
find / -type f -perm -4000 ! -user root             # 非 root SUID（可能异常）
```

### 7.4 防火墙后 SUID

容器 / K8s 必须 **drop SUID binaries**：

```yaml
# K8s securityContext
securityContext:
  allowPrivilegeEscalation: false
  runAsNonRoot: true
```

AppArmor / SELinux:

```text
deny capability fowner,
```

容器镜像剔除 SUID：`find / -xdev -perm -4000 -exec chmod u-s {} \;` 后再打镜像。

## 8. Linux capability 替代 SUID

Linux 2.6 起把 root 权限细分为 40+ capability。给单个二进制一个细粒度权限，不再 SUID。

```bash
getcap /usr/bin/ping
# cap_net_raw=ep

getcap /usr/sbin/sysctl
# cap_sys_admin=ep
```

设 capability：

```bash
setcap cap_net_bind_service=+ep /opt/my-server
```

常见 mapping：

| SUID 操作 | 现代 capability |
| --- | --- |
| `/usr/bin/ping` | cap_net_raw |
| `/usr/bin/mount` | cap_sys_admin |
| 绑定 80 端口 | cap_net_bind_service |
| 设置系统时间 | cap_sys_time |
| 查看路由表 | cap_net_admin |

Docker / K8s：

```bash
docker run --cap-add=NET_ADMIN --cap-drop=SETUID image
```

## 9. 高级 / 反直觉现象

### 9.1 SUID 文件 + 不可执行位

```bash
chmod 4666 file
ls -l file
# -rwSrw-rw-   ← SUID 但 x 没设
```

行为：SUID 不会生效（不可执行）。Linux 显示大写 `S`。

修复：

```bash
chmod 4775 file    # 加回 owner + group + x
```

### 9.2 文件被复制 / 移动，SUID 丢失

```bash
cp /bin/passwd ./testpasswd
ls -l ./testpasswd
# -rwxr-xr-x   ← SUID 丢了
```

原因：cp 默认 mode 也会忽略 SUID。`cp --preserve=mode` 或用 `cp -p`：

```bash
cp -p /bin/passwd /tmp/testpasswd
# 或
( cd /tmp && rsync -a /bin/passwd . )
```

`tar`/`rsync` 等可保留：

```bash
rsync -a --chmod=u+s src dst
```

### 9.3 sticky 在文件上无效（POSIX/Linux）

```bash
chmod 7777 file  # sticky 位
ls -l file
# -rwxrwxrwt
```

Linux 不"留住" 文件 + sticky（除非特殊）。Solaris / FreeBSD 仍保留 honored 行为。

### 9.4 SGID 文件继承

注意：**mkdir** 默认不继承 SGID，**touch** 会保留 SGID 目录中新建的 group。

### 9.5 noatime + SUID

有时 SUID + noatime 配合会出现 EXPECT_BEHAVIOR 错位；建议保留 default。

## 10. shell 中的对应命令行

### 10.1 实用命令汇总

| 命令 | 用途 |
| --- | --- |
| `chmod u+s / u-s` | 设置 / 取消 SUID |
| `chmod g+s / g-s` | 设置 / 取消 SGID |
| `chmod +t / -t` | 设置 / 取消 sticky |
| `chmod 4755 file` | 一行数值设定 |
| `ls -la` | 显示含 `s / t` 位 |
| `stat file` | 显示 octal mode 块 |
| `find / -perm -4000` | 列 SUID |
| `find / -perm /u+s` | 同上 |
| `getcap / setcap` | capability 操作 |
| `chattr +i` | immutable，不能随意改（含 SUID） |

### 10.2 一键排查脚本

```bash
# 找出非 root SUID 文件
find / -perm -4000 -type f ! -user root -ls

# 找出可被全员写的 SUID / SGID
find / \( -perm -4000 -perm -0002 \) -ls
find / \( -perm -2000 -perm -0002 \) -ls

# 同 + SGID
find / -perm -2000 -type f ! -user root -ls

# 显示所有 SUID + file 系统 + label
ls -lZ $(find / -perm -4000 -type f 2>/dev/null)

# 列出 SGID 目录
find / -type d -perm -2000 -ls
```

## 11. 实战例子

### 11.1 找高风险 SUID

```bash
find / -xdev -type f \
  \( -perm -4000 -perm -0002 -o -perm -2000 -perm -0002 \) \
  -ls
```

### 11.2 /tmp 安全

```bash
chmod 1777 /tmp
chown root:root /tmp
mount -t tmpfs tmpfs /tmp -o nodev,nosuid,noexec
```

### 11.3 项目协作目录

```bash
groupadd team
mkdir /opt/project
chown root:team /opt/project
chmod 2775 /opt/project
# team 组能 create / read / write
# 不在 team 组的用户只 read execute
```

### 11.4 容器 / K8s 安全裁剪

```bash
find / -xdev -perm -4000 -exec chmod u-s {} \;
# 之后打基础镜像
```

K8s：

```yaml
securityContext:
  capabilities:
    drop: ["ALL"]
    add: ["NET_BIND_SERVICE"]
```

### 11.5 文件 + sticky 实战

```bash
# 共享可写只允许 owner 删除
mkdir /shared
chmod 1777 /shared
chmod +t /shared

# 测试
echo a > /shared/x_a    # 用户 a
echo b > /shared/x_b    # 用户 b
rm /shared/x_b          # 用户 b 删自己
rm /shared/x_a          # 用户 b 删 a ← Operation not permitted
```

### 11.6 提权路径

```bash
# 经典系统漏：strace 调试 SUID
strace /usr/bin/passwd 2>&1 | head -30
# 同样：ltrace

# 调试时 setuid 被丢弃
perl -e 'use POSIX; print getuid, "\n";'
```

### 11.7 把脚本提权可执行

```bash
cat > /usr/local/bin/checkdisk <<EOF
#!/bin/bash
df -h
EOF
chmod 755 /usr/local/bin/checkdisk    # 普通脚本
chmod 4755 /usr/local/bin/checkdisk   # 跑成 root
```

注意：用 SUID 写脚本是反模式，建议用 cap_setuid + sudoers 限制。

## 12. 与 SELinux / AppArmor / Capability 集成

### 12.1 SELinux

```bash
chcon -t bin_t /usr/local/bin/myscript
semanage fcontext -a -t bin_t '/usr/local/bin/myscript(/)?'
# 让它能继续 SUID
setsebool -P allow_execheap 1
```

## 13. 一句话总结

```text
SUID = 进程以文件 owner 运行（4 + mode）
SGID = 以 group / 目录内子文件继承组（2 + mode）
sticky = 公共目录防被别人的 rm（1 + mode）

排查：find / -perm -4000 / 2000
防控：setuid 能不设就别设；用 capability 替代
```
